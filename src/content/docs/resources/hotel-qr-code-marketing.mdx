## Why QR codes matter for hotels

A hotel is full of high-intent offline moments. A guest reading a spa menu, a diner finishing a meal, an attendee at a wedding, a traveler holding a key card — each is a chance to drive a booking, an add-on or a return stay. QR codes connect those moments to a digital, bookable next step.

The technology is trivial; every phone camera scans a code. The difference between a QR code that works and one that's ignored is **what it leads to**. Too many hotel QR codes open a static PDF, a homepage, or a menu with no way to act. The opportunity is to make the scan **bookable and measurable**.

## Where hotels can place QR codes

| Placement | The bookable moment |
|---|---|
| Guest rooms & key cards | Extend the stay, book a return, add spa or dining. |
| Restaurants & bars | Reserve a table, book a chef's experience, plan a future stay. |
| Spa & wellness | Book treatments and wellness packages. |
| Front desk & lobby | Upsell upgrades, early check-in, late checkout, experiences. |
| Events & weddings | Give attendees a room block or destination storefront. |
| Printed collateral | Brochures, flyers, signage, business cards and welcome books. |
| Out-of-home & local partners | Posters, partner venues and destination placements. |

Each placement should map to a **specific intent** — a spa QR shouldn't drop the guest into a room-only flow.

## What a QR code should lead to

A scan should land on a destination that matches the moment and can complete an action:

- A **bookable offer** — the exact room, package, table, treatment or experience.
- A **storefront** — when one code should present several offers (event hotels, a destination collection, the property's full menu of bookable content).
- A **mobile-first** page — QR traffic is almost entirely on a phone.
- A **measurable** route — so the hotel knows which placement drove the booking.

## How it works on Wink

Wink turns a QR code into a real channel, not a static link.

- **[Studio](/products/studio/) generates the codes.** Create a bookable Shareable Link or asset and download a branded **QR code as PNG or SVG** for print, signage and in-property placements.
- **[WinkLinks](/products/winklinks/) hosts the destination.** When one code should hold more than a single offer, point it at a mobile-first Travel Storefront — bookable hotel cards, offers, lists and maps under one `i.trvl.as/your-name` link.
- **[Booking Engine](/products/booking-engine/) fulfills the booking.** A tap moves into checkout — the right room, rate and add-ons, payment, confirmation — and the whole stay, not just the room.
- **Attribution is preserved.** The booking stays connected to the campaign, placement or partner behind the code, so the hotel can see which QR codes actually create demand.

This is the same closed loop behind [hotel social commerce](/resources/hotel-social-commerce/) — the QR code is just an offline entry point into it.

## A practical QR playbook

### 1 — Pick the moment and the intent

Decide what each placement should sell. A restaurant table tent and a wedding banner are different jobs.

### 2 — Build the destination first

Create the bookable offer or storefront before you print anything. The destination is the campaign; the code is just the doorway.

### 3 — Generate and brand the code

Use Studio to create the QR code and download it as PNG or SVG so it stays crisp at any print size.

### 4 — Design for the scan

Add a clear call to action next to the code ("Scan to book the spa package"), and make sure the landing page loads fast on mobile.

### 5 — Measure and iterate

Track scans-to-bookings by placement. Move codes that don't convert, and double down on the ones that do.

## Common mistakes

- **QR codes that open a PDF or homepage.** The scan must lead to something bookable.
- **One generic code everywhere.** Match the code to the moment and intent.
- **No attribution.** If you can't tell which placement drove the booking, you can't improve it.
- **Desktop-shaped landing pages.** QR traffic is mobile — design for it.
- **Printing before building.** Stand up the destination first, then commit to print.
