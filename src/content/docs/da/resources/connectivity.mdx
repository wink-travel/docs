## Hvorfor forbindelse er vigtigt

Hver bookingsti afhænger af nøjagtig hoteltilgængelighed. Hvis prisen er forkert, mister gæsten tilliden; hvis tilgængeligheden er forkert, risikerer hotellet en mislykket booking; hvis lageret er forældet, fungerer ingen rute pålideligt. Wink driver mere end en bookingknap på hjemmesiden — de samme hoteldata understøtter hjemmesidestier, delbare links, QR-koder, webkomponenter, WinkLinks-butikker, partnerlinks, Traveliko-annoncer, sociale bookingruter, Agentic AI-overdragelser og udviklerflows. Alle har brug for det samme fundament: nøjagtig **ARI** — Tilgængelighed, Pris og Lager.

## De to opsætningsveje

**Vej 1 — Forbind en understøttet udbyder.** Brug denne, når hotellet allerede administrerer priser i en channel manager, PMS, CRS eller prisudbyder, som Wink understøtter. Hotellet vælger udbyderen i Extranet, aktiverer Wink som en kanal i udbyderens dashboard, kortlægger værelsestyper og prisplaner, og udbyderen sender ARI til Wink — hvilket automatisk udfylder Master Rate Calendar. Bedst til hoteller med flere kanaler, hyppige prisændringer, behov for live lager og lavere manuelt arbejde.

**Vej 2 — Indlæs priser manuelt i Extranet.** Brug denne, når hotellet ikke bruger en understøttet udbyder eller ønsker at betjene Wink manuelt via `Distribution > Master rate calendar` — enkelt-dato og masseopdateringer over datointervaller. Bedst til små lagre, tidlig opsætning eller test. **Det kræver disciplin:** hvis priser ændres i driften, skal nogen opdatere Wink. Og hvis en udbyder er forbundet, kan en manuel ændring blive overskrevet, når udbyderen sender sin næste opdatering for de samme datoer.

## Forbundet udbyder vs manuel indlæsning

| Spørgsmål | Forbundet udbyder | Manuel indlæsning i Extranet |
|---|---|---|
| Hvem opdaterer ARI? | Den understøttede udbyder sender opdateringer til Wink. | Hotellet opdaterer priser og tilgængelighed manuelt. |
| Bedst til | Hoteller med flere kanaler, hyppige ændringer, live lager. | Lille lager, begrænset brug, ingen forbundet udbyder. |
| Arbejdsmængde | Lavere dagligt arbejde efter opsætning. | Løbende manuel vedligeholdelse. |
| Realtidsadfærd | ARI opdateres automatisk fra udbyderen. | Kun så aktuelt som den sidste manuelle opdatering. |
| Risiko | Kortlægning eller udbyderopsætning skal være korrekt. | Forældede priser eller tilgængelighed, hvis ikke vedligeholdt. |
| Bookingnotifikation | Channel manager / CRS / PMS underrettet, hvor konfigureret. | Hotellet modtager bookingnotifikationer gennem Wink. |

## Understøttede udbydere

Wink understøtter en række channel managers samt PMS-forbindelser direkte eller gennem Channex som proxy. Bekræft din specifikke udbyderversion, opsætningsvej og kortlægningskrav med Wink-teamet, før du går live.

| Udbyder | Type | Noter |
|---|---|---|
| SiteMinder | Channel manager | Direkte integration |
| Cloudbeds | Channel manager | Direkte integration |
| Travelclick | Channel manager | Direkte integration |
| RateGain | Channel manager | Direkte integration |
| D-EDGE | Channel manager | Direkte integration |
| YieldPlanet | Channel manager | Direkte integration |
| Rate Tiger | Channel manager | Direkte integration |
| Hotel Link | Channel manager | Direkte integration |
| Channex | Channel manager + PMS proxy | Direkte, plus proxy for mange PMS-udbydere |
| SynXis | CRS | Ekstra opsætning via SynXis Channel Connect Express kan være nødvendig |

Mange PMS-systemer — for eksempel Mews, Apaleo, Opera Cloud og OTA Sync — kan sende ARI til Wink **gennem Channex** som proxy. Hvis din PMS forbinder til Channex, kan den nå Wink; bekræft din PMS-version og Channex-opsætning før livegang. (Dette er en repræsentativ liste — bekræft din udbyder med Wink-teamet.)

## Udbyderopsætning, kort fortalt

I Extranet, gå til `Distribution > Channel manager`, vælg din prisudbyder og gem. I udbyderens dashboard tilføjes **Wink**-kanalen, og værelsestyper og prisplaner oprettet i Wink kortlægges. Start en fuld prispush, hvis udbyderen ikke gør det automatisk, og tjek Master Rate Calendar — den kan opdatere inden for få minutter (tidsramme varierer efter udbyder og kortlægning). Brug **Verifier** til at simulere en rejsendes prisforespørgsel og test tilgængelighed, valuta, rabatter og prisvisning, før du sender live efterspørgsel. Opret en testbooking først, når teamet forstår notifikationsadfærden.

## Bookingnotifikationer

Forbindelse handler ikke kun om at sende priser *til* Wink — det er også, hvordan bookinger flyder tilbage. Når en booking foretages, kan channel manager, CRS eller PMS underrettes, hvor det er konfigureret; hotellet og gæsten modtager bekræftelses-e-mails; partnere modtager booking- og attribueringsbekræftelse på partner-ruter; og udviklere kan lytte til en `booking.created` webhook for realtidsdetaljer.

## Hvor Wink passer ind

Forbindelse ligger mellem Extranet og Booking Engine. [Extranet](/da/products/extranet/) er hotellets kontrollag for indhold, værelser, prisplaner, restriktioner, tilgængelighed, politikker og Booking Engine-indstillinger; en understøttet udbyder leverer ARI til det, eller hotellet vedligeholder Master Rate Calendar manuelt; og [Booking Engine](/da/products/booking-engine/) bruger disse godkendte data til at opfylde bookinger fra direkte, Social, WinkLinks, partner, Traveliko, Agentic AI og udviklerruter. Den simple regel: **jo stærkere forbindelsen er, desto mere pålidelig er bookingstien.**

## Almindelige fejl

- **At antage, at Wink kan sælge uden aktuel tilgængelighed.** Det har brug for ARI fra en udbyder eller manuelle Extranet-opdateringer først.
- **At forbinde en udbyder, men ikke kortlægge værelser og prisplaner.** Opsætningen er ikke færdig, før kortlægningen er korrekt.
- **At redigere priser manuelt, mens en udbyder er forbundet.** Manuelle ændringer kan blive overskrevet af den næste udbyderopdatering.
- **At glemme at verificere.** Test prisvisning, tilgængelighed og rabatlogik, før live efterspørgsel sendes.
- **At betragte forbindelse som kun en teknisk opgave.** Det påvirker omsætning, markedsføring, partnerruter, konvertering og gæstetillid.
