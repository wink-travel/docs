## Recomendar um hotel não é reservar um

A maior parte das "viagens com IA" hoje para na recomendação. Um assistente sugere três hotéis, depois encaminha o viajante para um site ou OTA para efetuar a reserva. A ligação quebra, o preço pode não estar disponível para reserva, e ninguém mantém o contexto da origem.

Um **agente de IA** é diferente de uma resposta de IA. Um agente não se limita a descrever um hotel — ele age: verifica disponibilidade em tempo real, monta uma reserva, processa o pagamento e pode reagir quando algo muda. Para que isso aconteça com segurança, o agente precisa de mais do que texto. Precisa de dados estruturados, atuais e reserváveis e de uma camada de transação que possa chamar.

Esta é a diferença entre [descoberta de IA](/pt-PT/resources/ai-discovery-hotels/), que é sobre ser **encontrado e compreendido**, e comércio agentic, que é sobre ser **transacionado**.

## O que um agente precisa antes de poder transacionar

Uma reserva de hotel é um evento comercial real: o quarto certo, a tarifa certa, disponibilidade real, políticas, pagamento e uma confirmação que sincroniza com o hotel. Um agente só pode completar isso se cada parte estiver disponível como uma operação chamável.

| O agente precisa de | Por que é importante |
|---|---|
| Oferta estruturada e em tempo real | Dados extraídos da web ficam desatualizados; um agente precisa de inventário atual controlado pelo hotel. |
| Tarifas e disponibilidade em tempo real | Um preço que o agente indica deve realmente poder ser reservado naquele momento. |
| Uma operação de reserva | Criar a reserva tem de ser uma chamada real de API, não um encaminhamento para um formulário web. |
| Pagamento | O agente (ou o viajante através dele) deve poder pagar, com lógica de políticas aplicada. |
| Atribuição | A fonte, campanha ou agente que criou a reserva deve permanecer associada. |
| Eventos | O agente deve poder reagir a confirmações, alterações, cancelamentos e reembolsos. |

Sem estes, um agente pode recomendar — mas não pode reservar.

## Como um agente de IA reserva um hotel na Wink

A Wink é API-first: cada funcionalidade da plataforma é chamável externamente, e um servidor MCP hospedado expõe os contratos de API em tempo real para os agentes. Um fluxo típico de agente:

### 1 — Conectar e ler os contratos em tempo real

O agente conecta-se ao servidor MCP hospedado e usa `api_search` e `docs_search` para encontrar as operações certas e ler os seus esquemas reais de pedido/resposta — sem adivinhações de endpoints, sem documentação desatualizada.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Pesquisar inventário reservável

O agente pesquisa oferta controlada pelo hotel, incluindo pesquisa espacial por geolocalização, e consulta tarifas e disponibilidade em tempo real através dos channel managers conectados.

### 3 — Criar a reserva

A criação da reserva é uma operação da API REST. O agente monta o quarto, tarifa, datas e hóspedes, e cria a reserva através da API.

### 4 — Processar pagamento e confirmar

O [Booking Engine](/pt-PT/products/booking-engine/) executa a transação — checkout, pagamento (a Wink é o comerciante registado), lógica de políticas de cancelamento, confirmação e sincronização da reserva com o PMS ou channel manager conectado. Atribuição de fonte e parceiro são preservadas durante a reserva.

### 5 — Reagir a eventos

O agente pode subscrever `booking.created` e outros eventos webhook para reconciliar, notificar o viajante ou desencadear ações subsequentes.

O princípio: **o agente cria ou encaminha a intenção; o Booking Engine permanece a camada de execução por trás de cada transferência.**

## Pesquisa de IA vs agentes de IA

Eles resolvem tarefas diferentes, e um hotel precisa estar preparado para ambos.

| | Pesquisa de IA / motores de resposta | Agentes de IA |
|---|---|---|
| Objetivo do viajante | Encontrar e comparar hotéis | Reservar e gerir uma estadia |
| O que o hotel precisa | [Conteúdo estruturado e rastreável](/pt-PT/resources/hotel-content-answer-engines/) | API em tempo real, tarifas, reserva, pagamento |
| Estado final | Uma recomendação | Uma reserva confirmada |
| Superfície Wink | Oferta limpa + conteúdo pronto para resposta | API REST, servidor MCP, Booking Engine |

[Descoberta de IA para hotéis](/pt-PT/resources/ai-discovery-hotels/) cobre o lado da pesquisa; este guia cobre o lado da transação.

## Quem constrói agentes no comércio hoteleiro

O comércio de viagens agentic não é só assistentes para consumidores. A mesma infraestrutura alimenta:

- **Assistentes de viagem para consumidores** que pesquisam, reservam e gerem uma estadia de ponta a ponta.
- **Agentes bancários, de fidelidade e super-apps** que incorporam reservas de hotéis numa experiência de cliente existente.
- **Automatizações de parceiros e criadores** que descobrem hotéis elegíveis, constroem ativos e mantêm a atribuição conectada — ganhando uma comissão padrão de 10% sobre reservas confirmadas.
- **Copilotos do lado do hotel** que ajudam equipas a gerar conteúdo e analisar desempenho através do [Extranet](/pt-PT/products/extranet/), [Social](/pt-PT/products/social/) e [Studio](/pt-PT/products/studio/), enquanto o hotel mantém as regras.

## Para onde isto caminha

As capacidades acima estão disponíveis hoje através da API REST e do servidor MCP. A direção é um comércio mais nativo para agentes: primitivas de reserva mais ricas para agentes, identidade e autorização de agentes para transacionar em nome do viajante, e agentes a participar como fontes atribuídas e geradoras de receita na rede de parceiros. A linha condutora é consistente — **infraestrutura de comércio de viagens para agentes de IA**, com o Booking Engine a executar por baixo.

## Erros comuns

- **Tratar descoberta de IA e agentes de IA como o mesmo projeto.** Um é conteúdo e estrutura; o outro é API e execução. Precisa de ambos.
- **Deixar agentes indicarem preços que não podem reservar.** As cotações devem vir de tarifas e disponibilidade em tempo real, não de páginas extraídas.
- **Perder a atribuição na transferência.** Se um agente cria a procura, a reserva deve permanecer ligada a essa fonte.
- **Pular a camada de execução.** Uma resposta não é uma reserva até que o checkout, pagamento e confirmação realmente aconteçam.
