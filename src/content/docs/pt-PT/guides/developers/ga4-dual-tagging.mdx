Ao ligar a sua propriedade Google Analytics 4 ao Wink, os seus eventos de reserva — desde visualizações de quartos até reservas concluídas — são automaticamente enviados para o seu próprio painel GA4 juntamente com as análises do Wink. Sem código, sem configuração técnica da sua parte.

<Aside type="tip">
Precisa de duas coisas do GA4: um **ID de Medição** e um **segredo da API do Protocolo de Medição**. O ID de Medição alimenta o funil de navegação no navegador do hóspede; o segredo da API permite que o Wink registe reservas concluídas (`purchase`) **do lado do servidor**, para que uma venda nunca se perca quando o hóspede é redirecionado para e a partir do fornecedor de pagamento.
</Aside>

---

## Como Funciona

```
Introduz o seu ID de Medição (G-XXXXXXXXXX) e o segredo da API no portal Wink
       ↓
Eventos de navegação (visualizações, carrinho, checkout) são enviados para a sua propriedade GA4 a partir do navegador
Reservas concluídas (purchase) são enviadas do lado do servidor — sobrevivendo ao redirecionamento de pagamento
       ↓
Inicia sessão em analytics.google.com e vê o seu funil completo de reservas
```

---

## O Que Precisa de Fazer

<Steps>

1. **Crie uma Propriedade GA4**

   Vá a [analytics.google.com](https://analytics.google.com): Admin → Criar Propriedade. Defina o seu fuso horário e moeda para corresponder ao seu mercado.

2. **Crie um Fluxo de Dados Web**

   Admin → Fluxos de Dados → Adicionar Fluxo → Web. Introduza `wink.travel` como URL. Isto gera o seu **ID de Medição** (`G-XXXXXXXXXX`). Copie-o.

3. **Crie um Segredo da API do Protocolo de Medição**

   Abra o mesmo Fluxo de Dados Web → desça até **Segredos da API do Protocolo de Medição** → **Criar**. Dê-lhe um nome (ex. "Wink") e copie o **valor do segredo** gerado. Este segredo permite que o Wink registe reservas concluídas do lado do servidor, para que uma venda nunca se perca durante o redirecionamento de pagamento.

4. **Introduza o Seu ID de Medição e Segredo da API no Portal Wink**

   Inicie sessão em [app.wink.travel](https://app.wink.travel), selecione a sua conta e vá ao separador **Personalizações**. Cole o seu ID de Medição e segredo da API nos campos **GA4** e guarde. Está feito — a sua integração GA4 está agora ativa.

   <Aside type="note">
   O segredo da API é **apenas para escrita**: uma vez guardado, nunca mais é mostrado. Em edições futuras, deixe o campo do segredo em branco para manter o valor que já armazenou.
   </Aside>

5. **Marque `purchase` como Evento Principal**

   Volte à sua propriedade GA4: Admin → Eventos → encontre `purchase` → ative **Marcar como evento principal**. Isto faz com que as reservas concluídas apareçam no seu relatório de Conversões.

6. **Veja os Seus Dados**

   Inicie sessão em [analytics.google.com](https://analytics.google.com) e verá as suas reservas, receitas e funil do hóspede — tudo acompanhado automaticamente através do Wink.

</Steps>

<Aside type="note">
Não precisa de instalar qualquer código de rastreio no seu próprio website para esta integração. O Wink trata de tudo. O seu ID de Medição é o destino para onde os seus dados de reserva são enviados, e o seu segredo da API permite que o Wink confirme reservas concluídas do lado do servidor.
</Aside>

<Aside type="tip">
**GA4 e GTM podem ser usados em conjunto.** Se também usar um contentor Google Tag Manager (por exemplo, um contentor Sojern), pode configurar ambos ao mesmo tempo — já não são mutuamente exclusivos. Veja [Integração GTM Analytics](/pt-PT/guides/developers/gtm-dual-tagging).
</Aside>

## O Que Pode Rastrear

Uma vez ligado, a sua propriedade GA4 recebe o conjunto completo de eventos de Comércio Eletrónico Avançado para a sua propriedade:

### Descoberta

| Evento | O Que Significa |
|---|---|
| `view_item_list` | Um hóspede viu a sua propriedade numa pesquisa ou lista de categorias |
| `select_item` | Um hóspede clicou na sua propriedade a partir de uma lista |
| `view_item` | Um hóspede visualizou a página de detalhes do seu hotel |

### Consideração

| Evento | O Que Significa |
|---|---|
| `view_promotion` | Um hóspede viu uma oferta promocional para a sua propriedade |
| `select_promotion` | Um hóspede clicou numa oferta promocional |
| `add_to_wishlist` | Um hóspede guardou a sua propriedade na lista de desejos |

### Funil de Reserva

| Evento | O Que Significa |
|---|---|
| `add_to_cart` | Um hóspede selecionou um quarto ou pacote |
| `view_cart` | Um hóspede visualizou o resumo da reserva |
| `remove_from_cart` | Um hóspede removeu um quarto ou pacote |
| `begin_checkout` | Um hóspede iniciou o processo de checkout |
| `add_payment_info` | Um hóspede introduziu os seus dados de pagamento |
| `add_shipping_info` | Um hóspede introduziu os seus dados pessoais |
| `purchase` | Um hóspede completou uma reserva |
| `refund` | Uma reserva foi cancelada e reembolsada |

Todos os eventos incluem dimensões relevantes como receita, moeda, tipo de quarto e valor da reserva — dando-lhe uma visão completa da jornada do hóspede desde a primeira impressão até à reserva concluída. Para desbloquear dimensões adicionais a nível de propriedade e quarto, como `city_name`, `cancellation_policy`, `bed_type` e mais, veja [Dimensões Personalizadas no GA4](/pt-PT/guides/developers/gtm-dual-tagging#custom-dimensions-in-ga4).

## Rastreio Cross-Domain (Avançado)

A integração padrão acima rastreia tudo o que acontece dentro do Wink. No entanto, se quiser rastrear os hóspedes desde o seu próprio website até à conclusão da reserva no Wink — e atribuir corretamente a fonte original do tráfego (Google Ads, campanhas de email, pesquisa orgânica, etc.) — é necessário um passo adicional em cada lado.

<Aside type="caution">
Esta secção aplica-se apenas se tiver o GA4 instalado no seu próprio website. Se não usar GA4 no seu site, a integração padrão acima é tudo o que precisa.
</Aside>

### Por Que Isto Importa

Sem rastreio cross-domain, um hóspede que visita primeiro o seu website e depois reserva no Wink aparecerá no seu GA4 como uma sessão **Direta** sem ligação à visita anterior. Quaisquer cliques do Google Ads, campanhas de email ou visitas de pesquisa orgânica que levaram à reserva não receberão crédito.

Com o rastreio cross-domain configurado, vê a jornada completa do hóspede:

```
google.com (anúncio pago)
       ↓
o seu website (hóspede navega pelos quartos)
       ↓
wink.travel (hóspede seleciona quarto e reserva)
       ↓
compra atribuída corretamente ao clique original do Google Ads
```

### Ação Necessária: Você

Configure a sua propriedade GA4 para reconhecer `wink.travel` como parte do seu próprio domínio, e não como uma referência externa. Isto diz ao GA4 para unir as duas sessões numa única jornada contínua do hóspede.

<Steps>
1. GA4 Admin → Fluxos de Dados → o seu fluxo
2. Configurar definições da tag → **Configurar os seus domínios**
3. Adicione `wink.travel` como domínio ligado
4. Guarde
</Steps>

### Ação Necessária: Wink

Contacte o [Suporte Wink](https://app.wink.travel) e forneça o domínio do seu website (ex. `seuhotel.com`). O Wink adicionará o seu domínio à lista de exclusão de referências na propriedade GA4 do Wink. Isto impede que o seu website seja registado como fonte de referência, o que de outra forma sobrescreveria a atribuição original do hóspede e iniciaria uma nova sessão.

<Aside type="tip">
A integração padrão acima é suficiente para a maioria das propriedades e dá-lhe visibilidade imediata das reservas e receitas no Wink. O rastreio cross-domain é uma opção avançada que vale a pena configurar quando estiver confortável com os seus dados GA4 e quiser uma análise de atribuição mais profunda.
</Aside>
