Les eines MCP de Wink es publiquen com a **conjunts d'eines** — punts finals enfocats, cadascun cobrint una tasca. Connectes el teu client d'IA al que coincideixi amb la teva feina, un o dos, no a tots.

Cada punt final utilitza **inici de sessió interactiu OAuth2** (flux d'autorització amb codi PKCE): el teu agent d'IA obre una pestanya del navegador, inicies sessió amb el teu compte Wink, i això és tot. No cal gestionar secrets de client.

```bash title="Un integrador de channel manager es connecta a un punt final"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Un hoteler que gestiona les seves pròpies tarifes es connecta a un altre"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## Per què les eines estan dividides en punts finals

Wink exposa al voltant de 500 eines. Donar-les totes a un agent alhora és tècnicament possible — i una mala idea.

**Les definicions d'eines consumeixen context.** Cada eina que un servidor MCP anuncia es carrega a la finestra de context del model abans que faci qualsevol feina, juntament amb la seva descripció i l'esquema complet de paràmetres. Cinc-cents d'aquestes consumeixen una gran part del pressupost que necessita la teva tasca real, en cada sol·licitud.

**La qualitat de la tria disminueix a mesura que la llista creix.** Un agent que tria entre 500 eines amb noms similars fa pitjors eleccions que un que tria entre 40. Si integres un channel manager, aproximadament vint eines són rellevants per a tu; les altres 480 són soroll que dificulta trobar l'eina correcta.

**La feina és realment separable.** Algú que sincronitza disponibilitat des d'un PMS i algú que crea pàgines d'afiliats comparteixen gairebé cap eina. Dividir per tasca significa que cada connexió porta el vocabulari d'una sola feina.

<Aside type="caution" title="Els conjunts d'eines no són permisos">
Triar un conjunt d'eines estret **no** restringeix el que pot fer el teu compte, i triar-ne un ampli no atorga res addicional. Cada eina fa complir els mateixos permisos de compte que el portal web, sota la teva identitat iniciada. Si el teu compte no pot cancel·lar una reserva al Wink Portal, l'agent tampoc pot — independentment del punt final al qual estigui connectat.

Tria conjunts d'eines per **enfocament**, no per seguretat.
</Aside>

Dos hosts serveixen conjunts d'eines. El nombre d'eines és aproximat i creix amb el temps.

### `https://integrations.wink.travel` — integracions de channel manager

Un punt final, perquè aquest host existeix per a una sola feina.

| Punt final | Eines | Què cobreix |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Connexió i verificació d'una integració de channel manager, PMS o CRS |

<Aside type="note" title="Integrar un channel manager vs. gestionar les teves pròpies tarifes">
Són feines diferents per a persones diferents, i no comparteixen punt final.

Un **proveïdor de channel manager, PMS o CRS** integra una sola vegada a través de `integrations.wink.travel/mcp/channel-manager`, i a partir d'aleshores intercanvia propietats, tarifes, disponibilitat i reserves per aquesta integració. Aquest únic punt final és tota la superfície.

Un **hotelier que canvia les seves pròpies tarifes manualment** utilitza els conjunts d'eines de l'extranet a `api.wink.travel` — `/mcp/extranet/rates` i companyia. Aquests no formen part d'una integració de channel manager i un integrador no té motiu per connectar-s'hi.

L'administració de comptes també és a `api.wink.travel`, a `/mcp/settings`. No hi ha `/mcp/settings` a l'host d'integracions.
</Aside>

Cada punt final també porta una eina `ping`, per confirmar que la connexió està activa abans de demanar que faci feina real.

## Quins conjunts d'eines necessito?

| Si ets… | Connecta't a |
|---|---|
| **Integrant un channel manager, PMS o CRS** | `integrations.wink.travel/mcp/channel-manager` — només aquest |
| **Gestionant el contingut d'una propietat** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Gestionant habitacions i tipus d'habitació** | `/mcp/extranet/facilities` |
| **Gestionant preus i disponibilitat** | `/mcp/extranet/rates` |
| **Gestionant reserves diàries** | `/mcp/extranet/operations` |
| **Fent créixer la distribució** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Creant pàgines d'afiliats** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Gestionant pàgines link-in-bio** | `/mcp/link-manager` + `/mcp/social` |
| **Reservant en nom dels viatgers** | `/mcp/travel-agent` |
| **Conciliant diners** | `/mcp/payment` |
| **Creant una experiència de reserva** | `/mcp/booking-engine` + `/mcp/reference` |

Comença amb un. Afegeix-ne un altre quan trobis que et falta alguna cosa que no pot fer — cada connexió és independent, i afegir-ne una no afecta les altres.

<Aside type="tip" title="Vols tot?">
`https://api.wink.travel/mcp` i `https://integrations.wink.travel/mcp` continuen disponibles i serveixen **totes** les eines del seu host. Són útils per explorar què hi ha, però no els recomanem per a la feina diària: la llista d'eines és prou gran per ofegar la teva tasca i degradar la selecció d'eines de l'agent. Prefereix els conjunts d'eines anteriors.
</Aside>

## Com funciona l'autenticació

Els servidors MCP de Wink utilitzen el flux **OAuth2 Authorization Code + PKCE** i suporten **Dynamic Client Registration (RFC 7591)**. Això és el que passa quan et connectes per primera vegada:

1. El teu client d'IA descobreix el servidor d'autorització a partir de les metadades `/.well-known/oauth-protected-resource` del punt final MCP.
2. El client es registra automàticament via **Dynamic Client Registration** — no cal configurar manualment l'aplicació.
3. El client obre una **pestanya del navegador** a `https://iam.wink.travel`. Inicies sessió amb el teu compte Wink i aproves els permisos sol·licitats a la pantalla de consentiment.
4. Wink emet un **token d'accés** vinculat al teu compte i la teva identitat.
5. El client d'IA adjunta el token a cada sol·licitud MCP. Tots els resultats d'eines s'escapen automàticament a la teva entitat gestora.
6. Els tokens expiren després de 3 hores. El teu client d'IA els renova silenciosament en segon pla sense tornar a demanar permís.

Cada crida d'eina s'executa **sota la teva identitat** — les mateixes regles ACL que protegeixen el portal web s'apliquen a l'agent d'IA.

## Àmbits

Quan aproves la pantalla de consentiment veuràs un desglossament del que l'agent està sol·licitant. Els clients MCP utilitzen el mateix vocabulari de permisos que la resta de la plataforma — consulta la [referència completa d'àmbits a la pàgina d'Autenticació](/ca/developers/authentication#scopes).

Hi ha dues coses específiques de MCP:

- **Els àmbits `mcp.read`, `mcp.write` i `mcp.remove` són addicionalment requerits** per obrir el transport MCP. Un client que tingui un àmbit `mcp.*` és admès a qualsevol punt final MCP de Wink, però cada eina que invoqui encara fa complir l'àmbit de secció del punt final que envolta (per exemple, `booking.read`).
- **El client d'IA sol·licita només els àmbits que necessita.** Pots denegar permisos individuals a la pantalla de consentiment — les eines que requereixen un àmbit denegat retornaran un error quan s'invoquin.

**Els conjunts d'eines no canvien res d'això.** El punt final al qual et connectes decideix quines eines es *llisten*, no què se'ls *permet fer*. Connectar-se a `/mcp/payment` no atorga cap permís financer que no tinguessis ja, i connectar-se a `/mcp/reference` no impedeix que una eina allà faci complir el seu propi àmbit. L'autorització es decideix per crida d'eina, a partir del teu token i les autoritzacions del teu compte.

## Resolució de problemes

**No s'obre la pestanya del navegador**

El teu client d'IA potser encara no suporta el flux interactiu PKCE. Verifica que tens una versió recent:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** actualitza des de l'actualitzador integrat de l'aplicació

**`401 Unauthorized` després d'iniciar sessió**

El teu token emmagatzemat pot estar caducat. Elimina i torna a afegir el servidor per forçar un nou inici de sessió:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Per a Claude Desktop i ChatGPT, elimina l'entrada del servidor a la configuració, reinicia l'aplicació i torna a afegir-lo.

**`403 Forbidden` en cridar una eina específica**

L'eina requereix un àmbit que no vas aprovar a la pantalla de consentiment, o un permís que el teu compte no té. Torna a connectar el servidor — la pantalla de consentiment apareixerà de nou i podràs aprovar el permís que falta. Si encara falla, l'eina necessita un permís de compte que no tens; connectar a un altre conjunt d'eines no ajudarà, perquè els conjunts d'eines no atorguen permisos.

**L'eina que necessito no està a la llista**

Probablement estàs connectat a un conjunt d'eines que no cobreix aquesta feina. Consulta el [directori de punts finals](#endpoint-directory) i afegeix el conjunt d'eines que sí que ho fa — les connexions són independents, així que afegir-ne un no canvia res dels altres. Si no saps quin el té, connecta't temporalment a `https://api.wink.travel/mcp`, troba l'eina i després consulta quin conjunt d'eines la llista.

**`404 Not Found` en un punt final de conjunt d'eines**

Revisa bé la ruta — els conjunts d'eines anidats tenen dos segments (`/mcp/extranet/rates`, no `/mcp/extranet-rates`), i els plans tenen un (`/mcp/link-manager`). Tingues en compte que una sol·licitud *no autenticada* a qualsevol ruta sota `/mcp` retorna `401`, no `404`, així que un `401` per si sol no indica si el punt final existeix.

**Em vaig connectar a `api.wink.travel/mcp/channel-manager` i no vaig obtenir res**

Aquest punt final no existeix. La integració de channel manager es serveix només des de `https://integrations.wink.travel/mcp/channel-manager`. Si també necessites llegir o escriure les tarifes pròpies d'una propietat manualment, això és una feina separada en un punt final separat — mira `/mcp/extranet/rates`.

**El servidor apareix però les crides a eines retornen "compte no trobat"**

Estàs iniciat amb un compte Wink que no té cap entitat gestora. Ves a [Wink Portal](https://app.wink.travel) i assegura't que el teu compte està configurat abans d'utilitzar el servidor MCP.

**El token caduca a mitja sessió**

Els tokens són vàlids durant 3 hores. Claude Code i Claude Desktop renoven els tokens silenciosament sense interrompre la sessió. Si veus errors d'autenticació després d'un període llarg d'inactivitat, escriu un nou missatge — el client es reautenticarà automàticament.

**Codex CLI mostra "MCP server unreachable"**

Comprova que el teu `~/.codex/config.json` és JSON vàlid (sense comes finals) i que `"type": "http"` està configurat. Codex requereix transport HTTP per a servidors remots; el transport stdio és només per a binaris locals.

**El menú "Connectors" de ChatGPT no apareix**

El suport MCP requereix la versió **1.2024.352** o superior de l'aplicació d'escriptori ChatGPT i una subscripció activa Plus, Pro, Team o Enterprise. Actualitza l'aplicació i comprova el teu pla a Configuració → Compte.

**El servidor Cursor mostra vermell / "Failed to connect"**

Verifica que el teu `~/.cursor/mcp.json` és JSON vàlid i conté `"type": "http"`. Després ves a **Configuració → Configuració de Cursor → MCP** i fes clic a **Actualitza**. Si l'error persisteix, reinicia completament Cursor — els canvis de configuració no sempre es detecten sense reinici.

**Els servidors MCP de Windsurf no apareixen a la configuració**

Windsurf requereix un reinici complet (no només recarregar la finestra) per detectar canvis a `mcp_config.json`. Fes servir **Fitxer → Surt** i torna a obrir. Si els servidors encara no apareixen, comprova que tens Windsurf **1.4+** a través de **Ajuda → Sobre Windsurf**.

**L'opció "Afegeix servidor" de Cline no és visible**

El gestor de servidors MCP requereix Cline **2.0** o superior. Obre el panell d'extensions de VS Code, troba Cline i fes clic a **Actualitza** si hi ha una actualització disponible. Després d'actualitzar, recarrega VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
