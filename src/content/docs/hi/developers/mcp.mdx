Wink के MCP टूल्स को **टूलसेट्स** के रूप में प्रकाशित किया गया है — फोकस्ड एंडपॉइंट्स, प्रत्येक एक काम को कवर करता है। आप अपने AI क्लाइंट को उन एक या दो से कनेक्ट करते हैं जो आपके काम से मेल खाते हैं, न कि सभी से।

हर एंडपॉइंट **इंटरैक्टिव OAuth2 लॉगिन** (PKCE ऑथराइजेशन कोड फ्लो) का उपयोग करता है: आपका AI एजेंट एक ब्राउज़र टैब खोलता है, आप अपने Wink अकाउंट से साइन इन करते हैं, और बस इतना ही। कोई क्लाइंट सीक्रेट्स प्रबंधित करने की जरूरत नहीं।

```bash title="एक चैनल मैनेजर इंटीग्रेटर एक एंडपॉइंट से कनेक्ट होता है"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="एक होटलियर जो अपनी खुद की दरें प्रबंधित करता है, दूसरे से कनेक्ट होता है"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## टूल्स को एंडपॉइंट्स में विभाजित क्यों किया गया है

Wink लगभग 500 टूल्स को एक्सपोज़ करता है। सभी को एक साथ एजेंट को देना तकनीकी रूप से संभव है — और यह एक खराब विचार है।

**टूल परिभाषाएँ कॉन्टेक्स्ट खर्च करती हैं।** हर टूल जिसे MCP सर्वर विज्ञापित करता है, मॉडल के कॉन्टेक्स्ट विंडो में लोड होता है, उसके विवरण और पूर्ण पैरामीटर स्कीमा के साथ, इससे पहले कि वह कोई काम करे। पाँच सौ ऐसे टूल्स आपके वास्तविक कार्य के लिए आवश्यक बजट का बड़ा हिस्सा हर एक अनुरोध पर खर्च कर देते हैं।

**सूची बढ़ने पर चयन की गुणवत्ता गिरती है।** 500 समान नाम वाले टूल्स में से चुनने वाला एजेंट 40 में से चुनने वाले की तुलना में खराब विकल्प बनाता है। यदि आप एक चैनल मैनेजर इंटीग्रेट करते हैं, तो लगभग बीस टूल्स आपके लिए प्रासंगिक होते हैं; बाकी 480 शोर हैं जो सही टूल को ढूंढना कठिन बनाते हैं।

**काम वास्तव में अलग किया जा सकता है।** कोई जो PMS से उपलब्धता सिंक करता है और कोई जो एफिलिएट लैंडिंग पेज क्यूरेट करता है, उनके लगभग कोई साझा टूल नहीं होते। काम के अनुसार विभाजन का मतलब है कि हर कनेक्शन एक काम की शब्दावली लेकर चलता है।

<Aside type="caution" title="टूलसेट्स अनुमति नहीं हैं">
एक संकीर्ण टूलसेट चुनना आपके अकाउंट की क्षमताओं को **प्रतिबंधित नहीं** करता, और एक व्यापक टूलसेट चुनना कोई अतिरिक्त अनुमति नहीं देता। हर टूल वेब पोर्टल के समान अकाउंट अनुमतियों को लागू करता है, आपके साइन-इन पहचान के तहत। यदि आपका अकाउंट Wink पोर्टल में बुकिंग रद्द नहीं कर सकता, तो एजेंट भी नहीं कर सकता — चाहे वह किसी भी एंडपॉइंट से कनेक्ट हो।

टूलसेट्स को **फोकस** के लिए चुनें, सुरक्षा के लिए नहीं।
</Aside>

### `https://integrations.wink.travel` — चैनल मैनेजर इंटीग्रेशन

एक एंडपॉइंट, क्योंकि यह होस्ट एक काम के लिए मौजूद है।

| एंडपॉइंट | टूल्स | क्या कवर करता है |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | चैनल मैनेजर, PMS या CRS इंटीग्रेशन को कनेक्ट और सत्यापित करना |

<Aside type="note" title="चैनल मैनेजर इंटीग्रेशन बनाम अपनी खुद की दरें प्रबंधित करना">
ये अलग-अलग काम हैं अलग-अलग लोगों के लिए, और ये एक ही एंडपॉइंट साझा नहीं करते।

एक **चैनल मैनेजर, PMS या CRS विक्रेता** एक बार `integrations.wink.travel/mcp/channel-manager` के माध्यम से इंटीग्रेट करता है, और तब से प्रॉपर्टीज़, दरें, उपलब्धता और आरक्षण उस इंटीग्रेशन के माध्यम से एक्सचेंज करता है। वह एकल एंडपॉइंट पूरी सतह है।

एक **होटलियर जो अपनी खुद की दरें हाथ से बदलता है** `api.wink.travel` पर एक्स्ट्रानेट टूलसेट्स का उपयोग करता है — `/mcp/extranet/rates` और अन्य। ये चैनल मैनेजर इंटीग्रेशन का हिस्सा नहीं हैं और एक इंटीग्रेटर के लिए उन्हें कनेक्ट करने का कोई कारण नहीं है।

अकाउंट प्रशासन भी `api.wink.travel` पर है, `/mcp/settings` पर। इंटीग्रेशन होस्ट पर `/mcp/settings` नहीं है।
</Aside>

हर एंडपॉइंट में एक `ping` टूल भी होता है, ताकि आप कनेक्शन लाइव है या नहीं, यह पुष्टि कर सकें इससे पहले कि आप असली काम के लिए कहें।

एक से शुरू करें। जब आपको लगे कि वह कुछ नहीं कर सकता जो आप चाहते हैं, तो दूसरा जोड़ें — हर कनेक्शन स्वतंत्र है, और एक जोड़ने से दूसरों पर कोई असर नहीं पड़ता।

<Aside type="tip" title="फिर भी सब कुछ चाहिए?">
`https://api.wink.travel/mcp` और `https://integrations.wink.travel/mcp` उपलब्ध रहते हैं और अपने होस्ट पर **हर** टूल सर्व करते हैं। ये यह देखने के लिए उपयोगी हैं कि क्या मौजूद है, लेकिन हम इन्हें दैनिक काम के लिए अनुशंसित नहीं करते: टूल सूची इतनी बड़ी है कि यह आपके कार्य को दबा सकती है और एजेंट के टूल चयन को खराब कर सकती है। ऊपर दिए गए टूलसेट्स को प्राथमिकता दें।
</Aside>

## प्रमाणीकरण कैसे काम करता है

Wink MCP सर्वर **OAuth2 ऑथराइजेशन कोड + PKCE** फ्लो का उपयोग करते हैं और **डायनामिक क्लाइंट रजिस्ट्रेशन (RFC 7591)** का समर्थन करते हैं। पहली बार कनेक्ट करते समय यह होता है:

1. आपका AI क्लाइंट MCP एंडपॉइंट के `/.well-known/oauth-protected-resource` मेटाडेटा से ऑथराइजेशन सर्वर खोजता है।
2. क्लाइंट **डायनामिक क्लाइंट रजिस्ट्रेशन** के माध्यम से स्वयं-पंजीकरण करता है — कोई मैनुअल एप्लिकेशन सेटअप आवश्यक नहीं।
3. क्लाइंट `https://iam.wink.travel` पर एक **ब्राउज़र टैब** खोलता है। आप अपने Wink अकाउंट से साइन इन करते हैं और सहमति स्क्रीन पर अनुरोधित अनुमतियों को मंजूरी देते हैं।
4. Wink आपके अकाउंट के लिए स्कोप्ड और आपकी पहचान से लिंक्ड एक **एक्सेस टोकन** जारी करता है।
5. AI क्लाइंट हर MCP अनुरोध के साथ टोकन संलग्न करता है। सभी टूल परिणाम स्वचालित रूप से आपके प्रबंधकीय इकाई के लिए स्कोप्ड होते हैं।
6. टोकन 3 घंटे बाद समाप्त हो जाते हैं। आपका AI क्लाइंट बिना फिर से पूछे पृष्ठभूमि में चुपचाप रिफ्रेश करता है।

हर टूल कॉल **आपकी पहचान के तहत** चलता है — वे ही ACL नियम जो वेब पोर्टल की सुरक्षा करते हैं, AI एजेंट पर भी लागू होते हैं।

<Steps>
1. सुनिश्चित करें कि Claude Code अपडेटेड है:
   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

2. ऊपर दिए गए [डायरेक्टरी](#endpoint-directory) से एक टूलसेट चुनें और जोड़ें। उदाहरण के लिए, कीमतें और उपलब्धता:
   ```bash
   claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
   ```

## स्कोप्स

जब आप सहमति स्क्रीन को मंजूरी देते हैं, तो आप देखेंगे कि एजेंट क्या अनुरोध कर रहा है। MCP क्लाइंट्स प्लेटफ़ॉर्म के बाकी हिस्सों के समान अनुमति शब्दावली का उपयोग करते हैं — पूर्ण
[स्कोप संदर्भ Authentication पेज पर देखें](/hi/developers/authentication#scopes)।

MCP के लिए दो विशेष बातें हैं:

- **`mcp.read` `mcp.write` `mcp.remove` स्कोप्स अतिरिक्त रूप से आवश्यक हैं** MCP ट्रांसपोर्ट खोलने के लिए। एक क्लाइंट जिसके पास `mcp.*` स्कोप है, किसी भी Wink MCP एंडपॉइंट में प्रवेश कर सकता है, लेकिन वह हर टूल कॉल पर उस एंडपॉइंट के सेक्शन स्कोप को लागू करता है (जैसे `booking.read`)।
- **AI क्लाइंट केवल आवश्यक स्कोप्स का अनुरोध करता है।** आप सहमति स्क्रीन पर व्यक्तिगत अनुमतियाँ अस्वीकार कर सकते हैं — जिन टूल्स को अस्वीकृत स्कोप की जरूरत होती है, वे कॉल पर त्रुटि लौटाएंगे।

**टूलसेट्स इनमें कोई बदलाव नहीं करते।** आप जिस एंडपॉइंट से कनेक्ट करते हैं, वह तय करता है कि कौन से टूल *सूचीबद्ध* हैं, न कि वे क्या *कर सकते हैं*। `/mcp/payment` से कनेक्ट करना कोई अतिरिक्त वित्तीय अनुमति नहीं देता, और `/mcp/reference` से कनेक्ट करना वहां के टूल को अपने स्कोप को लागू करने से नहीं रोकता। प्राधिकरण टोकन और आपके अकाउंट के ग्रांट्स के आधार पर टूल कॉल पर तय होता है।

## समस्या निवारण

**ब्राउज़र टैब नहीं खुलता**

आपका AI क्लाइंट इंटरैक्टिव PKCE फ्लो का समर्थन नहीं कर सकता। सुनिश्चित करें कि आप नवीनतम संस्करण चला रहे हैं:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT डेस्कटॉप:** ऐप के बिल्ट-इन अपडेटर से अपडेट करें

**साइन इन के बाद `401 Unauthorized`**

आपका कैश्ड टोकन पुराना हो सकता है। सर्वर को हटाएं और फिर से जोड़ें ताकि नया साइन-इन ट्रिगर हो:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Claude Desktop और ChatGPT में, सेटिंग्स से सर्वर एंट्री हटाएं, ऐप पुनः प्रारंभ करें, और फिर से जोड़ें।

**किसी विशेष टूल को कॉल करते समय `403 Forbidden`**

टूल को उस स्कोप की जरूरत है जिसे आपने सहमति स्क्रीन पर मंजूर नहीं किया, या आपके अकाउंट के पास वह अनुमति नहीं है। सर्वर को फिर से कनेक्ट करें — सहमति स्क्रीन फिर से आएगी और आप अनुमति दे सकते हैं। यदि फिर भी विफल रहता है, तो टूल को आपके अकाउंट की अनुमति चाहिए; अलग टूलसेट से कनेक्ट करने से मदद नहीं मिलेगी क्योंकि टूलसेट अनुमति नहीं देते।

**मुझे जो टूल चाहिए वह सूची में नहीं है**

आप संभवतः ऐसे टूलसेट से जुड़े हैं जो उस काम को कवर नहीं करता। [एंडपॉइंट डायरेक्टरी](#endpoint-directory) देखें और वह टूलसेट जोड़ें जो कवर करता है — कनेक्शन स्वतंत्र हैं, इसलिए एक जोड़ने से दूसरों पर कोई असर नहीं पड़ता। यदि आप सुनिश्चित नहीं हैं कि कौन सा है, तो अस्थायी रूप से `https://api.wink.travel/mcp` से कनेक्ट करें, टूल खोजें, फिर देखें कि कौन सा टूलसेट उसे सूचीबद्ध करता है।

**टूलसेट एंडपॉइंट पर `404 Not Found`**

पथ ध्यान से जांचें — नेस्टेड टूलसेट्स में दो सेगमेंट होते हैं (`/mcp/extranet/rates`, न कि `/mcp/extranet-rates`), और फ्लैट वाले में एक (`/mcp/link-manager`)। ध्यान दें कि `/mcp` के अंतर्गत बिना प्रमाणीकरण के अनुरोध पर `401` लौटता है, न कि `404`, इसलिए केवल `401` से यह पता नहीं चलता कि एंडपॉइंट मौजूद है या नहीं।

**मैंने `api.wink.travel/mcp/channel-manager` से कनेक्ट किया और कुछ नहीं मिला**

वह एंडपॉइंट मौजूद नहीं है। चैनल मैनेजर इंटीग्रेशन केवल `https://integrations.wink.travel/mcp/channel-manager` से सर्व होता है। यदि आपको प्रॉपर्टी की अपनी दरें हाथ से पढ़ने या लिखने की जरूरत है, तो वह अलग काम है और अलग एंडपॉइंट पर है — देखें `/mcp/extranet/rates`।

**सर्वर दिखाई देता है लेकिन टूल कॉल "account not found" लौटाते हैं**

आप ऐसे Wink अकाउंट से साइन इन हैं जिसके पास कोई प्रबंधकीय इकाई नहीं है। [Wink Portal](https://app.wink.travel) पर जाएं और सुनिश्चित करें कि आपका अकाउंट सेटअप है, फिर MCP सर्वर का उपयोग करें।

**टोकन सत्र के बीच समाप्त हो जाता है**

टोकन 3 घंटे के लिए वैध होते हैं। Claude Code और Claude Desktop बिना बाधा डाले टोकन चुपचाप रिफ्रेश करते हैं। यदि लंबे निष्क्रिय अवधि के बाद प्रमाणीकरण त्रुटियाँ दिखें, तो नया संदेश टाइप करें — क्लाइंट स्वचालित रूप से पुनः प्रमाणीकरण करेगा।

**Codex CLI "MCP server unreachable" दिखाता है**

सुनिश्चित करें कि आपका `~/.codex/config.json` वैध JSON है (कोई ट्रेलिंग कॉमा नहीं) और `"type": "http"` सेट है। Codex रिमोट सर्वरों के लिए HTTP ट्रांसपोर्ट की मांग करता है; stdio ट्रांसपोर्ट केवल स्थानीय बाइनरी के लिए है।

**ChatGPT "Connectors" मेनू गायब है**

MCP सपोर्ट के लिए ChatGPT डेस्कटॉप ऐप संस्करण **1.2024.352** या बाद का और सक्रिय प्लस, प्रो, टीम, या एंटरप्राइज़ सब्सक्रिप्शन आवश्यक है। ऐप अपडेट करें और Settings → Account में अपनी योजना जांचें।

**Cursor सर्वर लाल दिखाता है / "Failed to connect"**

सुनिश्चित करें कि आपका `~/.cursor/mcp.json` वैध JSON है और `"type": "http"` शामिल है। फिर **Settings → Cursor Settings → MCP** पर जाएं और **Refresh** पर क्लिक करें। यदि त्रुटि बनी रहती है, तो Cursor को पूरी तरह से पुनः प्रारंभ करें — कॉन्फ़िग परिवर्तन हमेशा बिना पुनः प्रारंभ के नहीं पकड़े जाते।

**Windsurf MCP सर्वर सेटिंग्स में सूचीबद्ध नहीं**

Windsurf को `mcp_config.json` में बदलाव लेने के लिए पूरी तरह से पुनः प्रारंभ करना पड़ता है (केवल विंडो रीलोड नहीं)। **File → Quit** करें और फिर पुनः खोलें। यदि सर्वर अभी भी नहीं दिखते, तो सुनिश्चित करें कि आप Windsurf **1.4+** पर हैं (**Help → About Windsurf** से जांचें)।

**Cline में "Add Server" विकल्प दिखाई नहीं देता**

MCP सर्वर मैनेजर के लिए Cline **2.0** या बाद का संस्करण आवश्यक है। VS Code एक्सटेंशंस पैनल खोलें, Cline खोजें, और यदि अपडेट उपलब्ध हो तो **Update** पर क्लिक करें। अपडेट के बाद, VS Code को रीलोड करें (`Ctrl+Shift+P` → "Developer: Reload Window")।
