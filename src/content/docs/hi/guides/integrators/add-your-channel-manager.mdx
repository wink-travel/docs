यह मार्गदर्शिका चैनल मैनेजर और PMS डेवलपर्स को Wink के साथ पूरी एकीकरण प्रक्रिया से गुजरती है — आपके खाते बनाने से लेकर इन्वेंटरी मैपिंग और पहला एंड-टू-एंड परीक्षण चलाने तक।

## वातावरण

चैनल मैनेजर (इंटीग्रेशन) API दो वातावरणों में उपलब्ध है। सभी विकास और प्रमाणन के लिए स्टेजिंग का उपयोग करें; केवल लाइव होने पर प्रोडक्शन पर स्विच करें।

| वातावरण    | बेस URL                          |
| ----------- | -------------------------------- |
| प्रोडक्शन    | https://integrations.wink.travel |
| स्टेजिंग    | https://staging-integrations.wink.travel |

## API संदर्भ

चैनल मैनेजर API मौजूदा हॉस्पिटैलिटी सिस्टम के साथ संगतता के लिए OTA प्रोटोकॉल मानकों (SOAP/XML) का पालन करता है। शुरुआत में पार्टनर एंडपॉइंट दस्तावेज़ देखें:

<LinkButton href="/hi/partner-api/partner/">
  चैनल मैनेजर API — पार्टनर एंडपॉइंट्स
</LinkButton>

## एकीकरण चरण

<Steps>
1. **Wink उपयोगकर्ता खाता बनाएं**

   [staging-app.wink.travel](https://staging-app.wink.travel) पर साइन अप करें। नीचे दिए गए सभी चरण स्टेजिंग का उपयोग करते हैं — आप लाइव होने से पहले प्रोडक्शन में पूरी प्रक्रिया दोहराएंगे।

2. **अपना एफिलिएट / चैनल मैनेजर खाता बनाएं**

   अपने नए उपयोगकर्ता के तहत एक खाता बनाएं और **एफिलिएट / चैनल मैनेजर** खाता प्रकार चुनें। यह वह खाता है जिसके रूप में आपका एकीकरण प्रमाणित होगा।

3. **एक एप्लिकेशन पंजीकृत करें और अपना पहला टोकन बनाएं**

   एक [एप्लिकेशन](/hi/account/applications) बनाएं और इसे चरण 2 के चैनल मैनेजर खाते से जोड़ें। क्लाइंट प्रकार के रूप में **MACHINE_2_MACHINE** चुनें — यह एक सर्वर-से-सर्वर एकीकरण है जिसमें कोई अंतिम उपयोगकर्ता रीडायरेक्ट नहीं होता। तुरंत **Client ID** और **Secret Key** कॉपी करें; सीक्रेट की केवल एक बार दिखती है और फिर पुनः प्राप्त नहीं की जा सकती।

   एप्लिकेशन वह है जो इस गाइड में हर कॉल के लिए `Authorization: Bearer <access_token>` के रूप में बियरर टोकन बनाता है। `client_credentials` ग्रांट का उपयोग करके `https://staging-iam.wink.travel/oauth2/token` पर अपने क्रेडेंशियल्स का आदान-प्रदान करें, `integrations.read integrations.write` स्कोप के साथ। आगे बढ़ने से पहले यह करें — बिना टोकन के आप खाता पहचानकर्ता नहीं देख सकते या कोई चैनल मैनेजर एंडपॉइंट नहीं पहुंच सकते। पूर्ण प्रवाह, प्रोडक्शन होस्ट, और स्कोप कैटलॉग के लिए [Authentication](/hi/developers/authentication) देखें।

4. **एक होटल खाता बनाएं**

   उसी उपयोगकर्ता के तहत दूसरा खाता बनाएं और **होटल** खाता प्रकार चुनें। यह आपको एक ऐसी संपत्ति देता है जिसका उपयोग आप परीक्षण के लिए कर सकते हैं बिना किसी वास्तविक होटल को शामिल किए।

5. **दोनों खातों की स्वीकृति की पुष्टि करें**

   कोई भी खाता तब तक उपयोग में नहीं आ सकता जब तक वह स्वीकृत न हो: एक अप्रूव्ड चैनल मैनेजर खाता किसी भी होटल की चैनल मैनेजर सूची में नहीं दिखेगा, और एक अप्रूव्ड होटल API द्वारा वापस नहीं किया जाएगा।

   - **स्टेजिंग** — स्वीकृति स्वचालित है। दोनों खाते बनाते ही उपयोग के लिए उपलब्ध होते हैं, और कोई अनुरोध करने की आवश्यकता नहीं होती।
   - **प्रोडक्शन** — स्वीकृति मैनुअल है। अपने Wink इंटीग्रेशन संपर्क को दोनों खातों के नाम और उनके अंतर्गत उपयोगकर्ता भेजें, फिर पुष्टि के लिए प्रतीक्षा करें।

6. **दोनों खातों को कनेक्ट करें**

   होटल खाते में लॉग इन करें और **Extranet → Distribution → Channel Manager** पर जाएं। सूची से अपना चैनल मैनेजर खाता चुनें — यह संपत्ति को आपके एकीकरण से लिंक करता है। यदि आपका खाता सूची में नहीं है, तो वह अभी स्वीकृत नहीं हुआ है; चरण 5 देखें।

7. **एक बुनियादी कमरे का प्रकार और दर योजना बनाएं**

   होटल खाते के अंदर कम से कम एक कमरे का प्रकार और एक दर योजना बनाएं। ये आवश्यक हैं इससे पहले कि आपका एकीकरण दरें और उपलब्धता पुश कर सके या बुकिंग खींच सके।

8. **मैप करें और परीक्षण करें**

   अपने सिस्टम में, API द्वारा लौटाए गए कमरे के प्रकार और दर योजना पहचानकर्ताओं को मैप करें। एक दर अपडेट और एक उपलब्धता अपडेट पुश करें, फिर एक परीक्षण बुकिंग करें और पुष्टि करें कि बुकिंग पुनः प्राप्ति एंडपॉइंट इसे सही ढंग से लौटाता है।
</Steps>

:::note
लाइव होने से पहले प्रोडक्शन में ऊपर दिए गए सभी चरण दोहराएं, जिसमें एक अलग प्रोडक्शन एप्लिकेशन पंजीकरण भी शामिल है — स्टेजिंग क्रेडेंशियल्स प्रोडक्शन पर काम नहीं करते। चरण 5 में Wink की समीक्षा के लिए बजट रखें — स्टेजिंग के विपरीत, प्रोडक्शन खाते स्वचालित रूप से स्वीकृत नहीं होते। Wink टीम आपके चैनल मैनेजर का उपयोग कर रहे किसी भी होटल को आपके नए प्रोडक्शन खाते में माइग्रेट करेगी।
:::

## अपने खाता पहचानकर्ता कैसे खोजें

हर चैनल मैनेजर API पथ आपके अपने खाते के लिए स्कोप्ड होता है:

```
/api/managing-entity/{managingEntityIdentifier}/channel-manager/...
```

`{managingEntityIdentifier}` आपके **चैनल मैनेजर खाते** का खाता ID (UUID) है — होटल का नहीं। इसे, साथ ही आपके उपयोगकर्ता के अन्य सभी खातों के ID और वर्तमान स्थिति को प्लेटफ़ॉर्म API से प्राप्त करें:

```bash
curl -s -X GET \
  "https://staging-api.wink.travel/api/managing-entity/list" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

प्रतिक्रिया आपके स्वामित्व वाले खातों की एक सूची है:

```json
[
  {
    "id": "3f1c8e42-7b90-4d55-a1e2-6c8d09b4f731",
    "type": "CHANNEL_MANAGER",
    "name": "Your Channel Manager",
    "status": "ACTIVE"
  },
  {
    "id": "d5b8a3c2-9e6f-4a1b-8d34-7c2e1f0a5b69",
    "type": "HOTEL",
    "name": "Your Test Property",
    "urlName": "your-test-property",
    "status": "ACTIVE"
  }
]
```

- चैनल मैनेजर प्रविष्टि का `id` आपका **`{managingEntityIdentifier}`** है।
- `HOTEL` प्रविष्टि का `id` आपका **`{propertyIdentifier}`** है।
- `status` वह जगह है जहां आप पुष्टि करते हैं कि प्रत्येक खाता स्वीकृत है — प्रोडक्शन में सबसे उपयोगी, जहां स्वीकृति मैनुअल होती है। **होटल** को `ACTIVE` पढ़ना चाहिए इससे पहले कि वह बुक करने योग्य हो या चैनल मैनेजर API के लिए दिखाई दे। आपका **चैनल मैनेजर** खाता तब तक `PENDING_APPROVAL` पढ़ता रहेगा जब तक आप [प्रमाणन](#certification) पास नहीं कर लेते; यह अपेक्षित है और विकास को अवरुद्ध नहीं करता।

:::caution
यह खोज **प्लेटफ़ॉर्म API** (`https://staging-api.wink.travel` स्टेजिंग पर, `https://api.wink.travel` प्रोडक्शन में) के खिलाफ चलती है, न कि [वातावरण](#environments) के तहत सूचीबद्ध चैनल मैनेजर API होस्ट के खिलाफ। एक ही एक्सेस टोकन का उपयोग करें — यह उपयोगकर्ता के लिए जारी किया जाता है, API के लिए नहीं।
:::

## प्रमाणन

प्रमाणन यह साबित करने का तरीका है — और Wink यह पुष्टि करता है — कि आपका एकीकरण सही ढंग से इन्वेंटरी मैप करता है, दर और उपलब्धता पुश करता है, और एंड-टू-एंड बुकिंग प्राप्त करता है। इसे स्व-सेवा के रूप में डिज़ाइन किया गया है: आप अपने सिस्टम से हर चरण चलाते हैं, और अंत में एक सिंगल सबूत बंडल जमा करते हैं। Wink बंडल की समीक्षा करता है और, पास होने पर, आपके एफिलिएट / चैनल मैनेजर खाते को **PENDING_APPROVAL** से **ACTIVE** में प्रमोट करता है।

प्रमाणन पूरी तरह से स्टेजिंग वातावरण (`https://staging-integrations.wink.travel`) के खिलाफ चलता है। इस अनुभाग में कुछ भी प्रोडक्शन को नहीं छूता।

### आप क्या साबित करेंगे

<Steps>
1. **प्रमाणीकरण।** आपका OAuth2 क्लाइंट एक एक्सेस टोकन प्राप्त कर सकता है और सफलतापूर्वक आपके एफिलिएट / चैनल मैनेजर खाते के खिलाफ `/ping` एंडपॉइंट को कॉल कर सकता है।

2. **इन्वेंटरी मैपिंग।** आप अपने खाते से जुड़े होटल(ओं) की सूची प्राप्त कर सकते हैं, आपने जो मास्टर दर (कमरे का प्रकार × दर योजना) कॉन्फ़िगर की है उसे पुनः प्राप्त कर सकते हैं, और सही ढंग से `masterRateIdentifier` पहचान सकते हैं जिस पर आपका सिस्टम लक्षित करेगा।

3. **दर और उपलब्धता पुश।** आप प्रमाणन सप्ताह के सभी सात दिनों को स्वतंत्र रूप से अपडेट कर सकते हैं — प्रत्येक दिन राशि, मात्रा, आगमन पर बंद / प्रस्थान पर बंद फ्लैग, और न्यूनतम/अधिकतम ठहराव अवधि के विभिन्न संयोजन के साथ — और Wink से ठीक वही मान पढ़ सकते हैं।

4. **बुकिंग पुल।** आप अपने परीक्षण संपत्ति के खिलाफ बनाई गई एक वास्तविक स्टेजिंग बुकिंग पुनः प्राप्त कर सकते हैं, इसे अपने PMS/CM UI में सही कमरे के ठहराव, अतिथि, और कुल के साथ प्रदर्शित कर सकते हैं, फिर Wink द्वारा बुकिंग रद्द किए जाने पर रद्दीकरण को प्रतिबिंबित कर सकते हैं।
</Steps>

### पूर्वापेक्षाएँ

प्रमाणन शुरू करने से पहले, [एकीकरण चरण](#integration-steps) के चरण 1–7 पूरे करें ताकि आपके पास हो:

- स्टेजिंग पर एक Wink उपयोगकर्ता जिसके पास एक **एफिलिएट / चैनल मैनेजर** खाता और एक **होटल** खाता हो जो उससे जुड़ा हो (Extranet → Distribution → Channel Manager)। स्टेजिंग खाते स्वचालित रूप से स्वीकृत होते हैं, इसलिए यहां कोई अनुरोध करने की आवश्यकता नहीं है।
- होटल खाते के अंदर कम से कम एक **कमरे का प्रकार** और एक **दर योजना** बनाई गई हो। होटल को प्रकाशित करें ताकि वह `https://staging-book.wink.travel/hotel/<your-slug>` पर बुक करने योग्य हो।
- अपने एफिलिएट / चैनल मैनेजर खाते के तहत एक पंजीकृत एप्लिकेशन हो जिसमें **Client ID**, **Secret Key**, और `integrations.read integrations.write` स्कोप हों (देखें [Authentication](/hi/developers/authentication))।
- अपने एफिलिएट / चैनल मैनेजर खाते का **`managingEntityIdentifier`** और होटल खाते का **`propertyIdentifier`** (दोनों UUID हैं — देखें [अपने खाता पहचानकर्ता कैसे खोजें](#finding-your-account-identifiers))।

### सामान्य अनुरोध कन्वेंशंस

इस अनुभाग में हर अनुरोध में ये हेडर होते हैं:

```http
Authorization: Bearer <access_token>
Wink-Version: 2.0
Accept: application/json
```

- `<access_token>` `client_credentials` ग्रांट से आता है `https://staging-iam.wink.travel/oauth2/token` पर — देखें [Authentication](/hi/developers/authentication#staging)।
- `Wink-Version` हेडर आवश्यक है; इसे छोड़ने पर v2 JSON API पर रूट नहीं होगा।
- `Content-Type: application/json` उन `PUT` अनुरोधों पर जो बॉडी के साथ होते हैं, जोड़ा जाता है।

नीचे के उदाहरणों में, प्लेसहोल्डर उन मानों से मेल खाते हैं जो आपने [पूर्वापेक्षाएँ](#prerequisites) में एकत्र किए हैं:

| प्लेसहोल्डर               | अर्थ                                                                                   |
|---------------------------|----------------------------------------------------------------------------------------|
| `{managingEntityIdentifier}` | आपका एफिलिएट / चैनल मैनेजर खाता ID (UUID) — देखें [अपने खाता पहचानकर्ता कैसे खोजें](#finding-your-account-identifiers)। |
| `{propertyIdentifier}`       | होटल खाता (संपत्ति) ID जिसे आपने CM खाते से जोड़ा है।                                  |
| `{masterRateIdentifier}`     | मास्टर दर (कमरे का प्रकार × दर योजना) जिसे आप प्रमाणित करेंगे।                        |
| `{bookingIdentifier}`        | स्टेजिंग बुकिंग ID जो बुकिंग सूची कॉल द्वारा लौटाया गया।                               |

### चरण A — पिंग

पुष्टि करें कि आपके क्रेडेंशियल्स अपेक्षित एफिलिएट / चैनल मैनेजर खाते को हल करते हैं।

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/ping" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

अपेक्षित प्रतिक्रिया:

```json
{
  "apiVersion": "2.0",
  "name": "Your Channel Manager Account Name",
  "status": "PENDING_APPROVAL"
}
```

एक **200** प्रतिक्रिया जिसमें मेल खाता `name` हो, यह संकेत है कि प्रमाणीकरण और खाता समाधान सही हैं। `status` तब तक `PENDING_APPROVAL` पढ़ेगा जब तक Wink आपको प्रमाणित नहीं करता।

### चरण B — संपत्तियों की सूची बनाएं

अपने खाते से जुड़े होटलों की पृष्ठीकृत सूची प्राप्त करें और पुष्टि करें कि आपका परीक्षण संपत्ति मौजूद है।

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/list?page=0&size=25" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

प्रतिक्रिया एक स्प्रिंग `Page` है जिसमें `ChannelManagerProperty` प्रविष्टियाँ हैं। उस प्रविष्टि को खोजें जिसका `identifier` आपके `{propertyIdentifier}` से मेल खाता हो और उसका `currencyCode` रिकॉर्ड करें — आपको [चरण D](#step-d--load-the-certification-week) में दर अपडेट की व्याख्या के लिए इसकी आवश्यकता होगी।

:::caution
खाली सूची एक कॉन्फ़िगरेशन संकेत है, गलत अनुरोध नहीं। एक होटल केवल तभी यहां लौटाया जाता है जब वह **`ACTIVE`** हो *और* उसे आपके चैनल मैनेजर खाते के तहत Extranet → Distribution → Channel Manager में असाइन किया गया हो। आगे डिबगिंग से पहले दोनों को `GET /api/managing-entity/list` के साथ जांचें (देखें [अपने खाता पहचानकर्ता कैसे खोजें](#finding-your-account-identifiers))। प्रोडक्शन में, एक तीसरा कारण जोड़ें: होटल यहां तब तक अदृश्य रहता है जब तक Wink ने इसे स्वीकृत न किया हो।
:::

### चरण C — मास्टर दरें प्राप्त करें

संपत्ति को उसके द्वारा प्रकाशित हर मास्टर दर (कमरे का प्रकार × दर योजना संयोजन) के साथ पुनः प्राप्त करें। उस दर को चुनें जिसके खिलाफ आप प्रमाणित करना चाहते हैं और उसका `identifier` अपने `{masterRateIdentifier}` के रूप में रिकॉर्ड करें।

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

प्रतिक्रिया लिफाफा `PropertyWithRoomRateList` है: एक `property` ब्लॉक और `rooms` नामक `PropertyRoomRate` प्रविष्टियों की एक सूची। प्रत्येक प्रविष्टि कमरे के प्रकार, दर योजना, अधिभोग सीमाएं, आधार दर, और वे दर संशोधक दिखाती है जिन्हें आप दैनिक दरें पुश करते समय संरक्षित करेंगे।

:::caution
पूरे प्रमाणन रन के लिए एकल मास्टर दर के खिलाफ प्रमाणित करें। प्रोडक्शन में अतिरिक्त कमरे के प्रकार और दर योजनाओं का मैपिंग अपेक्षित है, लेकिन सबूत बंडल को केवल एक मास्टर दर का एंड-टू-एंड उपयोग दिखाना चाहिए।
:::

### चरण D — प्रमाणन सप्ताह लोड करें

प्रमाणन शुरू करने वाले महीने के बाद वाले महीने के पहले सात कैलेंडर दिनों को कवर करने वाला **सात-दिन का दर कैलेंडर** लोड करें। उदाहरण के लिए, यदि आप 21 अगस्त को प्रमाणन शुरू करते हैं, तो 1 सितंबर से 7 सितंबर तक का लक्ष्य रखें।

आप **सात अलग-अलग `PUT` कॉल** भेजेंगे — प्रत्येक दिन के लिए एक — जहां `startDate == endDate` होगा। प्रत्येक दिन में राशि, मात्रा, प्रतिबंध फ्लैग, और ठहराव की न्यूनतम/अधिकतम अवधि का जानबूझकर अलग संयोजन होगा ताकि हर लिखने योग्य फ़ील्ड कम से कम एक बार परीक्षण हो। मान संपत्ति की मुद्रा में हैं (चरण B में रिकॉर्ड किए गए); `currencyCode` छोड़ दें तो यह सही ढंग से डिफ़ॉल्ट हो जाएगा।

| दिन | राशि    | मात्रा | closedOnArrival | closedOnDeparture | minLengthOfStay | maxLengthOfStay | यह क्या साबित करता है |
|-----|---------|--------|-----------------|-------------------|-----------------|-----------------|----------------------|
| 1   | 100.00  | 5      | false           | false             | 1               | 30              | आधार दिन।            |
| 2   | 125.00  | 4      | false           | false             | 1               | 14              | राशि + मात्रा + `maxLengthOfStay` परिवर्तन। |
| 3   | 150.00  | 3      | **true**        | false             | 1               | 30              | `closedOnArrival` पलटाव। |
| 4   | 175.00  | 2      | false           | **true**          | 2               | 7               | `closedOnDeparture` पलटाव + सख्त LOS विंडो। |
| 5   | 200.00  | **0**  | false           | false             | 1               | 30              | बिक चुका मात्रा।      |
| 6   | 225.00  | 5      | false           | false             | **3**           | **5**           | प्रतिबंधात्मक LOS विंडो। |
| 7   | 250.00  | 1      | false           | false             | 1               | 30              | अंतिम-कमरे की उपलब्धता। |

दिन 1 के लिए अनुरोध बॉडी इस प्रकार दिखती है। दिन 2 से 7 तक `startDate` / `endDate` / मानों को पंक्ति के अनुसार समायोजित करते हुए दोहराएं।

```bash
curl -s -X PUT \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/master-rate/{masterRateIdentifier}" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
        "startDate": "2026-09-01",
        "endDate":   "2026-09-01",
        "amount":    100.00,
        "master":    true,
        "closedOnArrival":   false,
        "closedOnDeparture": false,
        "quantity":          5,
        "minLengthOfStay":   1,
        "maxLengthOfStay":   30
      }'
```

प्रत्येक `PUT` `200` प्रतिक्रिया देता है जिसमें उस रेंज के लिए अपडेट किए गए `PropertyRate` प्रविष्टियों की सूची होती है (जब `startDate == endDate` तो एक प्रविष्टि)। उस प्रतिक्रिया को कैप्चर करें — यह आपके सबूत का हिस्सा होगा।

:::note
`master` हर प्रमाणन-सप्ताह कॉल पर `true` होना चाहिए। यह Wink को बताता है कि आपका अपडेट एक टेम्पलेट दर है, प्रति-बुकिंग ओवरराइड नहीं।
:::

### चरण E — प्रमाणन सप्ताह पढ़ें

संपूर्ण सप्ताह को एक कॉल में पुनः प्राप्त करें और पुष्टि करें कि प्रत्येक दिन के संग्रहीत मान उस पंक्ति से मेल खाते हैं जो आपने चरण D में भेजी थी — जिसमें बूलियन फ्लैग और ठहराव की अवधि की विंडो शामिल है।

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/master-rate/{masterRateIdentifier}?startDate=2026-09-01&endDate=2026-09-07" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

प्रतिक्रिया `PropertyRoomRateWithRateList` है। इसका `rates` एरे में **सात** प्रविष्टियाँ होनी चाहिए, प्रत्येक दिन के लिए एक, जिनमें `amount`, `quantity`, `closedOnArrival`, `closedOnDeparture`, `minLengthOfStay`, और `maxLengthOfStay` शामिल हैं जो आपने लोड किए थे। किसी भी फ़ील्ड में असंगति का मतलब है कि चरण D में संबंधित `PUT` अपेक्षित रूप से लागू नहीं हुआ — इसे ठीक करें और आगे बढ़ने से पहले पुनः सत्यापित करें।

### चरण F — एक परीक्षण बुकिंग करें

अपने ब्राउज़र में निम्न URL खोलें, `<your-slug>` को उस होटल खाते के स्लग से बदलें जिसे आपने पूर्वापेक्षाओं में प्रकाशित किया था:

```
https://staging-book.wink.travel/hotel/<your-slug>
```

एक आगमन और प्रस्थान तिथि चुनें जो पूरी तरह से आपके प्रमाणन सप्ताह के भीतर हो, उस कमरे के प्रकार + दर योजना संयोजन को चुनें जिसे आपने प्रमाणित किया था, और बुकिंग पूरी करें। स्टेजिंग एक परीक्षण भुगतान पथ का उपयोग करता है — कोई लाइव कार्ड चार्ज नहीं होता।

पुष्टि पृष्ठ प्रदर्शित होने के बाद, अतिथि को दिखाए गए **बुकिंग कोड** (फॉर्मेट `WNKxxxxx`) को रिकॉर्ड करें।

### चरण G — बुकिंग खींचें

अपने परीक्षण संपत्ति के लिए बनाए गए हर बुकिंग को उस विंडो के भीतर पुनः प्राप्त करें जो बुकिंग टाइमस्टैम्प को कवर करता है।

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/booking/list?startDate=2026-09-01T00:00:00&endDate=2026-09-08T00:00:00" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

उस प्रविष्टि को खोजें जिसका `bookingCode` आपने चरण F में रिकॉर्ड किया था। उसका `bookingIdentifier` रिकॉर्ड करें। फिर उस एकल बुकिंग को पुनः प्राप्त करें:

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/booking/{bookingIdentifier}" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

प्रतिक्रिया `PropertyBooking` है। इसे अपने PMS / चैनल-मैनेजर UI में आयात करें और पुष्टि करें कि निम्नलिखित प्रत्येक ऑपरेटर के लिए सही ढंग से प्रदर्शित होता है:

- `bookingCode`, `bookingIdentifier`, `createdDate`
- अतिथि: `firstName`, `lastName`, `email`
- `totalAmount` + `currencyCode` (नेट राशि जो होटल को सभी कमरों में मिलती है)
- `paymentMethodType`, `paymentMethodStatus`, `salesChannelName`
- `roomStays` में हर प्रविष्टि: `guestRoomName`, `ratePlanName`, `adults`, `children`, `startDate`, `endDate`, और प्रति-कमरा `amount`

बुकिंग का एक स्क्रीनशॉट लें जैसा कि यह आपके UI में दिखाई देता है — वह स्क्रीनशॉट आवश्यक सबूतों में से एक है।

### चरण H — बुकिंग रद्द करें और सत्यापित करें

Wink टीम से अनुरोध करें कि वे आपके लिए प्रमाणन बुकिंग रद्द करें (या यदि आपके पास अनुमति है तो होटल खाते के Extranet से स्वयं रद्द करें)। फिर चरण G के कॉल के साथ वही बुकिंग पुनः प्राप्त करें।

पुष्टि करें कि प्रतिक्रिया अब दिखाती है:

- `cancelled: true`
- एक भरा हुआ `cancelDate` टाइमस्टैम्प
- एक `paymentMethodStatus` जो रद्दीकरण जीवनचक्र को दर्शाता है (`CANCELLED`, `PARTIALLY_REFUNDED`, या `FULLY_REFUNDED` वापसी नीति के अनुसार)

अपडेट की गई बुकिंग को अपने UI में आयात करें और पुष्टि करें कि रद्दीकरण ऑपरेटर के लिए दिखाई देता है — स्थिति, रद्द किए जाने का टाइमस्टैम्प, और कोई भी वापसी संकेतक जो आपका UI सपोर्ट करता है। रद्द की गई बुकिंग का दूसरा स्क्रीनशॉट लें। यह अंतिम सबूत है।

### चरण I — अपना सबूत बंडल जमा करें

निम्नलिखित को एकल आर्काइव (`.zip`) में पैक करें जिसका नाम हो
`wink-cert-<your-channel-manager-name>-<yyyy-mm-dd>.zip`:

<Steps>
1. **API ट्रांस्क्रिप्ट।** चरण A से H तक हर अनुरोध के लिए, पूर्ण HTTP अनुरोध (मेथड, URL, अनुरोध हेडर जिसमें `Authorization` मान छिपा हो, और `PUT` कॉल के लिए JSON बॉडी) और पूर्ण HTTP प्रतिक्रिया (स्थिति कोड, प्रतिक्रिया हेडर, और JSON बॉडी) कैप्चर करें। ट्रांस्क्रिप्ट को इस तरह संरचित करें कि प्रत्येक अनुरोध/प्रतिक्रिया जोड़ी स्पष्ट रूप से संबंधित चरण के साथ लेबल हो (`step-a-ping.json`, `step-d-day-3-put.json`, `step-g-list-bookings.json`, आदि)। प्लेन-टेक्स्ट `.http` फाइलें या एकल `.har` निर्यात दोनों स्वीकार्य हैं।

2. **UI स्क्रीनशॉट: सक्रिय बुकिंग।** चरण G से स्क्रीनशॉट जिसमें प्रमाणन बुकिंग आपके PMS / चैनल-मैनेजर UI में अतिथि, तिथियाँ, कमरे का प्रकार, दर योजना, और कुल स्पष्ट रूप से पढ़ने योग्य हो।

3. **UI स्क्रीनशॉट: रद्द की गई बुकिंग।** चरण H से स्क्रीनशॉट जिसमें वही बुकिंग आपके UI में रद्दीकरण के बाद दिखाई दे, रद्द की गई स्थिति और टाइमस्टैम्प स्पष्ट रूप से पढ़ने योग्य हो।

4. **प्रमाणन सारांश।** आर्काइव के अंदर एक छोटा `README.md` जिसमें शामिल हो:
   - आपका चैनल मैनेजर / PMS नाम और संस्करण।
   - आपने जो `managingEntityIdentifier`, `propertyIdentifier`, `masterRateIdentifier`, और `bookingIdentifier` उपयोग किए।
   - स्टेजिंग होटल स्लग (`https://staging-book.wink.travel/hotel/<your-slug>` में `<your-slug>`)।
   - प्रमाणन सप्ताह की तिथि सीमा (दिन 1 → दिन 7 ISO-8601 में)।
   - प्रमाणन चलाने वाले इंजीनियर का नाम और ईमेल।
</Steps>

आर्काइव को अपने Wink इंटीग्रेशन संपर्क को भेजें। Wink समीक्षा करेगा, किसी भी विसंगति पर फॉलो-अप करेगा, और पास होने पर आपके एफिलिएट / चैनल मैनेजर खाते की स्थिति को `PENDING_APPROVAL` से `ACTIVE` में बदल देगा। आपका एकीकरण तब प्रोडक्शन ऑनबोर्डिंग के लिए पात्र होगा।

:::tip
ट्रांस्क्रिप्ट कैप्चर को स्वचालित करें। चरण D में सात `PUT` कॉल और चरण E में रीड-बैक प्रमाणन विफलताओं का सबसे आम स्रोत हैं — एक इंटरैक्टिव HTTP क्लाइंट जो हर अनुरोध और प्रतिक्रिया को चलाते समय सहेजता है, आपको यदि कोई मान दशमलव से अलग हो तो पूरी पुनरावृत्ति से बचाएगा।
:::

## वेबहुक सूचनाएं

आप चैनल मैनेजर वेबहुक इवेंट्स की सदस्यता लेकर रियल-टाइम सूचनाएं प्राप्त कर सकते हैं:

- `channel-manager.update.rate` — दर अपडेट प्राप्त हुआ।
- `channel-manager.update.availability` — उपलब्धता अपडेट प्राप्त हुआ।
- `channel-manager.update` — सामान्य चैनल मैनेजर अपडेट।

विवरण के लिए [Webhook Events Catalog](/hi/developers/webhook-events#channel-manager-events) देखें।
