## Ang pagrerekomenda ng hotel ay hindi pa booking

Karamihan sa "AI travel" ngayon ay humihinto sa rekomendasyon. Nagmumungkahi ang assistant ng tatlong hotel, tapos iniaabot ang manlalakbay sa isang website o OTA para mag-book talaga. Napuputol ang thread, maaaring hindi ma-book ang presyo, at walang nagtatago ng source context.

Iba ang **AI agent** sa AI answer. Hindi lang inilalarawan ng agent ang hotel — kumikilos ito: tinitingnan ang live availability, binubuo ang booking, kumukuha ng bayad, at kayang tumugon kapag may pagbabago. Para mangyari ito nang ligtas, kailangan ng agent ng higit pa sa teksto. Kailangan nito ng structured, kasalukuyang, bookable na data at isang transaction layer na matatawag.

Ito ang pagkakaiba ng [AI discovery](/tl/resources/ai-discovery-hotels/), na tungkol sa pagiging **natuklasan at naunawaan**, at agentic commerce, na tungkol sa pagiging **na-transact**.

## Ano ang kailangan ng agent bago ito makapag-transact

Ang pag-book ng hotel ay isang tunay na komersyal na pangyayari: ang tamang kuwarto, tamang rate, totoong availability, mga patakaran, bayad at kumpirmasyon na nag-synchronize pabalik sa hotel. Makukumpleto lang ito ng agent kung bawat bahagi ay available bilang callable operation.

| Kailangan ng agent | Bakit ito mahalaga |
|---|---|
| Structured, live supply | Ang web-scraped data ay nagiging luma; kailangan ng agent ang kasalukuyang, hotel-controlled inventory. |
| Real-time rates at availability | Ang presyo na ibinibigay ng agent ay dapat totoong ma-book sa sandaling iyon. |
| Isang booking operation | Ang paggawa ng reserbasyon ay dapat totoong API call, hindi simpleng paglipat sa web form. |
| Bayad | Dapat kayang magbayad ng agent (o ng manlalakbay sa pamamagitan nito), na may inilapat na policy logic. |
| Attribution | Dapat manatiling nakakabit ang pinagmulan, kampanya o agent na gumawa ng booking. |
| Mga pangyayari | Dapat kayang tumugon ng agent sa mga kumpirmasyon, pagbabago, pagkansela at refund. |

Kung wala ito, makakapag-rekomenda lang ang agent — hindi makakapag-book.

## Paano nagbu-book ang AI agent ng hotel sa Wink

API-first ang Wink: bawat feature ng platform ay maaaring tawagin mula sa labas, at isang hosted MCP server ang nagpapakita ng live API contracts sa mga agent. Isang tipikal na daloy ng agent:

### 1 — Kumonekta at basahin ang live contracts

Kumokonekta ang agent sa hosted MCP server at ginagamit ang `api_search` at `docs_search` para hanapin ang tamang operasyon at basahin ang tunay na request/response schemas — walang hulaan sa endpoints, walang luma-lumang dokumento.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Maghanap ng bookable inventory

Naghahanap ang agent ng hotel-controlled supply, kabilang ang geolocation spatial search, at binabasa ang live rates at availability mula sa mga konektadong channel managers.

### 3 — Gumawa ng booking

Ang paggawa ng booking ay isang REST API operation. Binubuo ng agent ang kuwarto, rate, petsa at mga bisita, at lumilikha ng reserbasyon sa pamamagitan ng API.

### 4 — Kumuha ng bayad at kumpirmahin

Pinatutupad ng [Booking Engine](/tl/products/booking-engine/) ang transaksyon — checkout, bayad (ang Wink ang merchant of record), logic ng cancellation-policy, kumpirmasyon, at pag-sync ng booking sa konektadong PMS o channel manager. Pinananatili ang source at partner attribution sa booking.

### 5 — Tumugon sa mga pangyayari

Maaaring mag-subscribe ang agent sa `booking.created` at iba pang webhook events para mag-reconcile, mag-notify sa manlalakbay, o mag-trigger ng follow-up actions.

Ang prinsipyo: **gumagawa o nagruruta ang agent ng intensyon; nananatiling fulfillment layer ang Booking Engine sa likod ng bawat handoff.**

## AI search vs AI agents

Iba ang mga trabahong nilulutas nila, at kailangang handa ang hotel para sa pareho.

| | AI search / answer engines | AI agents |
|---|---|---|
| Layunin ng manlalakbay | Maghanap at magkumpara ng mga hotel | Mag-book at mag-manage ng pananatili |
| Kailangan ng hotel | [Structured, crawlable content](/tl/resources/hotel-content-answer-engines/) | Live API, rates, booking, bayad |
| Pangwakas na estado | Isang rekomendasyon | Isang kumpirmadong booking |
| Surface ng Wink | Malinis na supply + content na handa sa sagot | REST API, MCP server, Booking Engine |

Sinasaklaw ng [AI discovery para sa mga hotel](/tl/resources/ai-discovery-hotels/) ang bahagi ng paghahanap; tinatalakay ng gabay na ito ang bahagi ng transaksyon.

## Sino ang gumagawa ng mga agent sa hotel commerce

Hindi lang consumer assistants ang agentic travel commerce. Pinapagana ng parehong infrastructure ang:

- **Consumer travel assistants** na naghahanap, nagbu-book at nagma-manage ng pananatili mula simula hanggang dulo.
- **Bank, loyalty at super-app agents** na nag-iembed ng hotel booking sa loob ng umiiral na karanasan ng customer.
- **Partner at creator automations** na natutuklasan ang mga kwalipikadong hotel, bumubuo ng mga asset at pinananatiling konektado ang attribution — kumikita ng 10% default commission sa kumpirmadong bookings.
- **Hotel-side copilots** na tumutulong sa mga team na gumawa ng content at suriin ang performance sa [Extranet](/tl/products/extranet/), [Social](/tl/products/social/) at [Studio](/tl/products/studio/), habang pinananatili ng hotel ang mga patakaran.

## Saan ito patungo

Live na ngayon ang mga kakayahan sa itaas sa pamamagitan ng REST API at MCP server. Ang direksyon ay mas malalim na agent-native commerce: mas mayamang agent-facing booking primitives, pagkakakilanlan at awtorisasyon ng agent para mag-transact sa ngalan ng manlalakbay, at ang mga agent ay nakikilahok bilang attributed, kumikitang mga pinagmulan sa partner network. Ang tuloy-tuloy na tema ay pareho — **travel commerce infrastructure para sa AI agents**, na may Booking Engine na nagpapatupad sa ilalim.

## Mga karaniwang pagkakamali

- **Pagturing sa AI discovery at AI agents bilang iisang proyekto.** Isa ay content at structure; ang isa ay API at fulfillment. Kailangan mo pareho.
- **Pagpapahintulot sa mga agent na mag-quote ng presyo na hindi nila ma-book.** Dapat manggaling ang mga quote sa live rates at availability, hindi sa mga scraped na pahina.
- **Pagkawala ng attribution sa handoff.** Kung ang agent ang gumawa ng demand, dapat manatiling konektado ang booking sa pinagmulan nito.
- **Pagskip sa fulfillment layer.** Hindi booking ang sagot hangga't hindi nangyayari ang checkout, bayad at kumpirmasyon.
