## Bakit mahalaga ang connectivity

Nakasalalay sa tumpak na suplay ng hotel ang bawat landas ng booking. Kapag mali ang rate, nawawalan ng tiwala ang guest; kapag mali ang availability, nanganganib ang hotel na mabigo ang booking; kapag luma ang imbentaryo, walang ruta ang maaasahan. Pinapagana ng Wink hindi lang ang button sa website para mag-book — ang parehong data ng hotel ang sumusuporta sa mga landas ng website, mga shareable link, QR code, web components, WinkLinks storefronts, mga partner link, mga listahan sa Traveliko, mga social booking route, Agentic AI handoffs at mga daloy para sa developer. Lahat sila ay nangangailangan ng parehong pundasyon: tumpak na **ARI** — Availability, Rate at Inventory.

## Ang dalawang paraan ng setup

**Paraan 1 — Ikonekta ang isang suportadong provider.** Gamitin ito kapag ang hotel ay kasalukuyang nagma-manage ng mga rate sa isang channel manager, PMS, CRS o rate provider na sinusuportahan ng Wink. Pinipili ng hotel ang provider sa Extranet, ina-activate ang Wink bilang channel sa dashboard ng provider, ini-map ang mga uri ng kuwarto at mga plano ng rate, at ipinapadala ng provider ang ARI sa Wink — na awtomatikong pinupuno ang Master Rate Calendar. Pinakamainam para sa mga multi-channel na hotel, madalas na pagbabago ng rate, pangangailangan ng live inventory at mas mababang manu-manong trabaho.

**Paraan 2 — Manu-manong i-load ang mga rate sa Extranet.** Gamitin ito kapag ang hotel ay hindi gumagamit ng suportadong provider o nais patakbuhin ang Wink nang manu-mano, sa pamamagitan ng `Distribution > Master rate calendar` — mga update para sa isang petsa at maramihang update sa mga saklaw ng petsa. Pinakamainam para sa maliit na imbentaryo, maagang setup o pagsubok. **Kailangan nito ng disiplina:** kung magbabago ang mga rate sa operasyon, kailangang may mag-update sa Wink. At kung may konektadong provider, maaaring mapalitan ang manu-manong pagbabago kapag nagpadala ng susunod na update ang provider para sa parehong mga petsa.

## Konektadong provider kumpara sa manu-manong pag-load

| Tanong | Konektadong provider | Manu-manong pag-load sa Extranet |
|---|---|---|
| Sino ang nag-a-update ng ARI? | Ang suportadong provider ang nagpapadala ng mga update sa Wink. | Ang hotel ang manu-manong nag-a-update ng mga rate at availability. |
| Pinakamainam para sa | Mga multi-channel na hotel, madalas na pagbabago, live inventory. | Maliit na imbentaryo, limitadong paggamit, walang konektadong provider. |
| Trabaho | Mas mababang araw-araw na trabaho pagkatapos ng setup. | Patuloy na manu-manong pagpapanatili. |
| Real-time na pag-uugali | Awtomatikong nag-a-update ang ARI mula sa provider. | Kasing bago lang ng huling manu-manong update. |
| Panganib | Dapat tama ang mapping o setup ng provider. | Luma o hindi napapanahong rate o availability kung hindi pinananatili. |
| Notipikasyon ng booking | Naabisuhan ang channel manager / CRS / PMS kung saan naka-configure. | Nakakatanggap ang hotel ng mga notipikasyon ng booking sa pamamagitan ng Wink. |

## Mga suportadong provider

Sinusuportahan ng Wink ang iba't ibang channel manager, pati na rin ang mga koneksyon sa PMS nang direkta o sa pamamagitan ng Channex bilang proxy. Kumpirmahin ang iyong partikular na bersyon ng provider, paraan ng setup at mga kinakailangan sa mapping kasama ang koponan ng Wink bago mag-live.

| Provider | Uri | Mga Tala |
|---|---|---|
| SiteMinder | Channel manager | Direktang integrasyon |
| Cloudbeds | Channel manager | Direktang integrasyon |
| Travelclick | Channel manager | Direktang integrasyon |
| RateGain | Channel manager | Direktang integrasyon |
| D-EDGE | Channel manager | Direktang integrasyon |
| YieldPlanet | Channel manager | Direktang integrasyon |
| Rate Tiger | Channel manager | Direktang integrasyon |
| Hotel Link | Channel manager | Direktang integrasyon |
| Channex | Channel manager + PMS proxy | Direktang integrasyon, plus proxy para sa maraming PMS provider |
| SynXis | CRS | Maaaring kailanganin ang dagdag na setup sa pamamagitan ng SynXis Channel Connect Express |

Maraming sistema ng PMS — halimbawa Mews, Apaleo, Opera Cloud at OTA Sync — ang maaaring mag-route ng ARI sa Wink **sa pamamagitan ng Channex** bilang proxy. Kung nakakonekta ang iyong PMS sa Channex, maaabot nito ang Wink; kumpirmahin ang bersyon ng iyong PMS at setup ng Channex bago mag-live. (Ito ay isang representatibong listahan — kumpirmahin ang iyong provider sa koponan ng Wink.)

## Setup ng provider, sa buod

Sa Extranet, pumunta sa `Distribution > Channel manager`, piliin ang iyong rate provider at i-save. Sa dashboard ng provider, idagdag ang **Wink** channel at i-map ang mga uri ng kuwarto at mga plano ng rate na ginawa sa Wink. Simulan ang isang buong push ng rate kung hindi ito awtomatikong ginagawa ng provider, pagkatapos tingnan ang Master Rate Calendar — maaaring mag-update ito sa loob ng ilang minuto (nagkakaiba ang oras depende sa provider at mapping). Gamitin ang **Verifier** upang i-simulate ang isang price request ng traveler at subukan ang availability, currency, diskwento at pagpapakita ng rate bago magpadala ng live demand. Gumawa ng test booking lamang kapag naintindihan na ng koponan ang pag-uugali ng notipikasyon.

## Mga notipikasyon ng booking

Hindi lang tungkol sa pagpapadala ng mga rate *sa* Wink ang connectivity — ito rin ang paraan ng pagdaloy ng mga booking pabalik. Kapag may booking, maaaring maabisuhan ang channel manager, CRS o PMS kung saan naka-configure; nakakatanggap ang hotel at traveler ng mga kumpirmasyon sa email; nakakatanggap ang mga partner ng kumpirmasyon ng booking at attribution sa mga partner route; at maaaring makinig ang mga developer sa `booking.created` webhook para sa real-time na detalye.

## Saan nakalagay ang Wink

Nasa pagitan ng Extranet at Booking Engine ang connectivity. Ang [Extranet](/tl/products/extranet/) ay ang control layer ng hotel para sa content, mga kuwarto, mga plano ng rate, mga restriksyon, availability, mga polisiya at mga setting ng Booking Engine; pinapakain ito ng ARI mula sa isang suportadong provider, o manu-manong pinananatili ng hotel ang Master Rate Calendar; at ginagamit ng [Booking Engine](/tl/products/booking-engine/) ang aprubadong data na iyon upang tuparin ang mga booking mula sa direct, Social, WinkLinks, partner, Traveliko, Agentic AI at mga developer route. Ang simpleng tuntunin: **kapag mas malakas ang connectivity, mas maaasahan ang landas ng booking.**

## Mga karaniwang pagkakamali

- **Pag-aakala na makakapagbenta ang Wink nang walang kasalukuyang availability.** Kailangan muna nito ng ARI mula sa provider o manu-manong update sa Extranet.
- **Pagkonekta ng provider ngunit hindi pagma-map ng mga kuwarto at plano ng rate.** Hindi kumpleto ang setup hangga't hindi tama ang mapping.
- **Manu-manong pag-edit ng mga rate habang konektado ang provider.** Maaaring mapalitan ang manu-manong pagbabago ng susunod na update ng provider.
- **Nakakalimutang mag-verify.** Subukan ang pagpapakita ng rate, availability at lohika ng diskwento bago magpadala ng live demand.
- **Pagtingin sa connectivity bilang isang teknikal na gawain lamang.** Nakakaapekto ito sa kita, marketing, mga partner route, conversion at tiwala ng guest.
