Ang mga MCP tool ng Wink ay ipinapublish bilang **toolsets** — mga nakatuong endpoint, bawat isa ay sumasaklaw sa isang trabaho. Ikokonekta mo ang iyong AI client sa isa o dalawang tumutugma sa iyong trabaho, hindi sa lahat.

Bawat endpoint ay gumagamit ng **interactive OAuth2 login** (PKCE authorization code flow): binubuksan ng iyong AI agent ang isang browser tab, mag-sign in ka gamit ang iyong Wink account, at iyon na. Walang kailangang i-manage na client secrets.

```bash title="Isang channel manager integrator ang kumokonekta sa isang endpoint"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Isang hotelier na nagma-manage ng sariling mga rate ang kumokonekta sa isa pa"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## Bakit hinati ang mga tool sa iba't ibang mga endpoint

Nag-eexpose ang Wink ng humigit-kumulang 500 na mga tool. Posibleng ibigay lahat ito sa isang agent nang sabay-sabay — ngunit hindi ito magandang ideya.

**Ang mga depinisyon ng tool ay kumakain ng context.** Bawat tool na ina-advertise ng isang MCP server ay niloload sa context window ng modelo bago ito gumawa ng anumang trabaho, kasama ang paglalarawan nito at buong parameter schema. Limang daan sa mga iyon ay kumokonsumo ng malaking bahagi ng budget na kailangan ng iyong aktwal na gawain, sa bawat request.

**Bumababa ang kalidad ng pagpili habang lumalaki ang listahan.** Ang isang agent na pumipili mula sa 500 na halos magkaparehong pangalan ng mga tool ay gumagawa ng mas masamang pagpili kaysa sa isang pumipili mula sa 40. Kung nag-iintegrate ka ng channel manager, mga dalawampung tool lang ang may kaugnayan sa iyo; ang iba pang 480 ay ingay na nagpapahirap hanapin ang tamang tool.

**Ang trabaho ay tunay na nahahati.** Ang isang tao na nagsi-sync ng availability mula sa PMS at ang isang tao na nagcu-curate ng affiliate landing pages ay halos walang pinagsasaluhang mga tool. Ang paghahati ayon sa trabaho ay nangangahulugan na bawat koneksyon ay nagdadala ng bokabularyo ng isang trabaho.

<Aside type="caution" title="Ang mga toolset ay hindi mga permiso">
Ang pagpili ng makitid na toolset ay **hindi** naglilimita sa kung ano ang magagawa ng iyong account, at ang pagpili ng malawak ay hindi nagbibigay ng anumang dagdag. Bawat tool ay nagpapatupad ng parehong mga permiso ng account tulad ng web portal, sa ilalim ng iyong naka-sign in na pagkakakilanlan. Kung hindi maaaring mag-cancel ng booking ang iyong account sa Wink Portal, hindi rin magagawa iyon ng agent — kahit anong endpoint pa ang nakakonekta dito.

Pumili ng mga toolset para sa **pokús**, hindi para sa seguridad.
</Aside>

## Direktoryo ng mga endpoint

Dalawang host ang nagseserbisyo ng mga toolset. Ang bilang ng mga tool ay tinatayang at lumalaki sa paglipas ng panahon.

### `https://api.wink.travel` — ang platform

| Endpoint | Mga Tool | Saklaw nito |
|---|---:|---|
| `/mcp/extranet/facilities` | ~64 | Ang bookable at on-site na imbentaryo: mga guest room at uri ng kuwarto, spa, mga restawran, mga meeting room, mga aktibidad, atraksyon, mga lugar, iba pang mga item na maaaring ibenta |
| `/mcp/extranet/property` | ~62 | Ang rekord ng property at mga komersyal na termino nito: profile at nilalaman, mga add-on, mga patakaran sa pagkansela, mga perk, mga anunsyo |

### `https://integrations.wink.travel` — mga channel manager integration

Isang endpoint lang, dahil ang host na ito ay para sa isang trabaho lang.

| Endpoint | Mga Tool | Saklaw nito |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Pagkonekta at pag-verify ng channel manager, PMS o CRS integration |

<Aside type="note" title="Pag-integrate ng channel manager vs. pamamahala ng sariling mga rate">
Iba't ibang trabaho ito para sa iba't ibang tao, at hindi sila nagbabahagi ng endpoint.

Ang isang **channel manager, PMS o CRS vendor** ay nag-iintegrate nang isang beses sa pamamagitan ng `integrations.wink.travel/mcp/channel-manager`, at mula noon ay nagpapalitan ng mga property, rate, availability at reservation sa pamamagitan ng integration na iyon. Ang iisang endpoint na iyon ang buong surface.

Ang isang **hotelier na nagbabago ng sariling mga rate nang mano-mano** ay gumagamit ng extranet toolset sa `api.wink.travel` — `/mcp/extranet/rates` at mga kaibigan nito. Hindi ito bahagi ng channel manager integration at walang dahilan ang integrator na kumonekta dito.

Ang pamamahala ng account ay nasa `api.wink.travel` din, sa `/mcp/settings`. Walang `/mcp/settings` sa integrations host.
</Aside>

Bawat endpoint ay may kasamang `ping` tool, kaya maaari mong kumpirmahin na live ang koneksyon bago ito utusan ng totoong trabaho.

### Agentic payments

Para sa kumpletong traveler booking flow, ikonekta ang **Wink Booking Engine** sa `https://api.wink.travel/mcp/booking-engine` at isang compatible na **payment wallet**. Ang pagdagdag ng Wink MCP ay nagbubukas ng browser sign-in at pagpili ng permiso; ang iyong client ang humahawak ng authentication.

Kasama sa Booking Engine ang destination lookup, paghahanap ng hotel at kuwarto, `agentic_booking_quote`, `agentic_booking_pay`, `agentic_booking_book`, pagkuha ng booking at mga resibo, kapag pinagana ang agentic booking at payment para sa environment na iyon. Tingnan ang [Agentic Payments](/tl/developers/agentic-payments/) para sa setup ng koneksyon, mga permiso na pipiliin at mga hakbang mula sa paghahanap hanggang kumpirmasyon.

## Anong mga toolset ang kailangan ko?

| Kung ikaw ay… | Kumonekta sa |
|---|---|
| **Nag-iintegrate ng channel manager, PMS o CRS** | `integrations.wink.travel/mcp/channel-manager` — ito lang |
| **Nagma-manage ng nilalaman ng property** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Nagma-manage ng mga kuwarto at uri ng kuwarto** | `/mcp/extranet/facilities` |
| **Nagma-manage ng mga presyo at availability** | `/mcp/extranet/rates` |
| **Nagpapatakbo ng araw-araw na reservation** | `/mcp/extranet/operations` |
| **Nagpapalago ng distribution** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Gumagawa ng mga affiliate page** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Nagpapatakbo ng link-in-bio pages** | `/mcp/link-manager` + `/mcp/social` |
| **Nagbo-booking para sa mga traveller** | `/mcp/travel-agent` |
| **Nagre-reconcile ng pera** | `/mcp/payment` |
| **Nagbo-book ng kuwarto gamit ang AI agent** | `/mcp/booking-engine` + isang compatible na payment wallet — tingnan ang [Agentic Payments](/tl/developers/agentic-payments/) |
| **Gumagawa ng booking experience** | `/mcp/booking-engine`; opsyonal ang `/mcp/reference` para sa karagdagang lookup |

**Kasama sa Booking Engine ang pangunahing booking workflow.** Nagbibigay ito ng account at customization discovery, destination lookup, availability ng hotel at detalye ng room-rate, shopping cart, checkout, at pamamahala ng booking ng traveller. Kasama rin ang agentic booking at payment tools kapag pinagana para sa environment na iyon.

Para sa paghahanap ng hotel sa isang lungsod, gamitin ang `destination_lookup_search_suggestions` para i-resolve ang destinasyon, pagkatapos ay `inventory_search_city` para hanapin ang mga available na hotel at rate. Parehong tool ay nasa `/mcp/booking-engine`, kaya hindi kailangan ng Reference connection ang flow na ito.

Idagdag ang `/mcp/reference` kapag kailangan mo ng mga supporting lookup tulad ng mga bansa, pera at exchange rate, mga suportadong wika, mga timezone, mas malawak na geographic search, mga klasipikasyon ng OTA, o pampublikong kaalaman tungkol sa property. Opsyonal ang mga ito sa booking flow.

Magsimula sa isa. Magdagdag ng isa pa kapag napansin mong may hinahanap kang hindi kaya ng isa — bawat koneksyon ay independyente, at ang pagdagdag ng isa ay hindi nakakaapekto sa iba.

<Aside type="tip" title="Gusto mo pa rin lahat?">
Ang `https://api.wink.travel/mcp` at `https://integrations.wink.travel/mcp` ay nananatiling available at nagseserbisyo ng **lahat** ng tool sa kanilang host. Magagamit ito para tuklasin kung ano ang meron, ngunit hindi namin inirerekomenda para sa araw-araw na trabaho: sapat na ang laki ng listahan ng tool para matabunan ang iyong gawain at pababain ang pagpili ng tool ng agent. Mas piliin ang mga toolset sa itaas.
</Aside>

## Paano gumagana ang authentication

Gumagamit ang mga MCP server ng Wink ng **OAuth2 Authorization Code + PKCE** flow at sumusuporta sa **Dynamic Client Registration (RFC 7591)**. Ganito ang nangyayari kapag kumonekta ka sa unang pagkakataon:

1. Nadidiskubre ng iyong AI client ang authorization server mula sa `/.well-known/oauth-protected-resource` metadata ng MCP endpoint.
2. Nagse-self-register ang client sa pamamagitan ng **Dynamic Client Registration** — walang kailangang manual na setup ng application.
3. Binubuksan ng client ang isang **browser tab** sa `https://iam.wink.travel`. Mag-sign in ka gamit ang iyong Wink account at aprubahan ang mga hinihinging permiso sa consent screen.
4. Nag-iisyu ang Wink ng **access token** na naka-scope sa iyong account at naka-link sa iyong pagkakakilanlan.
5. Ina-attach ng AI client ang token sa bawat MCP request. Lahat ng resulta ng tool ay awtomatikong naka-scope sa iyong managing entity.
6. Nag-e-expire ang mga token pagkatapos ng 3 oras. Silent na nire-refresh ng iyong AI client ang token sa background nang hindi na muling nagtatanong.

Bawat tawag sa tool ay tumatakbo **sa ilalim ng iyong pagkakakilanlan** — ang parehong mga ACL rule na nagpoprotekta sa web portal ay nalalapat sa AI agent.

## Mga Scope

Kapag inaprubahan mo ang consent screen makikita mo ang breakdown ng hinihingi ng agent. Gumagamit ang mga MCP client ng parehong bokabularyo ng permiso tulad ng buong platform — tingnan ang buong
[scope reference sa Authentication page](/tl/developers/authentication#scopes).

Dalawang bagay ang partikular sa MCP:

- **Kinakailangan din ang mga scope na `mcp.read` `mcp.write` `mcp.remove`** para mabuksan ang MCP transport. Ang client na may hawak na `mcp.*` scope ay pinapayagang pumasok sa anumang Wink MCP endpoint, ngunit bawat tool na tinatawag nito ay nagpapatupad pa rin ng section scope ng endpoint na kinabibilangan nito (hal. `booking.read`).
- **Humihiling ang AI client ng scope na kailangan lang nito.** Maaari mong tanggihan ang indibidwal na permiso sa consent screen — ang mga tool na nangangailangan ng tinanggihan na scope ay magbabalik ng error kapag tinawag.

**Hindi binabago ng mga toolset ang alinman dito.** Ang endpoint na kinokonekta mo ang nagdedesisyon kung aling mga tool ang *nakalista*, hindi kung ano ang *pinapayagan*. Ang pagkonekta sa `/mcp/payment` ay hindi nagbibigay ng karagdagang permiso sa pananalapi na wala ka pa, at ang pagkonekta sa `/mcp/reference` ay hindi pumipigil sa tool doon na ipatupad ang sariling scope nito. Ang awtorisasyon ay dinidesisyonan bawat tawag sa tool, mula sa iyong token at mga grant ng iyong account.

## Pag-troubleshoot

**Hindi bumubukas ang browser tab**

Maaaring hindi pa sinusuportahan ng iyong AI client ang interactive PKCE flow. Siguraduhing tumatakbo ka ng bagong bersyon:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** i-update mula sa built-in updater ng app

**`401 Unauthorized` pagkatapos mag-sign in**

Maaaring luma na ang iyong cached token. Alisin at idagdag muli ang server para mag-trigger ng bagong sign-in:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Para sa Claude Desktop at ChatGPT, alisin ang server entry sa settings, i-restart ang app, at idagdag muli.

**`403 Forbidden` kapag tumatawag ng partikular na tool**

Kailangan ng tool ng scope na hindi mo inaprubahan sa consent screen, o permiso na wala ang iyong account. Ikonekta muli ang server — lalabas ulit ang consent screen at maaari mong aprubahan ang nawawalang permiso. Kung hindi pa rin ito gumana, kailangan ng tool ng permiso ng account na wala ka; hindi makakatulong ang pagkonekta sa ibang toolset dahil hindi nagbibigay ng permiso ang mga toolset.

**Walang tool na kailangan ko sa listahan**

Malamang nakakonekta ka sa toolset na hindi sumasaklaw sa trabahong iyon. Tingnan ang [endpoint directory](#endpoint-directory) at idagdag ang toolset na sumasaklaw — independyente ang mga koneksyon, kaya ang pagdagdag ng isa ay hindi nakakaapekto sa iba. Kung hindi ka sigurado kung alin ang may tool, pansamantalang kumonekta sa `https://api.wink.travel/mcp`, hanapin ang tool, pagkatapos tingnan kung aling toolset ang naglilista nito.

**`404 Not Found` sa isang toolset endpoint**

Suriing mabuti ang path — ang mga nested toolset ay may dalawang segment (`/mcp/extranet/rates`, hindi `/mcp/extranet-rates`), at ang mga flat ay may isa (`/mcp/link-manager`). Tandaan na ang *hindi authenticated* na request sa anumang path sa ilalim ng `/mcp` ay nagbabalik ng `401`, hindi `404`, kaya ang `401` lang ay hindi nagsasabi kung umiiral ang endpoint.

**Kumonekta ako sa `api.wink.travel/mcp/channel-manager` at walang nangyari**

Walang ganoong endpoint. Ang channel manager integration ay nagseserbisyo lamang mula sa `https://integrations.wink.travel/mcp/channel-manager`. Kung kailangan mo ring basahin o isulat ang sariling mga rate ng property nang mano-mano, iyon ay hiwalay na trabaho sa hiwalay na endpoint — tingnan ang `/mcp/extranet/rates`.

**Lumilitaw ang server pero ang mga tawag sa tool ay nagbabalik ng "account not found"**

Naka-sign in ka sa Wink account na walang managing entity. Pumunta sa [Wink Portal](https://app.wink.travel) at siguraduhing naka-setup ang iyong account bago gamitin ang MCP server.

**Nag-e-expire ang token sa gitna ng session**

Valid ang mga token ng 3 oras. Silent na nire-refresh ng Claude Code at Claude Desktop ang mga token nang hindi nilalabag ang session. Kung makakita ka ng auth error pagkatapos ng mahabang idle, mag-type ng bagong mensahe — magre-re-authenticate ang client nang awtomatiko.

**Ipinapakita ng Codex CLI ang "MCP server unreachable"**

Suriin na valid ang iyong `~/.codex/config.json` na JSON (walang trailing commas) at naka-set ang `"type": "http"`. Nangangailangan ang Codex ng HTTP transport para sa remote server; ang stdio transport ay para sa local binaries lang.

**Walang "Connectors" menu sa ChatGPT**

Kailangan ng ChatGPT desktop app bersyon **1.2024.352** o mas bago at aktibong Plus, Pro, Team, o Enterprise subscription ang suporta sa MCP. I-update ang app at i-verify ang iyong plano sa Settings → Account.

**Nagpapakita ng pula / "Failed to connect" ang Cursor server**

Suriin na valid ang iyong `~/.cursor/mcp.json` na JSON at may `"type": "http"`. Pagkatapos pumunta sa **Settings → Cursor Settings → MCP** at i-click ang **Refresh**. Kung patuloy ang error, ganap na i-restart ang Cursor — hindi palaging nakukuha ang mga pagbabago sa config nang walang restart.

**Hindi nakalista ang Windsurf MCP server sa settings**

Kailangan ng Windsurf ng ganap na restart (hindi lang pag-reload ng window) para makuha ang mga pagbabago sa `mcp_config.json`. Gamitin ang **File → Quit** at buksan muli. Kung hindi pa rin lumalabas, tiyaking nasa Windsurf **1.4+** ka sa pamamagitan ng **Help → About Windsurf**.

**Hindi nakikita ang opsyon na "Add Server" sa Cline**

Kailangan ng MCP server manager ang Cline **2.0** o mas bago. Buksan ang VS Code Extensions panel, hanapin ang Cline, at i-click ang **Update** kung may update. Pagkatapos mag-update, i-reload ang VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
