Ang mga MCP tool ng Wink ay ipinapublish bilang **toolsets** — mga nakatuong endpoints, bawat isa ay sumasaklaw sa isang trabaho. Ikokonekta mo ang iyong AI client sa isa o dalawang tumutugma sa iyong trabaho, hindi sa lahat.

Bawat endpoint ay gumagamit ng **interactive OAuth2 login** (PKCE authorization code flow): magbubukas ang iyong AI agent ng browser tab, mag-sign in ka gamit ang iyong Wink account, at iyon na. Walang kailangang i-manage na client secrets.

```bash title="Isang channel manager integrator ang kumokonekta sa isang endpoint"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Isang hotelier na nagma-manage ng sariling mga rate ang kumokonekta sa isa pa"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## Bakit hinati ang mga tool sa iba't ibang endpoints

Nag-eexpose ang Wink ng humigit-kumulang 500 tool. Posibleng ibigay lahat ito sa isang agent nang sabay-sabay — ngunit hindi ito magandang ideya.

**Ang mga depinisyon ng tool ay kumakain ng context.** Bawat tool na ina-advertise ng isang MCP server ay niloload sa context window ng modelo bago ito gumawa ng anumang trabaho, kasama ang paglalarawan at buong parameter schema nito. Limang daan sa mga iyon ay kumokonsumo ng malaking bahagi ng budget na kailangan ng iyong aktwal na gawain, sa bawat request.

**Bumababa ang kalidad ng pagpili habang lumalaki ang listahan.** Ang isang agent na pumipili mula sa 500 na halos magkaparehong pangalan ng tool ay gumagawa ng mas mahihirap na pagpili kaysa sa isang pumipili mula sa 40. Kung nag-iintegrate ka ng channel manager, mga dalawampung tool lang ang may kaugnayan sa iyo; ang iba pang 480 ay ingay na nagpapahirap hanapin ang tamang tool.

**Ang trabaho ay tunay na nahahati.** Ang isang tao na nagsi-sync ng availability mula sa PMS at ang isang tao na nagcu-curate ng affiliate landing pages ay halos walang pinagsasaluhang tool. Ang paghahati ayon sa trabaho ay nangangahulugan na bawat koneksyon ay nagdadala ng bokabularyo ng isang trabaho.

<Aside type="caution" title="Ang mga toolsets ay hindi mga permiso">
Ang pagpili ng makitid na toolset ay **hindi** naglilimita sa kung ano ang magagawa ng iyong account, at ang pagpili ng malawak ay hindi nagbibigay ng dagdag na kapangyarihan. Bawat tool ay nagpapatupad ng parehong mga permiso ng account tulad ng web portal, sa ilalim ng iyong naka-sign in na pagkakakilanlan. Kung hindi makakansela ng iyong account ang isang booking sa Wink Portal, hindi rin magagawa iyon ng agent — kahit anong endpoint ang nakakonekta dito.

Pumili ng mga toolset para sa **pokús**, hindi para sa seguridad.
</Aside>

Dalawang host ang nagseserbisyo ng mga toolset. Ang bilang ng mga tool ay tinatayang at lumalaki sa paglipas ng panahon.

### `https://integrations.wink.travel` — mga integrasyon ng channel manager

Isang endpoint lang, dahil ang host na ito ay para sa isang trabaho lang.

| Endpoint | Mga Tool | Saklaw nito |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Pagkonekta at pag-verify ng channel manager, PMS o CRS integration |

<Aside type="note" title="Pag-integrate ng channel manager vs. pamamahala ng sariling mga rate">
Iba ang mga trabahong ito para sa iba't ibang tao, at hindi sila nagbabahagi ng endpoint.

Ang isang **channel manager, PMS o CRS vendor** ay nag-iintegrate nang isang beses sa pamamagitan ng `integrations.wink.travel/mcp/channel-manager`, at mula noon ay nagpapalitan ng mga property, rate, availability at reservation sa pamamagitan ng integrasyong iyon. Ang iisang endpoint na iyon ang buong surface.

Ang isang **hotelier na nagbabago ng sariling mga rate nang mano-mano** ay gumagamit ng mga extranet toolset sa `api.wink.travel` — `/mcp/extranet/rates` at mga kaibigan nito. Hindi ito bahagi ng channel manager integration at walang dahilan ang integrator na kumonekta dito.

Ang pamamahala ng account ay nasa `api.wink.travel` din, sa `/mcp/settings`. Walang `/mcp/settings` sa integrations host.
</Aside>

Bawat endpoint ay may kasamang `ping` tool, kaya maaari mong kumpirmahin na live ang koneksyon bago ito utusan ng totoong trabaho.

| **Gumagawa ng mga affiliate page** | `/mcp/studio/curation` + `/mcp/studio/embeds` |

Magagamit ito para tuklasin kung ano ang meron, ngunit hindi namin inirerekomenda para sa araw-araw na trabaho: sobrang laki ng listahan ng tool na maaaring makaapekto sa iyong gawain at pababain ang kalidad ng pagpili ng agent. Mas piliin ang mga toolset sa itaas.
</Aside>

## Paano gumagana ang authentication

Gumagamit ang mga MCP server ng Wink ng **OAuth2 Authorization Code + PKCE** flow at sumusuporta sa **Dynamic Client Registration (RFC 7591)**. Ganito ang nangyayari kapag kumonekta ka sa unang pagkakataon:

1. Nadidiskubre ng iyong AI client ang authorization server mula sa `/.well-known/oauth-protected-resource` metadata ng MCP endpoint.
2. Nagse-self-register ang client gamit ang **Dynamic Client Registration** — walang kailangang manual na setup ng application.
3. Nagbubukas ang client ng **browser tab** sa `https://iam.wink.travel`. Mag-sign in ka gamit ang iyong Wink account at aprubahan ang mga hinihinging permiso sa consent screen.
4. Nag-iisyu ang Wink ng **access token** na naka-scope sa iyong account at naka-link sa iyong pagkakakilanlan.
5. Ina-attach ng AI client ang token sa bawat MCP request. Lahat ng resulta ng tool ay awtomatikong naka-scope sa iyong managing entity.
6. Nag-e-expire ang mga token pagkatapos ng 3 oras. Silent na nire-refresh ng iyong AI client ang mga ito sa background nang hindi na muling humihingi ng pahintulot.

Bawat tawag sa tool ay tumatakbo **sa ilalim ng iyong pagkakakilanlan** — ang parehong mga patakaran ng ACL na nagpoprotekta sa web portal ay nalalapat sa AI agent.

## Mga Scope

Kapag inaprubahan mo ang consent screen makikita mo ang breakdown ng hinihingi ng agent. Gumagamit ang mga MCP client ng parehong bokabularyo ng permiso tulad ng buong platform — tingnan ang buong
[scope reference sa Authentication page](/tl/developers/authentication#scopes).

Dalawang bagay ang partikular sa MCP:

- **Kinakailangan din ang mga scope na `mcp.read` `mcp.write` `mcp.remove`** para mabuksan ang MCP transport. Ang client na may hawak na `mcp.*` scope ay pinapayagang pumasok sa anumang Wink MCP endpoint, ngunit bawat tool na tinatawag nito ay nagpapatupad pa rin ng section scope ng endpoint na kinabibilangan nito (hal. `booking.read`).
- **Humihiling lang ang AI client ng mga scope na kailangan nito.** Maaari mong tanggihan ang indibidwal na permiso sa consent screen — ang mga tool na nangangailangan ng tinanggihan na scope ay magbabalik ng error kapag tinawag.

**Hindi binabago ng mga toolset ang alinman dito.** Ang endpoint na kinokonekta mo ang nagdedesisyon kung aling mga tool ang *naka-lista*, hindi kung ano ang *pinapayagan*. Ang pagkonekta sa `/mcp/payment` ay hindi nagbibigay ng karagdagang permiso sa pananalapi na wala ka pa, at ang pagkonekta sa `/mcp/reference` ay hindi pumipigil sa tool doon na ipatupad ang sariling scope nito. Ang awtorisasyon ay dinidesisyonan bawat tawag sa tool, mula sa iyong token at mga grant ng iyong account.

## Pag-troubleshoot

**Hindi nagbubukas ang browser tab**

Maaaring hindi pa sinusuportahan ng iyong AI client ang interactive PKCE flow. Siguraduhing tumatakbo ka ng bagong bersyon:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** i-update mula sa built-in updater ng app

**`401 Unauthorized` pagkatapos mag-sign in**

Maaaring luma na ang iyong cached token. Alisin at idagdag muli ang server para mag-trigger ng bagong sign-in:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Para sa Claude Desktop at ChatGPT, alisin ang server entry sa settings, i-restart ang app, at idagdag muli.

**`403 Forbidden` kapag tumatawag ng partikular na tool**

Kailangan ng tool ng scope na hindi mo inaprubahan sa consent screen, o permiso na wala ang iyong account. Ikonekta muli ang server — lalabas ulit ang consent screen at maaari mong aprubahan ang nawawalang permiso. Kung hindi pa rin ito gumana, nangangailangan ang tool ng permiso ng account na wala ka; hindi makakatulong ang pagkonekta sa ibang toolset dahil hindi nagbibigay ng permiso ang mga toolset.

**Walang tool na kailangan ko sa listahan**

Malamang nakakonekta ka sa toolset na hindi sumasaklaw sa trabahong iyon. Tingnan ang [endpoint directory](#endpoint-directory) at idagdag ang toolset na sumasaklaw — independyente ang mga koneksyon, kaya ang pagdagdag ng isa ay hindi nakakaapekto sa iba. Kung hindi ka sigurado kung alin ang may tool, pansamantalang kumonekta sa `https://api.wink.travel/mcp`, hanapin ang tool, at tingnan kung aling toolset ito kabilang.

**`404 Not Found` sa toolset endpoint**

Suriing mabuti ang path — ang mga nested toolset ay may dalawang segment (`/mcp/extranet/rates`, hindi `/mcp/extranet-rates`), at ang mga flat ay may isa (`/mcp/link-manager`). Tandaan na ang *hindi authenticated* na request sa anumang path sa ilalim ng `/mcp` ay nagbabalik ng `401`, hindi `404`, kaya ang `401` lang ay hindi nagsasabi kung umiiral ang endpoint.

**Kumonekta ako sa `api.wink.travel/mcp/channel-manager` pero walang nangyari**

Walang ganoong endpoint. Ang channel manager integration ay nagseserbisyo lamang mula sa `https://integrations.wink.travel/mcp/channel-manager`. Kung kailangan mo ring basahin o baguhin ang sariling mga rate ng property nang mano-mano, ito ay hiwalay na trabaho sa hiwalay na endpoint — tingnan ang `/mcp/extranet/rates`.

**Lumilitaw ang server pero ang mga tawag sa tool ay nagbabalik ng "account not found"**

Naka-sign in ka sa Wink account na walang managing entity. Pumunta sa [Wink Portal](https://app.wink.travel) at siguraduhing naka-setup ang iyong account bago gamitin ang MCP server.

**Nag-e-expire ang token habang session**

Valid ang mga token ng 3 oras. Silent na nire-refresh ng Claude Code at Claude Desktop ang mga token nang hindi nilalabag ang session. Kung makakita ka ng auth error pagkatapos ng matagal na idle, mag-type ng bagong mensahe — magre-re-authenticate ang client nang awtomatiko.

**Nagpapakita ang Codex CLI ng "MCP server unreachable"**

Suriin na valid ang iyong `~/.codex/config.json` (walang trailing commas) at naka-set ang `"type": "http"`. Nangangailangan ang Codex ng HTTP transport para sa remote servers; ang stdio transport ay para lang sa local binaries.

**Walang "Connectors" menu sa ChatGPT**

Kailangan ng ChatGPT desktop app version **1.2024.352** o mas bago at aktibong Plus, Pro, Team, o Enterprise subscription ang suporta sa MCP. I-update ang app at tingnan ang iyong plano sa Settings → Account.

**Nagpapakita ng pula / "Failed to connect" ang Cursor server**

Suriin na valid ang iyong `~/.cursor/mcp.json` at may `"type": "http"`. Pumunta sa **Settings → Cursor Settings → MCP** at i-click ang **Refresh**. Kung patuloy ang error, ganap na i-restart ang Cursor — hindi palaging nakukuha ang mga pagbabago sa config nang walang restart.

**Hindi nakalista ang Windsurf MCP servers sa settings**

Kailangan ng Windsurf ng ganap na restart (hindi lang window reload) para makuha ang mga pagbabago sa `mcp_config.json`. Gamitin ang **File → Quit** at buksan muli. Kung hindi pa rin lumalabas, siguraduhing nasa Windsurf **1.4+** ka sa pamamagitan ng **Help → About Windsurf**.

**Hindi nakikita ang "Add Server" option sa Cline**

Kailangan ng MCP server manager ang Cline **2.0** o mas bago. Buksan ang VS Code Extensions panel, hanapin ang Cline, at i-click ang **Update** kung may available na update. Pagkatapos mag-update, i-reload ang VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
