## Preporučiti hotel nije isto što i rezervirati ga

Većina današnjeg "AI putovanja" staje na preporuci. Asistent predloži tri hotela, zatim putnika preusmjeri na web stranicu ili OTA za stvarnu rezervaciju. Nit se prekida, cijena možda nije rezervabilna i nitko ne čuva kontekst izvora.

**AI agent** se razlikuje od AI odgovora. Agent ne opisuje samo hotel — on djeluje: provjerava živu dostupnost, sastavlja rezervaciju, prima uplatu i može reagirati na promjene. Za to je potrebno više od teksta. Potrebni su mu strukturirani, aktualni, rezervabilni podaci i sloj transakcije koji može pozvati.

Ovo je razlika između [AI otkrivanja](/hr/resources/ai-discovery-hotels/), koje se tiče **bivanja pronađenim i razumljenim**, i agentic commercea, koji se tiče **obavljanja transakcija**.

## Što agent treba prije nego što može obaviti transakciju

Rezervacija hotela je stvarni komercijalni događaj: pravi soba, prava cijena, stvarna dostupnost, pravila, uplata i potvrda koja se sinkronizira s hotelom. Agent to može završiti samo ako je svaki dio dostupan kao pozivna operacija.

| Agent treba | Zašto je važno |
|---|---|
| Strukturirani, živi kapaciteti | Podaci prikupljeni web scrapingom zastarijevaju; agent treba aktualni inventar pod kontrolom hotela. |
| Cijene i dostupnost u stvarnom vremenu | Cijena koju agent navede mora biti stvarno rezervabilna u tom trenutku. |
| Operacija rezervacije | Kreiranje rezervacije mora biti stvarni API poziv, a ne preusmjeravanje na web formu. |
| Uplata | Agent (ili putnik preko njega) mora moći platiti, uz primjenu pravila. |
| Atribucija | Izvor, kampanja ili agent koji je kreirao rezervaciju trebaju ostati povezani. |
| Događaji | Agent treba moći reagirati na potvrde, promjene, otkazivanja i povrate. |

Bez ovoga agent može preporučiti — ali ne može rezervirati.

## Kako AI agent rezervira hotel na Wink platformi

Wink je API-prvi: svaka platformska funkcija je dostupna izvana, a hostani MCP server izlaže žive API ugovore agentima. Tipičan tijek agenta:

### 1 — Poveži se i pročitaj žive ugovore

Agent se povezuje na hostani MCP server i koristi `api_search` i `docs_search` da pronađe prave operacije i pročita njihove stvarne sheme zahtjeva/odgovora — bez nagađanja krajnjih točaka, bez zastarjelih dokumenata.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Pretraži rezervabilni inventar

Agent pretražuje hotelom kontrolirane kapacitete, uključujući prostornu pretragu geolokacije, i čita žive cijene i dostupnost preko povezanih channel managera.

### 3 — Kreiraj rezervaciju

Kreiranje rezervacije je REST API operacija. Agent sastavlja sobu, cijenu, datume i goste te kreira rezervaciju putem API-ja.

### 4 — Primi uplatu i potvrdi

[Booking Engine](/hr/products/booking-engine/) izvršava transakciju — naplatu, uplatu (Wink je trgovac zapisa), pravila otkazivanja, potvrdu i sinkronizaciju rezervacije s povezanim PMS-om ili channel managerom. Izvor i partner atribucija se čuvaju kroz rezervaciju.

### 5 — Reagiraj na događaje

Agent se može pretplatiti na `booking.created` i druge webhook događaje za usklađivanje, obavještavanje putnika ili pokretanje daljnjih radnji.

Načelo: **agent kreira ili usmjerava namjeru; Booking Engine ostaje sloj izvršenja ispod svakog prijenosa.**

## AI pretraživanje vs AI agenti

Rješavaju različite zadatke, a hotel treba biti spreman za oba.

| | AI pretraživanje / engine za odgovore | AI agenti |
|---|---|---|
| Cilj putnika | Pronaći i usporediti hotele | Rezervirati i upravljati boravkom |
| Što hotel treba | [Strukturirani, pretraživi sadržaj](/hr/resources/hotel-content-answer-engines/) | Živi API, cijene, rezervacije, uplata |
| Krajnji rezultat | Preporuka | Potvrđena rezervacija |
| Wink sučelje | Čist inventar + sadržaj spreman za odgovore | REST API, MCP server, Booking Engine |

[AI otkrivanje za hotele](/hr/resources/ai-discovery-hotels/) pokriva stranu pretraživanja; ovaj vodič pokriva stranu transakcija.

## Tko gradi agente za hotelijerski commerce

Agentic travel commerce nisu samo potrošački asistenti. Ista infrastruktura pokreće:

- **Potrošačke putničke asistente** koji pretražuju, rezerviraju i upravljaju boravkom od početka do kraja.
- **Bankovne, loyalty i super-app agente** koji ugrađuju rezervaciju hotela u postojeće korisničko iskustvo.
- **Automatizacije partnera i kreatora** koje pronalaze podobne hotele, grade sadržaje i čuvaju povezanost atribucije — zarađujući 10% osnovne provizije na potvrđene rezervacije.
- **Hotel-side copilote** koji pomažu timovima u generiranju sadržaja i analizi performansi kroz [Extranet](/hr/products/extranet/), [Social](/hr/products/social/) i [Studio](/hr/products/studio/), dok hotel zadržava pravila.

## Kuda ovo vodi

Gore navedene mogućnosti su danas dostupne kroz REST API i MCP server. Smjer je dublji agent-native commerce: bogatiji booking primitivci za agente, identitet i autorizacija agenata za transakcije u ime putnika, te agenti kao atribuirani, zarađujući izvori u partnerskoj mreži. Kroz cijeli proces je dosljedno — **infrastruktura travel commercea za AI agente**, s Booking Engineom kao slojem izvršenja ispod.

## Česte pogreške

- **Smatranje AI otkrivanja i AI agenata istim projektom.** Jedno je sadržaj i struktura; drugo je API i izvršenje. Potrebna su oba.
- **Dozvoljavanje agentima da navode cijene koje ne mogu rezervirati.** Ponude moraju dolaziti iz živih cijena i dostupnosti, ne sa scrapeanih stranica.
- **Gubitak atribucije pri prijenosu.** Ako agent stvara potražnju, rezervacija treba ostati povezana s tim izvorom.
- **Preskakanje sloja izvršenja.** Odgovor nije rezervacija dok se stvarno ne dogode naplata, uplata i potvrda.
