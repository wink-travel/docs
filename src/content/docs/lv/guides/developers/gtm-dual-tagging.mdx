Jūs varat savienot **jebkuru** Google Tag Manager (GTM) konteineru ar Wink, ievadot tā **GTM konteineru ID** Wink portālā. Kad tas ir savienots, jūsu konteiners tiek automātiski ielādēts jūsu īpašumam un tieši lasa Wink rezervācijas notikumus — aptverot pilnu viesu ceļojumu no meklēšanas līdz pabeigtai rezervācijai. Bieži izmantots piemērs ir **Sojern** konteiners atkārtotai mārketinga un reklāmas vajadzībām, bet jebkurš GTM konteiners darbojas vienādi.

<Aside type="tip">
Tas pieņem, ka jums jau ir GTM konteineru ID (formāts `GTM-XXXXXXX`). Ja jūsu konteiners nāk no partnera, piemēram, Sojern, lūdziet savam konta pārvaldniekam tieši **GTM konteineru ID** — tas atšķiras no pikseļa vai taga ID. Ja esat jauns Sojern, apmeklējiet [sojern.com/contact](https://www.sojern.com/contact), lai sāktu.
</Aside>

## Kas jums jādara

<Steps>

1. **Iegūstiet savu GTM konteineru ID**

   Iegūstiet savu **GTM konteineru ID** (formāts `GTM-XXXXXXX`). Ja tas nāk no partnera, piemēram, Sojern, pieprasiet tieši GTM konteineru ID — tas atšķiras no pikseļa vai taga ID.

2. **Ievadiet to Wink portālā**

   Piesakieties [app.wink.travel](https://app.wink.travel), izvēlieties savu kontu un dodieties uz cilni **Pielāgojumi**. Ielīmējiet savu GTM konteineru ID laukā **GTM** un saglabājiet. Jūsu integrācija tagad ir aktīva.

3. **(Pēc izvēles) Pievienojiet GA4 mērījumu ID + API slepeno atslēgu servera pirkumiem**

   GTM konteineri darbojas pilnībā viesu pārlūkprogrammā, tāpēc pabeigtu rezervāciju var nepamanīt, ja viesis aizver cilni maksājuma pāradresācijas laikā. Ja jūsu konteiners ielādē **GA4 īpašumu** un vēlaties, lai pabeigtas rezervācijas tiek uzticami reģistrētas, ievadiet arī šī GA4 **mērījumu ID** un **Measurement Protocol API slepeno atslēgu** GTM sadaļā. Tad Wink nosūtīs `purchase` notikumu **servera pusē**, tieši kā aprakstīts [GA4 analītikas integrācijas](/lv/guides/developers/ga4-dual-tagging) ceļvedī. Atstājiet šos laukus tukšus, ja nepieciešama tikai pārlūkprogrammas izsekošana.

4. **Apstipriniet ar savu pakalpojumu sniedzēju**

   Ja jūsu konteiners nāk no partnera, piemēram, Sojern, informējiet savu konta pārvaldnieku, ka integrācija ir aktīva. Viņi var pārbaudīt no savas puses, vai tagi `wink.travel` vietnē jūsu īpašumam tiek aktivizēti pareizi un vai dati plūst jūsu kontā.

</Steps>

<Aside type="note">
Jums nav nepieciešams ievietot nevienu pikseļa kodu savā mājaslapā šai integrācijai. Wink automātiski ielādē jūsu GTM konteineru visās lapās, kur jūsu īpašums ir aktīvs.

Tas darbojas ar **jebkuru** GTM konteineru ID — Sojern ir tikai bieži izmantots piemērs.
</Aside>

## Ko Wink dara no savas puses

Lai nodrošinātu caurspīdīgumu, šeit ir aprakstīts, ko Wink konfigurē, lai šī integrācija darbotos:

- **GTM konteineru ID lauks** ir pieejams cilnē Pielāgojumi jūsu Wink portālā. Kad ievadāt konteineru ID, Wink pārbauda formātu (`GTM-XXXXXXX`) un droši saglabā to pret jūsu īpašumu.
- **Katru lapu, kur jūsu īpašums ir aktīvs** Wink, jūsu konteiners tiek tieši injicēts lapā — koplietojot Wink paša `window.dataLayer` — tāpēc tas ielādējas kopā ar Wink konteineru bez papildu konfigurācijas. Tas notiek automātiski, bez nepieciešamības Wink komandai veikt darbu katram īpašumam.
- **Jūsu konteiners tiek ielādēts asinhroni**, tāpēc tas neietekmē lapas ielādes ātrumu jūsu viesiem.
- **Wink paša izsekošana un jūsu konteiners darbojas paralēli**, lasot no tā paša koplietotā `dataLayer`. Katrs rezervācijas notikums, ko Wink izseko, vienlaikus ir pieejams jūsu konteineram.
- **Kad jūsu īpašums netiek skatīts** — piemēram, kad viesis pārlūko citu viesnīcu Wink — jūsu konteiners netiek ielādēts, tāpēc tas saņem tikai jūsu īpašumam atbilstošos datus.
- **Ja esat norādījis GA4 mērījumu ID + API slepeno atslēgu** (3. solī), `purchase` notikums par pabeigtām rezervācijām tiek papildus nosūtīts **servera pusē** caur GA4 Measurement Protocol, tādējādi pārdošana tiek reģistrēta pat tad, ja viesis nekad neatgriežas apstiprinājuma lapā.

## DataLayer atsauce

Wink nosūta GA4 saderīgus notikumus `dataLayer` visā viesu ceļojuma laikā. Jūsu GTM konteiners lasa no tā paša koplietotā `dataLayer`, tāpēc jebkuram konfigurētajam aktivizatoram vai mainīgajam ir piekļuve visām zemāk aprakstītajām īpašībām.

Katrs notikums seko standarta GA4 Enhanced Ecommerce struktūrai: augstākā līmeņa `event` virkne un `ecommerce` objekts. Pirms katra push Wink notīra iepriekšējo ecommerce datus, lai novērstu novecojušu datu ietekmi uz jauniem aktivizatoriem.

<Aside type="note">
**dataLayer atiestatīšanas paraugs**

Wink atiestata ecommerce objektu pirms katra notikuma push:

```js
dataLayer.push({ ecommerce: null });   // notīra iepriekšējo notikumu
dataLayer.push({ event: '...', ecommerce: { ... } });
```

Neuzticieties, ka ecommerce īpašības saglabājas starp notikumiem. Vienmēr nolasiet tās aktivizatora laikā tajā pašā notikumā.
</Aside>

### Rezervācijas ceļojuma notikumi

Šie notikumi tiek aktivizēti automātiski, kad viesis pārvietojas rezervācijas piltuvē. Konfigurējiet savus GTM aktivizatorus kā **Pielāgotus notikumus**, kas atbilst zemāk norādītajiem notikumu nosaukumiem.

| Solis | Notikums | Kad tas aktivizējas |
|-------|----------|---------------------|
| 1 | `view_item_list` | Ielādē viesnīcu inventāra režģi vai sarakstu |
| 2 | `view_item` | Viesis apskata konkrētu īpašuma lapu |
| 3 | `add_to_cart` | Viesis pievieno istabu iepirkumu grozam |
| 4 | `begin_checkout` | Ielādējas norēķinu / maksājuma lapa |
| 5 | `add_payment_info` | Viesis izvēlas maksājuma veidu |
| 6 | `login` | Viesis autentificējas caur SSO |
| 7 | `purchase` | Rezervācija ir apstiprināta |
| 8 | `refund` | Rezervācija ir atcelta |

### Preces īpašības

Visiem notikumiem, kuros ir `items` masīvs, ir vienāda preces shēma. Katrs īpašums ir izvēles, ja vien nav norādīts kā obligāts.

| Īpašums | Tips | Apraksts |
|----------|------|----------|

| `start_date` | string | Ierašanās datums formātā `YYYY-MM-DD` |
| `end_date` | string | Izrakstīšanās datums formātā `YYYY-MM-DD` |
| `num_adults` | number | Pieaugušo skaits rezervācijā |
| `num_children` | number | Bērnu skaits rezervācijā |
| `cancellation_policy` | string | Viens no: `Refundable`, `Non-Refundable`, `Refundable-With-Restrictions`, `Non-Refundable-With-Restrictions` |
| `rate_plan_id` | string | Tarifa plāna identifikators |
| `room_rate_id` | string | Konkrētā istabas tarifa identifikators |
| `room_rate_name` | string | Istabas tarifa nosaukums |
| `num_perks` | number | Iekļauto priekšrocību skaits tarifā |

| `room_view` | string | Istabas skata apraksts (piemēram, `Ocean`, `City`) |
| `room_classification` | string | Istabas klasifikācija vai līmenis (piemēram, `Suite`, `Standard`) |
| `bed_type` | string | Gultas konfigurācija istabā (piemēram, `King`, `Twin`) |

### Pielāgotas dimensijas GA4

GA4 ignorē pielāgotos preces parametrus atskaitēs, līdz tos skaidri reģistrējat kā preces mēroga pielāgotas dimensijas. Jums jāreģistrē tikai tie parametri, kurus plānojat izmantot atskaitēs — nav nepieciešams reģistrēt visus 20.

<Steps>

1. **Atveriet pielāgotās definīcijas**

   GA4 dodieties uz **Admin** (apakšējā kreisā ikona ar zobratu) → izvēlieties savu īpašumu → **Datu displejs** → **Pielāgotas definīcijas**.

2. **Izveidojiet jaunu pielāgotu dimensiju**

   Noklikšķiniet uz **Izveidot pielāgotas dimensijas**.

3. **Aizpildiet dimensijas detaļas**

   - **Dimensijas nosaukums** — cilvēkam saprotams nosaukums, kas parādās GA4 atskaitēs (skatiet tabulu zemāk)
   - **Mērogs** — izvēlieties **Item**
   - **Notikuma parametrs** — precīzs parametra nosaukums, kāds ir dataLayer (skatiet tabulu zemāk)
   - **Apraksts** — pēc izvēles, bet ieteicams

4. **Saglabājiet un atkārtojiet**

   Noklikšķiniet uz **Saglabāt**, pēc tam atkārtojiet katram parametrā, ko vēlaties izsekot.

</Steps>

<Aside type="note">
Pielāgotas dimensijas var parādīties GA4 atskaitēs līdz 24 stundām pēc reģistrācijas. Vēsturiskie dati, kas savākti pirms reģistrācijas, netiek aizpildīti.

GA4 standarta īpašumos atļauj līdz 50 preces mēroga pielāgotām dimensijām (360 īpašumos vairāk).
</Aside>

Izmantojiet šo tabulu kā atsauci, veidojot pielāgotas dimensijas. **Notikuma parametra** vērtībai jāatbilst precīzi — GA4 ir reģistrjutīgs.

### `virtualPageView`

Šis ir pielāgots Wink notikums — nav daļa no standarta GA4 notikumu kopas. Tas tiek nosūtīts katrā lapas pārejā un satur ierīces un sesijas kontekstu. Tas nesatur `ecommerce` objektu.

```json
{
  "event": "virtualPageView",
  "device": "Desktop",
  "deviceAgent": "Mozilla/5.0 ...",
  "os": "MacOS",
  "path": "/hotels/grand-resort",
  "title": "Grand Resort — Wink",
  "userId": "user_abc123",
  "startDate": "2026-06-01",
  "endDate": "2026-06-05",
  "guests": "2",
  "rooms": "1"
}
```

| Īpašums | Apraksts |
|----------|----------|
| `device` | Atklātā ierīces veids — `Desktop`, `Android`, `iPhone`, `iPad` vai līdzīgi |
| `deviceAgent` | Neapstrādāta lietotāja aģenta virkne |
| `os` | Atklātā operētājsistēma — `Windows`, `MacOS`, `Linux`, `UNIX` |
| `path` | Pašreizējās lapas ceļš |
| `title` | Pašreizējās lapas nosaukums |
| `userId` | Autentificēta lietotāja identifikators (izlaists, ja nav pieslēdzies) |
| `startDate` | Ierašanās datums no pašreizējās meklēšanas sesijas |
| `endDate` | Izrakstīšanās datums no pašreizējās meklēšanas sesijas |
| `guests` | Viesu skaits no pašreizējās meklēšanas sesijas |
| `rooms` | Istabu skaits no pašreizējās meklēšanas sesijas |
