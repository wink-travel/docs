Šis raksts parāda, kā ātri uzstādīties kā izstrādātājam un sākt testēt mūsu API Wink platformā.

:::note
Testēšana vienmēr jāveic mūsu [staging vidē](/lv/getting-started/environments). Tur ir daudz mazāk datu, taču jūs varat testēt tik daudz, cik vēlaties, neietekmējot ražošanas vidi.

Kad esat gatavs palaist tiešraidē, mēs sertificēsim jūsu kontu un jūsu lietotni, un jūs varēsiet palaist to mūsu ražošanas vidē.
:::

Izpildiet šos soļus:

<Steps>
1. [Reģistrējiet](/lv/account/register) savu lietotāja kontu Wink.
2. [Izveidojiet filiāles kontu](/lv/portal/create-account). Jums tas būs nepieciešams, lai sasaistītu savu lietotni. Skatiet [kas ir Studio](/lv/portal/studio/what-is-studio) papildu informācijai.
3. [Izveidojiet lietotni](/lv/portal/settings/applications) un sasaistiet to ar filiāles kontu, ko izveidojāt 2. solī. Servera-servera API integrācijām izvēlieties klienta tipu **MACHINE_2_MACHINE**.
4. Kad esat izveidojis savu `Application`, nekavējoties nokopējiet un saglabājiet klienta ID un slepeno atslēgu — slepenā atslēga tiek parādīta tikai vienreiz un to vairs nevarēs iegūt.
</Steps>

## CDN

Wink izmanto Cloudinary visiem mūsu attēlu un video resursiem. Piekļūstot mūsu ceļojumu inventāram, jums būs pilnīga piekļuve visām Cloudinary uzlabotajām funkcijām.

Mūsu `cloud_name` ir `traveliko`.

### Cloudinary

- [Sākšana](https://cloudinary.com/documentation/dev_kickstart)
- [SDK](https://cloudinary.com/documentation/cloudinary_sdks)
- [Cloudinary GitHub](https://github.com/cloudinary)
-	[Video pamācības](https://cloudinary.com/documentation/cloudinary_sdks_tutorials)

### Piemērs

Katram ceļojumu inventāra veidam, ko atbalstām, būs iekšējs JSON masīvs ar nosaukumu `multimedias`. Multimediju ieraksta JSON izskatās šādi:

```json {3}
{
  "multimediaIdentifier": "multimedia-1",
  "identifier": "partners/radisson_blu_logo",
  "type": "IMAGE",
  "width": "1024",
  "height": "768",
  "category": "1",
  "descriptions": [
    {
      "name": "Lobby",
      "description": "Picture of the lobby",
      "language": "en"
    }
  ],
  "lifestyleType": "LIFESTYLE_BUSINESS",
  "attribution": [
    {
      "url": "https://www.hilton.com",
      "name": "Hilton"
    }
  ]
}
```

Augstāk izceltais rindiņa rāda Cloudinary unikālo ID `partners/radisson_blu_logo`. Tas ir viss, kas jums nepieciešams, lai iegūtu attēlu jebkurā formātā, kvalitātē un izmērā.

## Testēšana

Dodieties uz mūsu [API](/lv/api) sadaļu un izvēlieties API, ar kuru vēlaties strādāt.

### API dokumentācija

Mūsu dokumentācijas vietne ir izveidota tā, lai jūs varētu izpildīt API komandas tieši no vietnes.

Šajā piemērā vēlaties izmantot `Search Lookups (OAuth2)` API izsaukumu.

:::tip[Pro padoms]
Lai atvieglotu lietošanu, mēs iesakām integrētājiem izmantot galapunktus, kurus mēs apzīmējam kā `OAuth2`. Šie galapunkti zina, ka gaida API izsaucējus un jau zina, kurā kontā atrodaties, tāpēc jums nav jānorāda `companyIdentifier` URL.
:::

<Steps>
1. Izmantojiet [Lookup API](https://developer.wink.travel/lookup), lai izgūtu galamērķus vai viesnīcas.
2. Kreisajā navigācijas joslā noklikšķiniet uz `Authentication`.
3. Ievadiet savu klienta ID un slepeno atslēgu un noklikšķiniet uz pogas `Get TOKEN`.
4. Ja jūsu akreditācijas dati ir derīgi, redzēsiet, ka jūsu API atslēga ir piemērota.
5. Tagad varat testēt lookup galapunktu.
</Steps>

### Postman
To pašu var izdarīt ar Postman.

<Steps>
1. Lejupielādējiet [Postman](https://www.postman.com/downloads).
2. Noklikšķiniet uz `Download OpenAPI spec` lapas augšpusē [Lookup API](https://developer.wink.travel/lookup) lapā.
3. Importējiet to Postman.
4. Ja importējāt to kā jaunu kolekciju ar nosaukumu `Wink API`, noklikšķiniet uz horizontālās elipses (3 punkti) blakus kolekcijas nosaukumam un izvēlieties `Edit`.
5. Cilnē `Authorization` iestatiet `Auth type` uz OAuth2.
6. Laukā `Add auth data to` iestatiet uz `Request headers`.
7. Laukā `Header prefix` iestatiet uz `Bearer`.
8. Laukā `Token Name` ierakstiet jebkuru nosaukumu, kādu vēlaties saglabāt savam tokenam Postman. Piemēram, Wink Staging.
9. Laukā `Grant type` iestatiet uz `Client Credentials`.
10. Laukā `Access token URL` iestatiet https://staging-iam.wink.travel/oauth2/token.
11. Laukā `Client ID` ievadiet klienta ID, ko jūsu lietotne ģenerēja.
12. Laukā `Client Secret` ievadiet slepeno atslēgu, ko jūsu lietotne ģenerēja.
13. Laukā `Scope` ievadiet ar atstarpēm atdalītos piekļuves līmeņus, kas nepieciešami jūsu integrācijai (piemēram, `inventory.read inventory.write inventory.remove`). Skatiet [scope atsauci](/lv/developers/authentication#scopes) pilnai sarakstam.
14. Laukā `Client Authentication` iestatiet uz `Send as Basic Auth header`.
15. Noklikšķiniet uz pogas `Get New Access Token`, lai saņemtu un saglabātu savu tokenu.
16. Visos API izsaukumos Wink API kolekcijā pārliecinieties, ka autorizācijas cilnē ir iestatīts `Inherit auth from parent`, lai katrā izsaukumā tiktu iekļauts jūsu tokens.
</Steps>

:::tip[Pro padoms]
Ieteicams servera domēnu, klienta ID un slepeno atslēgu padarīt par vides mainīgajiem. Tā jūs viegli varēsiet pārslēgties starp staging un ražošanas vidēm un atkārtoti izmantot visus izveidotos darbības.
:::
