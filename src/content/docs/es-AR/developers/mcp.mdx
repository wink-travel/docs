Las herramientas MCP de Wink se publican como **conjuntos de herramientas** — endpoints enfocados, cada uno cubriendo una tarea. Conectás tu cliente de IA a uno o dos que coincidan con tu trabajo, no a todos.

Cada endpoint usa **inicio de sesión interactivo OAuth2** (flujo de código de autorización PKCE): tu agente de IA abre una pestaña del navegador, iniciás sesión con tu cuenta Wink, y listo. No hay secretos de cliente para gestionar.

```bash title="Un integrador de channel manager se conecta a un endpoint"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Un hotelero que gestiona sus propias tarifas se conecta a otro"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

---

## Por qué las herramientas están divididas en endpoints

Wink expone alrededor de 500 herramientas. Entregar todas a un agente a la vez es técnicamente posible — y una mala idea.

**Las definiciones de herramientas consumen contexto.** Cada herramienta que un servidor MCP anuncia se carga en la ventana de contexto del modelo antes de que realice cualquier trabajo, junto con su descripción y esquema completo de parámetros. Quinientas de esas consumen una gran parte del presupuesto que tu tarea real necesita, en cada solicitud.

**La calidad de elección disminuye a medida que crece la lista.** Un agente que elige entre 500 herramientas con nombres similares toma peores decisiones que uno que elige entre 40. Si integrás un channel manager, aproximadamente veinte herramientas son relevantes para vos; las otras 480 son ruido que dificulta encontrar la herramienta correcta.

**El trabajo es genuinamente separable.** Alguien que sincroniza disponibilidad desde un PMS y alguien que crea páginas afiliadas comparten casi ninguna herramienta. Dividir por tarea significa que cada conexión lleva el vocabulario de una tarea.

<Aside type="caution" title="Los conjuntos de herramientas no son permisos">
Elegir un conjunto de herramientas estrecho **no** restringe lo que tu cuenta puede hacer, y elegir uno amplio no otorga nada extra. Cada herramienta aplica los mismos permisos de cuenta que el portal web, bajo tu identidad iniciada. Si tu cuenta no puede cancelar una reserva en Wink Portal, el agente tampoco puede — sin importar a qué endpoint esté conectado.

Elegí conjuntos de herramientas para **enfoque**, no para seguridad.
</Aside>

## Directorio de endpoints

Dos hosts sirven conjuntos de herramientas. El conteo de herramientas es aproximado y crece con el tiempo.

### `https://api.wink.travel` — la plataforma

| Endpoint | Herramientas | Qué cubre |
|---|---:|---|
| `/mcp/extranet/facilities` | ~64 | Inventario reservable y en sitio: habitaciones y tipos de habitación, spas, restaurantes, salas de reuniones, actividades, atracciones, lugares, otros ítems vendibles |
| `/mcp/extranet/property` | ~62 | Registro de la propiedad y sus términos comerciales: perfil y contenido, complementos, políticas de cancelación, beneficios, anuncios |

| `/mcp/travel-agent` | ~8 | Reservas facilitadas por agentes en nombre de viajeros, y reportes de agentes |

### `https://integrations.wink.travel` — integraciones de channel manager

Un endpoint, porque este host existe para una sola tarea.

| Endpoint | Herramientas | Qué cubre |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Conexión y verificación de integración de channel manager, PMS o CRS |

<Aside type="note" title="Integrar un channel manager vs. gestionar tus propias tarifas">
Son tareas diferentes para personas diferentes, y no comparten un endpoint.

Un **vendedor de channel manager, PMS o CRS** integra una vez a través de `integrations.wink.travel/mcp/channel-manager`, y desde entonces intercambia propiedades, tarifas, disponibilidad y reservas por esa integración. Ese único endpoint es toda la superficie.

Un **hotelero que cambia sus propias tarifas manualmente** usa los conjuntos de herramientas del extranet en `api.wink.travel` — `/mcp/extranet/rates` y similares. Esos no forman parte de una integración de channel manager y un integrador no tiene razón para conectarse a ellos.

La administración de cuenta también está en `api.wink.travel`, en `/mcp/settings`. No existe `/mcp/settings` en el host de integraciones.
</Aside>

Cada endpoint también incluye una herramienta `ping`, para que puedas confirmar que la conexión está activa antes de pedirle que haga trabajo real.

## ¿Qué conjuntos de herramientas necesito?

| Si sos… | Conectate a |
|---|---|
| **Integrando un channel manager, PMS o CRS** | `integrations.wink.travel/mcp/channel-manager` — solo este |
| **Gestionando el contenido de una propiedad** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Gestionando habitaciones y tipos de habitación** | `/mcp/extranet/facilities` |
| **Gestionando precios y disponibilidad** | `/mcp/extranet/rates` |
| **Gestionando reservas diarias** | `/mcp/extranet/operations` |
| **Ampliando distribución** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Construyendo páginas afiliadas** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Gestionando páginas link-in-bio** | `/mcp/link-manager` + `/mcp/social` |
| **Reservando en nombre de viajeros** | `/mcp/travel-agent` |
| **Conciliando dinero** | `/mcp/payment` |
| **Construyendo una experiencia de reserva** | `/mcp/booking-engine` + `/mcp/reference` |

Empezá con uno. Agregá otro cuando necesites algo que el primero no pueda hacer — cada conexión es independiente, y agregar uno nunca afecta a los demás.

<Aside type="tip" title="¿Querés todo?">
`https://api.wink.travel/mcp` y `https://integrations.wink.travel/mcp` siguen disponibles y sirven **todas** las herramientas en su host. Son útiles para explorar qué existe, pero no los recomendamos para trabajo diario: la lista de herramientas es lo suficientemente grande para opacar tu tarea y degradar la selección de herramientas del agente. Preferí los conjuntos de herramientas arriba.
</Aside>

## Cómo funciona la autenticación

Los servidores MCP de Wink usan el flujo **OAuth2 Authorization Code + PKCE** y soportan **Dynamic Client Registration (RFC 7591)**. Esto es lo que sucede cuando te conectás por primera vez:

1. Tu cliente de IA descubre el servidor de autorización desde los metadatos `/.well-known/oauth-protected-resource` del endpoint MCP.
2. El cliente se registra automáticamente vía **Dynamic Client Registration** — no se requiere configuración manual de la aplicación.
3. El cliente abre una **pestaña del navegador** a `https://iam.wink.travel`. Iniciás sesión con tu cuenta Wink y aprobás los permisos solicitados en la pantalla de consentimiento.
4. Wink emite un **token de acceso** con alcance para tu cuenta y vinculado a tu identidad.
5. El cliente de IA adjunta el token a cada solicitud MCP. Todos los resultados de herramientas se limitan automáticamente a tu entidad gestora.
6. Los tokens expiran después de 3 horas. Tu cliente de IA los renueva silenciosamente en segundo plano sin pedirte que vuelvas a iniciar sesión.

Cada llamada a una herramienta se ejecuta **bajo tu identidad** — las mismas reglas de ACL que protegen el portal web se aplican al agente de IA.

## Alcances

Cuando aprobás la pantalla de consentimiento verás un desglose de lo que el agente está solicitando. Los clientes MCP usan el mismo vocabulario de permisos que el resto de la plataforma — consultá la referencia completa de [alcances en la página de Autenticación](/es-AR/developers/authentication#scopes).

Dos cosas son específicas de MCP:

- **Los alcances `mcp.read`, `mcp.write` y `mcp.remove` son requeridos adicionalmente** para abrir el transporte MCP. Un cliente que tenga un alcance `mcp.*` es admitido en cualquier endpoint MCP de Wink, pero cada herramienta que invoque sigue aplicando el alcance de sección del endpoint que envuelve (por ejemplo, `booking.read`).
- **El cliente de IA solicita solo los alcances que necesita.** Podés negar permisos individuales en la pantalla de consentimiento — las herramientas que requieran un alcance denegado devolverán un error al invocarlas.

**Los conjuntos de herramientas no cambian nada de esto.** El endpoint al que te conectás decide qué herramientas están *listadas*, no qué están *permitidas*. Conectarse a `/mcp/payment` no otorga ningún permiso financiero que no tuvieras ya, y conectarse a `/mcp/reference` no impide que una herramienta allí aplique su propio alcance. La autorización se decide por llamada a herramienta, a partir de tu token y los permisos de tu cuenta.

## Solución de problemas

**No se abre la pestaña del navegador**

Tu cliente de IA puede no soportar aún el flujo interactivo PKCE. Verificá que estés usando una versión reciente:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** actualizá desde el actualizador incorporado de la app

**`401 Unauthorized` después de iniciar sesión**

Tu token en caché puede estar obsoleto. Eliminá y agregá de nuevo el servidor para forzar un nuevo inicio de sesión:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Para Claude Desktop y ChatGPT, eliminá la entrada del servidor en configuración, reiniciá la app y agregala de nuevo.

**`403 Forbidden` al llamar a una herramienta específica**

La herramienta requiere un alcance que no aprobaste en la pantalla de consentimiento, o un permiso que tu cuenta no tiene. Reconectá el servidor — la pantalla de consentimiento aparecerá de nuevo y podrás aprobar el permiso faltante. Si sigue fallando, la herramienta necesita un permiso de cuenta que no tenés; conectarse a otro conjunto de herramientas no ayudará, porque los conjuntos no otorgan permisos.

**La herramienta que necesito no está en la lista**

Probablemente estés conectado a un conjunto de herramientas que no cubre esa tarea. Revisá el [directorio de endpoints](#endpoint-directory) y agregá el conjunto que sí lo haga — las conexiones son independientes, así que agregar uno no cambia nada de los otros. Si no estás seguro cuál lo tiene, conectate temporalmente a `https://api.wink.travel/mcp`, encontrá la herramienta y luego buscá qué conjunto la lista.

**`404 Not Found` en un endpoint de conjunto de herramientas**

Revisá bien la ruta — los conjuntos anidados tienen dos segmentos (`/mcp/extranet/rates`, no `/mcp/extranet-rates`), y los planos tienen uno (`/mcp/link-manager`). Tené en cuenta que una solicitud *no autenticada* a cualquier ruta bajo `/mcp` devuelve `401`, no `404`, así que un `401` solo no indica si el endpoint existe.

**Me conecté a `api.wink.travel/mcp/channel-manager` y no obtuve nada**

Ese endpoint no existe. La integración de channel manager se sirve solo desde `https://integrations.wink.travel/mcp/channel-manager`. Si también necesitás leer o escribir las tarifas propias de una propiedad manualmente, eso es una tarea separada en un endpoint separado — ver `/mcp/extranet/rates`.

**El servidor aparece pero las llamadas a herramientas devuelven "cuenta no encontrada"**

Estás iniciado sesión en una cuenta Wink que no tiene entidad gestora. Entrá a [Wink Portal](https://app.wink.travel) y asegurate de que tu cuenta esté configurada antes de usar el servidor MCP.

**El token expira en medio de la sesión**

Los tokens son válidos por 3 horas. Claude Code y Claude Desktop renuevan tokens silenciosamente sin interrumpir tu sesión. Si ves errores de autenticación tras un largo período inactivo, escribí un nuevo mensaje — el cliente se reautenticará automáticamente.

**Codex CLI muestra "MCP server unreachable"**

Verificá que tu `~/.codex/config.json` sea JSON válido (sin comas finales) y que `"type": "http"` esté configurado. Codex requiere transporte HTTP para servidores remotos; el transporte stdio es solo para binarios locales.

**El menú "Conectores" de ChatGPT no aparece**

El soporte MCP requiere la versión **1.2024.352** o superior de la app de escritorio ChatGPT y una suscripción activa Plus, Pro, Team o Enterprise. Actualizá la app y verificá tu plan en Configuración → Cuenta.

**El servidor Cursor muestra rojo / "Error al conectar"**

Verificá que tu `~/.cursor/mcp.json` sea JSON válido y contenga `"type": "http"`. Luego andá a **Configuración → Configuración de Cursor → MCP** y hacé clic en **Actualizar**. Si el error persiste, reiniciá completamente Cursor — los cambios en la configuración no siempre se detectan sin reiniciar.

**Los servidores MCP de Windsurf no aparecen en configuración**

Windsurf requiere un reinicio completo (no solo recargar ventana) para detectar cambios en `mcp_config.json`. Usá **Archivo → Salir** y relanzá. Si los servidores siguen sin aparecer, confirmá que estás en Windsurf **1.4+** vía **Ayuda → Acerca de Windsurf**.

**La opción "Agregar servidor" en Cline no es visible**

El gestor de servidores MCP requiere Cline **2.0** o superior. Abrí el panel de Extensiones de VS Code, buscá Cline y hacé clic en **Actualizar** si hay una actualización disponible. Después de actualizar, recargá VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
