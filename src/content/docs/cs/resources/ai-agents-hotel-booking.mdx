## Doporučit hotel není totéž jako ho rezervovat

Většina dnešního „AI cestování“ končí u doporučení. Asistent navrhne tři hotely a pak předá cestovatele na web nebo OTA, aby si rezervaci skutečně provedl. Vznikne přerušení, cena nemusí být rezervovatelná a nikdo neuchovává zdrojový kontext.

**AI agent** se liší od AI odpovědi. Agent nejen popisuje hotel — jedná: kontroluje aktuální dostupnost, sestavuje rezervaci, přijímá platbu a může reagovat na změny. Aby to mohlo bezpečně fungovat, agent potřebuje víc než text. Potřebuje strukturovaná, aktuální, rezervovatelná data a transakční vrstvu, kterou může volat.

To je rozdíl mezi [AI objevováním](/cs/resources/ai-discovery-hotels/), které je o **nalezení a pochopení**, a agentickým obchodem, který je o **provedení transakce**.

## Co agent potřebuje, než může provést transakci

Rezervace hotelu je skutečná obchodní událost: správný pokoj, správná cena, skutečná dostupnost, podmínky, platba a potvrzení, které se synchronizuje zpět do hotelu. Agent to může dokončit pouze pokud je každý prvek dostupný jako volatelná operace.

| Agent potřebuje | Proč je to důležité |
|---|---|
| Strukturovanou, živou nabídku | Data získaná webovým scrapingem zastarávají; agent potřebuje aktuální, hotelem řízený inventář. |
| Aktuální ceny a dostupnost | Cena, kterou agent uvádí, musí být skutečně rezervovatelná v daný moment. |
| Operaci rezervace | Vytvoření rezervace musí být skutečné API volání, ne předání na webový formulář. |
| Platbu | Agent (nebo cestovatel přes něj) musí být schopen zaplatit s aplikovanou logikou podmínek. |
| Atribuci | Zdroj, kampaň nebo agent, který rezervaci vytvořil, by měl zůstat připojen. |
| Události | Agent by měl být schopen reagovat na potvrzení, změny, zrušení a refundace. |

Bez těchto věcí může agent doporučit — ale nemůže rezervovat.

## Jak AI agent rezervuje hotel na Wink

Wink je API-first: každá funkce platformy je volatelná externě a hostovaný MCP server zpřístupňuje živé API kontrakty agentům. Typický agentický tok:

### 1 — Připojit se a načíst živé kontrakty

Agent se připojí k hostovanému MCP serveru a použije `api_search` a `docs_search` k nalezení správných operací a načtení jejich skutečných schémat požadavků/odpovědí — žádné hádání endpointů, žádné zastaralé dokumenty.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Vyhledat rezervovatelný inventář

Agent vyhledává hotelem řízenou nabídku, včetně prostorového vyhledávání podle geolokace, a čte živé ceny a dostupnost napříč připojenými channel managery.

### 3 — Vytvořit rezervaci

Vytvoření rezervace je REST API operace. Agent sestaví pokoj, cenu, data a hosty a vytvoří rezervaci přes API.

### 4 — Přijmout platbu a potvrdit

[Booking Engine](/cs/products/booking-engine/) realizuje transakci — checkout, platbu (Wink je obchodníkem záznamu), logiku storno podmínek, potvrzení a synchronizaci rezervace s připojeným PMS nebo channel managerem. Zdroj a partnerská atribuce jsou zachovány.

### 5 — Reagovat na události

Agent se může přihlásit k odběru `booking.created` a dalších webhook událostí, aby provedl vyrovnání, upozornil cestovatele nebo spustil následné akce.

Princip: **agent vytváří nebo směruje záměr; Booking Engine zůstává vrstvou plnění pod každým předáním.**

## AI vyhledávání vs AI agenti

Řeší různé úkoly a hotel musí být připraven na obojí.

| | AI vyhledávání / odpovědní engine | AI agenti |
|---|---|---|
| Cíl cestovatele | Najít a porovnat hotely | Rezervovat a spravovat pobyt |
| Co hotel potřebuje | [Strukturovaný, prohledávatelný obsah](/cs/resources/hotel-content-answer-engines/) | Živé API, ceny, rezervace, platba |
| Konečný stav | Doporučení | Potvrzená rezervace |
| Povrch Wink | Čistá nabídka + obsah připravený pro odpovědi | REST API, MCP server, Booking Engine |

[AI objevování hotelů](/cs/resources/ai-discovery-hotels/) pokrývá vyhledávací stránku; tento průvodce pokrývá transakční stránku.

## Kdo vytváří agenty pro hotelový obchod

Agentický cestovní obchod nejsou jen asistenti pro spotřebitele. Stejná infrastruktura pohání:

- **Spotřebitelské cestovní asistenty**, kteří vyhledávají, rezervují a spravují pobyt od začátku do konce.
- **Bankovní, věrnostní a super-app agenty**, kteří integrují hotelové rezervace do stávající zákaznické zkušenosti.
- **Automatizace partnerů a tvůrců**, které objevují způsobilé hotely, vytvářejí obsah a udržují propojení atribuce — vydělávají 10% základní provizi z potvrzených rezervací.
- **Hotelové kopiloty**, které pomáhají týmům generovat obsah a analyzovat výkon napříč [Extranetem](/cs/products/extranet/), [Social](/cs/products/social/) a [Studiem](/cs/products/studio/), zatímco hotel si udržuje pravidla.

## Kam to směřuje

Výše uvedené schopnosti jsou dnes živé přes REST API a MCP server. Směr je k hlubšímu agentickému obchodování: bohatší agentické rezervační primitivy, identita a autorizace agentů pro transakce jménem cestovatele a agenti jako přisuzované, vydělávající zdroje v partnerské síti. Spojovací linka je konzistentní — **infrastruktura cestovního obchodu pro AI agenty**, s Booking Engine jako vrstvou plnění pod tím.

## Běžné chyby

- **Považovat AI objevování a AI agenty za stejný projekt.** Jeden je obsah a struktura; druhý je API a plnění. Potřebujete obojí.
- **Nechat agenty uvádět ceny, které nemohou rezervovat.** Nabídky musí vycházet z živých cen a dostupnosti, ne ze scrapeovaných stránek.
- **Ztrácet atribuci při předání.** Pokud agent vytvoří poptávku, rezervace by měla zůstat propojena s tímto zdrojem.
- **Přeskakovat vrstvu plnění.** Odpověď není rezervace, dokud skutečně neproběhne checkout, platba a potvrzení.
