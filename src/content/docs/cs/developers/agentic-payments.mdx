Můžete vyhledat hotel, vybrat pokoj a dokončit rezervaci prostřednictvím svého AI agenta. Připojte ho k Wink a platební peněžence, poté mu řekněte, kde chcete bydlet. Wink používá **Machine Payments Protocol (MPP)** k přijetí platby z peněženky a vrácení potvrzení o rezervaci.

## 1. Připojte MCP servery

Pro kompletní rezervační proces váš agent potřebuje **Wink Booking Engine** a **platební peněženku**.

| Připojení | Co dělá | Jak ho přidat |
| --- | --- | --- |
| **Wink Booking Engine** — povinné | Vyhledává destinace, hotely a ceny pokojů, poskytuje nabídky a potvrzuje rezervace, a získává vaše rezervace a účtenky. | Přidejte `https://api.wink.travel/mcp/booking-engine` jako vzdálený HTTP MCP server. |
| **Platební peněženka** — povinná pro platbu | Poskytuje platební údaje po vašem schválení nákupu. | Připojte peněženku, která podporuje Stripe Shared Payment Tokens. Viz příklad Link níže. |
| Wink Reference — nepovinné | Vyhledává země, měny a další referenční data. | `https://api.wink.travel/mcp/reference` |
| Wink Docs — nepovinné | Pomáhá agentovi číst dokumentaci a API smlouvy. | `https://docs.mcp.wink.travel/mcp` |

Booking Engine MCP již obsahuje nástroje potřebné pro rezervační proces cestovatele, pokud je v daném prostředí povoleno agentické rezervování a platba. Samostatný Payment MCP od Wink je určen pro finanční operace jako účetní knihy a výběry; není potřeba k platbě za pokoj.

### Přihlaste se a vyberte oprávnění

1. Otevřete nastavení MCP nebo konektoru svého agenta a přidejte výše uvedenou URL Booking Engine. Pojmenujte ji například **Wink Booking**.
2. Váš agent otevře přihlašovací stránku Wink ve vašem prohlížeči. Přihlaste se pomocí Wink účtu, pod kterým chcete rezervovat.
3. Na obrazovce souhlasu vyberte oprávnění, která váš agent potřebuje, a schvalte připojení.
4. Vraťte se k agentovi. Načte dostupné nástroje a spravuje autentizaci pro další MCP volání.

Pro tento proces vyberte:

| Oprávnění | Proč je potřeba |
| --- | --- |
| Přístup AI agenta (`mcp.read`) | Umožňuje agentovi připojit se k Wink MCP. |
| Čtení marketingu (`marketing.read`) | Umožňuje agentovi najít konfiguraci rezervace vašeho účtu, nazývanou customizace. Váš účet musí mít také přístup k této konfiguraci. |
| Zápis plateb (`payment.write`) | Umožňuje agentovi zaplatit za nabídku a potvrdit rezervaci. |

Zachovejte požadovaná přihlašovací oprávnění připojení. Váš MCP klient spravuje přístupové tokeny; nemusíte kopírovat token do chatu ani nastavovat hlavičky požadavků. Pokud jste vynechali potřebné oprávnění, znovu se přihlaste přes přihlašovací proces klienta a schvalte ho.

### Připojte platební peněženku

Pro platby Stripe je jednou z možností **Linkova agentická peněženka**. Pokud váš klient podporuje lokální MCP servery a máte nainstalovaný Node.js, přidejte do jeho MCP konfigurace tento záznam:

```json
{
  "mcpServers": {
    "link": {
      "command": "npx",
      "args": ["@stripe/link-cli", "--mcp"]
    }
  }
}
```

Požádejte svého agenta, aby připojil váš Link účet, poté následujte ověřovací odkaz, který poskytne, a schvalte připojení. Link dodává Shared Payment Token používaný k platbě za rezervaci. Link momentálně podporuje účty v USA; před rezervací zkontrolujte limity výdajů. Viz [návod na nastavení Link](https://github.com/stripe/link-cli#quickstart) a [MCP konfigurace](https://github.com/stripe/link-cli#mcp-server).

Pokud má váš agent již připojenou kompatibilní peněženku, použijte toto připojení. Nastavení peněženky a schválení platby jsou oddělené od přihlášení do Wink.

## 2. Požádejte agenta, aby našel pokoj

Například:

> Najdi pokoj v Bangkoku pro dva dospělé od 15. do 17. ledna 2027. Ukáž mi dostupné možnosti, celkovou cenu a podmínky storna, než si vyberu.

Váš agent může najít přístupné Wink účty a jejich konfigurace rezervací. Pokud jich máte více, řekněte mu, který má použít. Pokud rezervujete přes dodaný rezervační odkaz nebo konfiguraci, dejte ji agentovi místo toho.

Agent pak vyřeší vaši destinaci, zkontroluje dostupné hotely a načte ceny pokojů pro vaše data. Vyberte pokoj a požádejte o nabídku.

Tento platební proces aktuálně podporuje **jeden pokoj, oceněný v USD, pouze pro dospělé**. Nabídka má čas vypršení platnosti. Požádání o ni vás nezpoplatní ani nepotvrdí rezervaci.

## 3. Zkontrolujte a schvalte platbu

Zkontrolujte hotel, pokoj, data, hosty, podmínky storna a uvedenou celkovou cenu. Až budete připraveni, požádejte agenta o rezervaci a dokončete jakékoli schválení požadované vaší peněženkou.

Peněženka poskytne **Stripe Shared Payment Token** k zaplacení nabídky.

**Platby Tempo stablecoinem brzy přijdou.**

Po úspěšné platbě vám agent poskytne **potvrzovací kód rezervace**. Může také získat podrobnosti rezervace a účtenku přes Booking Engine MCP.

Pokud je platba stále zpracovávána nebo je odpověď ztracena, nechte agenta zkontrolovat **stejný pokus o platbu**. Měl by znovu použít nabídku a platební údaje místo zahájení druhé platby. Pokud je platba zamítnuta, požádejte o novou nabídku a zkontrolujte ji před dalším pokusem.

## Referenční nástroje pro agenty a vývojáře

Všechny níže uvedené nástroje Wink jsou dostupné přes **Booking Engine MCP**. MCP klient automaticky posílá autentizaci pomocí oprávnění schválených při přihlášení.

| Krok | Nástroje a chování |
| --- | --- |
| Vyberte kontext rezervace | `managing_entity_list`, poté `customization_get_primary` nebo `customization_search` pro vybraný účet. Použijte dodanou customizaci, pokud je již známa. |
| Najděte destinaci | `destination_lookup_search_suggestions` a `destination_lookup_get`. |
| Vyhledejte hotely a pokoje | `inventory_search_city` nebo `inventory_search_geo`, poté `property_inventory_get` pro ceny a dostupnost. |
| Nabídněte vybraný pokoj | `agentic_booking_quote`. Předávejte detaily pokoje v argumentu `request`. |
| Zaplaťte a potvrďte | Získejte Shared Payment Token z připojené peněženky, poté zavolejte `agentic_booking_pay` s `request.quoteId` a `request.spt`. Zachovejte stejného přihlášeného uživatele Wink pro nabídku i platbu. |
| Získejte rezervaci a účtenku | Použijte `booking_search` nebo `booking_search_list` pro nalezení potvrzené rezervace, poté `booking_get` a `booking_receipt_get` s jejím identifikátorem. |

Požadavek na nabídku potřebuje `hotelIdentifier`, `roomRateIdentifier`, `checkIn`, `checkOut`, `adults`, `children` a `customizationIdentifier`. Data jsou ve formátu `YYYY-MM-DD`; `checkOut` musí být po `checkIn`. Nastavte `adults` alespoň na `1` a `children` na `0`.

Nabídka vrací `quoteId`, `amountUsdCents`, `currency`, `expiresAt` a `mppChallenges`. USD centy zobrazujte jako dolary: `10000` znamená **100,00 $**.

| Výsledek platby | Další krok |
| --- | --- |
| `PAYMENT_SUCCEEDED` | Uložte `bookingConfirmationCode` a `chargeReference`. |
| `IN_PROGRESS` | Chvíli počkejte a zkuste znovu stejnou nabídku a údaje. |
| `DECLINED` | Požádejte o novou nabídku a zkontrolujte ji před další platbou. |

Úspěšné opakování vrací existující rezervaci bez dalšího účtování. Timeout považujte za neznámý výsledek a zkuste stejnou platbu znovu. Pokud zůstane nevyřešený, kontaktujte podporu s ID nabídky.

### MCP klienti s podporou plateb

MCP klienti s podporou plateb mohou použít `agentic_booking_book` s poli pokoje přímo v `arguments`. První volání vrátí chybu `-32042` s platebními výzvami. Opakujte stejné volání s platebními údaji peněženky v `params._meta["org.paymentauth/credential"]`; úspěch obsahuje `result._meta["org.paymentauth/receipt"]`. Chyba `-32043` nese neúspěch platby a výzvu: definitivní zamítnutí vyžaduje novou nabídku, zatímco neúplný platební payload může zkusit znovu se stejnou výzvou. Pro `-32603` znamená `data.failure.reason` `payment-in-progress` nebo `already-consumed` opakování stejného údaje; samotný kód chyby nestačí.

## Rezervace přes REST

Použijte REST při vytváření integrace, která volá Wink přímo přes HTTP. Nabídka i platba používají **`POST https://api.wink.travel/api/mpp/booking`**.

Vaše aplikace potřebuje [Wink uživatelský přístupový token](/cs/developers/authentication/) s oprávněním `payment.write` k platbě. Zachovejte stejného uživatele pro obě volání. Token pošlete v `Wink-Authorization`, ponechte `Authorization` pro platební údaje peněženky. Tyto hlavičky platí pro REST; MCP klient spravuje vlastní autentizaci.

### 1. Požádejte o nabídku

Uložte vybraný pokoj jako `booking.json`, nahraďte příkladové identifikátory a data svým výběrem. Pole pokoje jdou přímo do JSON těla, bez obalu `request`.

```json
{
  "hotelIdentifier": "YOUR_HOTEL_ID",
  "roomRateIdentifier": "YOUR_ROOM_RATE_ID",
  "checkIn": "2027-01-15",
  "checkOut": "2027-01-17",
  "adults": 2,
  "children": 0,
  "customizationIdentifier": "YOUR_CUSTOMIZATION_ID"
}
```

Nastavte `WINK_ACCESS_TOKEN` na uživatelský přístupový token a odešlete požadavek:

```bash
curl -i https://api.wink.travel/api/mpp/booking \
  -H "Wink-Authorization: Bearer $WINK_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @booking.json
```

Wink vrátí **`402 Payment Required`** s `WWW-Authenticate: Payment ...` výzvou pro každou nabízenou metodu. JSON tělo obsahuje `quoteId`, `amount`, `currency`, `expiresAt` a `methods`. `amount` je řetězec v USD centech: `"10000"` znamená **100,00 $**. Nabídku zkontrolujte před vypršením; platba ještě nebyla provedena.

### 2. Zaplaťte a potvrďte

Nechte peněženku splnit vrácenou Stripe výzvu dodáním Shared Payment Token v `payload.spt`. Použijte platební údaje z této výzvy.

Nastavte `MPP_CREDENTIAL` na zakódované MPP údaje peněženky, které obsahují výzvu a platební payload. Opakujte **stejné tělo požadavku**, zachovejte hlavičku identity:

```bash
curl -i https://api.wink.travel/api/mpp/booking \
  -H "Wink-Authorization: Bearer $WINK_ACCESS_TOKEN" \
  -H "Authorization: Payment $MPP_CREDENTIAL" \
  -H 'Content-Type: application/json' \
  --data-binary @booking.json
```

Při úspěchu Wink vrátí **`200 OK`**, JSON tělo obsahující `bookingConfirmationCode` a hlavičku `Payment-Receipt`. Uložte potvrzení a účtenku. Úspěšné opakování vrací existující rezervaci bez dalšího účtování.

### Zpracování odpovědí a opakování

| Odpověď | Co dělat |
| --- | --- |
| `400` | Opravte neplatné údaje o pokoji nebo špatně formátované údaje. |
| `401` / `403` | Zkontrolujte autentizaci uživatele a oprávnění k platbě. |
| `402` | Prohlédněte vrácený problém a výzvu. Definitivní zamítnutí platby vyžaduje novou nabídku; neúplný platební payload znovu použije původní výzvu. Zkontrolujte cenu před platbou. |
| `409` | Výsledek platby není vyřešen. Chvíli počkejte a zkuste znovu stejné tělo a údaje na rezervačním endpointu. |
| `429` | Počkejte počet sekund uvedený v `Retry-After`, pak zkuste znovu. |

Odpověď `409` má tělo `application/problem+json`. Porovnejte jeho `type` s těmito přesnými URL:

| Typ problému | Význam |
| --- | --- |
| [https://api.wink.travel/problems/payment-in-progress](https://api.wink.travel/problems/payment-in-progress) | Pokus o platbu stále probíhá nebo není možné potvrdit vyrovnání. |
| [https://api.wink.travel/problems/already-consumed](https://api.wink.travel/problems/already-consumed) | Výzva nebo důkaz platby již byl použit možná úspěšným pokusem. To samo o sobě nepotvrzuje rezervaci. |

Oba znamenají **opakujte stejnou platbu; neplaťte novou nabídku**. URL identifikují a dokumentují problém; nejsou to platební nebo pollingové endpointy. Opakujte `POST /api/mpp/booking` a použijte typ problému místo volného textu `detail` k rozhodnutí, co dělat. Viz [referenční typy problémů](https://api.wink.travel/problems) pro všechny Wink platební problémy.

Timeout, ztracená odpověď nebo chyba serveru po odeslání platby může také zanechat výsledek neznámý. Opakujte stejný platební požadavek. Pokud výsledek zůstane nevyřešený, kontaktujte podporu s ID nabídky před zahájením další platby.
