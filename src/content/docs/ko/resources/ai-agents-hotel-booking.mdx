## 호텔 추천은 예약과 다릅니다

오늘날 대부분의 "AI 여행"은 추천에서 멈춥니다. 어시스턴트가 세 개의 호텔을 제안한 후, 여행자를 실제 예약을 위해 웹사이트나 OTA로 넘깁니다. 이 과정에서 연결이 끊기고, 가격이 예약 가능하지 않을 수 있으며, 출처 컨텍스트가 유지되지 않습니다.

**AI 에이전트**는 AI 답변과 다릅니다. 에이전트는 단순히 호텔을 설명하는 것이 아니라 행동합니다: 실시간 가용성을 확인하고, 예약을 조립하며, 결제를 처리하고, 변화가 있을 때 반응할 수 있습니다. 이를 안전하게 수행하려면 에이전트는 텍스트 이상의 것이 필요합니다. 구조화되고 최신이며 예약 가능한 데이터와 호출할 수 있는 거래 계층이 필요합니다.

이것이 [AI 발견](/ko/resources/ai-discovery-hotels/) — **발견되고 이해되는 것** — 과 에이전틱 상거래 — **거래되는 것** — 의 차이입니다.

## 에이전트가 거래를 하기 전에 필요한 것

호텔 예약은 실제 상업적 이벤트입니다: 적절한 객실, 적절한 요금, 실제 가용성, 정책, 결제 및 호텔과 동기화되는 확인. 에이전트는 각 요소가 호출 가능한 작업으로 제공될 때만 이를 완료할 수 있습니다.

| 에이전트가 필요한 것 | 이유 |
|---|---|
| 구조화되고 실시간인 공급 | 웹 스크랩 데이터는 오래되므로, 에이전트는 최신의 호텔 관리 재고가 필요합니다. |
| 실시간 요금 및 가용성 | 에이전트가 제시하는 가격은 그 순간 실제 예약 가능해야 합니다. |
| 예약 작업 | 예약 생성은 실제 API 호출이어야 하며, 웹 폼으로 넘기는 것이 아니어야 합니다. |
| 결제 | 에이전트(또는 이를 통해 여행자)는 정책 로직이 적용된 결제를 할 수 있어야 합니다. |
| 출처 | 예약을 생성한 출처, 캠페인 또는 에이전트가 연결되어 있어야 합니다. |
| 이벤트 | 에이전트는 확인, 변경, 취소 및 환불에 반응할 수 있어야 합니다. |

이것들이 없으면 에이전트는 추천만 할 수 있고 예약은 할 수 없습니다.

## Wink에서 AI 에이전트가 호텔을 예약하는 방법

Wink는 API 우선입니다: 모든 플랫폼 기능은 외부에서 호출 가능하며, 호스팅된 MCP 서버가 실시간 API 계약을 에이전트에 노출합니다. 일반적인 에이전트 흐름:

### 1 — 연결하고 실시간 계약 읽기

에이전트는 호스팅된 MCP 서버에 연결하여 `api_search`와 `docs_search`를 사용해 적절한 작업을 찾고 실제 요청/응답 스키마를 읽습니다 — 엔드포인트를 추측하거나 오래된 문서를 참조할 필요가 없습니다.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — 예약 가능한 재고 검색

에이전트는 호텔이 관리하는 공급을 검색하며, 지리 위치 공간 검색을 포함하고, 연결된 채널 매니저 전반의 실시간 요금과 가용성을 확인합니다.

### 3 — 예약 생성

예약 생성은 REST API 작업입니다. 에이전트는 객실, 요금, 날짜 및 투숙객을 조립하여 API를 통해 예약을 생성합니다.

### 4 — 결제 처리 및 확인

[Booking Engine](/ko/products/booking-engine/)이 거래를 이행합니다 — 체크아웃, 결제(Wink가 상인 기록자), 취소 정책 로직, 확인 및 연결된 PMS 또는 채널 매니저로 예약 동기화. 출처 및 파트너 귀속이 예약을 통해 보존됩니다.

### 5 — 이벤트에 반응

에이전트는 `booking.created` 및 기타 웹훅 이벤트를 구독하여 조정, 여행자 알림 또는 후속 조치 트리거가 가능합니다.

원칙: **에이전트가 의도를 생성하거나 라우팅하며; Booking Engine이 모든 전달 뒤에서 이행 계층으로 남아 있습니다.**

## AI 검색과 AI 에이전트

두 가지는 서로 다른 작업을 해결하며, 호텔은 둘 다 준비해야 합니다.

|  | AI 검색 / 답변 엔진 | AI 에이전트 |
|---|---|---|
| 여행자 목표 | 호텔 찾기 및 비교 | 숙박 예약 및 관리 |
| 호텔이 필요한 것 | [구조화되고 크롤링 가능한 콘텐츠](/ko/resources/hotel-content-answer-engines/) | 실시간 API, 요금, 예약, 결제 |
| 최종 상태 | 추천 | 확정된 예약 |
| Wink 노출면 | 깨끗한 공급 + 답변 준비된 콘텐츠 | REST API, MCP 서버, Booking Engine |

[호텔용 AI 발견](/ko/resources/ai-discovery-hotels/)은 검색 측면을 다루고; 이 가이드는 거래 측면을 다룹니다.

## 호텔 상거래에서 에이전트를 구축하는 주체

에이전틱 여행 상거래는 단순한 소비자 어시스턴트만이 아닙니다. 동일한 인프라가 다음을 지원합니다:

- **소비자 여행 어시스턴트**: 검색, 예약 및 숙박 관리 전 과정을 수행.
- **은행, 로열티 및 슈퍼앱 에이전트**: 기존 고객 경험 내에 호텔 예약을 내장.
- **파트너 및 크리에이터 자동화**: 적격 호텔을 발견하고 자산을 구축하며 출처를 연결 유지 — 확정 예약에 대해 기본 10% 수수료 획득.
- **호텔 측 코파일럿**: 팀이 [Extranet](/ko/products/extranet/), [Social](/ko/products/social/), [Studio](/ko/products/studio/) 전반에서 콘텐츠 생성 및 성과 분석을 지원하며, 호텔이 규칙을 유지.

## 향후 방향

위 기능들은 현재 REST API와 MCP 서버를 통해 실시간으로 제공됩니다. 방향은 더 깊은 에이전트 네이티브 상거래: 더 풍부한 에이전트 대상 예약 원시 기능, 여행자를 대신해 거래할 수 있는 에이전트 신원 및 권한 부여, 그리고 파트너 네트워크에서 귀속되고 수익을 창출하는 에이전트 참여입니다. 일관된 핵심은 — **AI 에이전트를 위한 여행 상거래 인프라**, Booking Engine이 그 아래에서 이행을 담당합니다.

## 흔한 실수

- **AI 발견과 AI 에이전트를 같은 프로젝트로 취급하는 것.** 하나는 콘텐츠와 구조, 다른 하나는 API와 이행입니다. 둘 다 필요합니다.
- **에이전트가 예약할 수 없는 가격을 제시하게 하는 것.** 견적은 스크랩된 페이지가 아니라 실시간 요금과 가용성에서 나와야 합니다.
- **전달 시 출처를 놓치는 것.** 에이전트가 수요를 생성했다면, 예약은 그 출처와 연결되어야 합니다.
- **이행 계층을 생략하는 것.** 답변은 체크아웃, 결제 및 확인이 실제로 이루어질 때까지 예약이 아닙니다.
