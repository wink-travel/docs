Wink는 두 가지 전송 방식을 제공합니다. 어떤 방식을 사용할지는 통합하는 API에 따라 다릅니다.

| | 전송 방식 | 스키마 | 문서 |
| --- | --- | --- | --- |
| 대부분의 Wink API | HTTPS를 통한 REST | OpenAPI 3 | 사이드바의 **API** 아래 모든 그룹 |
| Partner Integrator API | HTTP/2를 통한 gRPC | Protocol Buffers | [Partner](/ko/partner-api/partner/) |

<Aside type="note" title="더 이상 언어별 SDK를 제공하지 않습니다">
  수작업으로 관리된 SDK는 래핑하는 API보다 뒤처졌고, 실제로 필요한 언어를 모두 지원하지 못했습니다. 대신 스키마에서 클라이언트를 생성하세요 — 항상 최신 상태이며 — 또는 MCP 서버가 사용 사례에 맞게 작성한 통합 코드를 사용하세요.
</Aside>

## REST 클라이언트 생성하기

모든 API 그룹은 OpenAPI 3 문서를 제공합니다. OpenAPI 생성기에 문서를 지정하면 원하는 언어로 타입이 지정된 클라이언트를 얻을 수 있습니다.

```bash
# 그룹의 스펙은 참조 페이지 옆에서 제공됩니다.
curl -o wink-extranet.json https://api.wink.travel/v3/api-docs/extranet

npx @openapitools/openapi-generator-cli generate \
  -i wink-extranet.json -g typescript-fetch -o ./wink-client
```

## gRPC 클라이언트 생성하기

Partner Integrator API는 gRPC입니다. Wink가 두 가지 방식으로 제공하는 `.proto` 스키마에서 클라이언트를 생성합니다:

- **서버 리플렉션** — 서버가 스스로를 설명하므로 `grpcurl`, Postman, Insomnia 같은 도구가 실행 시점에 스키마를 다운로드 없이 발견할 수 있습니다. 리플렉션은 다른 호출과 동일한 베어러 토큰이 필요합니다.
- **`.proto` 파일** — 스키마를 직접 관리하고 미리 생성하고 싶을 때 사용합니다.

```bash
# 실행 중인 서버에서 스키마를 발견합니다 (인증 필요).
grpcurl -H "authorization: Bearer $WINK_TOKEN" \
  partner.wink.travel:443 list

# 그런 다음 클라이언트를 생성합니다 — 여기서는 Go; 지원하는 모든 언어가 동일한 방식으로 작동합니다.
protoc --go_out=. --go-grpc_out=. partner_lookup.proto
```

호출 시 REST가 `Authorization` 헤더에 토큰을 담는 것처럼, gRPC는 `authorization` 메타데이터 헤더에 베어러 토큰을 담습니다. 오류는 HTTP 상태 코드 대신 응답 트레일러의 gRPC 상태 코드로 전달되며 — [Partner 참조](/ko/partner-api/partner/)에서 예상 가능한 상태 코드를 확인할 수 있습니다.

## 또는 MCP 서버가 코드를 작성하게 하세요

AI 코딩 어시스턴트를 사용하는 경우, MCP 서버가 가장 빠른 방법입니다. MCP 서버는 Wink의 API를 어시스턴트가 호출하고 이해할 수 있는 도구로 노출하므로, 전체 클라이언트를 생성하고 엔드포인트를 직접 찾는 대신, 구축하려는 내용을 설명하면 그에 맞는 통합 코드를 받을 수 있습니다.
