通过将您的 Google Analytics 4 属性连接到 Wink，您的预订事件——从房间浏览到完成预订——会自动转发到您自己的 GA4 仪表板，与 Wink 自身的分析数据并行显示。无需编码，也无需您这边进行技术设置。

<Aside type="tip">
您只需要从 GA4 获取一项内容：**测量 ID**（`G-XXXXXXXXXX`）。Wink 会在客户的浏览器中加载它，并将您的整个预订漏斗——包括完成的预订（`purchase`）——直接流式传输到您的 GA4 属性。无需创建 API 密钥，也无需在您自己的网站上安装任何东西。
</Aside>

---

## 工作原理

```
您在 Wink 门户中输入测量 ID（G-XXXXXXXXXX）
       ↓
Wink 在客户浏览器中加载您的 GA4，并实时将预订事件
（浏览、购物车、结账）流式传输到您的 GA4 属性
       ↓
在感谢页面，完成的预订（purchase）事件在浏览器中触发——
Wink 重新连接支付重定向中断的 GA4 会话，
因此销售仍计入客户的原始访问
       ↓
您登录 analytics.google.com，查看完整的预订漏斗
```

## 您需要做什么

<Steps>

1. **创建 GA4 属性**

   访问 [analytics.google.com](https://analytics.google.com)：管理员 → 创建属性。设置您的时区和货币以匹配您的市场。

2. **创建网站数据流**

   管理员 → 数据流 → 添加数据流 → 网站。输入 `wink.travel` 作为网址。系统会生成您的 **测量 ID**（`G-XXXXXXXXXX`）。复制它。

3. **在 Wink 门户中输入测量 ID**

   登录 [app.wink.travel](https://app.wink.travel)，选择您的账户，打开自定义设置。在 **分析与集成** 部分，将测量 ID 粘贴到 **GA4 测量 ID** 字段并保存。完成后，您的 GA4 集成即已激活。

4. **将 `purchase` 标记为关键事件**

   返回您的 GA4 属性：管理员 → 事件 → 找到 `purchase` → 切换 **标记为关键事件**。这样完成的预订会出现在您的转化报告中。

5. **查看您的数据**

   登录 [analytics.google.com](https://analytics.google.com)，您将看到通过 Wink 自动跟踪的预订、收入和客户漏斗。

</Steps>

<Aside type="note">
此集成无需您在自己的网站上安装任何跟踪代码。Wink 会处理所有内容——您的测量 ID 只是预订数据发送的目标。
</Aside>

<Aside type="tip">
**GA4 和 GTM 可以同时使用。** 如果您还运行 Google Tag Manager 容器（例如 Sojern 容器），可以同时配置两者——它们并不互斥。详见 [GTM Analytics Integration](/zh-CN/guides/general/gtm-integration)。
</Aside>

## Wink 如何在预订引擎中使用您的测量 ID

所有操作均在**客户的浏览器中**完成——没有服务器间数据导出，也不涉及 API 密钥。

- **您的 GA4 在预订页面加载。** 每当客户在 Wink 预订引擎中查看您的房源时，Wink 会在其浏览器中加载您的测量 ID，与 Wink 自身的分析数据共享同一数据。浏览事件——搜索、房间浏览、购物车、结账——实时流式传输到您的 GA4 属性。
- **完成的预订在感谢页面触发。** 当客户完成支付并进入确认页面时，`purchase` 事件在客户端触发，携带完整的预订金额、货币和房型详情。
- **支付重定向不再丢失销售。** 信用卡支付会将客户浏览器跳转到支付提供商再返回，通常会中断浏览器中的 GA4 会话，使预订看起来像是全新的“直接”访问。为防止这种情况，Wink 会通过返回 URL 携带您的 GA4 会话标识，并在感谢页面**在 `purchase` 事件触发前**重新连接原始会话。因此，完成的预订归因于客户最初的访问，而非新会话。

<Aside type="note">
Wink 会对每笔预订的 `purchase` 事件去重，因此页面刷新或自动跳转到预订详情页不会导致销售重复计数。
</Aside>

## 您可以跟踪的内容

连接后，您的 GA4 属性将接收完整的增强型电子商务事件套件：

### 发现阶段

| 事件 | 含义 |
|---|---|
| `view_item_list` | 客户在搜索或分类列表中看到您的房源 |
| `select_item` | 客户从列表中点击了您的房源 |
| `view_item` | 客户查看了您的酒店详情页 |

### 考虑阶段

| 事件 | 含义 |
|---|---|
| `view_promotion` | 客户看到您的促销优惠 |
| `select_promotion` | 客户点击了促销优惠 |
| `add_to_wishlist` | 客户将您的房源添加到心愿单 |

### 预订漏斗

| 事件 | 含义 |
|---|---|
| `add_to_cart` | 客户选择了房间或套餐 |
| `view_cart` | 客户查看了预订摘要 |
| `remove_from_cart` | 客户移除了房间或套餐 |
| `begin_checkout` | 客户开始结账流程 |
| `add_payment_info` | 客户输入了支付信息 |
| `add_shipping_info` | 客户输入了入住信息 |
| `purchase` | 客户完成了预订 |
| `refund` | 预订被取消并退款 |

所有事件均包含相关维度，如收入、货币、房型和预订价值——为您提供从首次印象到完成预订的完整客户旅程视图。要解锁更多房源和房型级别的维度，如 `city_name`、`cancellation_policy`、`bed_type` 等，请参见 [GA4 中的自定义维度](/zh-CN/guides/general/gtm-integration#custom-dimensions-in-ga4)。

## 跨域跟踪（高级）

上述标准集成跟踪 Wink 内发生的所有操作。但如果您想从自己的网站一直跟踪客户到 Wink 上完成预订，并正确归因原始流量来源（Google Ads、邮件活动、自然搜索等），则需要在双方进行额外配置。

<Aside type="caution">
本节仅适用于您在自己网站上安装了 GA4 的情况。如果您未在网站上运行 GA4，以上标准集成已足够。
</Aside>

### 为什么重要

没有跨域跟踪，客户先访问您的网站再在 Wink 预订时，GA4 会将其视为**直接访问**，与之前的访问无关联。任何导致预订的 Google Ads 点击、邮件活动或自然搜索都不会被归因。

配置跨域跟踪后，您可以看到完整的客户旅程：

```
google.com（付费广告）
       ↓
您的网站（客户浏览房间）
       ↓
wink.travel（客户选择房间并预订）
       ↓
购买正确归因于最初的 Google Ads 点击
```

### 您需要做的操作

配置您的 GA4 属性，将 `wink.travel` 识别为您自己域名的一部分，而非外部推荐来源。这样 GA4 会将两个会话拼接成一个连续的客户旅程。

<Steps>
1. GA4 管理员 → 数据流 → 选择您的数据流
2. 配置标签设置 → **配置您的域名**
3. 添加 `wink.travel` 作为关联域名
4. 保存
</Steps>

### Wink 需要做的操作

联系 [Wink 支持](https://app.wink.travel)，提供您的网站域名（例如 `yourhotel.com`）。Wink 会将您的域名添加到 Wink GA4 属性的推荐排除列表，防止您的网站被记录为推荐来源，否则会覆盖客户的原始归因并启动新会话。

<Aside type="tip">
上述标准集成已满足大多数房源需求，能立即让您在 Wink 上看到预订和收入数据。跨域跟踪是高级选项，适合您熟悉 GA4 数据后，想获得更深入归因洞察时设置。
</Aside>
