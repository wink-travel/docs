## 推荐酒店不等于预订酒店

如今大多数“AI 旅游”止步于推荐。助理建议三个酒店，然后将旅行者交给网站或 OTA 实际预订。流程中断，价格可能无法预订，且无人保留来源上下文。

**AI 代理**不同于 AI 答案。代理不仅描述酒店——它会行动：检查实时可用性，组装预订，收款，并能在发生变化时做出反应。要安全实现这一点，代理需要的不仅是文本。它需要结构化、实时、可预订的数据和可调用的交易层。

这就是[AI 发现](/zh-CN/resources/ai-discovery-hotels/)（关于被**发现和理解**）与代理式商务（关于被**交易**）的区别。

## 代理在交易前需要什么

酒店预订是真实的商业事件：正确的房型、正确的价格、真实的可用性、政策、付款和同步回酒店的确认。代理只有在每个环节都作为可调用操作可用时才能完成。

| 代理需要 | 重要原因 |
|---|---|
| 结构化、实时供应 | 网络爬取数据会过时；代理需要实时、酒店控制的库存。 |
| 实时价格和可用性 | 代理报价的价格必须在当时可预订。 |
| 预订操作 | 创建预订必须是真实的 API 调用，而非跳转到网页表单。 |
| 付款 | 代理（或通过代理的旅行者）必须能付款，并应用政策逻辑。 |
| 归因 | 创建预订的来源、活动或代理应保持关联。 |
| 事件 | 代理应能对确认、变更、取消和退款做出反应。 |

没有这些，代理只能推荐，无法预订。

## AI 代理如何在 Wink 预订酒店

Wink 以 API 优先：每个平台功能都可外部调用，托管的 MCP 服务器向代理暴露实时 API 合约。典型代理流程：

### 1 — 连接并读取实时合约

代理连接到托管的 MCP 服务器，使用 `api_search` 和 `docs_search` 查找正确的操作并读取其真实请求/响应模式——无需猜测端点，无需过时文档。

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — 搜索可预订库存

代理搜索酒店控制的供应，包括地理位置空间搜索，并读取连接的渠道管理器的实时价格和可用性。

### 3 — 创建预订

预订创建是 REST API 操作。代理组装房型、价格、日期和客人信息，通过 API 创建预订。

### 4 — 收款并确认

[Booking Engine](/zh-CN/products/booking-engine/) 完成交易——结账、付款（Wink 是商户）、取消政策逻辑、确认及预订同步到连接的 PMS 或渠道管理器。预订保留来源和合作伙伴归因。

### 5 — 对事件做出反应

代理可订阅 `booking.created` 等 webhook 事件以进行对账、通知旅行者或触发后续操作。

原则是：**代理创建或路由意图；Booking Engine 始终是每次交接背后的履约层。**

## AI 搜索与 AI 代理

它们解决不同任务，酒店需同时准备。

|  | AI 搜索 / 答案引擎 | AI 代理 |
|---|---|---|
| 旅行者目标 | 查找和比较酒店 | 预订和管理住宿 |
| 酒店需求 | [结构化、可爬取内容](/zh-CN/resources/hotel-content-answer-engines/) | 实时 API、价格、预订、付款 |
| 最终结果 | 推荐 | 确认预订 |
| Wink 触点 | 干净供应 + 答案准备内容 | REST API、MCP 服务器、Booking Engine |

[酒店 AI 发现](/zh-CN/resources/ai-discovery-hotels/) 涵盖搜索端；本指南涵盖交易端。

## 谁在构建酒店商务代理

代理式旅游商务不仅是消费者助理。相同基础设施支持：

- **消费者旅游助理**，端到端搜索、预订和管理住宿。
- **银行、忠诚度和超级应用代理**，将酒店预订嵌入现有客户体验。
- **合作伙伴和创作者自动化**，发现合格酒店，构建资产并保持归因——确认预订可获得 10% 默认佣金。
- **酒店端协助工具**，帮助团队生成内容并分析 [Extranet](/zh-CN/products/extranet/)、[Social](/zh-CN/products/social/) 和 [Studio](/zh-CN/products/studio/) 的表现，同时酒店保持规则控制。

## 未来方向

上述能力通过 REST API 和 MCP 服务器已上线。未来方向是更深层的代理原生商务：更丰富的面向代理的预订原语，代理身份和授权以代表旅行者交易，代理作为合作伙伴网络中有归因的收益来源参与。贯穿始终的是一致的——**为 AI 代理打造的旅游商务基础设施**，Booking Engine 在背后履约。

## 常见错误

- **将 AI 发现和 AI 代理视为同一项目。** 一个是内容和结构，另一个是 API 和履约。两者都需要。
- **让代理报价无法预订的价格。** 报价必须来自实时价格和可用性，而非爬取页面。
- **交接时丢失归因。** 如果代理创造需求，预订应保持与该来源关联。
- **跳过履约层。** 答案不是预订，除非结账、付款和确认真正完成。
