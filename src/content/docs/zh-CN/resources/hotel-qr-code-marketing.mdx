## 为什么二维码对酒店很重要

酒店充满了高意向的线下时刻。客人阅读水疗菜单、用餐者用餐结束、婚礼参与者、持有房卡的旅客——每一个都是推动预订、附加销售或回访的机会。二维码将这些时刻连接到数字化、可预订的下一步。

技术很简单；每部手机相机都能扫描二维码。区别在于二维码的**落点**。太多酒店二维码打开的是静态PDF、首页或无法操作的菜单。机会在于让扫码**可预订且可衡量**。

## 酒店可以放置二维码的位置

| 位置 | 可预订的时刻 |
|---|---|
| 客房和房卡 | 延长住宿、预订回访、添加水疗或餐饮。 |
| 餐厅和酒吧 | 预订餐桌、预订厨师体验、规划未来住宿。 |
| 水疗和健康 | 预订护理和健康套餐。 |
| 前台和大堂 | 升级销售、提前入住、延迟退房、体验活动。 |
| 活动和婚礼 | 为参与者提供房间预留或目的地店面。 |
| 印刷宣传资料 | 宣传册、传单、标牌、名片和欢迎手册。 |
| 户外及本地合作伙伴 | 海报、合作场所和目的地投放。 |

每个位置应对应一个**具体意图**——水疗二维码不应将客人引导至仅限客房的流程。

## 二维码应指向什么

扫码应落在与时刻匹配且能完成操作的目的地：

- 一个**可预订的优惠**——具体的房型、套餐、餐桌、护理或体验。
- 一个**店面**——当一个二维码需展示多个优惠时（活动酒店、目的地合集、酒店全部可预订内容菜单）。
- 一个**移动优先**页面——二维码流量几乎全部来自手机。
- 一个**可衡量**的路径——让酒店知道哪个投放带来了预订。

## Wink上的工作原理

Wink将二维码变成真正的渠道，而非静态链接。

- **[Studio](/zh-CN/products/studio/)生成二维码。** 创建可预订的Shareable Link或资产，下载带品牌的**二维码PNG或SVG**，用于印刷、标牌和酒店内投放。
- **[WinkLinks](/zh-CN/products/winklinks/)托管目的地。** 当一个二维码需承载多个优惠时，指向移动优先的Travel Storefront——可预订的酒店卡片、优惠、列表和地图，统一在`i.trvl.as/your-name`链接下。
- **[Booking Engine](/zh-CN/products/booking-engine/)完成预订。** 一键进入结账——正确的房型、价格和附加服务，支付确认——覆盖整个住宿，而非仅房间。
- **归因保持完整。** 预订与二维码背后的活动、投放或合作伙伴保持关联，酒店可查看哪些二维码真正创造了需求。

这与[酒店社交电商](/zh-CN/resources/hotel-social-commerce/)背后的闭环相同——二维码只是线下的入口。

## 实用二维码操作手册

### 1 — 选择时刻和意图

确定每个投放应销售的内容。餐厅桌牌和婚礼横幅的任务不同。

### 2 — 先构建目的地

在印刷任何东西之前，先创建可预订优惠或店面。目的地即活动，二维码只是入口。

### 3 — 生成并品牌化二维码

使用Studio创建二维码，下载PNG或SVG格式，确保任何印刷尺寸下都清晰。

### 4 — 设计扫码体验

二维码旁添加明确的行动号召（“扫码预订水疗套餐”），确保落地页在手机上加载迅速。

### 5 — 测量并迭代

按投放位置跟踪扫码转预订。替换转化率低的二维码，加大有效二维码的投入。

## 常见错误

- **二维码打开PDF或首页。** 扫码必须指向可预订内容。
- **一个通用二维码到处用。** 二维码应匹配时刻和意图。
- **无归因。** 无法识别哪个投放带来预订，就无法优化。
- **桌面版落地页。** 二维码流量是移动端——设计要适配。
- **先印刷后搭建。** 先搭建目的地，再决定印刷。
