## 为什么“Link in Bio”对酒店很重要

社交平台限制可点击链接。Instagram、TikTok等类似平台的个人资料基本上只给品牌**一个链接**可用——因此“Link in Bio”成为酒店内容与粉丝下一步行动之间的门户。二维码背后、短链接活动和合作伙伴推荐中也存在同样的限制：一个链接必须承载当下的流量。

通用的Link in Bio工具解决了错误的一半问题。它们组织链接——但把人们**送走**到其他页面，不显示实时酒店库存，也无法完成预订。对酒店来说，这就是流失：关注来了，却消失在主页或OTA。

解决方案是把这个唯一链接当作**店面**，而不是目录。

## Link in Bio与旅行店面的区别

| | 通用Link in Bio | 旅行店面 |
|---|---|---|
| 内容 | 一串网址列表 | 可预订的酒店卡片、优惠、列表、地图 |
| 功能 | 送人离开 | 引导人们完成预订 |
| 库存 | 无 | 实时酒店库存和价格 |
| 结账 | 无 | 由Booking Engine完成 |
| 归因 | 无或仅基础点击 | 预订过程中保留归因 |
| 设计初衷 | 桌面端附带 | 移动优先 |

旅行店面看起来像Link in Bio页面——简洁、移动端、单一链接——但功能像一个可预订的店铺。

## 酒店旅行店面可以包含什么

一个公开链接可以展示整套可预订内容：

- **可预订的酒店卡片和优惠**——房型、套餐、季节性优惠。
- **精选列表**——“适合家庭”、“养生度假”、“活动酒店”。
- **可预订供应的地图和网格**。
- **丰富内容、文件和媒体**——宣传册、欢迎信息、画廊。
- **二维码目的地**——物业内二维码背后的店面。
- **普通链接**——用于所有非预订内容。

这就是为什么旅行店面同样适用于酒店的Instagram简介、婚礼房间预订、目的地活动或合作伙伴推荐页面。

- **[Studio](/zh-CN/products/studio/)构建资产。** 从批准的酒店供应中创建可预订卡片、链接、地图、网格和二维码。
- **[WinkLinks](/zh-CN/products/winklinks/)是店面。** 将这些资产汇集在一个移动优先的公开链接`i.trvl.as/your-name`下——卡片视图或列表视图。**免费使用**。
- **[Booking Engine](/zh-CN/products/booking-engine/)完成预订。** 一键进入结账——支付、确认、整个住宿流程——并保留来源和合作伙伴归因。

这是[酒店社交电商](/zh-CN/resources/hotel-social-commerce/)的闭环：内容吸引关注，店面展示可预订选项，Booking Engine完成转化。

## 谁在使用

- **酒店**——社交简介、二维码、邮件和物业内资料的唯一链接，展示房型、优惠、餐饮、水疗和体验。
- **合作伙伴和创作者**——基于网络酒店构建的目的地页面、活动集合或活动店面，享有[10%默认佣金和6个月归因](/zh-CN/partners/)。
- **活动**——房间预订或目的地店面，参会者可通过一个链接预订。

## 实用设置步骤

1. **认领你的链接**——设置`i.trvl.as/your-name`。
2. **在Studio构建资产**——你想展示的房型、优惠和集合。
3. **安排店面**——选择卡片或列表视图，突出最强的可预订优惠。
4. **将链接放到各处**——社交简介、二维码、邮件签名、活动链接、合作伙伴页面。
5. **保持内容更新**——替换季节性优惠和活动，确保店面始终反映你在销售的内容。
6. **进行测量**——查看哪些入口和来源转化，持续优化。

## 常见错误

- **使用只列网址的通用Link in Bio。** 它把关注者送走，而不是引导预订。
- **直接将简介链接到主页。** 应以可预订优惠为主，而非落地页。
- **让店面内容过时。** 更新优惠和活动，保持点击价值。
- **忽视合作伙伴。** 同一店面模型让合作伙伴展示你的酒店，且归因完整。
