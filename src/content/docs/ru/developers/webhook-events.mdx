На этой странице перечислены все события webhook, на которые вы можете подписаться в Wink. Для инструкций по настройке смотрите [Руководство по интеграции Webhook](/ru/developers/webhook-integration) или [страницу управления Webhook](/ru/portal/settings/webhooks).

## Как подписаться

1. Перейдите в **Applications > Webhooks** в вашем портале.
2. Создайте webhook и выберите события, которые хотите получать — или оставьте список пустым, чтобы получать все события.
3. Wink отправляет подписанный HTTP POST на ваш endpoint каждый раз, когда происходит событие. Смотрите [Интеграция Webhook](/ru/developers/webhook-integration) для информации об envelope, заголовках, проверке подписи и повторных попытках.

## Все типы событий

Эта таблица генерируется из каталога событий платформы во время сборки, поэтому всегда соответствует API.
Типы событий, помеченные как доставленные, содержат ссылку на их страницу справки в [Webhooks API](/ru/api/webhooks/), где
задокументировано точное тело JSON (`WebhookEnvelope` с событием-специфичным `object`), заголовки `Wink-*` и
политика повторных попыток. Типы событий, которые не доставляются, существуют внутри системы (платежи, бухгалтерия, синхронизация с channel-manager и др.), но в настоящее время не отправляются подписчикам webhook.

**Получатели** указывают, кто получает событие: `SUPPLIER` (отель), `AFFILIATE` (реселлер с активным
продажным каналом к отелю), `AGENT` (турагентство, сделавшее бронирование) или `SELF` (управляющая сущность,
к которой относится событие). Каждый получатель получает одинаковую структуру полезной нагрузки; детали, специфичные для роли, доступны по URL `links.self` в полезной нагрузке.

:::tip
Начинайте с подписки на все события во время разработки. Как только вы поймёте, какие полезные нагрузки нужны вашей системе, сузьте подписки, чтобы уменьшить шум. Отправьте себе тестовое событие из **Applications > Webhooks** (или `POST …/webhook/{id}/test`), чтобы подтвердить работу endpoint и проверку подписи перед запуском в продакшен.
:::
