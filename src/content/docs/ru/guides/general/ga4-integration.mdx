Подключив ваше свойство Google Analytics 4 к Wink, события бронирования — от просмотров номеров до завершённых бронирований — автоматически передаются в вашу панель GA4 вместе с собственной аналитикой Wink. Без кода и технической настройки с вашей стороны.

<Aside type="tip">
Вам нужны две вещи из GA4: **Measurement ID** и **Measurement Protocol API secret**. Measurement ID обеспечивает работу воронки просмотра в браузере гостя; API secret позволяет Wink фиксировать завершённые бронирования (`purchase`) **на стороне сервера**, чтобы продажа не потерялась при перенаправлении гостя к и от платёжного провайдера.
</Aside>

---

## Как это работает

```
Вы вводите Measurement ID (G-XXXXXXXXXX) и API secret в портале Wink
       ↓
События просмотра (просмотры, корзина, оформление) передаются в ваше свойство GA4 из браузера
Завершённые бронирования (purchase) отправляются серверно — сохраняются при перенаправлении оплаты
       ↓
Вы заходите в analytics.google.com и видите полную воронку бронирования
```

---

## Что нужно сделать

<Steps>

1. **Создайте свойство GA4**

   Перейдите на [analytics.google.com](https://analytics.google.com): Администратор → Создать свойство. Установите часовой пояс и валюту, соответствующие вашему рынку.

2. **Создайте поток данных для веба**

   Администратор → Потоки данных → Добавить поток → Веб. Введите `wink.travel` как URL. Это создаст ваш **Measurement ID** (`G-XXXXXXXXXX`). Скопируйте его.

3. **Создайте Measurement Protocol API Secret**

   Откройте тот же поток данных для веба → прокрутите до **Measurement Protocol API secrets** → **Создать**. Дайте ему имя (например, "Wink") и скопируйте сгенерированное **секретное значение**. Этот секрет позволяет Wink фиксировать завершённые бронирования на сервере, чтобы продажа не потерялась при перенаправлении оплаты.

4. **Введите Measurement ID и API Secret в портале Wink**

   Войдите в [app.wink.travel](https://app.wink.travel), выберите свой аккаунт и перейдите на вкладку **Настройки**. Вставьте Measurement ID и API secret в поля **GA4** и сохраните. Всё — интеграция GA4 активирована.

   <Aside type="note">
   API secret — это **только для записи**: после сохранения он больше не отображается. При последующих изменениях оставляйте поле секрета пустым, чтобы сохранить уже введённое значение.
   </Aside>

5. **Отметьте `purchase` как ключевое событие**

   Вернитесь в своё свойство GA4: Администратор → События → найдите `purchase` → включите **Отметить как ключевое событие**. Это позволит завершённым бронированиям отображаться в отчёте по конверсиям.

6. **Просматривайте данные**

   Войдите в [analytics.google.com](https://analytics.google.com), и вы увидите бронирования, доход и воронку гостей — всё автоматически отслеживается через Wink.

</Steps>

<Aside type="note">
Для этой интеграции не нужно устанавливать код отслеживания на вашем сайте. Wink делает всё за вас. Ваш Measurement ID — это место назначения для данных бронирования, а API secret позволяет Wink подтверждать завершённые бронирования на сервере.
</Aside>

<Aside type="tip">
**GA4 и GTM можно использовать вместе.** Если вы также используете контейнер Google Tag Manager (например, Sojern), вы можете настроить оба одновременно — они больше не исключают друг друга. Подробнее см. [Интеграция GTM Analytics](/ru/guides/developers/gtm-dual-tagging).
</Aside>

## Что можно отслеживать

После подключения ваше свойство GA4 получает полный набор событий Enhanced E-commerce для вашей недвижимости:

### Открытие

| Событие | Что означает |
|---|---|
| `view_item_list` | Гость увидел вашу недвижимость в поиске или списке категорий |
| `select_item` | Гость кликнул на вашу недвижимость из списка |
| `view_item` | Гость просмотрел страницу с деталями отеля |

### Рассмотрение

| Событие | Что означает |
|---|---|
| `view_promotion` | Гость увидел промоакцию для вашей недвижимости |
| `select_promotion` | Гость кликнул на промоакцию |
| `add_to_wishlist` | Гость добавил вашу недвижимость в список желаемого |

### Воронка бронирования

| Событие | Что означает |
|---|---|
| `add_to_cart` | Гость выбрал номер или пакет |
| `view_cart` | Гость просмотрел сводку бронирования |
| `remove_from_cart` | Гость удалил номер или пакет |
| `begin_checkout` | Гость начал процесс оформления |
| `add_payment_info` | Гость ввёл платёжные данные |
| `add_shipping_info` | Гость ввёл данные гостя |
| `purchase` | Гость завершил бронирование |
| `refund` | Бронирование было отменено и возвращено |

Все события включают соответствующие параметры, такие как доход, валюта, тип номера и стоимость бронирования — что даёт полное представление о пути гостя от первого впечатления до завершённого бронирования. Чтобы получить дополнительные параметры на уровне недвижимости и номеров, такие как `city_name`, `cancellation_policy`, `bed_type` и другие, смотрите [Пользовательские параметры в GA4](/ru/guides/developers/gtm-dual-tagging#custom-dimensions-in-ga4).

## Междоменное отслеживание (расширенное)

Стандартная интеграция выше отслеживает всё, что происходит внутри Wink. Однако если вы хотите отслеживать гостей от вашего собственного сайта до завершения бронирования на Wink — и правильно атрибутировать исходный источник трафика (Google Ads, email-кампании, органический поиск и т.д.) — потребуется дополнительный шаг с каждой стороны.

<Aside type="caution">
Этот раздел применим только если у вас установлен GA4 на вашем сайте. Если вы не используете GA4 на сайте, стандартной интеграции выше достаточно.
</Aside>

### Почему это важно

Без междоменного отслеживания гость, который сначала посетил ваш сайт, а затем забронировал на Wink, будет отображаться в GA4 как сессия **Direct** без связи с предыдущим визитом. Любые клики Google Ads, email-кампании или органический поиск, приведшие к бронированию, не будут учтены.

С настроенным междоменным отслеживанием вы увидите полный путь гостя:

```
google.com (платная реклама)
       ↓
ваш сайт (гость просматривает номера)
       ↓
wink.travel (гость выбирает номер и бронирует)
       ↓
покупка правильно атрибутируется к исходному клику Google Ads
```

### Что нужно сделать: вы

Настройте своё свойство GA4 так, чтобы `wink.travel` распознавался как часть вашего домена, а не как внешний реферал. Это позволит GA4 объединить две сессии в один непрерывный путь гостя.

<Steps>
1. Администратор GA4 → Потоки данных → ваш поток
2. Настроить параметры тегов → **Настроить ваши домены**
3. Добавить `wink.travel` как связанный домен
4. Сохранить
</Steps>

### Что нужно сделать: Wink

Свяжитесь с [службой поддержки Wink](https://app.wink.travel) и предоставьте домен вашего сайта (например, `yourhotel.com`). Wink добавит ваш домен в список исключений рефералов в свойстве GA4 Wink. Это предотвратит запись вашего сайта как источника реферала, что иначе перезаписало бы исходную атрибуцию гостя и начало новую сессию.

<Aside type="tip">
Стандартная интеграция выше подходит для большинства объектов и даёт мгновенный доступ к бронированиям и доходам в Wink. Междоменное отслеживание — это расширенная опция, которую стоит настроить, когда вы уверены в своих данных GA4 и хотите получить более глубокую атрибуцию.
</Aside>
