## Рекомендовать отель — это не бронировать его

Большинство «AI-путешествий» сегодня ограничивается рекомендацией. Ассистент предлагает три отеля, а затем передаёт путешественника на сайт или OTA для фактического бронирования. Поток прерывается, цена может быть недоступна для бронирования, и никто не сохраняет контекст источника.

**AI-агент** отличается от AI-ответа. Агент не просто описывает отель — он действует: проверяет живую доступность, собирает бронирование, принимает оплату и может реагировать на изменения. Для этого агенту нужно больше, чем текст. Ему нужны структурированные, актуальные, доступные для бронирования данные и слой транзакций, который он может вызвать.

Это разница между [AI discovery](/ru/resources/ai-discovery-hotels/), который отвечает за **нахождение и понимание**, и агентским коммерческим сервисом, который отвечает за **совершение транзакций**.

## Что нужно агенту, чтобы совершать транзакции

Бронирование отеля — это реальное коммерческое событие: правильный номер, правильный тариф, реальная доступность, правила, оплата и подтверждение, синхронизированное с отелем. Агент может завершить это только если каждый элемент доступен как вызываемая операция.

| Что нужно агенту | Почему это важно |
|---|---|
| Структурированный, живой инвентарь | Данные, собранные с сайтов, устаревают; агенту нужен актуальный, контролируемый отелем инвентарь. |
| Актуальные тарифы и доступность | Цена, которую агент указывает, должна быть действительно доступна для бронирования в данный момент. |
| Операция бронирования | Создание бронирования должно быть реальным вызовом API, а не передачей на веб-форму. |
| Оплата | Агент (или путешественник через него) должен иметь возможность оплатить с применением логики политики. |
| Атрибуция | Источник, кампания или агент, создавший бронирование, должны оставаться привязанными. |
| События | Агент должен иметь возможность реагировать на подтверждения, изменения, отмены и возвраты. |

Без этого агент может рекомендовать — но не может бронировать.

## Как AI-агент бронирует отель в Wink

Wink ориентирован на API: каждая функция платформы доступна извне, а размещённый MCP-сервер предоставляет живые API-контракты агентам. Типичный поток агента:

### 1 — Подключиться и прочитать живые контракты

Агент подключается к размещённому MCP-серверу и использует `api_search` и `docs_search`, чтобы найти нужные операции и прочитать их реальные схемы запросов/ответов — без догадок по эндпоинтам и устаревшей документации.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Искать доступный для бронирования инвентарь

Агент ищет инвентарь, контролируемый отелем, включая геолокационный пространственный поиск, и читает живые тарифы и доступность по подключённым channel manager.

### 3 — Создать бронирование

Создание бронирования — это операция REST API. Агент собирает номер, тариф, даты и гостей и создаёт резервирование через API.

### 4 — Принять оплату и подтвердить

[Booking Engine](/ru/products/booking-engine/) выполняет транзакцию — оформление, оплату (Wink выступает продавцом), логику политики отмены, подтверждение и синхронизацию бронирования с подключённой PMS или channel manager. Атрибуция источника и партнёра сохраняется через бронирование.

### 5 — Реагировать на события

Агент может подписаться на `booking.created` и другие webhook-события для сверки, уведомления путешественника или запуска последующих действий.

Принцип: **агент создаёт или направляет намерение; Booking Engine остаётся слоем исполнения под каждым переходом.**

## AI-поиск против AI-агентов

Они решают разные задачи, и отель должен быть готов к обоим.

| | AI-поиск / ответные движки | AI-агенты |
|---|---|---|
| Цель путешественника | Найти и сравнить отели | Забронировать и управлять проживанием |
| Что нужно отелю | [Структурированный, индексируемый контент](/ru/resources/hotel-content-answer-engines/) | Живой API, тарифы, бронирование, оплата |
| Итог | Рекомендация | Подтверждённое бронирование |
| Поверхность Wink | Чистый инвентарь + контент для ответов | REST API, MCP сервер, Booking Engine |

[AI discovery для отелей](/ru/resources/ai-discovery-hotels/) охватывает сторону поиска; это руководство — сторону транзакций.

## Кто создаёт агентов для туристического коммерческого сервиса отелей

Агентский туристический коммерческий сервис — это не только потребительские ассистенты. Та же инфраструктура поддерживает:

- **Потребительских туристических ассистентов**, которые ищут, бронируют и управляют проживанием от начала до конца.
- **Агентов банков, программ лояльности и суперприложений**, встраивающих бронирование отелей в существующий клиентский опыт.
- **Партнёрские и создательские автоматизации**, которые находят подходящие отели, создают материалы и сохраняют атрибуцию — зарабатывая 10% комиссию по умолчанию с подтверждённых бронирований.
- **Копилотов на стороне отеля**, которые помогают командам создавать контент и анализировать эффективность в [Extranet](/ru/products/extranet/), [Social](/ru/products/social/) и [Studio](/ru/products/studio/), при этом отель сохраняет контроль над правилами.

## Куда это движется

Вышеописанные возможности уже доступны через REST API и MCP сервер. Направление — более глубокий агентский нативный коммерческий сервис: расширенные примитивы бронирования для агентов, идентификация и авторизация агентов для транзакций от имени путешественника, а также участие агентов как атрибутированных источников дохода в партнёрской сети. Общая идея — **инфраструктура туристического коммерческого сервиса для AI-агентов**, с Booking Engine в роли слоя исполнения.

## Распространённые ошибки

- **Считать AI discovery и AI-агентов одним проектом.** Один — это контент и структура; другой — API и исполнение. Нужны оба.
- **Позволять агентам указывать цены, которые они не могут забронировать.** Цены должны исходить из живых тарифов и доступности, а не с сайтов.
- **Потеря атрибуции при передаче.** Если агент создаёт спрос, бронирование должно оставаться связанным с этим источником.
- **Пропускать слой исполнения.** Ответ — это не бронирование, пока не произойдёт оформление, оплата и подтверждение.
