Las herramientas MCP de Wink se publican como **conjuntos de herramientas** — endpoints enfocados, cada uno cubriendo una tarea. Conectas tu cliente de IA solo a uno o dos que coincidan con tu trabajo, no a todos.

Cada endpoint usa **inicio de sesión interactivo OAuth2** (flujo de código de autorización PKCE): tu agente de IA abre una pestaña del navegador, inicias sesión con tu cuenta Wink, y eso es todo. No hay secretos de cliente que administrar.

```bash title="Un integrador de channel manager se conecta a un endpoint"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Un hotelero que administra sus propias tarifas se conecta a otro"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

---

## Por qué las herramientas están divididas en endpoints

Wink expone alrededor de 500 herramientas. Entregar todas a un agente a la vez es técnicamente posible — y una mala idea.

**Las definiciones de herramientas consumen contexto.** Cada herramienta que un servidor MCP anuncia se carga en la ventana de contexto del modelo antes de que realice cualquier trabajo, junto con su descripción y esquema completo de parámetros. Quinientas de esas consumen una gran parte del presupuesto que tu tarea real necesita, en cada solicitud.

**La calidad de elección disminuye a medida que la lista crece.** Un agente que elige entre 500 herramientas con nombres similares toma peores decisiones que uno que elige entre 40. Si integras un channel manager, aproximadamente veinte herramientas son relevantes para ti; las otras 480 son ruido que dificulta encontrar la herramienta correcta.

**El trabajo es genuinamente separable.** Alguien sincronizando disponibilidad desde un PMS y alguien creando páginas afiliadas comparten casi ninguna herramienta. Dividir por tarea significa que cada conexión lleva el vocabulario de una tarea.

<Aside type="caution" title="Los conjuntos de herramientas no son permisos">
Elegir un conjunto de herramientas estrecho **no** restringe lo que tu cuenta puede hacer, y elegir uno amplio no otorga nada extra. Cada herramienta aplica los mismos permisos de cuenta que el portal web, bajo tu identidad iniciada. Si tu cuenta no puede cancelar una reserva en Wink Portal, el agente tampoco puede — sin importar a qué endpoint esté conectado.

Elige conjuntos de herramientas para **enfoque**, no para seguridad.
</Aside>

## Directorio de endpoints

Dos hosts sirven conjuntos de herramientas. El conteo de herramientas es aproximado y crece con el tiempo.

### `https://api.wink.travel` — la plataforma

| Endpoint | Herramientas | Qué cubre |
|---|---:|---|
| `/mcp/extranet/facilities` | ~64 | Inventario reservable y en sitio: habitaciones y tipos de habitación, spas, restaurantes, salas de reuniones, actividades, atracciones, lugares, otros artículos vendibles |

### `https://integrations.wink.travel` — integraciones de channel manager

Un endpoint, porque este host existe para una sola tarea.

| Endpoint | Herramientas | Qué cubre |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Conexión y verificación de una integración de channel manager, PMS o CRS |

<Aside type="note" title="Integrar un channel manager vs. administrar tus propias tarifas">
Son tareas diferentes para personas diferentes, y no comparten un endpoint.

Un **vendedor de channel manager, PMS o CRS** integra una vez a través de `integrations.wink.travel/mcp/channel-manager`, y desde entonces intercambia propiedades, tarifas, disponibilidad y reservaciones por esa integración. Ese único endpoint es toda la superficie.

Un **hotelero que cambia sus propias tarifas manualmente** usa los conjuntos de herramientas del extranet en `api.wink.travel` — `/mcp/extranet/rates` y similares. Estos no forman parte de una integración de channel manager y un integrador no tiene razón para conectarse a ellos.

La administración de cuenta también está en `api.wink.travel`, en `/mcp/settings`. No hay `/mcp/settings` en el host de integraciones.
</Aside>

Cada endpoint también incluye una herramienta `ping`, para que puedas confirmar que la conexión está activa antes de pedirle que haga trabajo real.

## ¿Qué conjuntos de herramientas necesito?

| Si eres… | Conéctate a |
|---|---|
| **Integrando un channel manager, PMS o CRS** | `integrations.wink.travel/mcp/channel-manager` — solo este |
| **Administrando el contenido de una propiedad** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Administrando habitaciones y tipos de habitación** | `/mcp/extranet/facilities` |
| **Administrando precios y disponibilidad** | `/mcp/extranet/rates` |
| **Manejando reservaciones diarias** | `/mcp/extranet/operations` |
| **Expandiendo distribución** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Creando páginas afiliadas** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Manejando páginas de link-in-bio** | `/mcp/link-manager` + `/mcp/social` |
| **Reservando en nombre de viajeros** | `/mcp/travel-agent` |
| **Conciliando dinero** | `/mcp/payment` |
| **Construyendo una experiencia de reserva** | `/mcp/booking-engine` + `/mcp/reference` |

Empieza con uno. Añade otro cuando te encuentres pidiendo algo que no pueda hacer — cada conexión es independiente, y añadir uno nunca afecta a los demás.

<Aside type="tip" title="¿Quieres todo?">
`https://api.wink.travel/mcp` y `https://integrations.wink.travel/mcp` siguen disponibles y sirven **todas** las herramientas en su host. Son útiles para explorar qué existe, pero no los recomendamos para trabajo diario: la lista de herramientas es lo suficientemente grande para opacar tu tarea y degradar la selección de herramientas del agente. Prefiere los conjuntos de herramientas arriba.
</Aside>

## Cómo funciona la autenticación

Los servidores MCP de Wink usan el flujo **OAuth2 Authorization Code + PKCE** y soportan **Dynamic Client Registration (RFC 7591)**. Esto es lo que sucede cuando te conectas por primera vez:

1. Tu cliente de IA descubre el servidor de autorización desde los metadatos `/.well-known/oauth-protected-resource` del endpoint MCP.
2. El cliente se registra automáticamente vía **Dynamic Client Registration** — no se requiere configuración manual de la aplicación.
3. El cliente abre una **pestaña del navegador** a `https://iam.wink.travel`. Inicias sesión con tu cuenta Wink y apruebas los permisos solicitados en la pantalla de consentimiento.
4. Wink emite un **token de acceso** con alcance para tu cuenta y vinculado a tu identidad.
5. El cliente de IA adjunta el token a cada solicitud MCP. Todos los resultados de herramientas se limitan automáticamente a tu entidad administradora.
6. Los tokens expiran después de 3 horas. Tu cliente de IA los renueva silenciosamente en segundo plano sin pedirte de nuevo.

Cada llamada a una herramienta se ejecuta **bajo tu identidad** — las mismas reglas ACL que protegen el portal web se aplican al agente de IA.

## Alcances

Cuando apruebas la pantalla de consentimiento verás un desglose de lo que el agente está solicitando. Los clientes MCP usan el mismo vocabulario de permisos que el resto de la plataforma — consulta la referencia completa de [alcances en la página de Autenticación](/es-MX/developers/authentication#scopes).

Dos cosas son específicas de MCP:

- **Los alcances `mcp.read`, `mcp.write` y `mcp.remove` son requeridos adicionalmente** para abrir el transporte MCP. Un cliente que tenga un alcance `mcp.*` es admitido en cualquier endpoint MCP de Wink, pero cada herramienta que invoque sigue aplicando el alcance de sección del endpoint que envuelve (por ejemplo, `booking.read`).
- **El cliente de IA solicita solo los alcances que necesita.** Puedes negar permisos individuales en la pantalla de consentimiento — las herramientas que requieran un alcance denegado devolverán un error al invocarlas.

**Los conjuntos de herramientas no cambian nada de esto.** El endpoint al que te conectas decide qué herramientas están *listadas*, no qué están *permitidas*. Conectarte a `/mcp/payment` no otorga ningún permiso financiero que no tuvieras ya, y conectarte a `/mcp/reference` no impide que una herramienta allí aplique su propio alcance. La autorización se decide por llamada a herramienta, a partir de tu token y los permisos de tu cuenta.

## Solución de problemas

**No se abre la pestaña del navegador**

Tu cliente de IA puede no soportar aún el flujo interactivo PKCE. Verifica que estés usando una versión reciente:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** actualiza desde el actualizador integrado de la app

**`401 Unauthorized` después de iniciar sesión**

Tu token en caché puede estar obsoleto. Elimina y vuelve a agregar el servidor para forzar un nuevo inicio de sesión:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Para Claude Desktop y ChatGPT, elimina la entrada del servidor en configuración, reinicia la app y agrégalo de nuevo.

**`403 Forbidden` al llamar a una herramienta específica**

La herramienta requiere un alcance que no aprobaste en la pantalla de consentimiento, o un permiso que tu cuenta no tiene. Reconecta el servidor — la pantalla de consentimiento aparecerá de nuevo y podrás aprobar el permiso faltante. Si sigue fallando, la herramienta necesita un permiso de cuenta que no tienes; conectarte a otro conjunto de herramientas no ayudará, porque los conjuntos no otorgan permisos.

**La herramienta que necesito no está en la lista**

Probablemente estás conectado a un conjunto de herramientas que no cubre esa tarea. Revisa el [directorio de endpoints](#endpoint-directory) y agrega el conjunto que sí lo haga — las conexiones son independientes, así que agregar uno no cambia nada de los demás. Si no sabes cuál lo tiene, conéctate temporalmente a `https://api.wink.travel/mcp`, encuentra la herramienta y luego busca qué conjunto la lista.

**`404 Not Found` en un endpoint de conjunto de herramientas**

Revisa bien la ruta — los conjuntos anidados tienen dos segmentos (`/mcp/extranet/rates`, no `/mcp/extranet-rates`), y los planos tienen uno (`/mcp/link-manager`). Nota que una solicitud *no autenticada* a cualquier ruta bajo `/mcp` devuelve `401`, no `404`, así que un `401` solo no indica si el endpoint existe.

**Me conecté a `api.wink.travel/mcp/channel-manager` y no obtuve nada**

Ese endpoint no existe. La integración de channel manager se sirve solo desde `https://integrations.wink.travel/mcp/channel-manager`. Si también necesitas leer o escribir las tarifas propias de una propiedad manualmente, esa es una tarea separada en un endpoint separado — mira `/mcp/extranet/rates`.

**El servidor aparece pero las llamadas a herramientas devuelven "cuenta no encontrada"**

Estás conectado a una cuenta Wink que no tiene entidad administradora. Ve a [Wink Portal](https://app.wink.travel) y asegúrate de que tu cuenta esté configurada antes de usar el servidor MCP.

**El token expira a mitad de sesión**

Los tokens son válidos por 3 horas. Claude Code y Claude Desktop renuevan tokens silenciosamente sin interrumpir tu sesión. Si ves errores de autenticación tras un largo periodo inactivo, escribe un nuevo mensaje — el cliente se reautenticará automáticamente.

**Codex CLI muestra "MCP server unreachable"**

Verifica que tu `~/.codex/config.json` sea JSON válido (sin comas finales) y que `"type": "http"` esté configurado. Codex requiere transporte HTTP para servidores remotos; el transporte stdio es solo para binarios locales.

**El menú "Conectores" de ChatGPT no aparece**

El soporte MCP requiere la versión **1.2024.352** o posterior de la app de escritorio ChatGPT y una suscripción activa Plus, Pro, Team o Enterprise. Actualiza la app y verifica tu plan en Configuración → Cuenta.

**El servidor Cursor muestra rojo / "Error al conectar"**

Verifica que tu `~/.cursor/mcp.json` sea JSON válido y contenga `"type": "http"`. Luego ve a **Configuración → Configuración de Cursor → MCP** y haz clic en **Actualizar**. Si el error persiste, reinicia completamente Cursor — los cambios de configuración no siempre se detectan sin reinicio.

**Los servidores MCP de Windsurf no aparecen en configuración**

Windsurf requiere un reinicio completo (no solo recargar ventana) para detectar cambios en `mcp_config.json`. Usa **Archivo → Salir** y vuelve a abrir. Si los servidores aún no aparecen, confirma que estás en Windsurf **1.4+** vía **Ayuda → Acerca de Windsurf**.

**La opción "Agregar servidor" en Cline no es visible**

El administrador de servidores MCP requiere Cline **2.0** o posterior. Abre el panel de Extensiones de VS Code, busca Cline y haz clic en **Actualizar** si hay una actualización disponible. Después de actualizar, recarga VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
