Las aplicaciones te dan acceso a todas las funciones de Wink como desarrollador. Puedes acceder a todos los mismos datos e incluso extender las propias funciones de Wink.
Puedes elegir usar el servidor OAuth2 de Wink para autenticar tu sitio de viajes de la misma manera que usarías Google o Facebook.
De esta forma, puedes extender las funciones de Wink en tu propio sitio web o aplicación.

:::note
Tu primera aplicación ya está creada cuando [creas una nueva cuenta](/es-MX/portal/create-account). Usamos esta aplicación para algunos escenarios de reserva.

No puedes reutilizar esta aplicación. Por favor, crea nuevas aplicaciones según las necesites.
:::

## Crear aplicación

Como no puedes acceder a la `clave secreta` de la aplicación que creamos para ti, necesitarás crear la tuya propia.
Puedes crear una aplicación aquí sin configurar primero una propiedad o empresa — no está vinculada
a ninguna cuenta específica.

### Tipos de cliente

Al crear una aplicación, eliges un tipo de cliente que determina cómo se autentica la app.
Esto no se puede cambiar después — si necesitas un tipo diferente, crea una nueva aplicación.

- **Aplicación web** — Una app renderizada en servidor que puede mantener de forma segura un secreto de cliente (flujo de código de autorización).
- **Aplicación de una sola página (SPA)** — Una app en navegador sin backend; usa PKCE, sin secreto de cliente.
- **Aplicación móvil** — Una app nativa iOS/Android; usa PKCE con tokens de actualización rotativos.
- **Máquina a máquina** — Un servicio backend que actúa por sí mismo (credenciales de cliente); sin inicio de sesión de usuario.

Aquí están los pasos para crear una aplicación:

<Steps>
1. Desde la página de aplicaciones, haz clic en el botón `Crear nueva aplicación`.
2. ***Nombre*** Dale un nombre a tu app. *ej. App Genial*
3. **Tipo de cliente** Elige el tipo que coincida con cómo se autentica tu app — consulta [Tipos de cliente](#client-types) arriba.
4. **URIs de redirección** Se requiere al menos una URI de redirección. Se usa para validar el dominio de redirección después de una autenticación exitosa. No se usa para aplicaciones máquina a máquina. *ej. https://www.sitio-genial.com*
5. **URIs de redirección post-cierre de sesión** *(Opcional)* URLs a donde se puede redirigir a los usuarios después de cerrar sesión. Déjalo en blanco para reutilizar las URIs de redirección anteriores.
6. **Scopes** Elige a qué puede acceder esta aplicación en tu nombre — consulta [Elección de scopes](#choosing-scopes) abajo.
7. Haz clic en el botón `Crear aplicación` para continuar.
</Steps>

Serás redirigido de vuelta a tu lista de aplicaciones, y un diálogo único mostrará el nuevo Client ID
y Client secret. Copia el secreto ahora y guárdalo en un lugar seguro — nunca se muestra de nuevo, y
no hay forma de recuperarlo después (solo puedes [rotarlo](#rotate-credentials) por uno nuevo).

## Elección de scopes

Cada aplicación siempre lleva los scopes **Inicio de sesión (OpenID Connect)** (`openid`, `profile`,
`email`, `offline_access`) — estos confirman la identidad del usuario y mantienen la sesión iniciada, por lo que
aparecen marcados y bloqueados; no son opcionales.

Todo lo demás es optativo. Los scopes restantes están agrupados en las mismas secciones funcionales
documentadas en [Scopes](/es-MX/developers/authentication#scopes) — Cuenta, Inventario y tarifas, Reservas,
Marketing y promociones, Contenido de propiedad, Análisis e informes, Integraciones con channel manager,
Pagos, y Contabilidad y libro mayor — cada uno con una descripción en lenguaje sencillo de lo que desbloquea. Usa
los enlaces `Todos` / `Ninguno` arriba de la lista para seleccionar o desmarcar todos los scopes opcionales a la vez.

:::note
**Pagos** y **Contabilidad y libro mayor** están marcados como **Sensibles** porque protegen el movimiento de dinero — solo otórgalos a aplicaciones que específicamente necesiten acceder a pagos o al libro mayor.
:::

Dos familias de scopes no se ofrecen deliberadamente en este formulario:

- **`mcp.*`** — Acceso de agentes AI al transporte [Model Context Protocol](/es-MX/developers/mcp), que se
  provisiona por separado y solo para clientes máquina a máquina.
- **Scopes de nivel administrador** (`administrator.*`) — acceso a nivel plataforma que no se otorga por
  aplicación.

Una vez creada una app, tanto esta pestaña como [Apps consentidas](/es-MX/account/apps) muestran sus scopes otorgados
agrupados por sección (ej. "Reservas: `booking.read`"), para que puedas ver qué puede hacer una app de un vistazo
sin abrirla.

## Rotar credenciales

Si un secreto de cliente pudo haberse filtrado, o simplemente quieres credenciales nuevas, rótalas en lugar de
recrear la app:

<Steps>
1. Encuentra la app en tu lista de aplicaciones y haz clic en `Rotar`.
2. Confirma el diálogo — el Client ID y secreto actuales dejan de funcionar inmediatamente.
3. Copia el nuevo Client ID y secreto del diálogo único antes de cerrarlo.
</Steps>

Rotar mantiene el nombre de la app, tipo de cliente, URIs de redirección y scopes — solo cambian las credenciales.

## Eliminar aplicación

:::caution
Por favor no elimines la app que creamos automáticamente para ti para asegurar que todas las funciones funcionen para tu cuenta.
:::

Si ya no necesitas una app, puedes eliminarla. Esto es permanente — las credenciales se revocan inmediatamente y no pueden recuperarse.

<Steps>
1. Encuentra la app en tu lista de aplicaciones y haz clic en `Eliminar`.
2. Confirma el diálogo para eliminar la aplicación permanentemente.
</Steps>
