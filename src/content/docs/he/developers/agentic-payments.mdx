אתם יכולים לחפש מלון, לבחור חדר ולהשלים את ההזמנה שלכם דרך הסוכן המבוסס בינה מלאכותית. חברו אותו ל-Wink ולארנק תשלום, ואז אמרו לו היכן תרצו לשהות. Wink משתמש ב**פרוטוקול תשלומים למכונה (MPP)** כדי לקבל את התשלום מהארנק ולהחזיר את אישור ההזמנה שלכם.

## 1. חברו את שרתי MCP

לזרימת ההזמנה המלאה, הסוכן שלכם צריך את **מנוע ההזמנות של Wink** ו**ארנק תשלום**.

| חיבור | מה הוא עושה | איך להוסיף אותו |
| --- | --- | --- |
| **מנוע ההזמנות של Wink** — חובה | מוצא יעדים, מחפש מלונות ומחירי חדרים, מציע ומאשר הזמנות, ומחזיר את ההזמנות והקבלות שלכם. | הוסיפו את `https://api.wink.travel/mcp/booking-engine` כשרת MCP מרוחק מסוג HTTP. |
| **ארנק תשלום** — חובה לתשלום | מספק אישורי תשלום לאחר שאתם מאשרים את הרכישה. | חברו ארנק התומך ב-Stripe Shared Payment Tokens או בתשלומי Tempo. ראו את דוגמת Link למטה. |
| הפניה ל-Wink — אופציונלי | מחפש מדינות, מטבעות ונתוני הפניה נוספים. | `https://api.wink.travel/mcp/reference` |
| מסמכי Wink — אופציונלי | עוזר לסוכן שלכם לקרוא תיעוד וחוזי API. | `https://docs.mcp.wink.travel/mcp` |

מנוע ההזמנות MCP כבר כולל את הכלים הדרושים לזרימת הזמנת הנוסע, כאשר הזמנה ותשלום סוכניים מופעלים לסביבה זו. MCP התשלום הנפרד של Wink מיועד לפעולות פיננסיות כגון ספרי חשבונות ומשיכות; הוא אינו נדרש לתשלום עבור חדר.

### התחברו ובחרו הרשאות

1. פתחו את הגדרות MCP או המחבר של הסוכן שלכם והוסיפו את כתובת מנוע ההזמנות שלמעלה. תנו לו שם כמו **Wink Booking**.
2. הסוכן שלכם פותח את דף ההתחברות של Wink בדפדפן שלכם. התחברו עם חשבון Wink שברצונכם להזמין תחתיו.
3. במסך ההסכמה, בחרו את ההרשאות שהסוכן שלכם צריך, ואז אשרו את החיבור.
4. חזרו לסוכן שלכם. הוא טוען את הכלים הזמינים ומנהל אימות לקריאות MCP הבאות.

לזרימה זו, בחרו:

| הרשאה | למה היא נדרשת |
| --- | --- |
| גישה לסוכן בינה מלאכותית (`mcp.read`) | מאפשרת לסוכן שלכם להתחבר ל-MCP של Wink. |
| קריאת שיווק (`marketing.read`) | מאפשרת לסוכן למצוא את תצורת ההזמנה של החשבון שלכם, הנקראת התאמה אישית. על החשבון שלכם להיות בעל גישה גם לתצורה זו. |
| כתיבת תשלום (`payment.write`) | מאפשרת לסוכן לשלם עבור הציטוט ולאשר את ההזמנה. |

שמרו את הרשאות ההתחברות שביקש החיבור. לקוח MCP שלכם מטפל באסימוני גישה; אין צורך להעתיק אסימון לשיחה או להגדיר כותרות בקשה. אם פספסתם הרשאה נדרשת, התחברו מחדש דרך זרימת ההתחברות של הלקוח ואשרו אותה.

### חברו ארנק תשלום

לתשלומי Stripe, אפשרות אחת היא **ארנק הסוכן של Link**. אם הלקוח שלכם תומך בשרתי MCP מקומיים ו-Node.js מותקן, הוסיפו את הערך הבא לקונפיגורציית MCP שלו:

```json
{
  "mcpServers": {
    "link": {
      "command": "npx",
      "args": ["@stripe/link-cli", "--mcp"]
    }
  }
}
```

בקשו מהסוכן שלכם לחבר את חשבון Link שלכם, ואז עקבו אחרי קישור האימות שהוא מספק ואשרו את החיבור. Link מספק את Shared Payment Token המשמש לתשלום עבור ההזמנה. Link תומך כיום בחשבונות בארה"ב; בדקו את מגבלות ההוצאה לפני ההזמנה. ראו [מדריך ההתקנה של Link](https://github.com/stripe/link-cli#quickstart) ו[קונפיגורציית MCP](https://github.com/stripe/link-cli#mcp-server).

ניתן גם להשתמש בארנק התומך באתגר תשלום Tempo שמציע Wink. אם לסוכן שלכם כבר יש ארנק תואם מחובר, השתמשו בחיבור זה. הגדרת הארנק ואישור התשלום הם נפרדים מהתחברות ל-Wink.

## 2. בקשו מהסוכן שלכם למצוא חדר

לדוגמה:

> מצא חדר בבנגקוק לשני מבוגרים מ-15 עד 17 בינואר 2027. הצג לי את האפשרויות הזמינות, המחיר הכולל ותנאי הביטול לפני שאבחר.

הסוכן שלכם יכול למצוא את חשבונות Wink שאליהם יש לכם גישה ואת תצורות ההזמנה שלהם. אם יש לכם כמה, אמרו לו איזה להשתמש. אם אתם מזמינים דרך קישור הזמנה או תצורה שסופקו, תנו זאת לסוכן במקום.

הסוכן אז פותר את היעד שלכם, בודק מלונות זמינים וטוען מחירי חדרים לתאריכים שלכם. בחרו חדר ובקשו הצעת מחיר.

זרימת תשלום זו תומכת כרגע ב**חדר אחד, במחיר בדולרים אמריקאיים, למבוגרים בלבד**. להצעת המחיר יש תוקף. בקשה להצעה אינה מחייבת תשלום או מאשרת הזמנה.

## 3. בדקו ואשרו תשלום

בדקו את המלון, החדר, התאריכים, האורחים, תנאי הביטול והסכום הכולל שהוצע. כשתהיו מוכנים, בקשו מהסוכן להזמין ולהשלים כל אישור שנדרש על ידי הארנק שלכם.

הסוכן משתמש באחת משיטות התשלום שהוצעו בהצעה:

- **Stripe:** הארנק מספק Shared Payment Token.
- **Tempo:** הארנק מבצע את ההעברה שצוינה באתגר ומספק את קוד העסקה שלו.

לאחר שהתשלום מצליח, הסוכן נותן לכם **קוד אישור הזמנה**. הוא יכול גם לשלוף את פרטי ההזמנה והקבלה דרך מנוע ההזמנות MCP.

אם התשלום עדיין בעיבוד או שהתגובה אבודה, אפשרו לסוכן לבדוק את **ניסיון התשלום אותו**. עליו להשתמש שוב בהצעה ובאישור התשלום במקום להתחיל תשלום שני. אם התשלום נדחה, בקשו הצעה חדשה ובחנו אותה לפני ניסיון נוסף.

## הפניה לכלים לסוכנים ומפתחים

כל כלי Wink למטה זמין דרך **מנוע ההזמנות MCP**. לקוח MCP שולח אימות אוטומטית באמצעות ההרשאות שאושרו במהלך ההתחברות.

| שלב | כלים והתנהגות |
| --- | --- |
| בחרו הקשר הזמנה | `managing_entity_list`, ואז `customization_get_primary` או `customization_search` עבור החשבון הנבחר. השתמשו בהתאמה אישית שסופקה אם כבר ידועה. |
| מצאו יעד | `destination_lookup_search_suggestions` ו-`destination_lookup_get`. |
| חפשו מלונות וחדרים | `inventory_search_city` או `inventory_search_geo`, ואז `property_inventory_get` למחירים וזמינות. |
| הציעו את החדר הנבחר | `agentic_booking_quote`. העבירו פרטי חדר בתוך הפרמטר `request`. |
| שלמו ואשרו | השיגו אישור מהארנק המחובר, ואז קראו ל-`agentic_booking_pay` עם `request.quoteId` ואחד בדיוק מתוך `request.spt` או `request.tempoTransactionHash`. שמרו על אותו משתמש מחובר ל-Wink עבור הצעה ותשלום. |
| שלפו את ההזמנה והקבלה | השתמשו ב-`booking_search` או `booking_search_list` למציאת ההזמנה המאושרת, ואז `booking_get` ו-`booking_receipt_get` עם מזהה ההזמנה. |

בקשת ההצעה דורשת `hotelIdentifier`, `roomRateIdentifier`, `checkIn`, `checkOut`, `adults`, `children` ו-`customizationIdentifier`. התאריכים בפורמט `YYYY-MM-DD`; `checkOut` חייב להיות אחרי `checkIn`. הגדירו `adults` לפחות ל-`1` ו-`children` ל-`0`.

ההצעה מחזירה `quoteId`, `amountUsdCents`, `currency`, `expiresAt` ו-`mppChallenges`. הציגו סנטים בדולרים אמריקאיים: `10000` פירושו **$100.00**. עבור Tempo, השתמשו באסימון, בשרשרת, במקבל ובכמות ביחידות הבסיס של האסימון שבאתגר הנבחר.

| תוצאת תשלום | שלב הבא |
| --- | --- |
| `PAYMENT_SUCCEEDED` | שמרו את `bookingConfirmationCode` ו-`chargeReference`. |
| `IN_PROGRESS` | המתינו מעט ונסו שוב את אותה הצעה ואישור. |
| `DECLINED` | בקשו הצעה חדשה ובחנו אותה לפני תשלום נוסף. |

ניסיון חוזר מוצלח מחזיר את ההזמנה הקיימת ללא חיוב נוסף. התייחסו לפסק זמן כתוצאה לא ידועה ונסו שוב את אותו תשלום. אם הבעיה נמשכת, פנו לתמיכה עם מזהה ההצעה.

### לקוחות MCP מודעים לתשלום

לקוחות MCP מודעים לתשלום יכולים להשתמש ב-`agentic_booking_book` עם שדות החדר ישירות ב-`arguments`. הקריאה הראשונה מחזירה שגיאה `-32042` עם אתגרי תשלום. נסו שוב את אותה קריאה עם אישור הארנק ב-`params._meta["org.paymentauth/credential"]`; הצלחה כוללת `result._meta["org.paymentauth/receipt"]`. שגיאה `-32043` מכילה כישלון תשלום ואתגר: דחייה סופית דורשת הצעה חדשה, בעוד שהטענה לא שלמה יכולה לנסות שוב עם אותו אתגר. עבור `-32603`, `data.failure.reason` של `payment-in-progress` או `already-consumed` משמעותו לנסות שוב את אותו אישור; קוד השגיאה לבדו אינו מספיק.

## הזמנה דרך REST

השתמשו ב-REST כאשר בונים אינטגרציה שקוראת ל-Wink ישירות דרך HTTP. גם ההצעה וגם התשלום משתמשים ב**`POST https://api.wink.travel/api/mpp/booking`**.

האפליקציה שלכם צריכה [אסימון גישה למשתמש Wink](/he/developers/authentication/) עם הרשאת `payment.write` לתשלום. שמרו על אותו משתמש לשתי הקריאות. שלחו את האסימון ב-`Wink-Authorization`, והשאירו את `Authorization` זמין לאישור התשלום של הארנק. כותרות אלו חלות על REST; לקוח MCP מטפל באימות שלו.

### 1. בקשו הצעה

שמרו את החדר הנבחר כ-`booking.json`, החליפו את מזהי הדוגמה והתאריכים בבחירתכם. שדות החדר נמצאים ישירות בגוף JSON, ללא עטיפת `request`.

```json
{
  "hotelIdentifier": "YOUR_HOTEL_ID",
  "roomRateIdentifier": "YOUR_ROOM_RATE_ID",
  "checkIn": "2027-01-15",
  "checkOut": "2027-01-17",
  "adults": 2,
  "children": 0,
  "customizationIdentifier": "YOUR_CUSTOMIZATION_ID"
}
```

הגדירו את `WINK_ACCESS_TOKEN` לאסימון הגישה של המשתמש ושלחו את הבקשה:

```bash
curl -i https://api.wink.travel/api/mpp/booking \
  -H "Wink-Authorization: Bearer $WINK_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @booking.json
```

Wink מחזיר **`402 Payment Required`** עם אתגר `WWW-Authenticate: Payment ...` עבור כל שיטה מוצעת. גוף ה-JSON כולל `quoteId`, `amount`, `currency`, `expiresAt` ו-`methods`. כאן, `amount` הוא מחרוזת בסנטים בדולרים אמריקאיים: `"10000"` פירושו **$100.00**. בדקו את ההצעה לפני שפג תוקפה; עדיין לא בוצע תשלום.

### 2. שלמו ואשרו

הארנק ממלא את אחד האתגרים שהוחזרו. עבור Stripe, הוא מספק `payload.spt`; עבור Tempo, הוא מספק `payload.hash` עם `payload.type` שהוגדר ל-`"hash"`. השתמשו בפרטי התשלום מהאתגר.

הגדירו את `MPP_CREDENTIAL` לאישור MPP המקודד של הארנק, הכולל את האתגר ופרטי התשלום. נסו שוב את **אותו גוף בקשה**, תוך שמירת כותרת הזהות:

```bash
curl -i https://api.wink.travel/api/mpp/booking \
  -H "Wink-Authorization: Bearer $WINK_ACCESS_TOKEN" \
  -H "Authorization: Payment $MPP_CREDENTIAL" \
  -H 'Content-Type: application/json' \
  --data-binary @booking.json
```

בהצלחה, Wink מחזיר **`200 OK`**, גוף JSON עם `bookingConfirmationCode`, וכותרת `Payment-Receipt`. שמרו את האישור והקבלה. ניסיון חוזר מוצלח מחזיר את ההזמנה הקיימת ללא חיוב נוסף.

### טיפול בתגובות וניסיונות חוזרים

| תגובה | מה לעשות |
| --- | --- |
| `400` | תקנו פרטי חדר שגויים או אישור שגוי. |
| `401` / `403` | בדקו את אימות המשתמש והרשאת התשלום. |
| `402` | בדקו את הבעיה והאתגר שהוחזרו. דחיית תשלום סופית דורשת הצעה חדשה; מטען תשלום לא שלם משתמש שוב באתגר המקורי. בדקו את המחיר לפני תשלום. |
| `409` | תוצאת התשלום לא ברורה. המתינו מעט, ואז נסו שוב את אותו גוף ואישור בנקודת ההזמנה. |
| `429` | המתינו את מספר השניות ב-`Retry-After`, ואז נסו שוב. |

תגובה `409` כוללת גוף `application/problem+json`. השוו את `type` לכתובות המדויקות הבאות:

| סוג הבעיה | משמעות |
| --- | --- |
| [https://api.wink.travel/problems/payment-in-progress](https://api.wink.travel/problems/payment-in-progress) | ניסיון תשלום עדיין מתבצע או שהסגירה לא אושרה עדיין. |
| [https://api.wink.travel/problems/already-consumed](https://api.wink.travel/problems/already-consumed) | האתגר או הוכחת התשלום כבר נוצלו בניסיון שעשוי להיות מוצלח. זה לבדו אינו מאשר את ההזמנה. |

שניהם משמעותם **נסו שוב את אותו תשלום; אל תשלמו עבור הצעה חדשה**. הכתובות מזהות ומתעדות את הבעיה; אינן נקודות קצה לתשלום או סקר. נסו שוב `POST /api/mpp/booking`, והשתמשו ב-`type` של הבעיה במקום ב-`detail` החופשי כדי להחליט מה לעשות. ראו את [הפניה לסוגי בעיות](https://api.wink.travel/problems) לכל בעיות התשלום של Wink.

פסק זמן, תגובה אבודה או שגיאת שרת לאחר שליחת התשלום יכולים גם להשאיר את התוצאה לא ידועה. נסו שוב את בקשת התשלום. אם התוצאה נשארת לא ברורה, פנו לתמיכה עם מזהה ההצעה לפני התחלת תשלום נוסף.
