## המלצה על מלון אינה הזמנה שלו

רוב "מסעות AI" היום נעצרים בהמלצה. עוזר מציע שלושה מלונות, ואז מעביר את המטייל לאתר או OTA כדי לבצע את ההזמנה בפועל. החוט נקטע, המחיר עשוי שלא להיות ניתן להזמנה, ואף אחד לא שומר על הקשר למקור.

**סוכן AI** שונה מתשובת AI. סוכן לא רק מתאר מלון — הוא פועל: בודק זמינות חיה, מרכיב הזמנה, מקבל תשלום, ויכול להגיב כשמשהו משתנה. כדי שזה יקרה בבטחה, הסוכן צריך יותר מטקסט. הוא צריך נתונים מובנים, עדכניים וניתנים להזמנה ושכבת עסקה שהוא יכול לקרוא לה.

זו ההבדל בין [גילוי AI](/he/resources/ai-discovery-hotels/), שעוסק בלהיות **נמצא ומובן**, לבין מסחר סוכני, שעוסק בלהיות **מבוצע**.

## מה סוכן צריך לפני שהוא יכול לבצע עסקה

הזמנת מלון היא אירוע מסחרי אמיתי: החדר הנכון, המחיר הנכון, זמינות אמיתית, מדיניות, תשלום ואישור שמתעדכן חזרה למלון. סוכן יכול להשלים זאת רק אם כל חלק זמין כפעולה שניתן לקרוא לה.

| הסוכן צריך | למה זה חשוב |
|---|---|
| מלאי מובנה וחי | נתונים שנגרפו מהרשת מתיישנים; סוכן צריך מלאי עדכני הנשלט על ידי המלון. |
| מחירים וזמינות בזמן אמת | המחיר שהסוכן מצטט חייב להיות ניתן להזמנה באותו רגע. |
| פעולה של הזמנה | יצירת ההזמנה חייבת להיות קריאת API אמיתית, לא העברה לטופס אינטרנט. |
| תשלום | הסוכן (או המטייל דרכו) חייב להיות מסוגל לשלם, עם יישום לוגיקת מדיניות. |
| שיוך | המקור, הקמפיין או הסוכן שיצר את ההזמנה צריכים להישאר מחוברים. |
| אירועים | הסוכן צריך להיות מסוגל להגיב לאישורים, שינויים, ביטולים והחזרים. |

ללא אלה, סוכן יכול להמליץ — אבל לא להזמין.

## איך סוכן AI מזמין מלון ב-Wink

Wink היא API-first: כל תכונת פלטפורמה ניתנת לקריאה מבחוץ, ושרת MCP מתארח חושף את חוזי ה-API החיים לסוכנים. זרימת סוכן טיפוסית:

### 1 — התחבר וקרא את החוזים החיים

הסוכן מתחבר לשרת MCP המתארח ומשתמש ב-`api_search` ו-`docs_search` כדי למצוא את הפעולות הנכונות ולקרוא את סכימות הבקשה/תגובה האמיתיות — בלי לנחש נקודות קצה, בלי מסמכים מיושנים.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — חפש מלאי שניתן להזמין

הסוכן מחפש מלאי הנשלט על ידי המלון, כולל חיפוש מרחבי גיאוגרפי, וקורא מחירים וזמינות חיים בערוצי ניהול מחוברים.

### 3 — צור את ההזמנה

יצירת ההזמנה היא פעולה ב-REST API. הסוכן מרכיב את החדר, המחיר, התאריכים והאורחים, ויוצר את ההזמנה דרך ה-API.

### 4 — קבל תשלום ואשר

[Booking Engine](/he/products/booking-engine/) מממש את העסקה — תשלום, קופה (Wink הוא הסוחר הרשום), לוגיקת מדיניות ביטול, אישור וסנכרון ההזמנה למערכת PMS או מנהל ערוצים מחוברים. שיוך המקור והשותף נשמרים דרך ההזמנה.

### 5 — הגיב לאירועים

הסוכן יכול להירשם ל-`booking.created` ולאירועי webhook אחרים כדי ליישב, להודיע למטייל, או להפעיל פעולות המשך.

העיקרון: **הסוכן יוצר או מנתב כוונה; Booking Engine נשאר שכבת המימוש מתחת לכל העברה.**

## חיפוש AI לעומת סוכני AI

הם פותרים משימות שונות, ומלון צריך להיות מוכן לשניהם.

| | חיפוש AI / מנועי תשובות | סוכני AI |
|---|---|---|
| מטרה של המטייל | למצוא ולהשוות מלונות | להזמין ולנהל שהייה |
| מה המלון צריך | [תוכן מובנה וניתן לזחילה](/he/resources/hotel-content-answer-engines/) | API חי, מחירים, הזמנה, תשלום |
| מצב סופי | המלצה | הזמנה מאושרת |
| ממשק Wink | מלאי נקי + תוכן מוכן לתשובות | REST API, שרת MCP, Booking Engine |

[גילוי AI למלונות](/he/resources/ai-discovery-hotels/) מכסה את צד החיפוש; מדריך זה מכסה את צד העסקה.

## מי בונה סוכנים למסחר מלונאי

מסחר נסיעות סוכני אינו רק עוזרים לצרכן. אותה תשתית מפעילה:

- **עוזרי נסיעות לצרכן** שמחפשים, מזמינים ומנהלים שהייה מקצה לקצה.
- **סוכני בנק, נאמנות וסופר-אפליקציות** שמשלבים הזמנת מלונות בתוך חוויית לקוח קיימת.
- **אוטומציות שותפים ויוצרים** שמגלות מלונות זכאים, בונות נכסים ושומרות על שיוך מחובר — מרוויחות עמלה ברירת מחדל של 10% על הזמנות מאושרות.
- **עוזרי צוות במלון** שעוזרים לצוותים ליצור תוכן ולנתח ביצועים ב-[Extranet](/he/products/extranet/), [Social](/he/products/social/) ו-[Studio](/he/products/studio/), בעוד המלון שומר על הכללים.

## לאן זה מתפתח

היכולות שלמעלה זמינות היום דרך REST API ושרת MCP. הכיוון הוא מסחר עמוק יותר יליד לסוכן: פרימיטיבים עשירים להזמנה מול סוכן, זהות וסמכות סוכן לביצוע עסקאות בשם המטייל, וסוכנים שמשתתפים כמקורות שיוך ומרוויחים ברשת השותפים. הקו המנחה הוא עקבי — **תשתית מסחר נסיעות לסוכני AI**, עם Booking Engine שמממש מתחת.

## טעויות נפוצות

- **לטפל בגילוי AI וסוכני AI כפרויקט אחד.** האחד הוא תוכן ומבנה; השני הוא API ומימוש. צריך את שניהם.
- **לתת לסוכנים לצטט מחירים שהם לא יכולים להזמין.** הציטוטים חייבים להגיע ממחירים וזמינות חיים, לא מדפי אינטרנט שנגרפו.
- **לשחרר את השיוך בהעברה.** אם סוכן יוצר ביקוש, ההזמנה צריכה להישאר מחוברת למקור.
- **דלג על שכבת המימוש.** תשובה אינה הזמנה עד שהקופה, התשלום והאישור מתבצעים בפועל.
