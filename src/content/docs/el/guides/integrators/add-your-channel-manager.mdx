Αυτός ο οδηγός καθοδηγεί τους προγραμματιστές channel manager και PMS σε όλη τη διαδικασία ενσωμάτωσης με το Wink — από τη δημιουργία των λογαριασμών σας μέχρι τη χαρτογράφηση του αποθέματος και τη διεξαγωγή του πρώτου σας ολοκληρωμένου τεστ.

## Περιβάλλοντα

Το Channel Manager (Integrations) API είναι διαθέσιμο σε δύο περιβάλλοντα. Χρησιμοποιήστε το staging για όλη την ανάπτυξη και πιστοποίηση· μεταβείτε σε παραγωγή μόνο κατά την έναρξη λειτουργίας.

| Περιβάλλον | Βασικό URL |
| ----------- | -------- |
| Παραγωγή    | https://integrations.wink.travel |
| Staging     | https://staging-integrations.wink.travel |

## Αναφορά API

Το Channel Manager API ακολουθεί τα πρότυπα πρωτοκόλλου OTA (SOAP/XML) για συμβατότητα με υπάρχοντα συστήματα φιλοξενίας. Ξεκινήστε με την ανασκόπηση της τεκμηρίωσης των endpoints συνεργατών:

<LinkButton href="/el/partner-api/partner/">
  Channel Manager API — Endpoints συνεργατών
</LinkButton>

## Βήματα ενσωμάτωσης

<Steps>
1. **Δημιουργήστε έναν λογαριασμό χρήστη Wink**

   Εγγραφείτε στο [staging-app.wink.travel](https://staging-app.wink.travel). Όλα τα παρακάτω βήματα χρησιμοποιούν το staging — θα επαναλάβετε ολόκληρη τη διαδικασία στην παραγωγή πριν την έναρξη λειτουργίας.

2. **Δημιουργήστε τον λογαριασμό σας Affiliate / Channel Manager**

   Υπό τον νέο σας χρήστη, δημιουργήστε έναν λογαριασμό και επιλέξτε τον τύπο λογαριασμού **Affiliate / Channel Manager**. Αυτός είναι ο λογαριασμός με τον οποίο θα αυθεντικοποιείται η ενσωμάτωσή σας.

3. **Καταχωρίστε μια εφαρμογή και δημιουργήστε το πρώτο σας token**

   Δημιουργήστε μια [Εφαρμογή](/el/account/applications) και συνδέστε την με τον λογαριασμό channel manager από το βήμα 2. Επιλέξτε **MACHINE_2_MACHINE** ως τύπο πελάτη — πρόκειται για ενσωμάτωση server-to-server χωρίς τελικό χρήστη για ανακατεύθυνση. Αντιγράψτε αμέσως το **Client ID** και το **Secret Key**· το μυστικό κλειδί εμφανίζεται μόνο μία φορά και δεν μπορεί να ανακτηθεί ξανά.

   Η εφαρμογή δημιουργεί το bearer token που κάθε κλήση σε αυτόν τον οδηγό μεταφέρει ως `Authorization: Bearer <access_token>`. Ανταλλάξτε τα διαπιστευτήριά σας για ένα token χρησιμοποιώντας το grant `client_credentials` στο `https://staging-iam.wink.travel/oauth2/token`, ζητώντας τα scopes `integrations.read integrations.write`. Κάντε το πριν προχωρήσετε — δεν μπορείτε να αναζητήσετε αναγνωριστικά λογαριασμών ή να φτάσετε σε οποιοδήποτε endpoint Channel Manager χωρίς token. Δείτε [Authentication](/el/developers/authentication) για ολόκληρη τη ροή, τον host παραγωγής και τον πλήρη κατάλογο scopes.

4. **Δημιουργήστε έναν λογαριασμό Ξενοδοχείου**

   Υπό τον ίδιο χρήστη, δημιουργήστε δεύτερο λογαριασμό και επιλέξτε τον τύπο λογαριασμού **Hotel**. Αυτό σας δίνει ένα ακίνητο που μπορείτε να χρησιμοποιήσετε για δοκιμές χωρίς να εμπλέκεται πραγματικό ξενοδοχείο.

5. **Επιβεβαιώστε ότι και οι δύο λογαριασμοί έχουν εγκριθεί**

   Κανένας λογαριασμός δεν μπορεί να χρησιμοποιηθεί μέχρι να εγκριθεί: ένας μη εγκεκριμένος λογαριασμός channel manager δεν εμφανίζεται στη λίστα channel manager κανενός ξενοδοχείου, και ένα μη εγκεκριμένο ξενοδοχείο δεν επιστρέφεται από το API.

   - **Staging** — η έγκριση είναι αυτόματη. Και οι δύο λογαριασμοί είναι διαθέσιμοι αμέσως μετά τη δημιουργία τους, χωρίς να χρειάζεται να κάνετε αίτηση.
   - **Παραγωγή** — η έγκριση είναι χειροκίνητη. Στείλτε στο contact των ενσωματώσεων Wink τα ονόματα και των δύο λογαριασμών και τον χρήστη υπό τον οποίο βρίσκονται, και περιμένετε επιβεβαίωση πριν συνεχίσετε.

6. **Συνδέστε τους δύο λογαριασμούς**

   Συνδεθείτε στον λογαριασμό Ξενοδοχείου και μεταβείτε στο **Extranet → Distribution → Channel Manager**. Επιλέξτε τον λογαριασμό channel manager από τη λίστα — αυτό συνδέει το ακίνητο με την ενσωμάτωσή σας. Αν ο λογαριασμός σας δεν είναι στη λίστα, δεν έχει εγκριθεί ακόμα· δείτε το βήμα 5.

7. **Δημιουργήστε έναν βασικό τύπο δωματίου και ένα πλάνο τιμών**

   Μέσα στον λογαριασμό Ξενοδοχείου, δημιουργήστε τουλάχιστον έναν τύπο δωματίου και ένα πλάνο τιμών. Αυτά απαιτούνται πριν η ενσωμάτωσή σας μπορεί να στείλει ενημερώσεις τιμών και διαθεσιμότητας ή να τραβήξει κρατήσεις.

8. **Χαρτογραφήστε και δοκιμάστε**

   Στο δικό σας σύστημα, χαρτογραφήστε τα αναγνωριστικά τύπου δωματίου και πλάνου τιμών που επιστρέφει το API. Στείλτε μια ενημέρωση τιμής και μια ενημέρωση διαθεσιμότητας, κάντε μια δοκιμαστική κράτηση και επιβεβαιώστε ότι το endpoint ανάκτησης κρατήσεων την επιστρέφει σωστά.
</Steps>

:::note
Επαναλάβετε όλα τα παραπάνω βήματα στην παραγωγή πριν την έναρξη λειτουργίας, συμπεριλαμβανομένης της καταχώρησης ξεχωριστής εφαρμογής παραγωγής — τα διαπιστευτήρια staging δεν λειτουργούν στην παραγωγή. Προβλέψτε χρόνο για την ανασκόπηση από το Wink στο βήμα 5 — σε αντίθεση με το staging, οι λογαριασμοί παραγωγής δεν εγκρίνονται αυτόματα. Η ομάδα Wink θα μεταφέρει οποιαδήποτε ξενοδοχεία ήδη χρησιμοποιούν τον channel manager σας στον νέο λογαριασμό παραγωγής.
:::

## Εύρεση των αναγνωριστικών λογαριασμού σας

Κάθε διαδρομή Channel Manager API είναι scoped στον δικό σας λογαριασμό:

```
/api/managing-entity/{managingEntityIdentifier}/channel-manager/...
```

Το `{managingEntityIdentifier}` είναι το αναγνωριστικό λογαριασμού (UUID) του **λογαριασμού channel manager σας** — όχι του ξενοδοχείου. Ανακτήστε το, μαζί με το ID και την τρέχουσα κατάσταση κάθε άλλου λογαριασμού που κατέχει ο χρήστης σας, από το Platform API:

```bash
curl -s -X GET \
  "https://staging-api.wink.travel/api/managing-entity/list" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Η απάντηση είναι ένας πίνακας με τους λογαριασμούς που κατέχετε:

```json
[
  {
    "id": "3f1c8e42-7b90-4d55-a1e2-6c8d09b4f731",
    "type": "CHANNEL_MANAGER",
    "name": "Ο Channel Manager σας",
    "status": "ACTIVE"
  },
  {
    "id": "d5b8a3c2-9e6f-4a1b-8d34-7c2e1f0a5b69",
    "type": "HOTEL",
    "name": "Το δοκιμαστικό σας ακίνητο",
    "urlName": "your-test-property",
    "status": "ACTIVE"
  }
]
```

- Το `id` της εγγραφής channel manager είναι το **`{managingEntityIdentifier}`** σας.
- Το `id` της εγγραφής `HOTEL` είναι το **`{propertyIdentifier}`** σας.
- Το `status` είναι όπου επιβεβαιώνετε ότι κάθε λογαριασμός έχει εγκριθεί — πιο χρήσιμο στην παραγωγή, όπου η έγκριση είναι χειροκίνητη. Το **ξενοδοχείο** πρέπει να έχει κατάσταση `ACTIVE` πριν μπορεί να γίνει κράτηση ή να είναι ορατό στο Channel Manager API. Ο λογαριασμός **channel manager** συνεχίζει να έχει κατάσταση `PENDING_APPROVAL` μέχρι να περάσετε την [Πιστοποίηση](#certification)· αυτό είναι αναμενόμενο και δεν εμποδίζει την ανάπτυξη.

:::caution
Αυτή η αναζήτηση εκτελείται στο **Platform API** (`https://staging-api.wink.travel` στο staging,
`https://api.wink.travel` στην παραγωγή), όχι στους hosts Channel Manager API που αναφέρονται στο
[Περιβάλλοντα](#περιβάλλοντα). Χρησιμοποιήστε το ίδιο access token — εκδίδεται ανά χρήστη, όχι ανά API.
:::

## Πιστοποίηση

Η πιστοποίηση είναι ο τρόπος με τον οποίο αποδεικνύετε — και το Wink επιβεβαιώνει — ότι η ενσωμάτωσή σας χαρτογραφεί σωστά το απόθεμα, στέλνει τιμές και διαθεσιμότητα, και λαμβάνει κρατήσεις ολοκληρωμένα. Έχει σχεδιαστεί να είναι αυτοεξυπηρετούμενη: εσείς εκτελείτε κάθε βήμα από το δικό σας σύστημα και υποβάλλετε ένα ενιαίο πακέτο αποδείξεων στο τέλος. Το Wink εξετάζει το πακέτο και, αν περάσετε, προωθεί τον λογαριασμό σας Affiliate / Channel Manager από **PENDING_APPROVAL** σε **ACTIVE**.

Η πιστοποίηση εκτελείται εξ ολοκλήρου στο περιβάλλον staging
(`https://staging-integrations.wink.travel`). Τίποτα σε αυτή την ενότητα δεν αφορά την παραγωγή.

### Τι θα αποδείξετε

<Steps>
1. **Αυθεντικοποίηση.** Ο OAuth2 client σας μπορεί να λάβει access token και να καλέσει επιτυχώς το
   endpoint `/ping` για τον λογαριασμό Affiliate / Channel Manager σας.

2. **Χαρτογράφηση αποθέματος.** Μπορείτε να καταγράψετε τα ξενοδοχεία που συνδέονται με τον λογαριασμό σας, να ανακτήσετε την κύρια τιμή (συνδυασμός τύπου δωματίου × πλάνου τιμών) που έχετε ρυθμίσει, και να εντοπίσετε σωστά το `masterRateIdentifier` που θα στοχεύει το σύστημά σας.

3. **Αποστολή τιμών & διαθεσιμότητας.** Μπορείτε να ενημερώσετε ανεξάρτητα και τις επτά ημέρες μιας εβδομάδας πιστοποίησης — με διαφορετικό συνδυασμό ποσού, ποσότητας, σημαιών κλεισίματος κατά άφιξη / αναχώρηση, και ελάχιστης/μέγιστης διάρκειας διαμονής σε κάθε ημέρα — και να διαβάσετε τις ακριβείς τιμές πίσω από το Wink.

4. **Ανάκτηση κράτησης.** Μπορείτε να ανακτήσετε μια πραγματική κράτηση staging που έγινε για το δοκιμαστικό σας ακίνητο, να την εμφανίσετε στο δικό σας PMS/CM UI με το σωστό δωμάτιο, επισκέπτη και σύνολο, και στη συνέχεια να αντικατοπτρίσετε μια ακύρωση μόλις το Wink σημάνει την κράτηση ως ακυρωμένη.
</Steps>

### Προαπαιτούμενα

Πριν ξεκινήσετε την πιστοποίηση, ολοκληρώστε τα βήματα 1–7 των [Βημάτων ενσωμάτωσης](#integration-steps) ώστε να έχετε:

- Έναν χρήστη Wink στο staging με λογαριασμό **Affiliate / Channel Manager** και λογαριασμό **Hotel**
  συνδεδεμένους μεταξύ τους (Extranet → Distribution → Channel Manager). Οι λογαριασμοί staging εγκρίνονται αυτόματα, οπότε δεν χρειάζεται να κάνετε αίτηση.
- Τουλάχιστον έναν **τύπο δωματίου** και ένα **πλάνο τιμών** δημιουργημένα μέσα στον λογαριασμό Ξενοδοχείου. Δημοσιεύστε το ξενοδοχείο ώστε να είναι διαθέσιμο για κράτηση στο `https://staging-book.wink.travel/hotel/<your-slug>`.
- Μια καταχωρημένη εφαρμογή υπό τον λογαριασμό Affiliate / Channel Manager με **Client ID**,
  **Secret Key**, και τα scopes `integrations.read integrations.write`
  (δείτε [Authentication](/el/developers/authentication)).
- Το **`managingEntityIdentifier`** του λογαριασμού Affiliate / Channel Manager και το
  **`propertyIdentifier`** του λογαριασμού Ξενοδοχείου (και τα δύο UUID — δείτε
  [Εύρεση των αναγνωριστικών λογαριασμού σας](#finding-your-account-identifiers)).

### Κοινές συμβάσεις αιτήσεων

Κάθε αίτηση σε αυτή την ενότητα χρησιμοποιεί αυτές τις κεφαλίδες:

```http
Authorization: Bearer <access_token>
Wink-Version: 2.0
Accept: application/json
```

- Το `<access_token>` προέρχεται από το grant `client_credentials` στο
  `https://staging-iam.wink.travel/oauth2/token` — δείτε [Authentication](/el/developers/authentication#staging).
- Η κεφαλίδα `Wink-Version` είναι υποχρεωτική· η παράλειψή της δεν θα δρομολογήσει στο v2 JSON API.
- Το `Content-Type: application/json` προστίθεται σε αιτήσεις `PUT` που φέρουν σώμα.

Σε όλα τα παραδείγματα παρακάτω, οι θέσεις κρατήσεων αντιστοιχούν στις τιμές που συγκεντρώσατε στα
[Προαπαιτούμενα](#prerequisites):

| Θέση κράτησης | Σημασία |
|---|---|
| `{managingEntityIdentifier}` | Το ID του λογαριασμού Affiliate / Channel Manager (UUID) — δείτε [Εύρεση των αναγνωριστικών λογαριασμού σας](#finding-your-account-identifiers). |
| `{propertyIdentifier}`       | Το ID του λογαριασμού Ξενοδοχείου (ακινήτου) που συνδέσατε με τον λογαριασμό CM. |
| `{masterRateIdentifier}`     | Η κύρια τιμή (συνδυασμός τύπου δωματίου × πλάνου τιμών) που θα πιστοποιήσετε. |
| `{bookingIdentifier}`        | Το ID της κράτησης staging που επιστράφηκε από την κλήση λίστας κρατήσεων. |

### Βήμα A — Ping

Επιβεβαιώστε ότι τα διαπιστευτήριά σας αντιστοιχούν στον λογαριασμό Affiliate / Channel Manager που περιμένετε.

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/ping" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Αναμενόμενη απάντηση:

```json
{
  "apiVersion": "2.0",
  "name": "Το όνομα του λογαριασμού Channel Manager σας",
  "status": "PENDING_APPROVAL"
}
```

Μια απάντηση **200** με ταιριαστό `name` είναι το σήμα ότι η αυθεντικοποίηση και η επίλυση λογαριασμού είναι σωστές. Το `status` θα διαβάζει `PENDING_APPROVAL` μέχρι το Wink να σας πιστοποιήσει.

### Βήμα B — Λίστα ακινήτων

Ανακτήστε τη σελιδοποιημένη λίστα ξενοδοχείων συνδεδεμένων με τον λογαριασμό σας και επιβεβαιώστε ότι το δοκιμαστικό σας ακίνητο είναι παρόν.

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/list?page=0&size=25" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Η απάντηση είναι μια Spring `Page` με εγγραφές `ChannelManagerProperty`. Εντοπίστε την εγγραφή της οποίας το `identifier` ταιριάζει με το `{propertyIdentifier}` σας και καταγράψτε το `currencyCode` της — θα το χρειαστείτε για την ερμηνεία των ενημερώσεων τιμών στο [Βήμα D](#step-d--load-the-certification-week).

:::caution
Μια κενή λίστα είναι ένδειξη ρύθμισης, όχι κακοσχηματισμένο αίτημα. Ένα ξενοδοχείο επιστρέφεται εδώ μόνο όταν είναι **`ACTIVE`** *και* έχει ανατεθεί στον λογαριασμό channel manager σας μέσω Extranet → Distribution → Channel Manager. Ελέγξτε και τα δύο με `GET /api/managing-entity/list` (δείτε [Εύρεση των αναγνωριστικών λογαριασμού σας](#finding-your-account-identifiers)) πριν προχωρήσετε σε περαιτέρω αποσφαλμάτωση. Στην παραγωγή, προσθέστε τρίτο λόγο: το ξενοδοχείο είναι αόρατο εδώ μέχρι το Wink να το εγκρίνει.
:::

### Βήμα C — Ανάκτηση κύριων τιμών

Ανακτήστε το ακίνητο μαζί με κάθε κύρια τιμή (συνδυασμός τύπου δωματίου × πλάνου τιμών) που δημοσιεύει. Επιλέξτε αυτή που σκοπεύετε να πιστοποιήσετε και καταγράψτε το `identifier` της ως το `{masterRateIdentifier}` σας.

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Το περιτύλιγμα της απάντησης είναι `PropertyWithRoomRateList`: ένα μπλοκ `property` συν έναν πίνακα `rooms` με εγγραφές `PropertyRoomRate`. Κάθε εγγραφή εμφανίζει τον τύπο δωματίου, το πλάνο τιμών, τα όρια πληρότητας, τη βασική τιμή και τους τροποποιητές τιμών που θα διατηρήσετε όταν στέλνετε ημερήσιες τιμές.

:::caution
Πιστοποιηθείτε έναντι μιας μόνο κύριας τιμής για ολόκληρη τη διαδικασία πιστοποίησης. Η χαρτογράφηση επιπλέον τύπων δωματίων και πλάνων τιμών αναμένεται στην παραγωγή, αλλά το πακέτο αποδείξεων χρειάζεται να δείξει μόνο μία κύρια τιμή που χρησιμοποιείται ολοκληρωμένα.
:::

### Βήμα D — Φορτώστε την εβδομάδα πιστοποίησης

Φορτώστε ένα **επταήμερο ημερολόγιο τιμών** που καλύπτει τις πρώτες επτά ημερολογιακές ημέρες του μήνα **μετά** τον μήνα που ξεκινάτε την πιστοποίηση. Για παράδειγμα, αν ξεκινήσετε την πιστοποίηση στις 21 Αυγούστου, στοχεύστε από 1 Σεπτεμβρίου έως 7 Σεπτεμβρίου.

Θα στείλετε **επτά ξεχωριστές κλήσεις `PUT`** — μία ανά ημέρα — όπου `startDate == endDate`. Κάθε ημέρα φέρει έναν σκόπιμα διαφορετικό συνδυασμό ποσού, ποσότητας, σημαιών κλεισίματος κατά άφιξη / αναχώρηση, και ορίων ελάχιστης/μέγιστης διάρκειας διαμονής ώστε κάθε πεδίο που μπορεί να γραφτεί να δοκιμαστεί τουλάχιστον μία φορά. Οι τιμές είναι στο νόμισμα του ακινήτου (καταγεγραμμένο στο Βήμα B)· παραλείψτε το `currencyCode` και θα οριστεί σωστά από προεπιλογή.

| Ημέρα | Ποσό | Ποσότητα | closedOnArrival | closedOnDeparture | minLengthOfStay | maxLengthOfStay | Τι αποδεικνύει |
|-------|-------|----------|-----------------|-------------------|-----------------|-----------------|----------------|
| 1     | 100.00 | 5        | false           | false             | 1               | 30              | Βασική ημέρα. |
| 2     | 125.00 | 4        | false           | false             | 1               | 14              | Αλλαγή ποσού + ποσότητας + `maxLengthOfStay`. |
| 3     | 150.00 | 3        | **true**        | false             | 1               | 30              | Αναστροφή `closedOnArrival`. |
| 4     | 175.00 | 2        | false           | **true**          | 2               | 7               | Αναστροφή `closedOnDeparture` + πιο αυστηρό παράθυρο διαμονής. |
| 5     | 200.00 | **0**    | false           | false             | 1               | 30              | Ποσότητα εξαντλημένη. |
| 6     | 225.00 | 5        | false           | false             | **3**           | **5**           | Περιοριστικό παράθυρο διαμονής. |
| 7     | 250.00 | 1        | false           | false             | 1               | 30              | Διαθεσιμότητα τελευταίου δωματίου. |

Το σώμα του αιτήματος για την Ημέρα 1 μοιάζει με το παρακάτω. Επαναλάβετε, προσαρμόζοντας `startDate` / `endDate` / τιμές ανά σειρά, για τις Ημέρες 2 έως 7.

```bash
curl -s -X PUT \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/master-rate/{masterRateIdentifier}" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
        "startDate": "2026-09-01",
        "endDate":   "2026-09-01",
        "amount":    100.00,
        "master":    true,
        "closedOnArrival":   false,
        "closedOnDeparture": false,
        "quantity":          5,
        "minLengthOfStay":   1,
        "maxLengthOfStay":   30
      }'
```

Κάθε `PUT` απαντά με `200` και τον πίνακα ενημερωμένων εγγραφών `PropertyRate` για το εύρος που στείλατε (μία εγγραφή όταν `startDate == endDate`). Αποθηκεύστε αυτή την απάντηση — θα είναι μέρος των αποδείξεών σας.

:::note
Το `master` πρέπει να είναι `true` σε κάθε κλήση της εβδομάδας πιστοποίησης. Αυτό λέει στο Wink ότι η ενημέρωσή σας είναι πρότυπη τιμή, όχι υπερισχύουσα ανά κράτηση.
:::

### Βήμα E — Ανάγνωση της εβδομάδας πιστοποίησης

Ανακτήστε ολόκληρη την εβδομάδα με μία κλήση και επιβεβαιώστε ότι οι αποθηκευμένες τιμές κάθε ημέρας ταιριάζουν με τις τιμές που στείλατε στο Βήμα D — συμπεριλαμβανομένων των boolean σημαιών και του παραθύρου διάρκειας διαμονής.

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/master-rate/{masterRateIdentifier}?startDate=2026-09-01&endDate=2026-09-07" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Η απάντηση είναι `PropertyRoomRateWithRateList`. Ο πίνακας `rates` πρέπει να περιέχει **επτά** εγγραφές, μία ανά ημέρα, καθεμία με τα πεδία `amount`, `quantity`, `closedOnArrival`, `closedOnDeparture`, `minLengthOfStay` και `maxLengthOfStay` που φορτώσατε. Οποιαδήποτε ασυμφωνία σε οποιοδήποτε πεδίο σημαίνει ότι το αντίστοιχο `PUT` στο Βήμα D δεν εφαρμόστηκε σωστά — διορθώστε το και επαληθεύστε ξανά πριν προχωρήσετε.

### Βήμα F — Κάντε μια δοκιμαστική κράτηση

Ανοίξτε το παρακάτω URL σε πρόγραμμα περιήγησης, αντικαθιστώντας το `<your-slug>` με το slug του λογαριασμού Ξενοδοχείου που δημοσιεύσατε στα Προαπαιτούμενα:

```
https://staging-book.wink.travel/hotel/<your-slug>
```

Επιλέξτε ημερομηνίες άφιξης και αναχώρησης που εμπίπτουν πλήρως στην εβδομάδα πιστοποίησής σας, επιλέξτε τον συνδυασμό τύπου δωματίου + πλάνου τιμών που πιστοποιήσατε, και ολοκληρώστε την κράτηση. Το staging χρησιμοποιεί δοκιμαστική διαδρομή πληρωμής — δεν χρεώνεται ζωντανή κάρτα.

Μόλις εμφανιστεί η σελίδα επιβεβαίωσης, καταγράψτε τον **κωδικό κράτησης** (μορφή `WNKxxxxx`) που εμφανίζεται στον επισκέπτη.

### Βήμα G — Ανάκτηση της κράτησης

Ανακτήστε κάθε κράτηση που δημιουργήθηκε για το δοκιμαστικό σας ακίνητο μέσα σε ένα παράθυρο που καλύπτει το χρονικό σήμα της κράτησης.

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/booking/list?startDate=2026-09-01T00:00:00&endDate=2026-09-08T00:00:00" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Βρείτε την εγγραφή της οποίας το `bookingCode` ταιριάζει με τον κωδικό που καταγράψατε στο Βήμα F. Καταγράψτε το `bookingIdentifier` της. Στη συνέχεια ανακτήστε αυτή την μεμονωμένη κράτηση:

```bash
curl -s -X GET \
  "https://staging-integrations.wink.travel/api/managing-entity/{managingEntityIdentifier}/channel-manager/property/{propertyIdentifier}/booking/{bookingIdentifier}" \
  -H "Authorization: Bearer <access_token>" \
  -H "Wink-Version: 2.0" \
  -H "Accept: application/json"
```

Η απάντηση είναι `PropertyBooking`. Εισάγετέ την στο δικό σας PMS / UI channel manager και επιβεβαιώστε ότι κάθε ένα από τα παρακάτω εμφανίζεται σωστά σε έναν χειριστή:

- `bookingCode`, `bookingIdentifier`, `createdDate`
- Επισκέπτης: `firstName`, `lastName`, `email`
- `totalAmount` + `currencyCode` (το καθαρό ποσό που λαμβάνει το ξενοδοχείο για όλα τα δωμάτια)
- `paymentMethodType`, `paymentMethodStatus`, `salesChannelName`
- Κάθε εγγραφή στο `roomStays`: `guestRoomName`, `ratePlanName`, `adults`, `children`, `startDate`,
  `endDate`, και ανά δωμάτιο `amount`

Κάντε ένα στιγμιότυπο οθόνης της κράτησης όπως εμφανίζεται στο UI σας — αυτό το στιγμιότυπο είναι ένα από τα απαιτούμενα αποδεικτικά στοιχεία.

### Βήμα H — Ακυρώστε την κράτηση και επιβεβαιώστε

Ζητήστε από την ομάδα Wink να ακυρώσει την πιστοποιητική κράτηση εκ μέρους σας (ή ακυρώστε την εσείς από το Extranet του λογαριασμού Ξενοδοχείου αν έχετε αυτή την άδεια). Στη συνέχεια ανακτήστε ξανά την ίδια κράτηση με την κλήση του Βήματος G.

Επιβεβαιώστε ότι η απάντηση τώρα εμφανίζει:

- `cancelled: true`
- Ένα συμπληρωμένο χρονικό σήμα `cancelDate`
- Μια `paymentMethodStatus` που αντικατοπτρίζει τον κύκλο ζωής ακύρωσης (`CANCELLED`, `PARTIALLY_REFUNDED`,
  ή `FULLY_REFUNDED` ανάλογα με την πολιτική επιστροφής)

Εισάγετε αυτή την ενημερωμένη κράτηση στο UI σας και επιβεβαιώστε ότι η ακύρωση είναι ορατή στον χειριστή — κατάσταση, χρονικό σήμα ακύρωσης, και οποιονδήποτε δείκτη επιστροφής που υποστηρίζει το UI σας. Κάντε ένα δεύτερο στιγμιότυπο οθόνης της ακυρωμένης κράτησης στο UI σας. Αυτό είναι το τελικό αποδεικτικό στοιχείο.

### Βήμα I — Υποβάλετε το πακέτο αποδείξεων

Συγκεντρώστε τα παρακάτω σε ένα ενιαίο αρχείο (`.zip`) με όνομα
`wink-cert-<your-channel-manager-name>-<yyyy-mm-dd>.zip`:

<Steps>
1. **Αρχείο καταγραφής API.** Για κάθε αίτηση που κάνατε στα Βήματα A έως H, καταγράψτε το πλήρες
   HTTP αίτημα (μέθοδος, URL, κεφαλίδες αιτήματος με την τιμή `Authorization` αποκρυμμένη, και το
   JSON σώμα για κλήσεις `PUT`) και την πλήρη HTTP απάντηση (κωδικός κατάστασης, κεφαλίδες απάντησης, και
   JSON σώμα). Δομήστε το αρχείο καταγραφής ώστε κάθε ζεύγος αίτησης/απάντησης να είναι σαφώς επισημασμένο με το
   βήμα στο οποίο ανήκει (`step-a-ping.json`, `step-d-day-3-put.json`, `step-g-list-bookings.json`,
   κ.ο.κ.). Αποδεκτά είναι αρχεία απλού κειμένου `.http` ή ένα ενιαίο εξαγόμενο `.har`.

2. **Στιγμιότυπο UI: ενεργή κράτηση.** Το στιγμιότυπο από το Βήμα G που δείχνει την πιστοποιητική
   κράτηση στο δικό σας PMS / UI channel manager, με τον επισκέπτη, τις ημερομηνίες, τον τύπο δωματίου, το πλάνο τιμών και το σύνολο ευανάγνωστα.

3. **Στιγμιότυπο UI: ακυρωμένη κράτηση.** Το στιγμιότυπο από το Βήμα H που δείχνει την ίδια κράτηση στο
   UI σας μετά την ακύρωση, με την κατάσταση ακύρωσης και το χρονικό σήμα ευανάγνωστα.

4. **Περίληψη πιστοποίησης.** Ένα σύντομο `README.md` μέσα στο αρχείο που αναφέρει:
   - Το όνομα και την έκδοση του channel manager / PMS σας.
   - Τα `managingEntityIdentifier`, `propertyIdentifier`, `masterRateIdentifier`, και
     `bookingIdentifier` που χρησιμοποιήσατε.
   - Το slug του ξενοδοχείου staging (το `<your-slug>` στο `https://staging-book.wink.travel/hotel/<your-slug>`).
   - Το εύρος ημερομηνιών της εβδομάδας πιστοποίησης (Ημέρα 1 → Ημέρα 7 σε ISO-8601).
   - Το όνομα και το email του μηχανικού που εκτέλεσε την πιστοποίηση.
</Steps>

Στείλτε το αρχείο στον contact ενσωματώσεων Wink. Το Wink θα το εξετάσει, θα ακολουθήσει για τυχόν
διαφορές, και — αν περάσετε — θα αλλάξει την κατάσταση του λογαριασμού Affiliate / Channel Manager σας από
`PENDING_APPROVAL` σε `ACTIVE`. Η ενσωμάτωσή σας τότε είναι επιλέξιμη για ένταξη στην παραγωγή.

:::tip
Αυτοματοποιήστε την καταγραφή αρχείου. Οι επτά κλήσεις `PUT` στο Βήμα D και η ανάγνωση στο Βήμα E είναι
η πιο συχνή πηγή αποτυχιών πιστοποίησης — ένας διαδραστικός HTTP client που αποθηκεύει κάθε
αίτηση και απάντηση καθώς εκτελείται θα σας γλιτώσει από πλήρη επανάληψη αν μια τιμή είναι λάθος κατά δεκαδικό.
:::

## Ειδοποιήσεις Webhook

Μπορείτε να εγγραφείτε σε γεγονότα webhook του channel manager για να λαμβάνετε ειδοποιήσεις σε πραγματικό χρόνο:

- `channel-manager.update.rate` — Λήψη ενημέρωσης τιμής.
- `channel-manager.update.availability` — Λήψη ενημέρωσης διαθεσιμότητας.
- `channel-manager.update` — Γενική ενημέρωση channel manager.

Δείτε τον [Κατάλογο Γεγονότων Webhook](/el/developers/webhook-events#channel-manager-events) για λεπτομέρειες.
