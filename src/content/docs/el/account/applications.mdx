Οι εφαρμογές σας δίνουν πρόσβαση σε όλες τις λειτουργίες του Wink ως προγραμματιστής. Μπορείτε να έχετε πρόσβαση σε όλα τα ίδια δεδομένα και ακόμη να επεκτείνετε τις λειτουργίες του Wink.
Μπορείτε να επιλέξετε να χρησιμοποιήσετε τον OAuth2 server του Wink για να αυθεντικοποιήσετε τον ταξιδιωτικό σας ιστότοπο με τον ίδιο τρόπο που θα χρησιμοποιούσατε το Google ή το Facebook.
Με αυτόν τον τρόπο μπορείτε να επεκτείνετε τις λειτουργίες του Wink στον δικό σας ιστότοπο ή εφαρμογή.

:::note
Η πρώτη σας εφαρμογή έχει ήδη δημιουργηθεί όταν [δημιουργήσατε νέο λογαριασμό](/el/portal/create-account). Χρησιμοποιούμε αυτήν την εφαρμογή για ορισμένα σενάρια κρατήσεων.

Δεν μπορείτε να επαναχρησιμοποιήσετε αυτήν την εφαρμογή. Παρακαλούμε δημιουργήστε νέες εφαρμογές ανάλογα με τις ανάγκες σας.
:::

## Δημιουργία εφαρμογής

Επειδή δεν έχετε πρόσβαση στο `secret key` της εφαρμογής που δημιουργήσαμε για εσάς, θα χρειαστεί να δημιουργήσετε τη δική σας.
Μπορείτε να δημιουργήσετε μια εφαρμογή εδώ χωρίς να ρυθμίσετε πρώτα μια ιδιοκτησία ή εταιρεία — δεν είναι δεμένη
σε κάποιον συγκεκριμένο λογαριασμό.

### Τύποι πελατών

Κατά τη δημιουργία μιας εφαρμογής, επιλέγετε έναν τύπο πελάτη που καθορίζει πώς η εφαρμογή αυθεντικοποιείται.
Αυτό δεν μπορεί να αλλάξει αργότερα — αν χρειάζεστε διαφορετικό τύπο, δημιουργήστε μια νέα εφαρμογή.

- **Web application** — Μια εφαρμογή που αποδίδεται από διακομιστή και μπορεί να κρατήσει με ασφάλεια ένα client secret (authorization code flow).
- **Single-page app (SPA)** — Μια εφαρμογή προγράμματος περιήγησης χωρίς backend· χρησιμοποιεί PKCE, χωρίς client secret.
- **Mobile app** — Μια εγγενής εφαρμογή iOS/Android· χρησιμοποιεί PKCE με περιστρεφόμενα refresh tokens.
- **Machine-to-machine** — Μια υπηρεσία backend που ενεργεί ως ο εαυτός της (client credentials)· χωρίς σύνδεση χρήστη.

Ακολουθούν τα βήματα για τη δημιουργία μιας εφαρμογής:

<Steps>
1. Από τη σελίδα εφαρμογών, κάντε κλικ στο κουμπί `Create new application`.
2. ***Όνομα*** Δώστε ένα όνομα στην εφαρμογή σας. *π.χ. Cool App*
3. **Τύπος πελάτη** Επιλέξτε τον τύπο που ταιριάζει με τον τρόπο που αυθεντικοποιείται η εφαρμογή σας — δείτε τους [Τύπους πελατών](#client-types) παραπάνω.
4. **Redirect URIs** Απαιτείται τουλάχιστον ένα redirect URI. Χρησιμοποιείται για την επικύρωση του domain ανακατεύθυνσης μετά από επιτυχή αυθεντικοποίηση. Δεν χρησιμοποιείται για εφαρμογές Machine-to-machine. *π.χ. https://www.cool-site.com*
5. **Post-logout redirect URIs** *(Προαιρετικό)* URLs όπου οι χρήστες μπορούν να ανακατευθυνθούν μετά την αποσύνδεση. Αφήστε κενό για να επαναχρησιμοποιηθούν τα redirect URIs παραπάνω.
6. **Scopes** Επιλέξτε τι μπορεί να έχει πρόσβαση αυτή η εφαρμογή εκ μέρους σας — δείτε [Επιλογή scopes](#choosing-scopes) παρακάτω.
7. Κάντε κλικ στο κουμπί `Create application` για να συνεχίσετε.
</Steps>

Ανακατευθύνεστε πίσω στη λίστα των εφαρμογών σας και εμφανίζεται ένα παράθυρο διαλόγου μόνο μία φορά με το νέο Client ID
και Client secret. Αντιγράψτε το secret τώρα και αποθηκεύστε το κάπου με ασφάλεια — δεν εμφανίζεται ξανά και
δεν υπάρχει τρόπος να το ανακτήσετε αργότερα (μόνο να το [περιστρέψετε](#rotate-credentials) για νέο).

## Επιλογή scopes

Κάθε εφαρμογή πάντα φέρει τα **Sign-in (OpenID Connect)** scopes (`openid`, `profile`,
`email`, `offline_access`) — αυτά επιβεβαιώνουν την ταυτότητα του χρήστη και τον κρατούν συνδεδεμένο, γι’ αυτό εμφανίζονται
επιλεγμένα και κλειδωμένα· δεν είναι επιλογή.

Όλα τα υπόλοιπα είναι προαιρετικά. Τα υπόλοιπα scopes ομαδοποιούνται στις ίδιες λειτουργικές ενότητες
που τεκμηριώνονται στα [Scopes](/el/developers/authentication#scopes) — Λογαριασμός, Απόθεμα & τιμές, Κρατήσεις,
Μάρκετινγκ & προωθήσεις, Περιεχόμενο ιδιοκτησίας, Αναλύσεις & αναφορές, Ενσωματώσεις διαχειριστή καναλιών,
Πληρωμές, και Λογιστική & καθολικό — κάθε μία με περιγραφή σε απλή γλώσσα για το τι ξεκλειδώνει. Χρησιμοποιήστε
τους συνδέσμους `All` / `None` πάνω από τη λίστα για να επιλέξετε ή να αποεπιλέξετε όλα τα προαιρετικά scopes ταυτόχρονα.

:::note
**Πληρωμές** και **Λογιστική & καθολικό** χαρακτηρίζονται ως **Ευαίσθητα** επειδή προστατεύουν τη μετακίνηση χρημάτων — παραχωρήστε τα μόνο σε εφαρμογές που χρειάζονται συγκεκριμένα πρόσβαση σε πληρωμές ή το καθολικό.
:::

Δύο οικογένειες scopes δεν προσφέρονται σκόπιμα σε αυτή τη φόρμα:

- **`mcp.*`** — Πρόσβαση AI-agent στο [Model Context Protocol](/el/developers/mcp) transport, που παρέχεται ξεχωριστά και μόνο για πελάτες machine-to-machine.
- **Scopes επιπέδου διαχειριστή** (`administrator.*`) — πρόσβαση σε επίπεδο πλατφόρμας που δεν παραχωρείται ανά εφαρμογή.

Μόλις δημιουργηθεί μια εφαρμογή, τόσο αυτή η καρτέλα όσο και τα [Consented Apps](/el/account/apps) εμφανίζουν τα παραχωρημένα scopes
ομαδοποιημένα ανά ενότητα (π.χ. "Bookings: `booking.read`"), ώστε να μπορείτε να δείτε τι μπορεί να κάνει μια εφαρμογή με μια ματιά
χωρίς να την ανοίξετε.

## Περιστροφή διαπιστευτηρίων

Αν υπάρχει υποψία ότι το client secret έχει διαρρεύσει ή απλώς θέλετε φρέσκα διαπιστευτήρια, περιστρέψτε τα αντί να
δημιουργήσετε ξανά την εφαρμογή:

<Steps>
1. Βρείτε την εφαρμογή στη λίστα σας και κάντε κλικ στο `Rotate`.
2. Επιβεβαιώστε το παράθυρο διαλόγου — το τρέχον Client ID και secret παύουν να λειτουργούν αμέσως.
3. Αντιγράψτε το νέο Client ID και secret από το παράθυρο διαλόγου που εμφανίζεται μόνο μία φορά πριν το κλείσετε.
</Steps>

Η περιστροφή διατηρεί το όνομα της εφαρμογής, τον τύπο πελάτη, τα redirect URIs και τα scopes — αλλάζουν μόνο τα διαπιστευτήρια.

## Αφαίρεση εφαρμογής

:::caution
Παρακαλούμε μην διαγράψετε την εφαρμογή που δημιουργήσαμε αυτόματα για εσάς ώστε να διασφαλιστεί η λειτουργία όλων των χαρακτηριστικών για τον λογαριασμό σας.
:::

Αν δεν χρειάζεστε πλέον μια εφαρμογή, μπορείτε να την αφαιρέσετε. Αυτό είναι μόνιμο — τα διαπιστευτήρια ανακαλούνται αμέσως και δεν μπορούν να ανακτηθούν.

<Steps>
1. Βρείτε την εφαρμογή στη λίστα σας και κάντε κλικ στο `Delete`.
2. Επιβεβαιώστε το παράθυρο διαλόγου για να διαγράψετε οριστικά την εφαρμογή.
</Steps>
