## ホテルの推奨は予約ではない

今日のほとんどの「AIトラベル」は推奨で止まります。アシスタントが3つのホテルを提案し、その後旅行者をウェブサイトやOTAに引き渡して実際の予約を行います。そこで接続が切れ、価格が予約可能でない場合もあり、ソースのコンテキストは保持されません。

**AIエージェント**はAIの回答とは異なります。エージェントは単にホテルを説明するだけでなく、行動します：リアルタイムの空室状況を確認し、予約を組み立て、支払いを行い、何かが変わったときに対応できます。それを安全に行うには、エージェントはテキスト以上のものが必要です。構造化され、最新で予約可能なデータと呼び出せる取引レイヤーが必要です。

これは、**見つけられ理解される**ことに関する[AIディスカバリー](/ja/resources/ai-discovery-hotels/)と、**取引される**ことに関するエージェント型コマースの違いです。

## エージェントが取引を行うために必要なもの

ホテル予約は実際の商取引イベントです：適切な部屋、適切な料金、実際の空室状況、ポリシー、支払い、そしてホテルに同期される確認。エージェントはこれらの各要素が呼び出し可能な操作として利用可能でなければ完了できません。

| エージェントが必要なもの | 重要な理由 |
|---|---|
| 構造化されたリアルタイム供給 | ウェブスクレイピングされたデータは古くなるため、エージェントは最新のホテル管理在庫が必要です。 |
| リアルタイムの料金と空室状況 | エージェントが提示する価格は、その時点で実際に予約可能でなければなりません。 |
| 予約操作 | 予約作成は実際のAPI呼び出しでなければならず、ウェブフォームへの引き渡しではありません。 |
| 支払い | エージェント（またはそれを通じた旅行者）が支払いを行い、ポリシーロジックが適用されなければなりません。 |
| 帰属情報 | 予約を作成したソース、キャンペーン、エージェントは紐付いたままであるべきです。 |
| イベント | エージェントは確認、変更、キャンセル、返金に対応できるべきです。 |

これらがなければ、エージェントは推奨はできますが予約はできません。

## WinkでAIエージェントがホテルを予約する方法

WinkはAPIファーストです：すべてのプラットフォーム機能は外部から呼び出し可能で、ホストされたMCPサーバーがリアルタイムAPI契約をエージェントに公開します。典型的なエージェントの流れ：

### 1 — 接続してリアルタイム契約を読む

エージェントはホストされたMCPサーバーに接続し、`api_search`と`docs_search`を使って適切な操作を見つけ、実際のリクエスト/レスポンススキーマを読みます — エンドポイントを推測せず、古いドキュメントもありません。

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — 予約可能な在庫を検索

エージェントはホテル管理の供給を検索し、ジオロケーション空間検索を含め、接続されたチャネルマネージャー全体のリアルタイム料金と空室状況を読み取ります。

### 3 — 予約を作成

予約作成はREST API操作です。エージェントは部屋、料金、日付、ゲストを組み立て、APIを通じて予約を作成します。

### 4 — 支払いを受け取り確認

[Booking Engine](/ja/products/booking-engine/)が取引を履行します — チェックアウト、支払い（Winkがマーチャントオブレコード）、キャンセルポリシーロジック、確認、接続されたPMSやチャネルマネージャーへの予約同期。ソースとパートナーの帰属は予約を通じて保持されます。

### 5 — イベントに対応

エージェントは`booking.created`などのWebhookイベントを購読し、照合、旅行者への通知、フォローアップアクションのトリガーが可能です。

原則：**エージェントは意図を作成またはルーティングし、Booking Engineがすべての引き渡しの下で履行レイヤーとして機能します。**

## AI検索とAIエージェントの違い

それぞれ異なる役割を果たし、ホテルは両方に対応する必要があります。

|  | AI検索 / 回答エンジン | AIエージェント |
|---|---|---|
| 旅行者の目的 | ホテルを見つけて比較する | 宿泊を予約・管理する |
| ホテルに必要なもの | [構造化されクロール可能なコンテンツ](/ja/resources/hotel-content-answer-engines/) | リアルタイムAPI、料金、予約、支払い |
| 最終結果 | 推奨 | 確定予約 |
| Winkの提供面 | クリーンな供給 + 回答対応コンテンツ | REST API、MCPサーバー、Booking Engine |

[ホテル向けAIディスカバリー](/ja/resources/ai-discovery-hotels/)は検索側をカバーし、このガイドは取引側をカバーします。

## ホテルコマースでエージェントを構築するのは誰か

エージェント型トラベルコマースは消費者アシスタントだけではありません。同じインフラが支えるのは：

- 宿泊の検索、予約、管理をエンドツーエンドで行う**消費者向けトラベルアシスタント**。
- 既存の顧客体験内にホテル予約を組み込む**銀行、ロイヤルティ、スーパーアプリのエージェント**。
- 対象ホテルを発見し、アセットを構築し、帰属を維持しながら予約に対して10%のデフォルトコミッションを得る**パートナーおよびクリエイターの自動化**。
- [Extranet](/ja/products/extranet/)、[Social](/ja/products/social/)、[Studio](/ja/products/studio/)を横断してコンテンツ生成やパフォーマンス分析を支援し、ホテルがルールを管理する**ホテル側のコパイロット**。

## 今後の展望

上記の機能は現在REST APIとMCPサーバーを通じて利用可能です。今後の方向性はより深いエージェントネイティブコマース：エージェント向けの豊富な予約プリミティブ、旅行者に代わって取引を行うためのエージェントのIDと認可、パートナーネットワークで帰属し収益を得るエージェントの参加です。共通のテーマは一貫しています — **AIエージェントのためのトラベルコマースインフラ**、その下でBooking Engineが履行を担います。

## よくある間違い

- **AIディスカバリーとAIエージェントを同じプロジェクトとみなすこと。** 一方はコンテンツと構造、もう一方はAPIと履行。両方が必要です。
- **エージェントに予約できない価格を見積もらせること。** 見積もりはリアルタイムの料金と空室状況から出す必要があります。スクレイピングされたページではありません。
- **引き渡し時に帰属情報を失うこと。** エージェントが需要を作り出した場合、予約はそのソースに紐付いたままであるべきです。
- **履行レイヤーを省略すること。** 回答はチェックアウト、支払い、確認が実際に行われるまで予約ではありません。
