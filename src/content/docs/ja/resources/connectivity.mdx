## 接続性が重要な理由

すべての予約経路は正確なホテル供給に依存しています。料金が間違っていればゲストの信頼を失い、空室状況が誤っていれば予約失敗のリスクがあり、在庫が古ければどの経路も信頼できません。Winkは単なるウェブサイトの予約ボタン以上の役割を果たしており、同じホテルデータがウェブサイト経路、共有リンク、QRコード、ウェブコンポーネント、WinkLinksストアフロント、パートナーリンク、Travelikoリスティング、ソーシャル予約経路、Agentic AIの引き継ぎ、開発者フローを支えています。すべてに必要なのは正確な**ARI**（空室状況、料金、在庫）です。

## 2つのセットアップ方法

**方法1 — サポートされているプロバイダーに接続する。** ホテルがすでにWinkがサポートするチャネルマネージャー、PMS、CRS、料金プロバイダーで料金を管理している場合に使用します。ホテルはExtranetでプロバイダーを選択し、プロバイダーダッシュボードでWinkをチャネルとして有効化し、部屋タイプと料金プランをマッピングします。プロバイダーがARIをWinkに送信し、マスターレートカレンダーを自動で埋めます。複数チャネルのホテル、頻繁な料金変更、リアルタイム在庫が必要な場合や手動作業を減らしたい場合に最適です。

**方法2 — Extranetで料金を手動登録する。** ホテルがサポートされているプロバイダーを使わない場合や、`Distribution > Master rate calendar`を通じてWinkを手動で運用したい場合に使用します。単一日付や日付範囲の一括更新が可能です。小規模在庫、初期セットアップ、テストに最適です。**注意が必要です：** 運用中に料金が変わった場合は誰かがWinkを更新しなければなりません。プロバイダー接続がある場合、手動変更は次のプロバイダー更新で上書きされる可能性があります。

## 接続プロバイダーと手動登録の違い

| 質問 | 接続プロバイダー | Extranetでの手動登録 |
|---|---|---|
| ARIの更新者は？ | サポートされたプロバイダーがWinkに更新を送信。 | ホテルが料金と空室状況を手動で更新。 |
| 適しているのは？ | 複数チャネルのホテル、頻繁な変更、リアルタイム在庫。 | 小規模在庫、限定的な利用、接続プロバイダーなし。 |
| 作業負荷 | セットアップ後は日々の負荷が低い。 | 継続的な手動メンテナンスが必要。 |
| リアルタイム性 | プロバイダーから自動でARI更新。 | 最後の手動更新時点の情報のみ。 |
| リスク | マッピングやプロバイダー設定の誤り。 | メンテナンス不足による古い料金や空室。 |
| 予約通知 | 設定されたチャネルマネージャー/CRS/PMSに通知。 | Winkを通じてホテルが予約通知を受け取る。 |

## サポートされているプロバイダー

Winkは多くのチャネルマネージャーと、直接またはChannexを介したPMS接続をサポートしています。ライブ前にWinkチームと特定のプロバイダーのバージョン、セットアップ方法、マッピング要件を確認してください。

| プロバイダー | 種類 | 備考 |
|---|---|---|
| SiteMinder | チャネルマネージャー | 直接連携 |
| Cloudbeds | チャネルマネージャー | 直接連携 |
| Travelclick | チャネルマネージャー | 直接連携 |
| RateGain | チャネルマネージャー | 直接連携 |
| D-EDGE | チャネルマネージャー | 直接連携 |
| YieldPlanet | チャネルマネージャー | 直接連携 |
| Rate Tiger | チャネルマネージャー | 直接連携 |
| Hotel Link | チャネルマネージャー | 直接連携 |
| Channex | チャネルマネージャー + PMSプロキシ | 直接連携、複数PMSのプロキシとしても機能 |
| SynXis | CRS | SynXis Channel Connect Expressによる追加設定が必要な場合あり |

多くのPMSシステム（例：Mews、Apaleo、Opera Cloud、OTA Sync）は**Channexを介して**WinkにARIを送信できます。PMSがChannexに接続されていればWinkに届きます。ライブ前にPMSのバージョンとChannexの設定を確認してください。（これは代表的なリストです。プロバイダーはWinkチームにご確認ください。）

## プロバイダー設定の概要

Extranetで`Distribution > Channel manager`に進み、料金プロバイダーを選択して保存します。プロバイダーダッシュボードで**Wink**チャネルを追加し、Winkで作成した部屋タイプと料金プランをマッピングします。プロバイダーが自動で全料金プッシュを行わない場合は手動で開始し、マスターレートカレンダーを確認します。数分以内に更新されることがあります（プロバイダーやマッピングによって異なります）。**Verifier**を使って旅行者の価格リクエストをシミュレーションし、空室状況、通貨、割引、料金表示をテストしてからライブ需要を送信してください。通知動作を理解したらテスト予約を作成します。

## 予約通知

接続性は料金をWinkに送るだけでなく、予約が戻る流れも含みます。予約が成立すると、設定されたチャネルマネージャー、CRS、PMSに通知され、ホテルと旅行者には確認メールが届きます。パートナー経路ではパートナーに予約と帰属の確認が送られ、開発者は`booking.created`ウェブフックでリアルタイムの詳細を受け取れます。

## Winkの位置づけ

接続性はExtranetとBooking Engineの間に位置します。[Extranet](/ja/products/extranet/)はホテル側の管理レイヤーで、コンテンツ、部屋、料金プラン、制限、空室状況、ポリシー、Booking Engine設定を管理します。サポートされたプロバイダーがARIを供給するか、ホテルがマスターレートカレンダーを手動で管理します。[Booking Engine](/ja/products/booking-engine/)は承認済みデータを使い、直接予約、ソーシャル、WinkLinks、パートナー、Traveliko、Agentic AI、開発者経路からの予約を処理します。シンプルなルールは：**接続性が強いほど予約経路は信頼性が高い。**

## よくある間違い

- **Winkは最新の空室状況なしで販売できると誤解する。** まずプロバイダーか手動Extranet更新からARIが必要です。
- **プロバイダーに接続しても部屋や料金プランのマッピングをしない。** マッピングが正しくないとセットアップは完了しません。
- **プロバイダー接続中に料金を手動で編集する。** 手動変更は次のプロバイダー更新で上書きされる可能性があります。
- **検証を忘れる。** ライブ需要を送る前に料金表示、空室状況、割引ロジックをテストしてください。
- **接続性を単なる技術的作業と考える。** 収益、マーケティング、パートナー経路、コンバージョン、ゲストの信頼に影響します。
