Wink は 2 つのトランスポートを提供しています。どちらを使用するかは統合する API によって異なります。

| | トランスポート | スキーマ | ドキュメント |
| --- | --- | --- | --- |
| ほとんどの Wink API | HTTPS 上の REST | OpenAPI 3 | サイドバーの **API** 以下の任意のグループ |
| Partner Integrator API | HTTP/2 上の gRPC | Protocol Buffers | [Partner](/ja/partner-api/partner/) |

<Aside type="note" title="言語SDKの公開は終了しました">
  手作業で管理された SDK はラップしている API に遅れがちで、実際に必要な言語をカバーしていませんでした。代わりにスキーマからクライアントを生成してください — 常に最新です — または MCP サーバーにユースケースに合わせた統合コードを書かせましょう。
</Aside>

## REST クライアントの生成

すべての API グループは OpenAPI 3 ドキュメントを公開しています。任意の OpenAPI ジェネレーターに指定すれば、言語に対応した型付きクライアントが得られます。

```bash
# グループの仕様はリファレンスページの隣で提供されています。
curl -o wink-extranet.json https://api.wink.travel/v3/api-docs/extranet

npx @openapitools/openapi-generator-cli generate \
  -i wink-extranet.json -g typescript-fetch -o ./wink-client
```

## gRPC クライアントの生成

Partner Integrator API は gRPC です。Wink は `.proto` スキーマを 2 つの方法で公開しています。

- **サーバーリフレクション** — サーバーが自身を記述するため、`grpcurl`、Postman、Insomnia などのツールがファイルをダウンロードせずに実行時にスキーマを検出できます。リフレクションには他の呼び出しと同じベアラートークンが必要です。
- **`.proto` ファイル** — スキーマをベンダリングして事前に生成したい場合はこちら。

```bash
# 実行中のサーバーからスキーマを検出（認証済み）。
grpcurl -H "authorization: Bearer $WINK_TOKEN" \
  partner.wink.travel:443 list

# 次にクライアントを生成 — ここでは Go。サポートされているすべての言語で同様です。
protoc --go_out=. --go-grpc_out=. partner_lookup.proto
```

呼び出しは REST の `Authorization` ヘッダーと同様に `authorization` メタデータヘッダーにベアラートークンを含みます。エラーは HTTP ステータスコードではなく、レスポンスのトレーラーに gRPC ステータスコードとして返されます — [Partner リファレンス](/ja/partner-api/partner/) に期待されるステータスが記載されています。

## または MCP サーバーに書かせる

AI コーディングアシスタントを使う場合、MCP サーバーが最速のルートです。Wink の API をアシスタントが呼び出して推論できるツールとして公開しているため、クライアント全体を生成してエンドポイントを探す代わりに、作りたいものを説明するだけでユースケースに合わせた統合コードが得られます。
