WinkのMCPツールは**ツールセット**として公開されています — それぞれが1つのジョブに特化したエンドポイントです。AIクライアントは作業に合った1つか2つのエンドポイントに接続し、すべてに接続するわけではありません。

すべてのエンドポイントは**インタラクティブなOAuth2ログイン**（PKCE認可コードフロー）を使用します：AIエージェントがブラウザタブを開き、Winkアカウントでサインインするだけです。クライアントシークレットの管理は不要です。

```bash title="チャネルマネージャーの統合者が1つのエンドポイントに接続"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="自分で料金を管理するホテル経営者が別のエンドポイントに接続"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## なぜツールが複数のエンドポイントに分かれているのか

Winkは約500のツールを公開しています。すべてを一度にエージェントに渡すことは技術的には可能ですが、良いアイデアではありません。

**ツール定義はコンテキストを消費します。** MCPサーバーが広告するすべてのツールは、作業を始める前にモデルのコンテキストウィンドウに読み込まれます。説明や完全なパラメータスキーマも含まれます。500個もあると、実際のタスクに必要な予算の大部分を消費してしまいます。

**リストが増えると選択の質が下がります。** 500個の似た名前のツールから選ぶエージェントは、40個から選ぶ場合よりも悪い選択をします。チャネルマネージャーを統合する場合、約20個のツールが関連し、残りの480個はノイズとなり、正しいツールを見つけにくくします。

**作業は本質的に分離可能です。** PMSから空室状況を同期する人とアフィリエイトのランディングページを管理する人はほとんどツールを共有しません。ジョブごとに分割することで、各接続は1つのジョブの語彙を持ちます。

<Aside type="caution" title="ツールセットは権限ではありません">
狭いツールセットを選んでも**アカウントの権限は制限されません**し、広いツールセットを選んでも追加の権限は付与されません。すべてのツールは、サインインしたあなたのIDのもとでウェブポータルと同じアカウント権限を適用します。Winkポータルで予約をキャンセルできない場合、どのエンドポイントに接続していてもエージェントもキャンセルできません。

ツールセットは**フォーカスのために選び、セキュリティのためではありません**。
</Aside>

## エンドポイント一覧

2つのホストがツールセットを提供しています。ツール数は概算で、時間とともに増加します。

### `https://api.wink.travel` — プラットフォーム

| エンドポイント | ツール数 | 対応範囲 |
|---|---:|---|
| `/mcp/extranet/facilities` | 約64 | 予約可能かつ現地の在庫：客室と部屋タイプ、スパ、レストラン、会議室、アクティビティ、アトラクション、場所、その他販売可能なアイテム |
| `/mcp/extranet/property` | 約62 | 物件情報と商業条件：プロフィールとコンテンツ、アドオン、キャンセルポリシー、特典、告知 |
| `/mcp/settings` | 約60 | アカウント管理：管理主体のプロフィールとブランディング、マネージャーと権限、カスタマイズ、Webhook、通知設定 |
| `/mcp/studio/embeds` | 約48 | キュレーションされた在庫の公開：ウィジェット、グリッドとランキンググリッド、カード、地図、在庫やサプライヤーページへのディープリンク |
| `/mcp/extranet/rates` | 約44 | 価格と空室状況：在庫の料金期間と割当、料金プラン、マスターレート、特別料金やプロモーション料金 |
| `/mcp/extranet/operations` | 約39 | ライブ物件の運営：予約とそのライフサイクル、ゲストレビューと返信、カレンダーフィード、スケジュールされたタスク |
| `/mcp/extranet/distribution` | 約37 | 在庫の販売先：販売チャネルと料金修正、アフィリエイトやサプライヤーの関係リクエスト、登録、リード獲得 |
| `/mcp/studio/curation` | 約35 | マーチャンダイズ可能なコレクションの構築：静的・動的リスト、ランキングリスト、保存検索、物件集計 |
| `/mcp/link-manager` | 約28 | シンジケートされたリンクコレクション、そのデザイン、カテゴリとタグ、短縮URL |
| `/mcp/reference` | 約24 | 読み取り専用の参照データ：国、通貨と為替レート、言語、タイムゾーン、地理的検索、IPジオロケーション |
| `/mcp/analytics` | 約18 | 予約と収益の分析：概要、折れ線グラフ、リーダーボード、アフィリエイトパフォーマンス、シェア指標 |
| `/mcp/payment` | 約18 | 財務業務：元帳、出金と手数料見積もり、予約資金の集計 |
| `/mcp/booking-engine` | 約17 | 旅行者向けのショッピングパス：検索と参照、ショッピングカートとチェックアウト、バケットリスト、キャンペーンカスタマイズ |
| `/mcp/social` | 約17 | 連携されたソーシャルアカウント、投稿の公開とスケジューリング、投稿インサイトの閲覧 |
| `/mcp/travel-agent` | 約8 | 旅行者の代理予約とエージェントレポート |

### `https://integrations.wink.travel` — チャネルマネージャー統合

このホストは1つのジョブのために存在するため、エンドポイントは1つだけです。

| エンドポイント | ツール数 | 対応範囲 |
|---|---:|---|
| `/mcp/channel-manager` | 約9 | チャネルマネージャー、PMS、CRS統合の接続と検証 |

<Aside type="note" title="チャネルマネージャー統合と自社料金管理の違い">
これらは異なるジョブであり、異なる担当者が行い、エンドポイントも共有しません。

**チャネルマネージャー、PMS、CRSベンダー**は`integrations.wink.travel/mcp/channel-manager`を通じて一度統合し、その後は物件、料金、空室状況、予約をその統合経由でやり取りします。この単一のエンドポイントが全体のインターフェースです。

**自社で料金を手動で変更するホテル経営者**は`api.wink.travel`のエクストラネットツールセット（`/mcp/extranet/rates`など）を使用します。これらはチャネルマネージャー統合の一部ではなく、統合者が接続する理由はありません。

アカウント管理も`api.wink.travel`の`/mcp/settings`にあります。統合ホストには`/mcp/settings`はありません。
</Aside>

すべてのエンドポイントには`ping`ツールも含まれており、実際の作業を依頼する前に接続が生きているか確認できます。

### エージェント支払い

完全な旅行者予約フローには、`https://api.wink.travel/mcp/booking-engine`の**Wink Booking Engine**と互換性のある**支払いウォレット**を接続します。Wink MCPを追加するとブラウザでサインインと権限選択が開き、その後クライアントが認証を処理します。

Booking Engineには、目的地検索、ホテル・部屋検索、`agentic_booking_quote`、`agentic_booking_pay`、`agentic_booking_book`、予約取得と領収書が含まれます。エージェント予約と支払いがその環境で有効な場合です。接続設定、選択すべき権限、検索から確認までの手順は[Agentic Payments](/ja/developers/agentic-payments/)を参照してください。

## どのツールセットが必要？

| あなたが… | 接続先 |
|---|---|
| **チャネルマネージャー、PMS、CRSを統合する場合** | `integrations.wink.travel/mcp/channel-manager` — これだけ |
| **物件のコンテンツを管理する場合** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **部屋や部屋タイプを管理する場合** | `/mcp/extranet/facilities` |
| **価格と空室状況を管理する場合** | `/mcp/extranet/rates` |
| **日々の予約を運営する場合** | `/mcp/extranet/operations` |
| **流通を拡大する場合** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **アフィリエイトページを作成する場合** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **リンクインバイオページを運営する場合** | `/mcp/link-manager` + `/mcp/social` |
| **旅行者の代理で予約する場合** | `/mcp/travel-agent` |
| **資金を照合する場合** | `/mcp/payment` |
| **AIエージェントで部屋を予約する場合** | `/mcp/booking-engine` + 互換性のある支払いウォレット — [Agentic Payments](/ja/developers/agentic-payments/)参照 |
| **予約体験を構築する場合** | `/mcp/booking-engine`；必要に応じて追加の参照用に`/mcp/reference` |

**Booking Engineはコアの予約ワークフローを含みます。** アカウントとカスタマイズの検出、目的地検索、ホテルの空室と料金詳細、ショッピングカート、チェックアウト、旅行者の予約管理を提供します。エージェント予約と支払いツールも環境で有効な場合に含まれます。

都市ベースのホテル検索には、目的地を解決する`destination_lookup_search_suggestions`、空室ホテルと料金を探す`inventory_search_city`を使います。両方とも`/mcp/booking-engine`にあるため、参照接続は不要です。

国、通貨と為替レート、対応言語、タイムゾーン、広域地理検索、OTA分類、公開物件情報などの補助的な参照が必要な場合は`/mcp/reference`を追加します。これらは予約フローのオプション追加です。

まず1つから始めて、できないことがあれば別のツールセットを追加してください。各接続は独立しており、追加しても他に影響しません。

<Aside type="tip" title="すべてを使いたい場合">
`https://api.wink.travel/mcp`と`https://integrations.wink.travel/mcp`はそれぞれのホスト上の**すべての**ツールを提供し続けています。存在を調べるには便利ですが、日常作業には推奨しません：ツールリストが大きすぎて作業を圧迫し、エージェントのツール選択を悪化させます。上記のツールセットを優先してください。
</Aside>

## 認証の仕組み

Wink MCPサーバーは**OAuth2認可コード＋PKCE**フローを使用し、**動的クライアント登録（RFC 7591）**に対応しています。初回接続時の流れは以下の通りです：

1. AIクライアントはMCPエンドポイントの`/.well-known/oauth-protected-resource`メタデータから認可サーバーを検出します。
2. クライアントは**動的クライアント登録**で自己登録します — 手動のアプリ設定は不要です。
3. クライアントは`https://iam.wink.travel`の**ブラウザタブ**を開きます。Winkアカウントでサインインし、同意画面で権限を承認します。
4. Winkはアカウントに紐づく**アクセストークン**を発行します。
5. AIクライアントはすべてのMCPリクエストにトークンを付与します。すべてのツール結果は管理主体にスコープされます。
6. トークンは3時間で期限切れになります。AIクライアントはバックグラウンドで静かに更新します。

すべてのツール呼び出しは**あなたのIDのもとで実行されます** — ウェブポータルを保護するACLルールがAIエージェントにも適用されます。

## AIクライアントの接続方法

<Tabs>
  <TabItem label="Claude Code">

<Steps>
1. Claude Codeが最新であることを確認：
   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

2. [上記のディレクトリ](#endpoint-directory)からツールセットを選び追加します。例：価格と空室状況
   ```bash
   claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
   ```

3. Claude Codeがサーバーに接続し、認可サーバーを検出してデフォルトブラウザを開きます。

4. **Winkにサインイン**し、同意画面で権限を承認します。

5. Claude Codeが接続を確認します。`/mcp`と入力してサーバーが表示され、ツールが読み込まれているか確認してください。
</Steps>

作業に必要なだけツールセットを追加してください — それぞれが独立したサーバーエントリで名前も別です：
```bash
claude mcp add wink-operations https://api.wink.travel/mcp/extranet/operations --transport http
claude mcp add wink-analytics  https://api.wink.travel/mcp/analytics           --transport http
```

サインインは1回だけです。最初のブラウザ承認後、Claude Codeは追加のWinkエンドポイントでもWinkセッションを再利用します。

:::tip[チームと共有]
`claude mcp add`に`--scope project`を付けると、Claude CodeはサーバーURLをリポジトリルートの`.mcp.json`に書き込みます。そのファイルをコミットすれば、チーム全員が同じツールセットを使い、初回接続時に各自がブラウザでサインインを完了します。
:::

  </TabItem>

5. 下部ツールバーのプラグアイコンが両方のサーバーが接続済みであることを示します。
</Steps>

2. アクティビティバー（左サイドバー）の**Clineアイコン**をクリックしてClineパネルを開く。

3. Clineツールバーの**MCPサーバーアイコン**（プラグアイコン）をクリックし、**MCP設定を編集**を選択。

4. VS Codeが`cline_mcp_settings.json`を開く。Winkエントリを追加：

   ```json title="cline_mcp_settings.json"
   {
     "mcpServers": {
       "wink-extranet-rates": {
         "type": "http",
         "url": "https://api.wink.travel/mcp/extranet/rates"
       },
       "wink-extranet-operations": {
         "type": "http",
         "url": "https://api.wink.travel/mcp/extranet/operations"
       }
     }
   }
   ```

5. **ファイルを保存**。Clineが自動的にリロードされ、`https://iam.wink.travel`のブラウザタブが開きます。

6. **Winkにサインイン**し、権限を承認。MCPサーバーパネルに両方のサーバーがアクティブとして表示されます。

## スコープ

同意画面でエージェントが要求している内容の内訳が表示されます。MCPクライアントはプラットフォームの他の部分と同じ権限語彙を使います — 詳細は[認証ページのスコープリファレンス](/ja/developers/authentication#scopes)を参照。

MCP特有の点は2つ：

- **`mcp.read`、`mcp.write`、`mcp.remove`スコープはMCPトランスポートを開くために追加で必要です。** `mcp.*`スコープを持つクライアントは任意のWink MCPエンドポイントにアクセスできますが、呼び出すツールはそれぞれのエンドポイントのセクションスコープ（例：`booking.read`）を依然として適用します。
- **AIクライアントは必要なスコープだけを要求します。** 同意画面で個別の権限を拒否できます — 拒否されたスコープを必要とするツールは呼び出すとエラーを返します。

**ツールセットはこれらを変更しません。** 接続するエンドポイントが*リストされる*ツールを決め、*許可される*操作は決めません。`/mcp/payment`に接続しても新たな財務権限は付与されず、`/mcp/reference`に接続してもツールが独自のスコープを適用するのを止めません。認可はツール呼び出しごとにトークンとアカウントの権限から決まります。

## トラブルシューティング

**ブラウザタブが開かない**

AIクライアントがインタラクティブなPKCEフローに対応していない可能性があります。最新版を使っているか確認してください：
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPTデスクトップ:** アプリ内のアップデーターで更新

**サインイン後に`401 Unauthorized`が出る**

キャッシュされたトークンが古い可能性があります。サーバーを削除して再追加し、新しいサインインを促してください：

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Claude DesktopやChatGPTでは設定からサーバーを削除し、アプリを再起動して再追加してください。

**特定のツール呼び出しで`403 Forbidden`**

ツールが同意画面で承認されなかったスコープを要求しているか、アカウントに権限がありません。サーバーを再接続すると同意画面が再表示され、権限を承認できます。失敗する場合はツールが必要とするアカウント権限が不足しています。ツールセットを変えても権限は付与されません。

**必要なツールがリストにない**

接続しているツールセットがそのジョブをカバーしていない可能性があります。[エンドポイント一覧](#endpoint-directory)を確認し、該当するツールセットを追加してください。接続は独立しているため、追加しても他に影響しません。どれにあるか分からない場合は一時的に`https://api.wink.travel/mcp`に接続してツールを探し、どのツールセットにあるか調べてください。

**ツールセットエンドポイントで`404 Not Found`**

パスをよく確認してください。ネストされたツールセットは2セグメント（例：`/mcp/extranet/rates`）、フラットなものは1セグメント（例：`/mcp/link-manager`）です。認証されていないリクエストは`/mcp`以下で`401`を返すため、`401`だけではエンドポイントの存在は判断できません。

**`api.wink.travel/mcp/channel-manager`に接続しても何も起きない**

そのエンドポイントは存在しません。チャネルマネージャー統合は`https://integrations.wink.travel/mcp/channel-manager`のみで提供されています。物件の料金を手動で読み書きする必要がある場合は別のジョブで別のエンドポイント（`/mcp/extranet/rates`）を使います。

**サーバーは表示されるがツール呼び出しで「アカウントが見つかりません」**

Winkアカウントに管理主体が設定されていません。[Wink Portal](https://app.wink.travel)でアカウント設定を確認してください。

**トークンがセッション中に期限切れになる**

トークンは3時間有効です。Claude CodeとClaude Desktopはトークンを静かに更新します。長時間アイドル後に認証エラーが出たら、新しいメッセージを入力すると自動で再認証されます。

**Codex CLIで「MCPサーバーに接続できません」**

`~/.codex/config.json`が有効なJSONであること（末尾のカンマなし）と`"type": "http"`が設定されていることを確認してください。CodexはリモートサーバーにHTTPトランスポートを要求します。stdioトランスポートはローカルバイナリ用です。

**ChatGPTの「Connectors」メニューがない**

MCPサポートはChatGPTデスクトップアプリのバージョン**1.2024.352**以降かつPlus、Pro、Team、Enterpriseサブスクリプションが必要です。アプリを更新し、設定 → アカウントでプランを確認してください。

**Cursorサーバーが赤表示 / 「接続失敗」**

`~/.cursor/mcp.json`が有効なJSONで`"type": "http"`を含むことを確認。**設定 → Cursor設定 → MCP**で**更新**をクリック。エラーが続く場合はCursorを完全に再起動してください。設定変更は再起動しないと反映されないことがあります。

**WindsurfでMCPサーバーが設定に表示されない**

Windsurfは`mcp_config.json`の変更を反映するために完全な再起動が必要です（ウィンドウの再読み込みだけでは不十分）。**ファイル → 終了**して再起動してください。まだ表示されない場合はWindsurfのバージョンが**1.4以上**か確認してください（**ヘルプ → Windsurfについて**）。

**Clineで「サーバー追加」オプションが見えない**

MCPサーバーマネージャーはClineのバージョン**2.0**以降が必要です。VS Codeの拡張機能パネルでClineを探し、更新があればクリック。更新後、VS Codeをリロードしてください（`Ctrl+Shift+P` → 「Developer: Reload Window」）。
