Šiame straipsnyje parodyta, kaip greitai susikurti paskyrą kaip kūrėjas ir pradėti testuoti mūsų API Wink platformoje.

:::note
Testavimas visada turėtų vykti mūsų [staging aplinkoje](/lt/getting-started/environments). Ten yra daug mažiau duomenų, tačiau galite testuoti tiek, kiek norite, neįtakojant gamybinės aplinkos.

Kai būsite pasiruošę, pereikite į gamybinę aplinką patys: sukurkite programą gamybinėje aplinkoje (tapatybės duomenys neperkelia tarp aplinkų) ir pašalinkite `staging-` iš URL, taigi `https://staging-api.wink.travel` taps `https://api.wink.travel`. Kūrėjams nereikia patvirtinimo žingsnio. Tik [kanalų vadybininkai](/lt/guides/integrators/add-your-channel-manager/#certification) ir [kelionių agentai](/lt/portal/travel-agent/what-is-agent/) yra sertifikuojami prieš gamybą.

Sukurti paskyrą staging ar gamybinėje aplinkoje reiškia, kad sutinkate su Wink naudojimo sąlygomis ir mokėjimo sąlygomis, o ši sutartis yra privaloma.
:::

Atlikite šiuos veiksmus:

<Steps>
1. [Užsiregistruokite](/lt/getting-started/sign-up) vartotojo paskyrą Wink platformoje.
2. [Sukurkite filialo paskyrą](/lt/portal/create-account). Ją reikės susieti su savo programa. Daugiau konteksto rasite skyriuje [kas yra Studio](/lt/portal/studio/what-is-studio).
3. [Sukurkite programą](/lt/account/applications) ir susiekite ją su filialo paskyra, kurią sukūrėte 2 žingsnyje. Serverio-serverio API integracijoms pasirinkite **MACHINE_2_MACHINE** kaip kliento tipą.
4. Sukūrę `Application`, iš karto nukopijuokite ir išsaugokite kliento ID ir slaptą raktą — slaptas raktas rodomas tik vieną kartą ir jo negalima atgauti.
</Steps>

## CDN

Wink platformoje naudojame Cloudinary visiems mūsų vaizdų ir vaizdo įrašų ištekliams. Prisijungę prie mūsų kelionių inventoriaus, turėsite pilną prieigą prie visų Cloudinary pažangių funkcijų.

Mūsų `cloud_name` yra `traveliko`.

### Cloudinary

- [Pradžia](https://cloudinary.com/documentation/dev_kickstart)
- [SDK](https://cloudinary.com/documentation/cloudinary_sdks)
- [Cloudinary GitHub](https://github.com/cloudinary)
-	[Vaizdo pamokos](https://cloudinary.com/documentation/cloudinary_sdks_tutorials)

### Pavyzdys

Kiekvienam kelionių inventoriaus tipui, kurį palaikome, bus įdėtas JSON masyvas pavadinimu `multimedias`. Multimedia įrašo JSON atrodo taip:

```json {3}
{
  "multimediaIdentifier": "multimedia-1",
  "identifier": "partners/radisson_blu_logo",
  "type": "IMAGE",
  "width": "1024",
  "height": "768",
  "category": "1",
  "descriptions": [
    {
      "name": "Lobby",
      "description": "Picture of the lobby",
      "language": "en"
    }
  ],
  "lifestyleType": "LIFESTYLE_BUSINESS",
  "attribution": [
    {
      "url": "https://www.hilton.com",
      "name": "Hilton"
    }
  ]
}
```

Pažymėta eilutė rodo Cloudinary unikalų ID `partners/radisson_blu_logo`. Tai viskas, ko reikia, kad gautumėte vaizdą bet kokiu formatu, kokybe ir dydžiu.

## Testavimas

Eikite į mūsų [API](/lt/api/overview/) skyrių ir pasirinkite API, su kuria norite dirbti.

### API dokumentacija

Mūsų dokumentacijos svetainė sukurta taip, kad galite vykdyti API užklausas tiesiogiai iš svetainės.

Šiame pavyzdyje norite naudoti `Search Lookups (OAuth2)` API užklausą.

:::tip[Pro patarimas]
Patogumui rekomenduojame integratoriams naudoti galinius taškus, kuriuos mes žymime kaip `OAuth2`. Šie galiniai taškai žino, kad API kvietėjai yra prisijungę ir jau žino, kurioje paskyroje esate, todėl jums nereikia nurodyti `companyIdentifier` URL.
:::

<Steps>
1. Naudokite [Lookup API](https://developer.wink.travel/lookup), kad gautumėte paskirties vietas arba viešbučius.
2. Kairėje naršymo juostoje spustelėkite `Authentication`.
3. Įveskite savo kliento ID ir slaptą raktą, tada spustelėkite mygtuką `Get TOKEN`.
4. Jei jūsų duomenys galioja, pamatysite, kad jūsų API raktas buvo pritaikytas.
5. Dabar galite testuoti lookup galinį tašką.
</Steps>

### Postman
Tą patį galite atlikti naudodami Postman.

<Steps>
1. Atsisiųskite [Postman](https://www.postman.com/downloads).
2. Spustelėkite `Download OpenAPI spec` viršuje [Lookup API](https://developer.wink.travel/lookup) puslapyje.
3. Importuokite jį į Postman.
4. Jei importavote kaip naują kolekciją pavadinimu `Wink API`, spustelėkite horizontalią elipsę (3 taškai) šalia kolekcijos pavadinimo ir pasirinkite `Edit`.
5. Skiltyje `Authorization` nustatykite `Auth type` į OAuth2.
6. Lauke `Add auth data to` pasirinkite `Request headers`.
7. Lauke `Header prefix` įrašykite `Bearer`.
8. Lauke `Token Name` įrašykite norimą pavadinimą savo saugomam tokenui Postman, pvz., Wink Staging.
9. Lauke `Grant type` pasirinkite `Client Credentials`.
10. Lauke `Access token URL` įrašykite https://staging-iam.wink.travel/oauth2/token.
11. Lauke `Client ID` įrašykite kliento ID, kurį sugeneravo jūsų programa.
12. Lauke `Client Secret` įrašykite slaptą raktą, kurį sugeneravo jūsų programa.
13. Lauke `Scope` įrašykite tarpu atskirtus reikalingus integracijos leidimus (pvz., `inventory.read inventory.write inventory.remove`). Visą sąrašą rasite [scope reference](/lt/developers/authentication#scopes).
14. Lauke `Client Authentication` pasirinkite `Send as Basic Auth header`.
15. Spustelėkite mygtuką `Get New Access Token`, kad gautumėte ir išsaugotumėte tokeną.
16. Visoms API užklausoms Wink API kolekcijoje įsitikinkite, kad autorizacijos skirtuke yra pasirinkta `Inherit auth from parent`, kad tokenas būtų pridėtas prie kiekvienos užklausos.
</Steps>

:::tip[Pro patarimas]
Rekomenduojama serverio domeną, kliento ID ir slaptą raktą paversti aplinkos kintamaisiais. Taip lengvai galėsite keistis tarp staging ir gamybinių aplinkų bei pakartotinai naudoti visas sukurtas operacijas.
:::
