Galite prijungti **bet kurį** Google Tag Manager (GTM) konteinerį prie Wink, įvesdami jo **GTM konteinerio ID** Wink portale. Prijungus, jūsų konteineris automatiškai įkeliama jūsų nuosavybei ir tiesiogiai skaito Wink užsakymų įvykius — apimdamas visą svečio kelionę nuo paieškos iki užsakymo užbaigimo. Dažnas naudojimo atvejis yra **Sojern** konteineris pakartotinei rinkodarai ir reklamai, tačiau bet kuris GTM konteineris veikia taip pat.

<Aside type="tip">
Tai reiškia, kad jau turite GTM konteinerio ID (formatu `GTM-XXXXXXX`). Jei jūsų konteineris yra iš partnerio, pvz., Sojern, paprašykite savo paskyros vadybininko būtent **GTM konteinerio ID** — jis skiriasi nuo pikselio ar žymos ID. Naujas Sojern? Aplankykite [sojern.com/contact](https://www.sojern.com/contact), kad pradėtumėte.
</Aside>

## Ką turite padaryti

<Steps>

1. **Gaukite savo GTM konteinerio ID**

   Gaukite savo **GTM konteinerio ID** (formatu `GTM-XXXXXXX`). Jei jis gaunamas iš partnerio, pvz., Sojern, paprašykite būtent GTM konteinerio ID — jis skiriasi nuo pikselio ar žymos ID.

2. **Įveskite jį Wink portale**

   Prisijunkite prie [app.wink.travel](https://app.wink.travel), pasirinkite savo paskyrą ir atidarykite pritaikymo nustatymus. Skiltyje **Analytics & integrations** įklijuokite savo GTM konteinerio ID į laukelį **GTM Container ID** ir išsaugokite. Jūsų integracija dabar veikia.

3. **Patvirtinkite su savo tiekėju**

   Jei jūsų konteineris yra iš partnerio, pvz., Sojern, praneškite savo paskyros vadybininkui, kad integracija aktyvi. Jie gali patikrinti iš savo pusės, ar žymos tinkamai veikia `wink.travel` jūsų nuosavybei ir ar duomenys teka į jūsų paskyrą.

</Steps>

<Aside type="note">
Jums nereikia įdėti jokio pikselio kodo savo svetainėje šiai integracijai. Wink automatiškai įkelia jūsų GTM konteinerį visuose puslapiuose, kuriuose aktyvi jūsų nuosavybė.

Tai veikia su **bet kuriuo** GTM konteinerio ID — Sojern yra tik dažnas pavyzdys.
</Aside>

## Ką Wink daro savo pusėje

Skaidrumui, štai ką Wink konfigūruoja, kad ši integracija veiktų:

- **GTM konteinerio ID laukas** yra prieinamas skiltyje **Analytics & integrations** jūsų pritaikymo nustatymuose. Įvedus konteinerio ID, Wink patikrina formato teisingumą (`GTM-XXXXXXX`) ir saugiai jį saugo jūsų nuosavybei.
- **Kiekviename puslapyje, kuriame aktyvi jūsų nuosavybė** Wink tiesiogiai įterpia jūsų konteinerį į puslapį — dalijantis Wink pačios `window.dataLayer` — todėl jis įsikrauna kartu su Wink konteineriu be papildomų konfigūracijų. Tai vyksta automatiškai, be papildomo Wink komandos darbo kiekvienai nuosavybei.
- **Jūsų konteineris įkeliama asinchroniškai**, todėl tai nepaveikia puslapio įkėlimo greičio jūsų svečiams.
- **Wink sekimas ir jūsų konteineris veikia lygiagrečiai**, skaitydami iš to paties bendro `dataLayer`. Kiekvienas Wink sekamas užsakymo įvykis tuo pačiu metu yra prieinamas jūsų konteineriui.
- **Kai jūsų nuosavybė nėra peržiūrima** — pavyzdžiui, kai svečias naršo kitą viešbutį Wink — jūsų konteineris neįkeliama, todėl gauna tik duomenis, susijusius su jūsų nuosavybe.
- **Užbaigtas užsakymas (`purchase`) įvyksta naršyklėje padėkos puslapyje.** GTM konteinerio ID yra juodoji dėžė — Wink negali žinoti, kokios žymos jame yra — todėl Wink niekada nekviečia Google savo serverių vardu. Vietoje to, bet kokia GA4 ar konversijų žyma jūsų konteineryje gauna `purchase` klientinėje pusėje, kaip ir kiekvienas kitas užsakymo įvykis. Kadangi mokėjimo tiekėjas nukreipia svečio naršyklę išvykstant ir grįžtant, Wink atkuria analizės sesiją, kurią pertraukė nukreipimas, **prieš** paleisdamas `purchase`, todėl pardavimas priskiriamas svečio originaliam apsilankymui, o ne naujai sesijai.

## DataLayer nuoroda

Wink siunčia GA4 suderinamus įvykius į `dataLayer` visos svečio kelionės metu. Jūsų GTM konteineris skaito iš to paties bendro `dataLayer`, todėl bet kuris sukonfigūruotas trigeris ar kintamasis turi prieigą prie visų žemiau aprašytų savybių.

Kiekvienas įvykis atitinka standartinę GA4 Enhanced Ecommerce struktūrą: viršutinio lygio `event` eilutę ir `ecommerce` objektą. Prieš kiekvieną push, Wink išvalo ankstesnį ecommerce krovinių rinkinį, kad išvengtų pasenusių duomenų įsiskverbimo į naujus trigerius.

<Aside type="note">
**dataLayer atstatymo modelis**

Wink atstato ecommerce objektą prieš kiekvieną įvykio push:

```js
dataLayer.push({ ecommerce: null });   // išvalyti ankstesnį įvykį
dataLayer.push({ event: '...', ecommerce: { ... } });
```

Nesitikėkite, kad ecommerce savybės išliks tarp įvykių. Visada skaitykite jas trigerio metu tame pačiame įvykyje.
</Aside>

### Užsakymo kelionės įvykiai

Šie įvykiai automatiškai paleidžiami, kai svečias juda užsakymo piltuvėliu. Konfigūruokite savo GTM trigerius kaip **Custom Event** trigerius, atitinkančius žemiau pateiktus įvykių pavadinimus.

| Žingsnis | Įvykis | Kada paleidžiamas |
|------|-------|---------------|
| 1 | `view_item_list` | Įkeliama viešbučių inventoriaus tinklelio arba sąrašo peržiūra |
| 2 | `view_item` | Svečias peržiūri konkrečios nuosavybės puslapį |
| 3 | `add_to_cart` | Svečias prideda kambarį į krepšelį |
| 4 | `begin_checkout` | Įkeliama atsiskaitymo / mokėjimo puslapis |
| 5 | `add_payment_info` | Svečias pasirenka mokėjimo būdą |
| 6 | `login` | Svečias autentifikuojasi per SSO |
| 7 | `purchase` | Užsakymas patvirtinamas |
| 8 | `refund` | Užsakymas atšaukiamas |

### Prekės savybės

Visi įvykiai, turintys `items` masyvą, naudoja tą pačią prekės schemą. Kiekviena savybė yra neprivaloma, nebent pažymėta kaip privaloma.

| Savybė | Tipas | Aprašymas |

| `start_date` | string | Atvykimo data formatu `YYYY-MM-DD` |

| `num_adults` | number | Suaugusiųjų skaičius užsakyme |
| `num_children` | number | Vaikų skaičius užsakyme |
| `cancellation_policy` | string | Viena iš: `Refundable`, `Non-Refundable`, `Refundable-With-Restrictions`, `Non-Refundable-With-Restrictions` |

| `room_rate_id` | string | Konkretios kambario kainos identifikatorius |

| `room_view` | string | Kambario vaizdo aprašymas (pvz., `Ocean`, `City`) |
| `room_classification` | string | Kambario klasifikacija ar kategorija (pvz., `Suite`, `Standard`) |
| `bed_type` | string | Lovos konfigūracija kambaryje (pvz., `King`, `Twin`) |

### Individualios dimensijos GA4

GA4 ignoruoja individualius prekės parametrus ataskaitose, kol jų aiškiai neužregistruojate kaip prekės lygmens individualias dimensijas. Registruoti reikia tik tuos parametrus, kuriuos ketinate naudoti ataskaitose — nereikia registruoti visų 20.

<Steps>

1. **Atidarykite individualių apibrėžimų skiltį**

   GA4 eikite į **Admin** (apatinis kairysis pavaros piktograma) → pasirinkite savo nuosavybę → **Data display** → **Custom definitions**.

2. **Sukurkite naują individualią dimensiją**

   Spauskite **Create custom dimensions**.

3. **Užpildykite dimensijos duomenis**

   - **Dimension name** — žmogui suprantamas pavadinimas, kuris bus matomas GA4 ataskaitose (žr. lentelę žemiau)
   - **Scope** — pasirinkite **Item**
   - **Event parameter** — tikslus parametro pavadinimas, kaip jis pateikiamas dataLayer (žr. lentelę žemiau)
   - **Description** — neprivaloma, bet rekomenduojama

4. **Išsaugokite ir kartokite**

   Spauskite **Save**, tada pakartokite kiekvienam parametrui, kurį norite sekti.

</Steps>

<Aside type="note">
Individualios dimensijos gali pradėti rodyti duomenis GA4 ataskaitose per 24 valandas po registracijos. Istoriniai duomenys, surinkti prieš registraciją, nėra papildomai įtraukiami.

GA4 leidžia iki 50 prekės lygmens individualių dimensijų standartinėse nuosavybėse (360 nuosavybėse leidžiama daugiau).
</Aside>

Naudokite žemiau pateiktą lentelę kaip nuorodą kuriant individualias dimensijas. **Event parameter** reikšmė turi tiksliai sutapti — GA4 atsižvelgia į didžiąsias ir mažąsias raides.

| Dimensijos pavadinimas | Event parameter | Tipas |
|----------------|-----------------|------|
| Nuosavybės ID | `property_id` | Tekstas |
| Nuosavybės pavadinimas | `property_name` | Tekstas |
| Nuosavybės prekės ženklas | `property_brand` | Tekstas |
| Nuosavybės tinklas | `property_chain` | Tekstas |
| Nuosavybės URL pavadinimas | `property_url_name` | Tekstas |
| Miesto pavadinimas | `city_name` | Tekstas |
| Šalies kodas | `country_code` | Tekstas |
| Atvykimo data | `start_date` | Tekstas |
| Išvykimo data | `end_date` | Tekstas |
| Suaugusiųjų skaičius | `num_adults` | Skaičius |
| Vaikų skaičius | `num_children` | Skaičius |
| Atšaukimo politika | `cancellation_policy` | Tekstas |
| Kainų plano ID | `rate_plan_id` | Tekstas |
| Kambario kainos ID | `room_rate_id` | Tekstas |
| Kambario kainos pavadinimas | `room_rate_name` | Tekstas |
| Privalumų skaičius | `num_perks` | Skaičius |
| Kambario vieta | `room_location` | Tekstas |
| Kambario vaizdas | `room_view` | Tekstas |
| Kambario klasifikacija | `room_classification` | Tekstas |

### `virtualPageView`

Tai yra individualus Wink įvykis — ne standartinės GA4 įvykių rinkinio dalis. Jis siunčiamas kiekvieną kartą keičiant puslapį ir neša įrenginio bei sesijos kontekstą. Jame nėra `ecommerce` objekto.

```json
{
  "event": "virtualPageView",
  "device": "Desktop",
  "deviceAgent": "Mozilla/5.0 ...",
  "os": "MacOS",
  "path": "/hotels/grand-resort",
  "title": "Grand Resort — Wink",
  "userId": "user_abc123",
  "startDate": "2026-06-01",
  "endDate": "2026-06-05",
  "guests": "2",
  "rooms": "1"
}
```

| Savybė | Aprašymas |
|----------|-------------|
| `device` | Aptiktas įrenginio tipas — `Desktop`, `Android`, `iPhone`, `iPad` ar panašiai |
| `deviceAgent` | Žalias vartotojo agento eilutė |
| `os` | Aptikta operacinė sistema — `Windows`, `MacOS`, `Linux`, `UNIX` |
| `path` | Dabartinis puslapio kelias |
| `title` | Dabartinis puslapio pavadinimas |
| `userId` | Autentifikuoto vartotojo identifikatorius (praleidžiamas, jei neprisijungta) |
| `startDate` | Atvykimo data iš dabartinės paieškos sesijos |
| `endDate` | Išvykimo data iš dabartinės paieškos sesijos |
| `guests` | Svečio skaičius iš dabartinės paieškos sesijos |
| `rooms` | Kambarių skaičius iš dabartinės paieškos sesijos |
