## Rekomendowanie hotelu to nie to samo co jego rezerwacja

Większość „AI w turystyce” dziś zatrzymuje się na rekomendacji. Asystent proponuje trzy hotele, a potem przekazuje podróżnego na stronę lub OTA, by faktycznie zarezerwować. Wątek się urywa, cena może być nieaktualna, a nikt nie zachowuje kontekstu źródła.

**AI agent** różni się od odpowiedzi AI. Agent nie tylko opisuje hotel — działa: sprawdza dostępność na żywo, tworzy rezerwację, pobiera płatność i reaguje na zmiany. Aby to działało bezpiecznie, agent potrzebuje więcej niż tekst. Potrzebuje ustrukturyzowanych, aktualnych, rezerwowalnych danych i warstwy transakcyjnej, którą może wywołać.

To różnica między [odkrywaniem AI](/pl/resources/ai-discovery-hotels/), które polega na **byciu znalezionym i zrozumianym**, a agentowym handlem, który polega na **zawieraniu transakcji**.

## Co agent potrzebuje, zanim zacznie transakcję

Rezerwacja hotelu to prawdziwe zdarzenie handlowe: odpowiedni pokój, właściwa cena, realna dostępność, zasady, płatność i potwierdzenie synchronizujące się z hotelem. Agent może to zrealizować tylko, jeśli każdy element jest dostępny jako wywoływalna operacja.

| Agent potrzebuje | Dlaczego to ważne |
|---|---|
| Ustrukturyzowany, aktualny zasób | Dane ze skanowania stron szybko się dezaktualizują; agent potrzebuje aktualnego, kontrolowanego przez hotel inwentarza. |
| Ceny i dostępność w czasie rzeczywistym | Cena podana przez agenta musi być faktycznie rezerwowalna w danym momencie. |
| Operacja rezerwacji | Tworzenie rezerwacji musi być prawdziwym wywołaniem API, a nie przekierowaniem do formularza internetowego. |
| Płatność | Agent (lub podróżny przez niego) musi móc zapłacić, z zastosowaniem logiki polityk. |
| Atrybucja | Źródło, kampania lub agent, który stworzył rezerwację, powinny pozostać przypisane. |
| Zdarzenia | Agent powinien móc reagować na potwierdzenia, zmiany, anulacje i zwroty. |

Bez tego agent może rekomendować — ale nie może rezerwować.

## Jak AI agent rezerwuje hotel na Wink

Wink jest API-first: każda funkcja platformy jest wywoływalna z zewnątrz, a hostowany serwer MCP udostępnia agentom na żywo kontrakty API. Typowy przebieg agenta:

### 1 — Połącz się i odczytaj aktualne kontrakty

Agent łączy się z hostowanym serwerem MCP i używa `api_search` oraz `docs_search`, by znaleźć odpowiednie operacje i odczytać ich aktualne schematy zapytań/odpowiedzi — bez zgadywania endpointów, bez przestarzałej dokumentacji.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Wyszukaj rezerwowalny inwentarz

Agent przeszukuje kontrolowany przez hotel zasób, w tym wyszukiwanie przestrzenne geolokalizacji, i odczytuje aktualne ceny oraz dostępność w połączonych channel managerach.

### 3 — Utwórz rezerwację

Tworzenie rezerwacji to operacja REST API. Agent składa pokój, cenę, daty i gości, i tworzy rezerwację przez API.

### 4 — Pobierz płatność i potwierdź

[Booking Engine](/pl/products/booking-engine/) realizuje transakcję — finalizację, płatność (Wink jest sprzedawcą), logikę polityk anulacji, potwierdzenie i synchronizację rezerwacji z podłączonym PMS lub channel managerem. Źródło i atrybucja partnera są zachowane przez rezerwację.

### 5 — Reaguj na zdarzenia

Agent może subskrybować `booking.created` i inne webhooki, by uzgadniać, powiadamiać podróżnego lub wywoływać dalsze akcje.

Zasada: **agent tworzy lub kieruje intencję; Booking Engine pozostaje warstwą realizacji pod każdą przekazaniem.**

## Wyszukiwanie AI a AI agents

Rozwiązują różne zadania, a hotel musi być gotowy na oba.

| | Wyszukiwanie AI / silniki odpowiedzi | AI agents |
|---|---|---|
| Cel podróżnego | Znaleźć i porównać hotele | Zarezerwować i zarządzać pobytem |
| Co hotel potrzebuje | [Ustrukturyzowana, indeksowalna treść](/pl/resources/hotel-content-answer-engines/) | Żywe API, ceny, rezerwacje, płatności |
| Końcowy efekt | Rekomendacja | Potwierdzona rezerwacja |
| Powierzchnia Wink | Czysty zasób + treść gotowa do odpowiedzi | REST API, serwer MCP, Booking Engine |

[Odkrywanie AI dla hoteli](/pl/resources/ai-discovery-hotels/) opisuje stronę wyszukiwania; ten przewodnik dotyczy strony transakcji.

## Kto buduje agentów na handlu hotelowym

Agentowy handel w turystyce to nie tylko asystenci konsumenccy. Ta sama infrastruktura napędza:

- **Konsumenckich asystentów podróży**, którzy wyszukują, rezerwują i zarządzają pobytem od początku do końca.
- **Agentów bankowych, lojalnościowych i super-aplikacji**, osadzających rezerwacje hoteli w istniejącym doświadczeniu klienta.
- **Automatyzacje partnerów i twórców**, które odkrywają kwalifikujące się hotele, tworzą zasoby i utrzymują atrybucję — zarabiając 10% domyślnej prowizji od potwierdzonych rezerwacji.
- **Kopilotów po stronie hotelu**, którzy pomagają zespołom generować treści i analizować wyniki w [Extranet](/pl/products/extranet/), [Social](/pl/products/social/) i [Studio](/pl/products/studio/), podczas gdy hotel zachowuje kontrolę nad zasadami.

## Dokąd to zmierza

Powyższe możliwości są dostępne dziś przez REST API i serwer MCP. Kierunek to głębszy, natywny dla agentów handel: bogatsze prymitywy rezerwacji skierowane do agentów, tożsamość i autoryzacja agentów do transakcji w imieniu podróżnego oraz udział agentów jako przypisanych, zarabiających źródeł w sieci partnerów. Wspólny mianownik to — **infrastruktura handlu turystycznego dla AI agents**, z Booking Engine realizującym pod spodem.

## Częste błędy

- **Traktowanie odkrywania AI i AI agents jako tego samego projektu.** Jedno to treść i struktura; drugie to API i realizacja. Potrzebujesz obu.
- **Pozwalanie agentom podawać ceny, których nie mogą zarezerwować.** Oferty muszą pochodzić z aktualnych cen i dostępności, nie ze stron skanowanych.
- **Utrata atrybucji przy przekazaniu.** Jeśli agent generuje popyt, rezerwacja powinna pozostać powiązana z tym źródłem.
- **Pomijanie warstwy realizacji.** Odpowiedź to nie rezerwacja, dopóki nie nastąpi finalizacja, płatność i potwierdzenie.
