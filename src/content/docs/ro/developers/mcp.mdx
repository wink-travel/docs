Uneltele MCP ale Wink sunt publicate ca **seturi de unelte** — endpoint-uri focalizate, fiecare acoperind o singură sarcină. Conectezi clientul tău AI la unul sau două care se potrivesc muncii tale, nu la toate.

Fiecare endpoint folosește **autentificare interactivă OAuth2** (fluxul codului de autorizare PKCE): agentul tău AI deschide o filă de browser, te autentifici cu contul Wink și gata. Nu există secrete de client de gestionat.

```bash title="Un integrator de channel manager se conectează la un endpoint"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Un hotelier care își gestionează propriile tarife se conectează la altul"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## De ce uneltele sunt împărțite pe endpoint-uri

Wink expune aproximativ 500 de unelte. Să le dai pe toate unui agent dintr-o dată este tehnic posibil — și o idee proastă.

**Definițiile uneltelor consumă context.** Fiecare unealtă pe care un server MCP o anunță este încărcată în fereastra de context a modelului înainte să facă orice lucru, împreună cu descrierea și schema completă a parametrilor săi. Cinci sute dintre acestea consumă o mare parte din bugetul de context necesar sarcinii tale reale, la fiecare cerere.

**Calitatea alegerii scade pe măsură ce lista crește.** Un agent care alege din 500 de unelte cu nume similare face alegeri mai slabe decât unul care alege din 40. Dacă integrezi un channel manager, aproximativ douăzeci de unelte sunt relevante pentru tine; celelalte 480 sunt zgomot care face mai dificilă găsirea uneltei potrivite.

**Munca este cu adevărat separabilă.** Cineva care sincronizează disponibilitatea dintr-un PMS și cineva care creează pagini de afiliat împărtășesc aproape nicio unealtă. Împărțirea pe sarcini înseamnă că fiecare conexiune poartă vocabularul unei singure sarcini.

<Aside type="caution" title="Seturile de unelte nu sunt permisiuni">
Alegerea unui set restrâns de unelte **nu** limitează ce poate face contul tău, iar alegerea unuia larg nu acordă nimic în plus. Fiecare unealtă aplică aceleași permisiuni de cont ca portalul web, sub identitatea ta autentificată. Dacă contul tău nu poate anula o rezervare în Wink Portal, nici agentul nu poate — indiferent de endpoint-ul la care este conectat.

Alege seturi de unelte pentru **focalizare**, nu pentru securitate.
</Aside>

## Directorul endpoint-urilor

Două gazde servesc seturi de unelte. Numărul uneltelor este aproximativ și crește în timp.

### `https://integrations.wink.travel` — integrări channel manager

Un singur endpoint, pentru că această gazdă există pentru o singură sarcină.

| Endpoint | Unelte | Ce acoperă |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Conectarea și verificarea unei integrări channel manager, PMS sau CRS |

<Aside type="note" title="Integrarea unui channel manager vs. gestionarea propriilor tarife">
Acestea sunt sarcini diferite pentru persoane diferite și nu împart un endpoint.

Un **vendor channel manager, PMS sau CRS** integrează o singură dată prin `integrations.wink.travel/mcp/channel-manager` și de atunci schimbă proprietăți, tarife, disponibilitate și rezervări prin acea integrare. Acest singur endpoint este întreaga suprafață.

Un **hotelier care își schimbă manual propriile tarife** folosește seturile de unelte extranet de pe `api.wink.travel` — `/mcp/extranet/rates` și altele. Acestea nu fac parte din integrarea channel manager și un integrator nu are motiv să se conecteze la ele.

Administrarea contului este de asemenea pe `api.wink.travel`, la `/mcp/settings`. Nu există `/mcp/settings` pe gazda de integrări.
</Aside>

Fiecare endpoint poartă și o unealtă `ping`, astfel încât poți confirma că o conexiune este activă înainte de a-i cere să facă o muncă reală.

## Ce seturi de unelte am nevoie?

| Dacă ești… | Conectează-te la |
|---|---|
| **Integrezi un channel manager, PMS sau CRS** | `integrations.wink.travel/mcp/channel-manager` — doar acesta |
| **Gestionezi conținutul unei proprietăți** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Gestionezi camere și tipuri de camere** | `/mcp/extranet/facilities` |
| **Gestionezi prețuri și disponibilitate** | `/mcp/extranet/rates` |
| **Gestionezi rezervările zilnice** | `/mcp/extranet/operations` |
| **Crești distribuția** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Construiești pagini de afiliat** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Gestionezi pagini link-in-bio** | `/mcp/link-manager` + `/mcp/social` |
| **Faci rezervări în numele călătorilor** | `/mcp/travel-agent` |
| **Reconcilii bani** | `/mcp/payment` |
| **Construiești o experiență de rezervare** | `/mcp/booking-engine` + `/mcp/reference` |

Începe cu unul. Adaugă altul când găsești că ai nevoie de ceva ce nu poate face — fiecare conexiune este independentă și adăugarea uneia nu afectează pe celelalte.

<Aside type="tip" title="Vrei totuși totul?">
`https://api.wink.travel/mcp` și `https://integrations.wink.travel/mcp` rămân disponibile și servesc **toate** uneltele de pe gazda lor. Sunt utile pentru explorare, dar nu le recomandăm pentru munca zilnică: lista de unelte este suficient de mare încât să copleșească sarcina ta și să degradeze selecția uneltelor agentului. Preferă seturile de unelte de mai sus.
</Aside>

## Cum funcționează autentificarea

Serverele MCP Wink folosesc fluxul **OAuth2 Authorization Code + PKCE** și suportă **Dynamic Client Registration (RFC 7591)**. Iată ce se întâmplă când te conectezi prima dată:

1. Clientul tău AI descoperă serverul de autorizare din metadatele endpoint-ului MCP `/.well-known/oauth-protected-resource`.
2. Clientul se înregistrează singur prin **Dynamic Client Registration** — nu este nevoie de configurare manuală a aplicației.
3. Clientul deschide o **filă de browser** către `https://iam.wink.travel`. Te autentifici cu contul Wink și aprobi permisiunile cerute pe ecranul de consimțământ.
4. Wink emite un **token de acces** legat de contul și identitatea ta.
5. Clientul AI atașează tokenul la fiecare cerere MCP. Toate rezultatele uneltelor sunt automat limitate la entitatea ta de management.
6. Tokenurile expiră după 3 ore. Clientul AI le reîmprospătează silențios în fundal fără a cere din nou autentificare.

Fiecare apel de unealtă rulează **sub identitatea ta** — aceleași reguli ACL care protejează portalul web se aplică agentului AI.

## Scopuri

Când aprobi ecranul de consimțământ vei vedea o defalcare a ceea ce cere agentul. Clienții MCP folosesc același vocabular de permisiuni ca restul platformei — vezi referința completă a
[scopurilor pe pagina de Autentificare](/ro/developers/authentication#scopes).

Două lucruri sunt specifice MCP:

- **Scopurile `mcp.read`, `mcp.write`, `mcp.remove` sunt suplimentar necesare** pentru a deschide transportul MCP. Un client care deține un scop `mcp.*` este admis la orice endpoint MCP Wink, dar fiecare unealtă pe care o invocă aplică în continuare scopul secțiunii endpoint-ului pe care îl înfășoară (ex. `booking.read`).
- **Clientul AI cere doar scopurile de care are nevoie.** Poți refuza permisiuni individuale pe ecranul de consimțământ — uneltele care necesită un scop refuzat vor returna o eroare când sunt invocate.

**Seturile de unelte nu schimbă nimic din toate acestea.** Endpoint-ul la care te conectezi decide ce unelte sunt *listate*, nu ce unelte sunt *permise*. Conectarea la `/mcp/payment` nu acordă permisiuni financiare pe care nu le aveai deja, iar conectarea la `/mcp/reference` nu împiedică o unealtă să aplice propriul scop. Autorizarea se decide la fiecare apel de unealtă, din tokenul tău și drepturile contului tău.

## Depanare

**Fila de browser nu se deschide**

Clientul tău AI poate să nu suporte încă fluxul interactiv PKCE. Verifică că folosești o versiune recentă:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** actualizează din updaterul încorporat al aplicației

**`401 Unauthorized` după autentificare**

Tokenul tău cache poate fi expirat. Elimină și adaugă din nou serverul pentru a declanșa o autentificare nouă:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Pentru Claude Desktop și ChatGPT, elimină intrarea serverului din setări, repornește aplicația și adaugă-l din nou.

**`403 Forbidden` când apelezi o unealtă specifică**

Unealta necesită un scop pe care nu l-ai aprobat pe ecranul de consimțământ sau o permisiune pe care contul tău nu o deține. Reconectează serverul — ecranul de consimțământ va apărea din nou și poți aproba permisiunea lipsă. Dacă tot eșuează, unealta are nevoie de o permisiune de cont pe care nu o ai; conectarea la un alt set de unelte nu va ajuta, pentru că seturile de unelte nu acordă permisiuni.

**Unealta de care am nevoie nu este în listă**

Probabil ești conectat la un set de unelte care nu acoperă acea sarcină. Verifică [directorul endpoint-urilor](#endpoint-directory) și adaugă setul de unelte care o face — conexiunile sunt independente, deci adăugarea unuia nu schimbă nimic la celelalte. Dacă nu ești sigur care îl are, conectează-te temporar la `https://api.wink.travel/mcp`, găsește unealta, apoi verifică care set de unelte o listează.

**`404 Not Found` pe un endpoint de set de unelte**

Verifică cu atenție calea — seturile de unelte imbricate au două segmente (`/mcp/extranet/rates`, nu `/mcp/extranet-rates`), iar cele plate au unul (`/mcp/link-manager`). Reține că o cerere *neautentificată* către orice cale sub `/mcp` returnează `401`, nu `404`, deci un `401` singur nu indică dacă endpoint-ul există.

**M-am conectat la `api.wink.travel/mcp/channel-manager` și nu am primit nimic**

Acest endpoint nu există. Integrarea channel manager este servită doar de la `https://integrations.wink.travel/mcp/channel-manager`. Dacă ai nevoie și să citești sau să scrii tarifele proprii ale unei proprietăți manual, aceasta este o sarcină separată pe un endpoint separat — vezi `/mcp/extranet/rates`.

**Serverul apare, dar apelurile uneltelor returnează "contul nu a fost găsit"**

Ești autentificat într-un cont Wink care nu are o entitate de management. Mergi la [Wink Portal](https://app.wink.travel) și asigură-te că contul tău este configurat înainte de a folosi serverul MCP.

**Tokenul expiră în timpul sesiunii**

Tokenurile sunt valabile 3 ore. Claude Code și Claude Desktop reîmprospătează tokenurile silențios fără a întrerupe sesiunea. Dacă vezi erori de autentificare după o perioadă lungă de inactivitate, tastează un mesaj nou — clientul se va reautentifica automat.

**Codex CLI afișează "MCP server unreachable"**

Verifică dacă `~/.codex/config.json` este JSON valid (fără virgule finale) și că `"type": "http"` este setat. Codex necesită transport HTTP pentru servere remote; transportul stdio este doar pentru binare locale.

**Meniul "Connectors" din ChatGPT lipsește**

Suportul MCP necesită versiunea aplicației desktop ChatGPT **1.2024.352** sau mai nouă și un abonament activ Plus, Pro, Team sau Enterprise. Actualizează aplicația și verifică planul în Setări → Cont.

**Serverul Cursor apare roșu / "Failed to connect"**

Verifică dacă `~/.cursor/mcp.json` este JSON valid și conține `"type": "http"`. Apoi mergi la **Settings → Cursor Settings → MCP** și apasă **Refresh**. Dacă eroarea persistă, repornește complet Cursor — modificările de configurare nu sunt întotdeauna preluate fără restart.

**Serverele MCP Windsurf nu apar în setări**

Windsurf necesită o repornire completă (nu doar reîncărcarea ferestrei) pentru a prelua modificările din `mcp_config.json`. Folosește **File → Quit** și redeschide. Dacă serverele încă nu apar, confirmă că ai Windsurf **1.4+** prin **Help → About Windsurf**.

**Opțiunea "Add Server" din Cline nu este vizibilă**

Managerul de servere MCP necesită Cline **2.0** sau mai nou. Deschide panoul Extensions din VS Code, găsește Cline și apasă **Update** dacă există o actualizare. După actualizare, reîncarcă VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
