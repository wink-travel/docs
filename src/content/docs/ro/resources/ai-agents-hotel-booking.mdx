## Recomandarea unui hotel nu înseamnă rezervarea lui

Majoritatea „turismului AI” de astăzi se oprește la recomandare. Un asistent sugerează trei hoteluri, apoi predă călătorul către un site web sau un OTA pentru a face rezervarea efectivă. Firul se rupe, prețul poate să nu fie rezervabil, iar nimeni nu păstrează contextul sursei.

Un **agent AI** este diferit de un răspuns AI. Un agent nu doar descrie un hotel — acționează: verifică disponibilitatea live, asamblează o rezervare, preia plata și poate reacționa când ceva se schimbă. Pentru ca asta să se întâmple în siguranță, agentul are nevoie de mai mult decât text. Are nevoie de date structurate, actuale, rezervabile și un strat de tranzacție pe care să îl poată apela.

Aceasta este diferența dintre [descoperirea AI](/ro/resources/ai-discovery-hotels/), care ține de a fi **găsit și înțeles**, și comerțul agentic, care ține de a fi **tranzacționat**.

## Ce are nevoie un agent înainte să poată tranzacționa

O rezervare de hotel este un eveniment comercial real: camera potrivită, tariful corect, disponibilitate reală, politici, plată și o confirmare care se sincronizează înapoi cu hotelul. Un agent poate finaliza asta doar dacă fiecare element este disponibil ca o operațiune apelabilă.

| Ce are nevoie agentul | De ce contează |
|---|---|
| Ofertă structurată, live | Datele extrase de pe web devin învechite; agentul are nevoie de inventar actual, controlat de hotel. |
| Tarife și disponibilitate în timp real | Prețul pe care agentul îl oferă trebuie să fie efectiv rezervabil în acel moment. |
| O operațiune de rezervare | Crearea rezervării trebuie să fie un apel real API, nu o redirecționare către un formular web. |
| Plata | Agentul (sau călătorul prin el) trebuie să poată plăti, cu aplicarea logicii politicilor. |
| Atribuirea | Sursa, campania sau agentul care a creat rezervarea trebuie să rămână atașate. |
| Evenimente | Agentul trebuie să poată reacționa la confirmări, modificări, anulări și rambursări. |

Fără acestea, un agent poate recomanda — dar nu poate rezerva.

## Cum rezervă un agent AI un hotel pe Wink

Wink este API-first: fiecare funcție a platformei este apelabilă extern, iar un server MCP găzduit expune contractele API live agenților. Un flux tipic de agent:

### 1 — Conectare și citirea contractelor live

Agentul se conectează la serverul MCP găzduit și folosește `api_search` și `docs_search` pentru a găsi operațiunile potrivite și a citi schemele reale de cerere/răspuns — fără ghiciri la endpoint-uri, fără documentații învechite.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Căutarea inventarului rezervabil

Agentul caută oferta controlată de hotel, inclusiv căutare spațială geolocalizată, și citește tarifele și disponibilitatea live prin managerii de canal conectați.

### 3 — Crearea rezervării

Crearea rezervării este o operațiune REST API. Agentul asamblează camera, tariful, datele și oaspeții și creează rezervarea prin API.

### 4 — Preluarea plății și confirmarea

[Booking Engine](/ro/products/booking-engine/) îndeplinește tranzacția — checkout, plata (Wink este comerciantul înregistrat), logica politicii de anulare, confirmarea și sincronizarea rezervării cu PMS-ul sau managerul de canal conectat. Atribuirea sursei și partenerului este păstrată prin rezervare.

### 5 — Reacția la evenimente

Agentul se poate abona la `booking.created` și alte evenimente webhook pentru reconciliere, notificarea călătorului sau declanșarea unor acțiuni ulterioare.

Principiul: **agentul creează sau direcționează intenția; Booking Engine rămâne stratul de îndeplinire sub fiecare predare.**

## Căutarea AI vs agenții AI

Rezolvă sarcini diferite, iar un hotel trebuie să fie pregătit pentru ambele.

| | Căutare AI / motoare de răspuns | Agenți AI |
|---|---|---|
| Scopul călătorului | Găsirea și compararea hotelurilor | Rezervarea și gestionarea unui sejur |
| Ce are nevoie hotelul | [Conținut structurat, crawlabil](/ro/resources/hotel-content-answer-engines/) | API live, tarife, rezervare, plată |
| Stadiul final | O recomandare | O rezervare confirmată |
| Suprafața Wink | Ofertă curată + conținut pregătit pentru răspuns | REST API, server MCP, Booking Engine |

[Descoperirea AI pentru hoteluri](/ro/resources/ai-discovery-hotels/) acoperă partea de căutare; acest ghid acoperă partea de tranzacție.

## Cine construiește agenți pe comerțul hotelier

Comerțul agentic în turism nu sunt doar asistenți pentru consumatori. Aceeași infrastructură alimentează:

- **Asistenți de turism pentru consumatori** care caută, rezervă și gestionează un sejur de la început până la sfârșit.
- **Agenți bancari, de loialitate și super-app** care integrează rezervarea hotelurilor în experiența existentă a clientului.
- **Automatizări pentru parteneri și creatori** care descoperă hoteluri eligibile, construiesc active și păstrează atribuirea conectată — câștigând un comision implicit de 10% la rezervările confirmate.
- **Copiloți din partea hotelului** care ajută echipele să genereze conținut și să analizeze performanța în [Extranet](/ro/products/extranet/), [Social](/ro/products/social/) și [Studio](/ro/products/studio/), în timp ce hotelul păstrează regulile.

## În ce direcție se îndreaptă

Capabilitățile de mai sus sunt live astăzi prin REST API și server MCP. Direcția este un comerț agentic mai profund: primitive de rezervare mai bogate pentru agenți, identitate și autorizare pentru agenți pentru a tranzacționa în numele călătorului și agenți care participă ca surse atribuite, câștigătoare în rețeaua de parteneri. Firul roșu este consecvent — **infrastructură de comerț în turism pentru agenți AI**, cu Booking Engine care îndeplinește în spate.

## Greșeli comune

- **A trata descoperirea AI și agenții AI ca același proiect.** Unul este conținut și structură; celălalt este API și îndeplinire. Ai nevoie de ambele.
- **A permite agenților să ofere prețuri pe care nu le pot rezerva.** Cotațiile trebuie să vină din tarife și disponibilitate live, nu din pagini extrase.
- **A pierde atribuirea la predare.** Dacă un agent creează cerere, rezervarea trebuie să rămână conectată la acea sursă.
- **A sări peste stratul de îndeplinire.** Un răspuns nu este o rezervare până când checkout-ul, plata și confirmarea nu au loc efectiv.
