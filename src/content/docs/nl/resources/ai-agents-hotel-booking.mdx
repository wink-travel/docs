## Een hotel aanbevelen is niet hetzelfde als er een boeken

De meeste "AI-reis" stopt vandaag bij de aanbeveling. Een assistent suggereert drie hotels en verwijst de reiziger dan door naar een website of OTA om daadwerkelijk te boeken. De verbinding breekt, de prijs is mogelijk niet boekbaar, en niemand bewaart de broncontext.

Een **AI-agent** is anders dan een AI-antwoord. Een agent beschrijft niet alleen een hotel — hij handelt: hij controleert live beschikbaarheid, stelt een boeking samen, verwerkt betaling en kan reageren als er iets verandert. Om dat veilig te laten gebeuren, heeft de agent meer nodig dan tekst. Hij heeft gestructureerde, actuele, boekbare data en een transactielaag die hij kan aanroepen.

Dit is het verschil tussen [AI discovery](/nl/resources/ai-discovery-hotels/), dat gaat over **gevonden en begrepen worden**, en agentic commerce, dat gaat over **transacteren**.

## Wat een agent nodig heeft voordat hij kan transacteren

Een hotelboeking is een echte commerciële gebeurtenis: de juiste kamer, het juiste tarief, echte beschikbaarheid, voorwaarden, betaling en een bevestiging die terug synchroon loopt naar het hotel. Een agent kan dat alleen afronden als elk onderdeel beschikbaar is als een aanroepbare operatie.

| Wat de agent nodig heeft | Waarom het belangrijk is |
|---|---|
| Gestructureerde, live voorraad | Web-scraped data raakt verouderd; een agent heeft actuele, door het hotel gecontroleerde inventaris nodig. |
| Real-time tarieven & beschikbaarheid | Een prijs die de agent noemt moet op dat moment daadwerkelijk boekbaar zijn. |
| Een boekingsoperatie | Het maken van de reservering moet een echte API-aanroep zijn, geen doorverwijzing naar een webformulier. |
| Betaling | De agent (of de reiziger via hem) moet kunnen betalen, met toepasselijke beleidslogica. |
| Attributie | De bron, campagne of agent die de boeking maakte moet verbonden blijven. |
| Gebeurtenissen | De agent moet kunnen reageren op bevestigingen, wijzigingen, annuleringen en terugbetalingen. |

Zonder deze kan een agent aanbevelen — maar niet boeken.

## Hoe een AI-agent een hotel boekt op Wink

Wink is API-first: elke platformfunctie is extern aanroepbaar, en een gehoste MCP-server biedt de live API-contracten aan agents. Een typische agent-flow:

### 1 — Verbinden en de live contracten lezen

De agent verbindt met de gehoste MCP-server en gebruikt `api_search` en `docs_search` om de juiste operaties te vinden en hun actuele request/response-schema’s te lezen — geen giswerk bij endpoints, geen verouderde documentatie.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Boekbare inventaris zoeken

De agent zoekt in door het hotel gecontroleerde voorraad, inclusief geolocatie-ruimtelijke zoekopdrachten, en leest live tarieven en beschikbaarheid via aangesloten channel managers.

### 3 — De boeking maken

Boeking maken is een REST API-operatie. De agent stelt de kamer, het tarief, de data en gasten samen en maakt de reservering via de API.

### 4 — Betaling verwerken en bevestigen

[Booking Engine](/nl/products/booking-engine/) verzorgt de transactie — afrekenen, betaling (Wink is de merchant of record), annuleringsbeleid, bevestiging en synchronisatie van de boeking met het aangesloten PMS of channel manager. Bron- en partnerattributie blijven behouden via de boeking.

### 5 — Reageren op gebeurtenissen

De agent kan zich abonneren op `booking.created` en andere webhook-events om te reconciliëren, de reiziger te informeren of vervolgacties te triggeren.

Het principe: **de agent creëert of leidt intentie; Booking Engine blijft de fulfillmentlaag onder elke overdracht.**

## AI-zoekopdrachten versus AI-agents

Ze lossen verschillende taken op, en een hotel moet voor beide klaar zijn.

| | AI-zoekopdrachten / antwoordmachines | AI-agents |
|---|---|---|
| Doel reiziger | Hotels vinden en vergelijken | Een verblijf boeken en beheren |
| Wat het hotel nodig heeft | [Gestructureerde, doorzoekbare content](/nl/resources/hotel-content-answer-engines/) | Live API, tarieven, boeking, betaling |
| Eindresultaat | Een aanbeveling | Een bevestigde boeking |
| Wink interface | Schone voorraad + antwoordklare content | REST API, MCP-server, Booking Engine |

[AI discovery voor hotels](/nl/resources/ai-discovery-hotels/) behandelt de zoekkant; deze gids behandelt de transactiekant.

## Wie bouwt agents op hotel commerce

Agentic travel commerce is niet alleen consumentenassistenten. Dezelfde infrastructuur ondersteunt:

- **Consumentenreisassistenten** die een verblijf end-to-end zoeken, boeken en beheren.
- **Bank-, loyaliteits- en super-app agents** die hotelboekingen integreren in een bestaande klantervaring.
- **Partner- en creator-automatiseringen** die geschikte hotels ontdekken, assets bouwen en attributie verbonden houden — met een standaard commissie van 10% op bevestigde boekingen.
- **Hotel-side copilots** die teams helpen content te genereren en prestaties te analyseren via [Extranet](/nl/products/extranet/), [Social](/nl/products/social/) en [Studio](/nl/products/studio/), terwijl het hotel de regels behoudt.

## Waar dit naartoe gaat

De bovenstaande mogelijkheden zijn vandaag live via de REST API en MCP-server. De richting is diepere agent-native commerce: rijkere agentgerichte boekingsprimitieven, agentidentiteit en autorisatie om namens een reiziger te transacteren, en agents die deelnemen als toegeschreven, verdienende bronnen in het partnernetwerk. De rode draad is consistent — **travel commerce-infrastructuur voor AI-agents**, met Booking Engine als fulfillmentlaag eronder.

## Veelvoorkomende fouten

- **AI discovery en AI-agents als hetzelfde project behandelen.** De één is content en structuur; de ander is API en fulfillment. Je hebt beide nodig.
- **Agents prijzen laten noemen die ze niet kunnen boeken.** Offertes moeten komen van live tarieven en beschikbaarheid, niet van gescrapete pagina’s.
- **Attributie laten vallen bij de overdracht.** Als een agent vraag creëert, moet de boeking verbonden blijven aan die bron.
- **De fulfillmentlaag overslaan.** Een antwoord is geen boeking totdat afrekenen, betaling en bevestiging daadwerkelijk plaatsvinden.
