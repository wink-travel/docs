Winks MCP-verktyg publiceras som **verktygssatser** — fokuserade slutpunkter, var och en täcker ett jobb. Du ansluter din AI-klient till en eller två som matchar ditt arbete, inte till alla.

Varje slutpunkt använder **interaktiv OAuth2-inloggning** (PKCE-auktoriseringskodflöde): din AI-agent öppnar en webbläsarflik, du loggar in med ditt Wink-konto, och det är allt. Inga klienthemligheter att hantera.

```bash title="En kanalhanteringsintegratör ansluter till en slutpunkt"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="En hotellägare som hanterar sina egna priser ansluter till en annan"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

---

## Varför verktygen är uppdelade över slutpunkter

Wink exponerar omkring 500 verktyg. Att ge alla till en agent på en gång är tekniskt möjligt — och en dålig idé.

**Verktygsdefinitioner kostar kontext.** Varje verktyg som en MCP-server annonserar laddas in i modellens kontextfönster innan det gör något arbete, tillsammans med dess beskrivning och fullständiga parameterschema. Fem hundra sådana förbrukar en stor del av budgeten som din faktiska uppgift behöver, vid varje enskild förfrågan.

**Valkvaliteten försämras när listan växer.** En agent som väljer bland 500 liknande namngivna verktyg gör sämre val än en som väljer bland 40. Om du integrerar en kanalhanterare är ungefär tjugo verktyg relevanta för dig; de andra 480 är brus som gör det svårare att hitta rätt verktyg.

**Arbetet är verkligen separerbart.** Någon som synkroniserar tillgänglighet från ett PMS och någon som kuraterar affiliate-landningssidor delar nästan inga verktyg. Uppdelning efter jobb innebär att varje anslutning bär vokabulären för ett jobb.

<Aside type="caution" title="Verktygssatser är inte behörigheter">
Att välja en smal verktygssats begränsar **inte** vad ditt konto kan göra, och att välja en bred ger inte något extra. Varje verktyg upprätthåller samma kontobehörigheter som webbportalen, under din inloggade identitet. Om ditt konto inte kan avboka en bokning i Wink Portal kan inte agenten heller — oavsett vilken slutpunkt den är ansluten till.

Välj verktygssatser för **fokus**, inte för säkerhet.
</Aside>

### `https://integrations.wink.travel` — kanalhanterarintegrationer

En slutpunkt, eftersom denna värd finns för ett jobb.

| Slutpunkt | Verktyg | Vad den täcker |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Anslutning och verifiering av kanalhanterare, PMS eller CRS-integration |

<Aside type="note" title="Integrera en kanalhanterare vs. hantera egna priser">
Detta är olika jobb för olika personer, och de delar inte en slutpunkt.

En **kanalhanterare, PMS- eller CRS-leverantör** integrerar en gång via `integrations.wink.travel/mcp/channel-manager`, och utbyter därefter fastigheter, priser, tillgänglighet och reservationer över den integrationen. Den enda slutpunkten är hela ytan.

En **hotellägare som ändrar sina egna priser manuellt** använder extranet-verktygssatserna på `api.wink.travel` — `/mcp/extranet/rates` och liknande. Dessa är inte en del av en kanalhanterarintegration och en integratör har ingen anledning att ansluta till dem.

Kontoadministration finns också på `api.wink.travel`, på `/mcp/settings`. Det finns ingen `/mcp/settings` på integrationsvärden.
</Aside>

Varje slutpunkt har också ett `ping`-verktyg, så att du kan bekräfta att en anslutning är aktiv innan du ber den göra verkligt arbete.

## Vilka verktygssatser behöver jag?

| Om du är… | Anslut till |
|---|---|
| **Integrerar en kanalhanterare, PMS eller CRS** | `integrations.wink.travel/mcp/channel-manager` — bara denna |
| **Hantera en fastighets innehåll** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Hantera rum och rumstyper** | `/mcp/extranet/facilities` |
| **Hantera priser och tillgänglighet** | `/mcp/extranet/rates` |
| **Driva dagliga reservationer** | `/mcp/extranet/operations` |
| **Växa distributionen** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Bygga affiliate-sidor** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Driva länk-i-bio-sidor** | `/mcp/link-manager` + `/mcp/social` |
| **Boka för resenärer** | `/mcp/travel-agent` |
| **Avstämma pengar** | `/mcp/payment` |
| **Bygga en bokningsupplevelse** | `/mcp/booking-engine` + `/mcp/reference` |

Börja med en. Lägg till en annan när du märker att du behöver något den inte kan göra — varje anslutning är oberoende, och att lägga till en påverkar aldrig de andra.

<Aside type="tip" title="Vill du ändå ha allt?">
`https://api.wink.travel/mcp` och `https://integrations.wink.travel/mcp` finns kvar och tillhandahåller **alla** verktyg på sin värd. De är användbara för att utforska vad som finns, men vi rekommenderar dem inte för dagligt arbete: verktygslistan är tillräckligt stor för att tränga ut din uppgift och försämra agentens verktygsval. Föredra verktygssatserna ovan.
</Aside>

## Hur autentisering fungerar

Wink MCP-servrar använder **OAuth2 Authorization Code + PKCE**-flödet och stödjer **Dynamic Client Registration (RFC 7591)**. Så här går det till när du ansluter första gången:

1. Din AI-klient upptäcker auktoriseringsservern från MCP-slutpunktens `/.well-known/oauth-protected-resource` metadata.
2. Klienten registrerar sig själv via **Dynamic Client Registration** — ingen manuell applikationsinställning krävs.
3. Klienten öppnar en **webbläsarflik** till `https://iam.wink.travel`. Du loggar in med ditt Wink-konto och godkänner de begärda behörigheterna på samtyckesskärmen.
4. Wink utfärdar en **åtkomsttoken** som är begränsad till ditt konto och kopplad till din identitet.
5. AI-klienten bifogar token till varje MCP-förfrågan. Alla verktygsresultat är automatiskt begränsade till din hanterande enhet.
6. Token går ut efter 3 timmar. Din AI-klient uppdaterar tyst i bakgrunden utan att fråga igen.

Varje verktygsanrop körs **under din identitet** — samma ACL-regler som skyddar webbportalen gäller för AI-agenten.

## Behörigheter

När du godkänner samtyckesskärmen ser du en uppdelning av vad agenten begär. MCP
klienter använder samma behörighetsvokabulär som resten av plattformen — se fullständig
[behörighetsreferens på autentiseringssidan](/sv/developers/authentication#scopes).

Två saker är specifika för MCP:

- **`mcp.read` `mcp.write` `mcp.remove`-behörigheter krävs dessutom** för att öppna MCP-
  transporten. En klient med en `mcp.*`-behörighet släpps in till vilken Wink MCP-slutpunkt som helst, men varje
  verktyg den anropar upprätthåller fortfarande sektionens behörighet för den slutpunkt den omsluter (t.ex. `booking.read`).
- **AI-klienten begär bara de behörigheter den behöver.** Du kan neka individuella behörigheter på
  samtyckesskärmen — verktyg som kräver en nekad behörighet returnerar ett fel vid anrop.

**Verktygssatser ändrar inget av detta.** Den slutpunkt du ansluter till bestämmer vilka verktyg som *listas*,
inte vad de *får göra*. Att ansluta till `/mcp/payment` ger inga finansiella behörigheter du
inte redan hade, och att ansluta till `/mcp/reference` hindrar inte ett verktyg där från att upprätthålla
sin egen behörighet. Auktorisering avgörs per verktygsanrop, från din token och ditt kontos behörigheter.

## Felsökning

**Webbläsarflik öppnas inte**

Din AI-klient kanske inte stöder det interaktiva PKCE-flödet än. Kontrollera att du kör en aktuell version:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** uppdatera via appens inbyggda uppdaterare

**`401 Unauthorized` efter inloggning**

Din cachade token kan vara föråldrad. Ta bort och lägg till servern igen för att trigga en ny inloggning:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

För Claude Desktop och ChatGPT, ta bort serverposten från inställningarna, starta om appen och lägg till den igen.

**`403 Forbidden` vid anrop av specifikt verktyg**

Verktyget kräver en behörighet du inte godkände på samtyckesskärmen, eller en behörighet ditt konto inte har. Anslut servern igen — samtyckesskärmen visas på nytt och du kan godkänna den saknade behörigheten. Om det fortfarande misslyckas behöver verktyget en kontobehörighet du inte har; att ansluta till en annan verktygssats hjälper inte, eftersom verktygssatser inte ger behörigheter.

**Verktyget jag behöver finns inte i listan**

Du är förmodligen ansluten till en verktygssats som inte täcker det jobbet. Kontrollera [slutpunktskatalogen](#endpoint-directory) och lägg till verktygssatsen som gör det — anslutningar är oberoende, så att lägga till en ändrar inget för de andra. Om du är osäker på vilken som har det, anslut till `https://api.wink.travel/mcp` tillfälligt, hitta verktyget, och se sedan vilken verktygssats som listar det.

**`404 Not Found` på en verktygssats-slutpunkt**

Kontrollera sökvägen noggrant — de nästlade verktygssatserna har två segment (`/mcp/extranet/rates`, inte `/mcp/extranet-rates`), och de platta har ett (`/mcp/link-manager`). Observera att en *oauktoriserad* förfrågan till någon sökväg under `/mcp` returnerar `401`, inte `404`, så enbart `401` säger inte om slutpunkten finns.

**Jag anslöt till `api.wink.travel/mcp/channel-manager` och fick inget**

Den slutpunkten finns inte. Kanalhanterarintegration serveras endast från `https://integrations.wink.travel/mcp/channel-manager`. Om du också behöver läsa eller skriva en fastighets egna priser manuellt är det ett separat jobb på en separat slutpunkt — se `/mcp/extranet/rates`.

**Servern visas men verktygsanrop returnerar "konto hittades inte"**

Du är inloggad på ett Wink-konto som inte har någon hanterande enhet. Gå till [Wink Portal](https://app.wink.travel) och se till att ditt konto är korrekt inställt innan du använder MCP-servern.

**Token går ut mitt i sessionen**

Token är giltiga i 3 timmar. Claude Code och Claude Desktop uppdaterar token tyst utan att avbryta din session. Om du ser autentiseringsfel efter en lång inaktiv period, skriv ett nytt meddelande — klienten autentiserar automatiskt om.

**Codex CLI visar "MCP server unreachable"**

Kontrollera att din `~/.codex/config.json` är giltig JSON (inga avslutande kommatecken) och att `"type": "http"` är satt. Codex kräver HTTP-transport för fjärrservrar; stdio-transport är endast för lokala binärer.

**ChatGPT:s "Connectors"-meny saknas**

MCP-stöd kräver ChatGPT desktop-app version **1.2024.352** eller senare och en aktiv Plus-, Pro-, Team- eller Enterprise-prenumeration. Uppdatera appen och kontrollera din plan under Inställningar → Konto.

**Cursor-server visar rött / "Failed to connect"**

Verifiera att din `~/.cursor/mcp.json` är giltig JSON och innehåller `"type": "http"`. Gå sedan till **Settings → Cursor Settings → MCP** och klicka på **Refresh**. Om felet kvarstår, starta om Cursor helt — konfigurationsändringar plockas inte alltid upp utan omstart.

**Windsurf MCP-servrar visas inte i inställningar**

Windsurf kräver full omstart (inte bara fönsterladdning) för att plocka upp ändringar i `mcp_config.json`. Använd **Arkiv → Avsluta** och starta om. Om servrar fortfarande inte visas, kontrollera att du har Windsurf **1.4+** via **Hjälp → Om Windsurf**.

**Cline "Add Server"-alternativ syns inte**

MCP-serverhanteraren kräver Cline **2.0** eller senare. Öppna VS Code Extensions-panelen, hitta Cline och klicka på **Uppdatera** om en uppdatering finns. Efter uppdatering, ladda om VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
