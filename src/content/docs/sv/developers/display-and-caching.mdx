Demand Partner Agreement tillåter inte prisjämförelse med Wink-utbud "annat än som uttryckligen tillåts" (punkt 11.3). Denna sida förklarar hur Wink ger det tillståndet för sökvisning, och reglerna din visning måste följa när du har det.

## Vad sökvisning innebär

**Sökvisning** är att visa hotell från Partner API som svar på en användares sökning, tillsammans med andra hotell erbjudanden, inklusive obetalda alternativ från andra källor, med en klicklänk som öppnar det valda hotellets Wink Booking Engine under ditt affiliatekonto.

Det omfattar endast sökning, innehåll och klicklänk. Att skapa, ändra eller avboka bokningar via Partner API kräver Winks separata skriftliga godkännande.

## Regler för varje visning

- **Livepriser.** Priser och tillgänglighet måste spegla live-data vid visningstillfället (punkt 8.2).
- **Oförändrade priser.** Visa varje pris exakt som Partner API returnerar det, utan påslag, avgift eller ändring. Hotellet sätter och kontrollerar sitt pris.
- **Korrekt presentation.** Visa priser, inkluderingar och avbokningsregler korrekt och utan att ändra deras innebörd (punkt 6.1).
- **Presentera aldrig Wink som säljare.** Din produkt ska vara visuellt och strukturellt åtskild från Wink, aldrig framställa sig som Wink, och aldrig framställa Wink som en separat online resebyrå eller som säljare (punkt 7.4). Kontraktet för vistelsen är mellan resenären och hotellet.
- **Upplysning.** Upplys om din kommersiella relation med Wink där lagen kräver det (punkt 6.2).
- **Ingen vidareanvändning.** Får inte underlicensiera, överföra eller avslöja Wink-utbudsdata eller innehåll till någon annan (punkt 11.3).

## Tillfällig visning

Wink sätter ingen tidsgräns för hur länge du får behålla ett sökresultat, eftersom ingen vet när ett pris kommer att ändras: ett hotell kan ändra det om fem sekunder eller om ett år. Det viktiga är att priset och tillgängligheten du visar stämmer överens med live-data vid visningstillfället (punkt 8.2). Hämta igen från Partner API när resplanen ändras, och innan du visar ett resultat du inte kan vara säker på fortfarande är aktuellt.

Visning som följer dessa regler är inte en "statisk kopia av innehåll" enligt punkt 7.5, inte heller cachelagring av föråldrade priser enligt punkt 8.2.

## Cachelagring av fastighetsinnehåll

Fastighetsinnehåll (namn, beskrivningar, bilder, bekvämligheter och regler) har ingen tidsgräns för cachelagring. Använd varje fastighets `lastUpdate` från Partner API som din cache-nyckel, och uppdatera fastighetens innehåll när det ändras.

## Identifierare du får behålla

Du får behålla dessa, och endast dessa:

- Wink fastighets-ID och fastighetens `urlName`,
- bokningsreferensnummer för bokningar som tillskrivs dig,
- dina egna attribut-, klient- och konfigurations-ID:n, med tillhörande klick- och bokningsdatum.

Använd dem endast för att undvika dubbletter av hotelllistningar över källor, samt för attributering, rapportering och provisionsavstämning. Behåll inte priser, tillgänglighet eller fastighetsinnehåll utöver reglerna ovan, och använd inte någon data från Wink, inklusive dessa identifierare, för att träna, finjustera eller utvärdera en modell, eller för att bygga eller förbättra en utbudsdatabas (punkterna 7.5 och 10.6).

## Hur man begär tillstånd

Sökvisning kräver Winks uttryckliga skriftliga tillstånd, givet som ett sidobrev till ditt Demand Partner Agreement. Det träder i kraft när både brevet och avtalet är accepterade, och Wink kan återkalla det med varsel eller omedelbart om reglerna ovan bryts.

För att begära det, mejla [legal@wink.travel](mailto:legal@wink.travel) med:

- ditt produktnamn,
- dess URL, om den är live,
- hur du planerar att använda Wink-utbudet: vad du kommer att visa, var och tillsammans med vad.

Vi tar det därifrån.
