Denna sida listar varje webhook-händelse du kan prenumerera på i Wink. För installationsinstruktioner, se [Webhook Integration Guide](/sv/developers/webhook-integration) eller [Webhooks management page](/sv/portal/settings/webhooks).

## Hur man prenumererar

1. Navigera till **Applications > Webhooks** i din portal.
2. Skapa en webhook och välj de händelser du vill ta emot — eller lämna listan tom för att ta emot alla händelser.
3. Wink skickar en signerad HTTP POST till din endpoint varje gång händelsen inträffar. Se [Webhook Integration](/sv/developers/webhook-integration) för information om kuvert, headers, signaturverifiering och omförsök.

## Varje händelsetyp

Denna tabell genereras från plattformens händelsekatalog vid byggtid, så den matchar alltid API:et.
Händelsetyper markerade som levererade länkar till deras referenssida i [Webhooks API](/sv/api/webhooks/), som
dokumenterar den exakta JSON-kroppen (`WebhookEnvelope` med ett händelsespecifikt `object`), `Wink-*` headers och
omförsökspolicyn. Händelsetyper som inte levereras finns internt (betalningar, bokföring, kanalhanterarsynk,
…) men skickas för närvarande inte till webhook-prenumeranter.

**Mottagare** anger vem som tar emot en händelse: `SUPPLIER` (hotellet), `AFFILIATE` (en återförsäljare med en aktiv
försäljningskanal till hotellet), `AGENT` (resebyrån som gjorde bokningen) eller `SELF` (den hanterande enheten
som händelsen gäller). Varje mottagare får samma payload-format; rollspecifik information finns bakom
payloadens `links.self` URL.

:::tip
Börja med att prenumerera på alla händelser under utvecklingen. När du förstår vilka payloads ditt system behöver, begränsa dina prenumerationer för att minska brus. Skicka en testhändelse till dig själv från **Applications > Webhooks** (eller `POST …/webhook/{id}/test`) för att bekräfta din endpoint och signaturkontroll innan du går live.
:::
