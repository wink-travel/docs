Webhookid võimaldavad teie süsteemidel saada reaalajas teavitusi, kui teie Wink kontol toimuvad sündmused — uued broneeringud, tühistamised, maksete uuendused ja palju muud. See juhend juhendab teid seadistamise ja parimate tavade osas.

## Sihtgrupp

See juhend on mõeldud arendajatele, kes integreerivad Winki väliste süsteemidega, nagu kinnisvarahaldussüsteemid (PMS), kanalihaldurid, CRM-id või kohandatud juhtpaneelid.

## Kuidas webhookid töötavad

1. Registreerite Winkis webhooki URL-i.
2. Kui toimub sündmus (nt uus broneering), saadab Wink teie URL-ile HTTP POST päringu.
3. Teie server töötleb andmepaketi ja vastab `200 OK`-ga.

## Webhooki seadistamine

<Steps>
1. Logige sisse oma kontole (Extranet, Studio või TripPay — kõik toetavad webhooke).
2. Minge jaotisse `Applications` ja seejärel `Webhooks`. Vaadake [Webhookid](/et/portal/settings/webhooks).
3. Klõpsake `Create webhook`.
4. Sisestage **nimi** (nt "PMS Broneeringu sünkroonimine").
5. Sisestage oma **webhooki URL** — HTTPS lõpp-punkt teie serveris.
6. **Valige sündmused** — valige konkreetsed sündmused, millele tellida, või jätke tühjaks, et saada kõik sündmused.
7. Lülitage **Enabled** sisse.
8. Klõpsake `Save` — vastuses kuvatakse teie **allkirjastamise saladus ainult korra**; salvestage see kohe.
</Steps>

## Mida te saate

Iga edastus on HTTP `POST` teie webhooki URL-ile koos `Content-Type: application/json` ja selle ümbrisega:

```json
{
  "id": "0198a4f2-6b0e-7c1d-9a3e-2f4b8c6d1e0a",
  "type": "booking.create",
  "occurredAt": "2026-08-15T09:30:00Z",
  "ownerIdentifier": "3c6b1a5d-8e2f-4a0b-9c7d-6e4f0a8b2c51",
  "recipientRole": "SUPPLIER",
  "schemaVersion": 2,
  "object": { "...": "sündmusele spetsiifiline andmepakett, nt BookingWebhookPayload" }
}
```

- `id` — sündmuse identifikaator; identne kõigi teie konto lõpp-punktidega, mis seda sündmust saavad, ja iga taastegemise korral. Kasutage seda kui oma **idempotentsuse võtit**.
- `type` — sündmuse tüübi võti (saadetakse ka päises `Wink-Event-Type`). Töötlege `type` ja `schemaVersion` alusel `object`i.
- `object` — kureeritud kokkuvõte ressursist, mille kohta sündmus on (identifikaatorid, olek, väljad, millega tegutsete) pluss `links.self`, tarnija poolne kanoniline REST URL kogu ressursile. Hankige see oma API volitustega, kui vajate rohkem kui kokkuvõtet; kui saate sündmuse edasimüüjana või reisibüroona, kasutage sama identifikaatoriga oma API vastavat ressursi lõpp-punkti.

Iga andmepaketi skeem on dokumenteeritud sündmuse kaupa [Webhookide API](/et/api/webhooks/) viites.

### Päised

| Päis | Tähendus |
|---|---|
| `Wink-Version` | Liidese versioon, `2.0`. |
| `Wink-Event-Id` | Sama mis `id` kehas — teie idempotentsuse võti. |
| `Wink-Delivery-Id` | Unikaalne iga lõpp-punkti ja sündmuse kohta; muutub ainult uuesti edastamisel. |
| `Wink-Event-Type` | Sama mis `type` kehas. |
| `Wink-Delivery-Attempt` | Selle edastuse 1-põhine katse number. |
| `Wink-Signature` | HMAC allkiri — vt allpool. |

## Allkirjade kontrollimine

Igal webhookil on **allkirjastamise saladus** (`whsec_…`), mille Wink näitab **ainult korra**, kui webhook luuakse või saladus uuendatakse. Salvestage see nagu parool. Iga edastus kannab

```
Wink-Signature: t=1755250200,v1=5d41402abc4b2a76b9719d911017c592…
```

kus `t` on Unix ajatempli sekundites ja `v1` on väiketähtedega heksades **HMAC-SHA256** stringist
`t + "." + rawBody`, võtitena kasutades teie saladust, ning `rawBody` on täpne päringu keha baitidena — ärge uuesti serialiseerige JSON-i enne kontrollimist. 24 tundi pärast saladuse uuendamist kannab päis teist `v1=` väärtust, mis on allkirjastatud eelmise saladusega; aktsepteerige edastust, kui **ükskõik milline** `v1` sobib.

Kontrollige neljas etapis: parsige `t` ja iga `v1`; arvutage HMAC uuesti `t.rawBody` peal oma saladusega; võrrelge konstantse aja võrdlusega; lükake tagasi, kui `|now − t|` ületab teie tolerantsi (soovitatav 5 minutit).

```js
// Node.js (Express-stiilis; veenduge, et teil on RAW keha, mitte parsitud objekt)
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verifyWinkSignature(header, rawBody, secret, toleranceSeconds = 300) {
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=').map((s) => s.trim())));
  const t = Number(parts.t);
  if (!Number.isFinite(t) || Math.abs(Date.now() / 1000 - t) > toleranceSeconds) return false;
  const expected = createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  return header
    .split(',')
    .filter((p) => p.trim().startsWith('v1='))
    .map((p) => p.trim().slice(3))
    .some((v1) => v1.length === expected.length && timingSafeEqual(Buffer.from(v1, 'utf8'), Buffer.from(expected, 'utf8')));
}
```

```java
// Java
static boolean verify(String header, String rawBody, String secret, long nowSeconds, long toleranceSeconds) throws Exception {
    long t = Long.MIN_VALUE;
    List<String> signatures = new ArrayList<>();
    for (String part : header.split(",")) {
        String[] kv = part.trim().split("=", 2);
        if (kv[0].equals("t")) t = Long.parseLong(kv[1]);
        else if (kv[0].equals("v1")) signatures.add(kv[1]);
    }
    if (t == Long.MIN_VALUE || Math.abs(nowSeconds - t) > toleranceSeconds) return false;
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
    byte[] expected = HexFormat.of().formatHex(mac.doFinal((t + "." + rawBody).getBytes(StandardCharsets.UTF_8))).getBytes(StandardCharsets.US_ASCII);
    return signatures.stream().anyMatch(v1 -> MessageDigest.isEqual(expected, v1.toLowerCase().getBytes(StandardCharsets.US_ASCII)));
}
```

Pöörake saladus ümber portaalis või käsuga `POST /api/managing-entity/{id}/webhook/{webhookId}/rotate-secret`;
vastus näitab uut saladust ainult korra ning vana saladus kehtib 24 tundi, kuni see on täielikult kasutusele võetud.

## Taastegemised ja uuesti edastamine

- Vastake mis tahes `2xx` koodiga 10 sekundi jooksul, et kinnitada vastuvõtt. Tehke raske töö asünkroonselt.
- `5xx`, aegumine, `408` või `429` korral proovib süsteem uuesti tagasilöökidega: 1 minut, 5 minutit, 30 minutit, 2 tundi,
  6 tundi, 12 tundi, seejärel iga päev — kokku 10 katset umbes 3 päeva jooksul — pärast mida märgitakse edastus **surnuks**.
- Iga teine `4xx` käsitletakse kui "te lükkasite selle edastuse tagasi" ja seda **ei proovita uuesti**.
- Iga sündmus, edastus ja katse (olek, vastuse lõik) on nähtav jaotises **Applications > Webhooks**
  ja API kaudu (`…/webhook/event/grid`, `…/webhook/delivery/grid`). Võite **uuesti edastada** mis tahes edastuse
  (`POST …/webhook/delivery/{deliveryId}/redeliver`, mis alustab uut taastegemiste seeriat), uuesti edastada kõik surnud
  edastused korraga (`POST …/webhook/{webhookId}/redeliver-dead`) või tühistada ühe.
- Edastused säilitatakse 30 päeva.

## Testisündmused

Saatke endale sünteetiline `webhook.test` sündmus portaalist või käsuga
`POST /api/managing-entity/{id}/webhook/{webhookId}/test`. See on allkirjastatud ja edastatud täpselt nagu päris
sündmus, nii et saate kontrollida oma lõpp-punkti, allkirja kontrolli ja idempotentsuse käsitlemist enne elusündmustele tellimist.

## Parimad tavad

- **Kasutage HTTPS-i** — Wink saadab andmepakette ainult HTTPS lõpp-punktidele.
- **Vastake kiiresti** — Tagastage `200 OK` kohe, kui saate andmepaketi. Tehke raske töö asünkroonselt.
- **Idempotentsus** — Teie töötleja peaks olema idempotentne; duplikaatide vältimiseks kasutage `Wink-Event-Id`. Wink proovib uuesti, kui ei saa `2xx` vastust.
- **Allika valideerimine** — Kontrollige `Wink-Signature` päist (vt [Allkirjade kontrollimine](#verifying-signatures)) enne töötlemist; lükake tagasi kõik, mis ei sobi.
- **Logimine** — Logige iga webhooki andmepakett, mida saate. See teeb integreerimisprobleemide silumise palju lihtsamaks.

## Paus ja kustutamine

Võite webhooki **keelata** ilma seda kustutamata. See peatab edastamise, et saaksite tõrkeotsingut teha ilma konfiguratsiooni kaotamata. Kui olete valmis, lülitage see uuesti sisse.

Webhooki kustutamine eemaldab selle jäädavalt. Kõik integreerimised, mis sõltuvad sellest webhookist, lõpetavad teavituste saamise.
