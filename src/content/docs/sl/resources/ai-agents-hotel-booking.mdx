## Priporočanje hotela ni enako rezervaciji

Večina današnjih "AI potovanj" se ustavi pri priporočilu. Asistent predlaga tri hotele, nato pa popotnika preda na spletno stran ali OTA za dejansko rezervacijo. Nit se prekine, cena morda ni rezervabilna in nihče ne ohranja konteksta vira.

**AI agent** se razlikuje od AI odgovora. Agent ne opisuje le hotela — deluje: preverja živo razpoložljivost, sestavi rezervacijo, sprejme plačilo in se lahko odzove, ko se kaj spremeni. Da se to zgodi varno, agent potrebuje več kot besedilo. Potrebuje strukturirane, aktualne, rezervabilne podatke in sloj transakcij, ki ga lahko kliče.

To je razlika med [AI odkrivanjem](/sl/resources/ai-discovery-hotels/), ki je o tem, da si **najden in razumljen**, in agentnim trgovanjem, ki je o tem, da si **transaktiran**.

## Kaj agent potrebuje, preden lahko izvede transakcijo

Rezervacija hotela je pravi komercialni dogodek: prava soba, prava cena, resnična razpoložljivost, pravila, plačilo in potrditev, ki se sinhronizira nazaj s hotelom. Agent lahko to izvede le, če je vsak del na voljo kot klicna operacija.

| Agent potrebuje | Zakaj je pomembno |
|---|---|
| Strukturirano, živo ponudbo | Podatki, pridobljeni s spletnim strganjem, zastarajo; agent potrebuje aktualen, s hotelom nadzorovan inventar. |
| Cene in razpoložljivost v realnem času | Cena, ki jo agent navaja, mora biti dejansko rezervabilna v tistem trenutku. |
| Operacijo rezervacije | Ustvarjanje rezervacije mora biti pravi klic API-ja, ne predaja na spletni obrazec. |
| Plačilo | Agent (ali popotnik prek njega) mora imeti možnost plačila z upoštevanjem pravilnikov. |
| Atribucijo | Vir, kampanja ali agent, ki je ustvaril rezervacijo, mora ostati pripet. |
| Dogodke | Agent se mora lahko odzvati na potrditve, spremembe, odpovedi in vračila. |

Brez tega lahko agent le priporoča — ne more rezervirati.

## Kako AI agent rezervira hotel na Wink

Wink je API-prvi: vsaka funkcija platforme je klicna od zunaj, gostovani MCP strežnik pa agentom razkriva žive API pogodbe. Tipičen potek agenta:

### 1 — Poveži se in preberi žive pogodbe

Agent se poveže z gostovanim MCP strežnikom in uporabi `api_search` in `docs_search`, da najde prave operacije in prebere njihove dejanske sheme zahtevkov/odgovorov — brez ugibanja končnih točk, brez zastarelih dokumentov.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Išči rezervabilen inventar

Agent išče s hotelom nadzorovano ponudbo, vključno z geolokacijskim prostorskim iskanjem, in bere žive cene ter razpoložljivost prek povezanih upravljavcev kanalov.

### 3 — Ustvari rezervacijo

Ustvarjanje rezervacije je REST API operacija. Agent sestavi sobo, ceno, datume in goste ter ustvari rezervacijo prek API-ja.

### 4 — Sprejmi plačilo in potrdi

[Booking Engine](/sl/products/booking-engine/) izvede transakcijo — zaključek nakupa, plačilo (Wink je trgovec v registru), logiko pravilnikov odpovedi, potrditev in sinhronizacijo rezervacije s povezanimi PMS ali upravljavcem kanalov. Vir in partnerska atribucija se ohranita skozi rezervacijo.

### 5 — Odzovi se na dogodke

Agent se lahko naroči na `booking.created` in druge webhook dogodke za uskladitev, obveščanje popotnika ali sprožitev nadaljnjih dejanj.

Načelo: **agent ustvarja ali usmerja namen; Booking Engine ostaja sloj izvršitve pod vsakim prenosom.**

## AI iskanje proti AI agentom

Rešujeta različne naloge, hotel pa mora biti pripravljen na obe.

| | AI iskanje / odgovorni sistemi | AI agenti |
|---|---|---|
| Cilj popotnika | Najti in primerjati hotele | Rezervirati in upravljati bivanje |
| Kaj hotel potrebuje | [Strukturirane, preplezljive vsebine](/sl/resources/hotel-content-answer-engines/) | Živ API, cene, rezervacije, plačila |
| Končni rezultat | Priporočilo | Potrjena rezervacija |
| Wink površina | Čista ponudba + vsebina pripravljena za odgovore | REST API, MCP strežnik, Booking Engine |

[AI odkrivanje za hotele](/sl/resources/ai-discovery-hotels/) pokriva iskalno stran; ta vodič pokriva transakcijsko stran.

## Kdo gradi agente za hotelsko trgovanje

Agentno potovalno trgovanje niso le potrošniški asistenti. Enaka infrastruktura poganja:

- **Potrošniške potovalne asistente**, ki iščejo, rezervirajo in upravljajo bivanje od začetka do konca.
- **Bančne, zvestobne in super-aplikacijske agente**, ki vključujejo rezervacijo hotela v obstoječo uporabniško izkušnjo.
- **Partnerske in ustvarjalne avtomatizacije**, ki odkrijejo primerne hotele, ustvarjajo vsebine in ohranjajo povezano atribucijo — zaslužijo 10 % privzete provizije na potrjene rezervacije.
- **Hotelske pomočnike**, ki pomagajo ekipam ustvarjati vsebine in analizirati uspešnost prek [Extranet](/sl/products/extranet/), [Social](/sl/products/social/) in [Studio](/sl/products/studio/), medtem ko hotel ohranja pravila.

## Kam to vodi

Zgornje zmogljivosti so danes žive prek REST API-ja in MCP strežnika. Smer je globlje agentno naravno trgovanje: bogatejši agentno usmerjeni rezervacijski primitivni elementi, identiteta in avtorizacija agenta za transakcije v imenu popotnika ter agenti kot pripisani, zaslužni viri v partnerski mreži. Rdeča nit je dosledna — **infrastruktura potovalnega trgovanja za AI agente**, z Booking Engine kot slojem izvršitve spodaj.

## Pogoste napake

- **Zamujanje, da sta AI odkrivanje in AI agenti isti projekt.** Eden je vsebina in struktura; drugi je API in izvršitev. Potrebujete oba.
- **Dovoljevanje agentom, da navajajo cene, ki jih ne morejo rezervirati.** Ponudbe morajo izhajati iz živih cen in razpoložljivosti, ne iz strganih strani.
- **Izguba atribucije ob prenosu.** Če agent ustvari povpraševanje, mora rezervacija ostati povezana s tem virom.
- **Preskakovanje sloja izvršitve.** Odgovor ni rezervacija, dokler se dejansko ne izvede zaključek nakupa, plačilo in potrditev.
