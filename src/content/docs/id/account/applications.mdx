Aplikasi memberi Anda akses ke semua fitur Wink sebagai pengembang. Anda dapat mengakses semua data yang sama dan bahkan memperluas fitur Wink sendiri.
Anda dapat memilih untuk menggunakan server OAuth2 Wink untuk mengautentikasi situs perjalanan Anda dengan cara yang sama seperti menggunakan Google atau Facebook.
Dengan begitu Anda dapat memperluas fitur Wink ke dalam situs web atau aplikasi Anda sendiri.

:::note
Aplikasi pertama Anda sudah dibuat saat Anda [membuat akun baru](/id/portal/create-account). Kami menggunakan aplikasi tersebut untuk beberapa skenario pemesanan.

Anda tidak dapat menggunakan kembali aplikasi ini. Silakan buat aplikasi baru sesuai kebutuhan Anda.
:::

## Buat aplikasi

Karena Anda tidak dapat mengakses `secret key` dari aplikasi yang kami buat untuk Anda, Anda perlu membuat aplikasi sendiri.
Anda dapat membuat aplikasi di sini tanpa harus terlebih dahulu menyiapkan properti atau perusahaan — aplikasi ini tidak terikat
pada akun tertentu.

### Jenis klien

Saat membuat aplikasi, Anda memilih jenis klien yang menentukan cara aplikasi mengautentikasi.
Ini tidak dapat diubah nanti — jika Anda membutuhkan jenis yang berbeda, buat aplikasi baru.

- **Web application** — Aplikasi yang dirender di server dan dapat menyimpan client secret dengan aman (authorization code flow).
- **Single-page app (SPA)** — Aplikasi browser tanpa backend; menggunakan PKCE, tanpa client secret.
- **Mobile app** — Aplikasi iOS/Android asli; menggunakan PKCE dengan token refresh yang berputar.
- **Machine-to-machine** — Layanan backend yang bertindak sebagai dirinya sendiri (client credentials); tanpa login pengguna.

Berikut langkah-langkah membuat aplikasi:

<Steps>
1. Dari halaman aplikasi, klik tombol `Create new application`.
2. ***Name*** Beri nama aplikasi Anda. *misal Cool App*
3. **Client type** Pilih jenis yang sesuai dengan cara aplikasi Anda mengautentikasi — lihat [Jenis klien](#client-types) di atas.
4. **Redirect URIs** Minimal satu redirect URI diperlukan. Ini digunakan untuk memvalidasi domain redirect setelah autentikasi berhasil. Tidak digunakan untuk aplikasi Machine-to-machine. *misal https://www.cool-site.com*
5. **Post-logout redirect URIs** *(Opsional)* URL tempat pengguna dapat diarahkan setelah logout. Kosongkan untuk menggunakan ulang redirect URI di atas.
6. **Scopes** Pilih apa yang dapat diakses aplikasi ini atas nama Anda — lihat [Memilih scopes](#choosing-scopes) di bawah.
7. Klik tombol `Create application` untuk melanjutkan.
</Steps>

Anda akan diarahkan kembali ke daftar aplikasi Anda, dan dialog sekali tampil akan menampilkan Client ID
dan Client secret baru. Salin secret sekarang dan simpan di tempat yang aman — secret ini tidak akan ditampilkan lagi, dan
tidak ada cara untuk mendapatkannya kembali (hanya bisa [memutar ulang](#rotate-credentials) untuk yang baru).

## Memilih scopes

Setiap aplikasi selalu membawa **Sign-in (OpenID Connect)** scopes (`openid`, `profile`,
`email`, `offline_access`) — ini mengonfirmasi identitas pengguna dan menjaga mereka tetap masuk, sehingga
ditandai centang dan terkunci; ini bukan pilihan.

Semua yang lain bersifat opsional. Scopes yang tersisa dikelompokkan ke dalam bagian fungsional yang sama
seperti yang didokumentasikan di [Scopes](/id/developers/authentication#scopes) — Akun, Inventaris & tarif, Pemesanan,
Pemasaran & promosi, Konten properti, Analitik & laporan, Integrasi channel manager,
Pembayaran, dan Akuntansi & buku besar — masing-masing dengan deskripsi bahasa biasa tentang apa yang dibuka. Gunakan
tautan `All` / `None` di atas daftar untuk memilih atau menghapus semua scopes opsional sekaligus.

:::note
**Pembayaran** dan **Akuntansi & buku besar** ditandai **Sensitif** karena mereka mengatur pergerakan uang — hanya berikan kepada aplikasi yang memang perlu mengakses pembayaran atau buku besar.
:::

Dua keluarga scope sengaja **tidak ditawarkan** pada formulir ini:

- **`mcp.*`** — akses agen AI ke transport [Model Context Protocol](/id/developers/mcp), yang
  disediakan secara terpisah dan hanya untuk klien machine-to-machine.
- **Scopes tingkat administrator** (`administrator.*`) — akses tingkat platform yang tidak diberikan per
  aplikasi.

Setelah aplikasi dibuat, tab ini dan [Consented Apps](/id/account/apps) menampilkan scopes yang diberikan
dikelompokkan per bagian (misal "Bookings: `booking.read`"), sehingga Anda dapat melihat apa yang dapat dilakukan aplikasi secara sekilas
tanpa membukanya.

## Memutar ulang kredensial

Jika client secret mungkin telah bocor, atau Anda hanya ingin kredensial baru, putar ulang daripada
membuat ulang aplikasi:

<Steps>
1. Temukan aplikasi di daftar aplikasi Anda dan klik `Rotate`.
2. Konfirmasi dialog — Client ID dan secret saat ini langsung tidak berlaku.
3. Salin Client ID dan secret baru dari dialog sekali tampil sebelum menutupnya.
</Steps>

Memutar ulang mempertahankan nama aplikasi, jenis klien, redirect URI, dan scopes — hanya kredensial yang berubah.

## Hapus aplikasi

:::caution
Harap jangan hapus aplikasi yang kami buat otomatis untuk Anda agar semua fitur dapat berfungsi untuk akun Anda.
:::

Jika Anda tidak lagi membutuhkan aplikasi, Anda dapat menghapusnya. Ini bersifat permanen — kredensial dicabut segera dan tidak dapat dipulihkan.

<Steps>
1. Temukan aplikasi di daftar aplikasi Anda dan klik `Delete`.
2. Konfirmasi dialog untuk menghapus aplikasi secara permanen.
</Steps>
