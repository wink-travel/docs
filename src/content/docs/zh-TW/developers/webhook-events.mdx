本頁列出您可以在 Wink 訂閱的所有 webhook 事件。設定說明請參考 [Webhook 整合指南](/zh-TW/developers/webhook-integration) 或 [Webhook 管理頁面](/zh-TW/portal/settings/webhooks)。

## 如何訂閱

1. 在您的後台中前往 **Applications > Webhooks**。
2. 建立一個 webhook 並選擇您想接收的事件 — 或留空以接收所有事件。
3. 每當事件發生時，Wink 會向您的端點發送簽名的 HTTP POST。請參閱 [Webhook 整合](/zh-TW/developers/webhook-integration) 了解信封格式、標頭、簽名驗證及重試機制。

## 所有事件類型

此表格由平台事件目錄於建置時生成，因此始終與 API 保持一致。
標示為已送達的事件類型會連結至 [Webhooks API](/zh-TW/api/webhooks/) 的參考頁面，該頁面
記錄了精確的 JSON 主體（`WebhookEnvelope`，包含事件特定的 `object`）、`Wink-*` 標頭及
重試政策。未送達的事件類型存在於內部（付款、帳本、渠道管理同步等），但目前不會送給 webhook 訂閱者。

**接收者** 表示誰會收到事件：`SUPPLIER`（飯店）、`AFFILIATE`（與飯店有活躍銷售渠道的轉售商）、`AGENT`（完成訂房的旅行社）或 `SELF`（事件所屬的管理實體）。每個接收者收到的有效載荷格式相同；角色特定的細節藏於有效載荷的 `links.self` URL。

開發階段建議先訂閱所有事件。當您了解系統需要哪些有效載荷後，再縮小訂閱範圍以減少干擾。您可以從 **Applications > Webhooks**（或使用 `POST …/webhook/{id}/test`）發送測試事件，確認端點與簽名驗證無誤後再正式上線。
:::
