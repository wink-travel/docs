Wink **合作夥伴 API** 是一種已驗證的高吞吐量方式，供整合者查詢可預訂的旅遊庫存 — 這是驅動我們可嵌入小工具和公開瀏覽端點的相同供應，作為一個一流的程式化介面公開。免費的 Web Components 和公開瀏覽端點適合輕量且面向使用者的嵌入，而合作夥伴 API 則為大規模搜尋、定價和預訂系統而建。存取是依整合者驗證並按使用量計費，因此您只需支付實際傳送的流量費用。

## API 參考

兩個介面提供可預訂庫存，對應上述兩個層級：

- **免費 — 消費者 / 預訂引擎 API**（REST，`/api/public/**`）：匿名，面向瀏覽器與小工具。[瀏覽預訂引擎參考 →](/zh-TW/api/booking-engine/)
- **付費 — 合作夥伴整合者 API**（**gRPC**，`wink.partner.v1`）：已驗證、計量使用量，為大規模伺服器對伺服器整合而建。[瀏覽整合者參考 →](/zh-TW/partner-api/partner/)

合作夥伴整合者 API 採用 gRPC 而非 REST。您可使用產生的用戶端透過 HTTP/2 呼叫
`partner.wink.travel:443`，並傳遞 Bearer Token 及您要呼叫的帳戶：

```bash
grpcurl -H "authorization: Bearer $WINK_TOKEN" partner.wink.travel:443 list
```

上述參考頁面記錄了每個服務、訊息與錯誤狀態，且架構也可透過伺服器反射在執行時取得，因此 `grpcurl`、Postman 和 Insomnia 可直接發現，無需下載任何檔案。

若您想事先產生用戶端，`.proto` 原始檔案已發布於
[github.com/wink-travel/partner-api-proto](https://github.com/wink-travel/partner-api-proto)。

## 使用量與限制說明

### 免費層級

免費層級設計讓您無成本建置、測試並執行適度的生產流量。

- **無公開每分鐘限制。** Wink 會監控請求速率，並可能施加合理使用限制以保護服務。若收到 **HTTP 429 (請求過多)**，請依 `Retry-After` 標頭指定的秒數等待後再重試。
- **每月配額 — 每月 10,000 單位。** 配額依帳戶授予，並於每月 1 日（UTC）重置。達到配額且未加入按使用量付費的帳戶，將於當月剩餘時間收到 **HTTP 429，直到下月 1 日** — 硬性停止，附帶 `Retry-After` 標頭及邀請升級付費層級的訊息。已加入付費的帳戶則繼續運作，並對超出配額的使用量計費。

免費層級不包含服務等級協議或優先支援。

### 付費層級

付費層級取消每月上限，僅對實際使用量計費。

- **計量飯店住宿晚數 — 每晚 $0.0001。** 無月度上限，依實際量計費。Wink 仍可能施加合理使用限制以保護服務。搜尋與庫存呼叫依飯店住宿晚數計費；內容與查詢呼叫每次計一單位，批次請求可降低費用。

付費層級包含下述服務等級協議 — 99.9% 正常運作承諾及 P95 回應時間低於 500 毫秒目標 — 以及優先且依嚴重度分類的支援。

## 服務等級協議

_生效日期：2026 年 7 月 5 日 · 版本 1.0_

本服務等級協議（以下簡稱「SLA」）訂定 Wink（「Wink」、「我們」）對客戶（「客戶」、「您」）於已聲明適用 SLA 的層級，對已驗證 Wink 合作夥伴 API（「合作夥伴 API」或「服務」）的可用性承諾、服務信用及支援目標。此 SLA 納入並受您與 Wink 間存取合作夥伴 API 之協議（「協議」）約束，且適用於您持續維持有效且付費的合作夥伴 API 訂閱。未定義之專有名詞，依協議定義。

### 1. 定義

1. **「正常運作時間」** 指合作夥伴 API 可接受並成功回應格式正確且已驗證請求的期間。
2. **「停機時間」** 指合作夥伴 API 未能成功回應格式正確且已驗證請求的分鐘數，排除第 4 節所列除外情況。影響極少數請求的孤立錯誤不視為停機時間。
3. **「每月正常運作百分比」** 指特定日曆月內總分鐘數減去停機分鐘數，再除以該月總分鐘數，並以百分比表示。
4. **「預定維護」** 指 Wink 依第 4 節規定提前通知的計劃性服務維護。
5. **「服務信用」** 指依受影響日曆月您支付或應付的合作夥伴 API 費用百分比計算的信用額度，作為未達正常運作承諾的唯一且排他性補償，並可抵扣未來合作夥伴 API 費用。
6. **「回應時間」** 指 Wink 於服務邊界收到格式正確且已驗證請求起，至開始回傳回應之間的經過時間，不含網路傳輸及 Wink 無法控制的用戶端時間。

### 2. 可用性與效能承諾

Wink 將以商業合理努力，確保合作夥伴 API 在每個日曆月達成 **至少 99.9% 的每月正常運作百分比**（「正常運作承諾」）。正常運作承諾於 Wink 服務邊界測量，排除第 4 節所述 Wink 合理無法控制之因素。Wink 監控系統為每月正常運作百分比與回應時間的權威紀錄來源。

Wink 進一步目標為成功、格式正確且已驗證請求達成 **第 95 百分位數（P95）回應時間低於 500 毫秒**（「效能目標」），於每月於 Wink 服務邊界測量。效能目標排除第 4 節因素、因請求本身造成的應用層錯誤，以及異常大型或複雜批次請求。效能目標為服務目標；第 3 節服務信用僅適用於未達 **正常運作承諾**，且為可用性不足的唯一且排他性補償。

### 3. 服務信用

若任一日曆月每月正常運作百分比低於正常運作承諾，您可依下表比例申請服務信用，計算基礎為該月您支付或應付的合作夥伴 API 費用：

| 每月正常運作百分比 | 服務信用 |
|---|---|
| 低於 99.9% 但不低於 99.0% | 10% |
| 低於 99.0% 但不低於 95.0% | 25% |
| 低於 95.0% | 50% |

1. **申請信用。** 您必須於停機事件發生之日曆月結束後 **三十（30）天內** 向 Wink 提交書面申請。申請須包含您主張的每次停機日期與時間，以及您合理可取得的任何支援日誌或證據。逾期申請不予受理。
2. **信用形式。** 核准的服務信用將抵扣未來合作夥伴 API 費用，無現金價值。非退款，除非適用法律另有規定。
3. **最高信用額度。** 單一日曆月所授予的服務信用總額不超過該月您支付或應付的合作夥伴 API 費用 50%。
4. **唯一且排他性補償。** 服務信用為您因 Wink 未達正常運作承諾或其他可用性不足的 **唯一且排他性補償**。
