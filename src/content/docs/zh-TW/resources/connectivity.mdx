## 為什麼連接性很重要

每條訂房路徑都依賴準確的飯店供應。價格錯誤會讓旅客失去信任；可用性錯誤會導致訂房失敗；庫存過時則無法可靠運作。Wink 不僅驅動網站訂房按鈕 — 同一份飯店資料支援網站路徑、可分享連結、QR 碼、網頁元件、WinkLinks 商店、合作夥伴連結、Traveliko 列表、社群訂房路徑、Agentic AI 交接與開發者流程。所有這些都需要相同基礎：準確的 **ARI** — 可用性、價格與庫存。

## 兩種設定路徑

**路徑 1 — 連接支援的供應商。** 適用於飯店已在 Wink 支援的通路管理器、PMS、CRS 或價格供應商管理價格時。飯店在 Extranet 選擇供應商，於供應商後台啟用 Wink 通路，映射房型與價格方案，供應商便會將 ARI 傳送至 Wink，自動填入主價格日曆。適合多通路飯店、頻繁價格變動、即時庫存需求及降低手動工作量。

**路徑 2 — 在 Extranet 手動載入價格。** 適用於飯店未使用支援的供應商，或想透過 `Distribution > Master rate calendar` 手動操作 Wink — 包含單日及批次日期範圍更新。適合小規模庫存、早期設定或測試。**此方式需嚴格維護：** 若營運中價格變動，必須有人更新 Wink。若已連接供應商，手動變更可能會被供應商下一次同日期更新覆蓋。

## 連接供應商與手動載入比較

| 問題 | 連接供應商 | Extranet 手動載入 |
|---|---|---|
| 誰更新 ARI？ | 支援的供應商將更新傳送至 Wink。 | 飯店手動更新價格與可用性。 |
| 適用對象 | 多通路飯店、頻繁變動、即時庫存。 | 小規模庫存、有限使用、無連接供應商。 |
| 工作量 | 設定後每日工作量較低。 | 持續手動維護。 |
| 即時性 | ARI 自動從供應商更新。 | 僅與最後手動更新同步。 |
| 風險 | 映射或供應商設定必須正確。 | 若未維護，價格或可用性會過時。 |
| 訂房通知 | 通路管理器 / CRS / PMS 於設定處接收通知。 | 飯店透過 Wink 收到訂房通知。 |

## 支援的供應商

Wink 支援多種通路管理器，並可直接或透過 Channex 作為代理連接 PMS。上線前請與 Wink 團隊確認您的供應商版本、設定路徑與映射需求。

| 供應商 | 類型 | 備註 |
|---|---|---|
| SiteMinder | 通路管理器 | 直接整合 |
| Cloudbeds | 通路管理器 | 直接整合 |
| Travelclick | 通路管理器 | 直接整合 |
| RateGain | 通路管理器 | 直接整合 |
| D-EDGE | 通路管理器 | 直接整合 |
| YieldPlanet | 通路管理器 | 直接整合 |
| Rate Tiger | 通路管理器 | 直接整合 |
| Hotel Link | 通路管理器 | 直接整合 |
| Channex | 通路管理器 + PMS 代理 | 直接整合，並代理多種 PMS 供應商 |
| SynXis | CRS | 可能需額外透過 SynXis Channel Connect Express 設定 |

許多 PMS 系統 — 例如 Mews、Apaleo、Opera Cloud 與 OTA Sync — 可透過 **Channex** 代理將 ARI 傳送至 Wink。若您的 PMS 連接 Channex，即可連接 Wink；上線前請確認 PMS 版本與 Channex 設定。（此為代表性清單，請與 Wink 團隊確認您的供應商。）

## 供應商設定簡述

在 Extranet，前往 `Distribution > Channel manager`，選擇您的價格供應商並儲存。於供應商後台新增 **Wink** 通路，映射 Wink 建立的房型與價格方案。若供應商未自動推送完整價格，請手動啟動，然後檢查主價格日曆 — 可能在幾分鐘內更新（時間依供應商與映射而異）。使用 **Verifier** 模擬旅客價格查詢，測試可用性、貨幣、折扣與價格顯示，確認無誤後再送出實際需求。團隊了解通知行為後，才建立測試訂房。

## 訂房通知

連接性不僅是將價格 *傳送給* Wink — 訂房也會回流。訂房完成後，通路管理器、CRS 或 PMS 可於設定處接收通知；飯店與旅客會收到確認郵件；合作夥伴會在合作路徑收到訂房與歸因確認；開發者可監聽 `booking.created` webhook 以取得即時詳情。

## Wink 的定位

連接性位於 Extranet 與訂房引擎之間。[Extranet](/zh-TW/products/extranet/) 是飯店端的控制層，管理內容、房型、價格方案、限制、可用性、政策與訂房引擎設定；支援的供應商會將 ARI 傳入，或飯店手動維護主價格日曆；[訂房引擎](/zh-TW/products/booking-engine/) 使用核准資料，完成來自直接、社群、WinkLinks、合作夥伴、Traveliko、Agentic AI 與開發者路徑的訂房。簡單規則：**連接性越強，訂房路徑越可靠。**

## 常見錯誤

- **假設 Wink 可在無最新可用性下銷售。** 必須先從供應商或手動 Extranet 更新取得 ARI。
- **連接供應商卻未映射房型與價格方案。** 映射正確前設定不算完成。
- **供應商連接中手動編輯價格。** 手動變更可能被供應商下一次更新覆蓋。
- **忘記驗證。** 上線前測試價格顯示、可用性與折扣邏輯。
- **將連接性視為純技術任務。** 它影響營收、行銷、合作路徑、轉換率與旅客信任。
