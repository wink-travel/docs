Questo articolo ti mostra come configurarti rapidamente come sviluppatore e iniziare a testare le nostre API su Wink.

:::note
I test devono sempre essere effettuati nel nostro [ambiente di staging](/it/getting-started/environments). Ci sono molti meno dati, ma sei libero di testare quanto vuoi senza influire sull'ambiente di produzione.

Quando sei pronto, passa tu stesso alla produzione: crea un'applicazione in produzione (le credenziali non vengono trasferite tra gli ambienti) e rimuovi `staging-` dagli URL, quindi `https://staging-api.wink.travel` diventa `https://api.wink.travel`. Non è previsto alcun passaggio di approvazione per gli sviluppatori. Solo i [channel manager](/it/guides/integrators/add-your-channel-manager/#certification) e gli [agenti di viaggio](/it/portal/travel-agent/what-is-agent/) sono certificati prima della produzione.

Creare un account in staging o in produzione richiede l'accettazione dei Termini e delle Condizioni di pagamento di Wink, e tale accettazione è vincolante.
:::

Segui questi passaggi:

<Steps>
1. [Registrati](/it/getting-started/sign-up) con il tuo account utente su Wink.
2. [Crea un account affiliato](/it/portal/create-account). Ti servirà per associare la tua Applicazione. Consulta [cos’è Studio](/it/portal/studio/what-is-studio) per maggiori dettagli.
3. [Crea un’Applicazione](/it/account/applications) e associa l’account affiliato creato al Passo 2. Per integrazioni API server-to-server, scegli **MACHINE_2_MACHINE** come tipo di client.
4. Una volta creata la tua `Applicazione`, copia e salva immediatamente client-id e chiave segreta — la chiave segreta viene mostrata una sola volta e non può essere recuperata.
</Steps>

## CDN

Su Wink utilizziamo Cloudinary per tutti i nostri asset di immagini e video. Quando accedi al nostro inventario di viaggi, avrai pieno accesso a tutte le funzionalità avanzate di Cloudinary.

Il nostro `cloud_name` è  `traveliko`.

### Cloudinary

- [Guida introduttiva](https://cloudinary.com/documentation/dev_kickstart)
- [SDK](https://cloudinary.com/documentation/cloudinary_sdks)
- [Cloudinary su GitHub](https://github.com/cloudinary)
-	[Video Tutorial](https://cloudinary.com/documentation/cloudinary_sdks_tutorials)

### Esempio

Per ogni tipo di inventario di viaggi che supportiamo, ci sarà un array JSON annidato chiamato `multimedias`. Il JSON per una voce multimediale è simile a questo:

```json {3}
{
  "multimediaIdentifier": "multimedia-1",
  "identifier": "partners/radisson_blu_logo",
  "type": "IMAGE",
  "width": "1024",
  "height": "768",
  "category": "1",
  "descriptions": [
    {
      "name": "Lobby",
      "description": "Foto della hall",
      "language": "en"
    }
  ],
  "lifestyleType": "LIFESTYLE_BUSINESS",
  "attribution": [
    {
      "url": "https://www.hilton.com",
      "name": "Hilton"
    }
  ]
}
```

La riga evidenziata sopra mostra l’ID univoco Cloudinary `partners/radisson_blu_logo`. È tutto ciò che ti serve per recuperare l’immagine in qualsiasi formato, qualità e dimensione desideri.

## Test

Vai alla nostra sezione [API](/it/api/overview/) e scegli l’API con cui vuoi lavorare.

### Documentazione API

Il nostro sito di documentazione è strutturato in modo che tu possa eseguire comandi API direttamente dal sito.

In questo esempio, vuoi usare la chiamata API `Search Lookups (OAuth2)`.

:::tip[Consiglio professionale]
Per facilità d’uso, consigliamo agli integratori di utilizzare gli endpoint che designiamo come `OAuth2`. Questi endpoint riconoscono chi chiama l’API e sanno già a quale account appartieni, quindi non devi specificare il `companyIdentifier` negli URL.
:::

<Steps>
1. Usa la [Lookup API](https://developer.wink.travel/lookup) per recuperare destinazioni o hotel.
2. Nella barra di navigazione a sinistra, clicca su `Authentication`.
3. Inserisci client-id e client secret e clicca sul pulsante `Get TOKEN`.
4. Se le tue credenziali sono valide, vedrai che la tua chiave API è stata applicata.
5. Ora puoi testare l’endpoint lookup.
</Steps>

### Postman
Puoi fare la stessa cosa con Postman.

<Steps>
1. Scarica [Postman](https://www.postman.com/downloads).
2. Clicca su `Download OpenAPI spec` in cima alla pagina della [Lookup API](https://developer.wink.travel/lookup).
3. Importalo in Postman.
4. Se lo hai importato come nuova collezione chiamata `Wink API`, clicca sui tre puntini orizzontali accanto al nome della collezione e seleziona `Edit`.
5. Nella scheda `Authorization`, imposta il `Auth type` su OAuth2.
6. Imposta il campo `Add auth data to` su `Request headers`.
7. Imposta il campo `Header prefix` su `Bearer`.
8. Imposta il campo `Token Name` con il nome che vuoi dare al token salvato in Postman, ad esempio Wink Staging.
9. Imposta il campo `Grant type` su `Client Credentials`.
10. Imposta il campo `Access token URL` su https://staging-iam.wink.travel/oauth2/token.
11. Imposta il campo `Client ID` con il Client ID generato dalla tua app.
12. Imposta il campo `Client Secret` con il Client Secret generato dalla tua app.
13. Imposta il campo `Scope` con gli scope separati da spazi di cui la tua integrazione ha bisogno (es. `inventory.read inventory.write inventory.remove`). Consulta la [riferimento scope](/it/developers/authentication#scopes) per l’elenco completo.
14. Imposta il campo `Client Authentication` su `Send as Basic Auth header`.
15. Clicca sul pulsante `Get New Access Token` per recuperare il token e salvarlo.
16. Per tutte le chiamate API nella collezione Wink API, assicurati che la scheda di autenticazione dica `Inherit auth from parent` così il token viene incluso in ogni chiamata.
</Steps>

:::tip[Consiglio professionale]
Si consiglia di trasformare il dominio del server, il client ID e il client secret in variabili d’ambiente. In questo modo puoi facilmente passare tra ambienti di staging e produzione e riutilizzare tutte le operazioni create.
:::
