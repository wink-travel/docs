Gli strumenti MCP di Wink sono pubblicati come **toolset** — endpoint focalizzati, ognuno dedicato a un lavoro specifico. Connetti il tuo client AI a uno o due di questi che corrispondono al tuo lavoro, non a tutti.

Ogni endpoint utilizza il **login OAuth2 interattivo** (flusso di autorizzazione con codice PKCE): il tuo agente AI apre una scheda del browser, effettui l’accesso con il tuo account Wink, e il gioco è fatto. Nessun segreto client da gestire.

```bash title="Un integratore di channel manager si connette a un endpoint"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Un albergatore che gestisce le proprie tariffe si connette a un altro"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## Perché gli strumenti sono divisi in endpoint

Wink espone circa 500 strumenti. Fornire tutti a un agente contemporaneamente è tecnicamente possibile — ma una cattiva idea.

**Le definizioni degli strumenti consumano contesto.** Ogni strumento pubblicizzato da un server MCP viene caricato nella finestra di contesto del modello prima che esegua qualsiasi lavoro, insieme alla sua descrizione e allo schema completo dei parametri. Cinquecento di questi consumano una grande parte del budget che il tuo compito reale richiede, a ogni singola richiesta.

**La qualità della scelta diminuisce con l’aumentare della lista.** Un agente che sceglie tra 500 strumenti con nomi simili fa scelte peggiori rispetto a uno che sceglie tra 40. Se integri un channel manager, circa venti strumenti sono rilevanti per te; gli altri 480 sono rumore che rende più difficile trovare lo strumento giusto.

**Il lavoro è realmente separabile.** Chi sincronizza la disponibilità da un PMS e chi cura pagine affiliate condividono quasi nessuno strumento. Dividere per lavoro significa che ogni connessione porta il vocabolario di un solo lavoro.

<Aside type="caution" title="I toolset non sono permessi">
Scegliere un toolset ristretto **non** limita ciò che il tuo account può fare, e sceglierne uno ampio non concede nulla in più. Ogni strumento applica le stesse autorizzazioni dell’account del portale web, sotto la tua identità autenticata. Se il tuo account non può cancellare una prenotazione nel Wink Portal, nemmeno l’agente può farlo — indipendentemente dall’endpoint a cui è connesso.

Scegli i toolset per **focalizzazione**, non per sicurezza.
</Aside>

## Directory degli endpoint

Due host servono i toolset. Il numero di strumenti è approssimativo e cresce nel tempo.

### `https://integrations.wink.travel` — integrazioni channel manager

Un solo endpoint, perché questo host esiste per un solo lavoro.

| Endpoint | Strumenti | Cosa copre |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Connessione e verifica di integrazione channel manager, PMS o CRS |

<Aside type="note" title="Integrare un channel manager vs. gestire le proprie tariffe">
Sono lavori diversi per persone diverse, e non condividono un endpoint.

Un **fornitore di channel manager, PMS o CRS** integra una volta sola tramite `integrations.wink.travel/mcp/channel-manager`, e da lì scambia proprietà, tariffe, disponibilità e prenotazioni tramite quell’integrazione. Quel singolo endpoint è tutta la superficie.

Un **albergatore che modifica manualmente le proprie tariffe** usa i toolset extranet su `api.wink.travel` — `/mcp/extranet/rates` e affini. Questi non fanno parte di un’integrazione channel manager e un integratore non ha motivo di connettersi a essi.

L’amministrazione account è anch’essa su `api.wink.travel`, in `/mcp/settings`. Non esiste `/mcp/settings` sull’host delle integrazioni.
</Aside>

Ogni endpoint include anche uno strumento `ping`, così puoi confermare che la connessione è attiva prima di chiedere un lavoro reale.

### Pagamenti agentici

Per il flusso completo di prenotazione del viaggiatore, connetti **Wink Booking Engine** su `https://api.wink.travel/mcp/booking-engine` e un **wallet di pagamento** compatibile. Aggiungere il MCP di Wink apre il login nel browser e la selezione dei permessi; il tuo client gestisce poi l’autenticazione.

Booking Engine include ricerca destinazioni, ricerca hotel e camere, `agentic_booking_quote`, `agentic_booking_pay`, `agentic_booking_book`, recupero prenotazioni e ricevute, quando prenotazione e pagamento agentici sono abilitati per quell’ambiente. Vedi [Agentic Payments](/it/developers/agentic-payments/) per configurazione, permessi da selezionare e passaggi dalla ricerca alla conferma.

## Quali toolset mi servono?

| Se sei… | Connettiti a |
|---|---|
| **Integratore di channel manager, PMS o CRS** | `integrations.wink.travel/mcp/channel-manager` — solo questo |
| **Gestore del contenuto di una struttura** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Gestore di camere e tipologie** | `/mcp/extranet/facilities` |
| **Gestore di prezzi e disponibilità** | `/mcp/extranet/rates` |
| **Gestore delle prenotazioni quotidiane** | `/mcp/extranet/operations` |
| **Sviluppatore della distribuzione** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Costruttore di pagine affiliate** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Gestore di pagine link-in-bio** | `/mcp/link-manager` + `/mcp/social` |
| **Prenotazione per conto di viaggiatori** | `/mcp/travel-agent` |
| **Riconciliazione finanziaria** | `/mcp/payment` |
| **Prenotazione di una camera con un agente AI** | `/mcp/booking-engine` + wallet di pagamento compatibile — vedi [Agentic Payments](/it/developers/agentic-payments/) |
| **Costruttore di un’esperienza di prenotazione** | `/mcp/booking-engine`; opzionalmente `/mcp/reference` per ricerche aggiuntive |

**Booking Engine include il flusso di prenotazione principale.** Fornisce scoperta account e personalizzazione, ricerca destinazioni, disponibilità hotel e dettagli tariffe camere, carrelli, checkout e gestione prenotazioni viaggiatori. Include anche strumenti di prenotazione e pagamento agentici quando abilitati per quell’ambiente.

Per una ricerca hotel basata su città, usa `destination_lookup_search_suggestions` per risolvere la destinazione, poi `inventory_search_city` per trovare hotel e tariffe disponibili. Entrambi gli strumenti sono in `/mcp/booking-engine`, quindi questo flusso non richiede una connessione Reference.

Aggiungi `/mcp/reference` quando ti servono ricerche di supporto come paesi, valute e tassi di cambio, lingue supportate, fusi orari, ricerche geografiche più ampie, classificazioni OTA o conoscenza pubblica delle proprietà. Sono aggiunte opzionali al flusso di prenotazione.

Inizia con uno. Aggiungi un altro quando ti accorgi che ti serve qualcosa che il primo non può fare — ogni connessione è indipendente, e aggiungerne una non influenza le altre.

<Aside type="tip" title="Vuoi ancora tutto?">
`https://api.wink.travel/mcp` e `https://integrations.wink.travel/mcp` rimangono disponibili e servono **tutti** gli strumenti sul loro host. Sono utili per esplorare cosa esiste, ma non li consigliamo per il lavoro quotidiano: la lista degli strumenti è abbastanza grande da sovraccaricare il tuo compito e peggiorare la selezione degli strumenti da parte dell’agente. Preferisci i toolset sopra indicati.
</Aside>

## Come funziona l’autenticazione

I server MCP di Wink usano il flusso **OAuth2 Authorization Code + PKCE** e supportano la **Dynamic Client Registration (RFC 7591)**. Ecco cosa succede quando ti connetti per la prima volta:

1. Il tuo client AI scopre il server di autorizzazione dai metadati `/.well-known/oauth-protected-resource` dell’endpoint MCP.
2. Il client si registra automaticamente tramite **Dynamic Client Registration** — nessuna configurazione manuale dell’applicazione richiesta.
3. Il client apre una **scheda del browser** su `https://iam.wink.travel`. Effettui l’accesso con il tuo account Wink e approvi i permessi richiesti nella schermata di consenso.
4. Wink emette un **token di accesso** associato al tuo account e collegato alla tua identità.
5. Il client AI allega il token a ogni richiesta MCP. Tutti i risultati degli strumenti sono automaticamente limitati all’entità gestore del tuo account.
6. I token scadono dopo 3 ore. Il client AI aggiorna silenziosamente il token in background senza richiedere nuovamente l’accesso.

Ogni chiamata a uno strumento avviene **sotto la tua identità** — le stesse regole ACL che proteggono il portale web si applicano all’agente AI.

## Scopes

Quando approvi la schermata di consenso vedrai un dettaglio di cosa l’agente sta richiedendo. I client MCP usano lo stesso vocabolario di permessi della piattaforma — vedi la [riferimento completo degli scope nella pagina Autenticazione](/it/developers/authentication#scopes).

Due cose sono specifiche per MCP:

- **Gli scope `mcp.read`, `mcp.write` e `mcp.remove` sono richiesti in aggiunta** per aprire il trasporto MCP. Un client che possiede uno scope `mcp.*` è ammesso a qualsiasi endpoint MCP Wink, ma ogni strumento invocato applica comunque lo scope della sezione dell’endpoint che incapsula (es. `booking.read`).
- **Il client AI richiede solo gli scope di cui ha bisogno.** Puoi negare permessi individuali nella schermata di consenso — gli strumenti che richiedono uno scope negato restituiranno un errore se invocati.

**I toolset non cambiano nulla di questo.** L’endpoint a cui ti connetti decide quali strumenti sono *elencati*, non cosa sono *autorizzati a fare*. Connettersi a `/mcp/payment` non concede permessi finanziari che non avevi già, e connettersi a `/mcp/reference` non impedisce a uno strumento di applicare il proprio scope. L’autorizzazione è decisa per ogni chiamata strumento, dal tuo token e dai permessi del tuo account.

## Risoluzione problemi

**La scheda del browser non si apre**

Il tuo client AI potrebbe non supportare ancora il flusso PKCE interattivo. Verifica di usare una versione recente:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** aggiorna tramite l’updater integrato nell’app

**`401 Unauthorized` dopo l’accesso**

Il token memorizzato potrebbe essere scaduto. Rimuovi e aggiungi di nuovo il server per forzare un nuovo login:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Per Claude Desktop e ChatGPT, rimuovi la voce server dalle impostazioni, riavvia l’app e aggiungila di nuovo.

**`403 Forbidden` chiamando uno strumento specifico**

Lo strumento richiede uno scope che non hai approvato nella schermata di consenso, o un permesso che il tuo account non possiede. Riconnetti il server — la schermata di consenso apparirà di nuovo e potrai approvare il permesso mancante. Se continua a fallire, lo strumento richiede un permesso account che non hai; connettersi a un toolset diverso non aiuta, perché i toolset non concedono permessi.

**Lo strumento che mi serve non è nella lista**

Probabilmente sei connesso a un toolset che non copre quel lavoro. Controlla la [directory degli endpoint](#endpoint-directory) e aggiungi il toolset che lo contiene — le connessioni sono indipendenti, quindi aggiungerne uno non cambia gli altri. Se non sei sicuro, connettiti temporaneamente a `https://api.wink.travel/mcp`, trova lo strumento, poi verifica a quale toolset appartiene.

**`404 Not Found` su un endpoint toolset**

Controlla attentamente il percorso — i toolset nidificati hanno due segmenti (`/mcp/extranet/rates`, non `/mcp/extranet-rates`), quelli piatti ne hanno uno (`/mcp/link-manager`). Nota che una richiesta *non autenticata* a qualsiasi percorso sotto `/mcp` restituisce `401`, non `404`, quindi un `401` da solo non indica se l’endpoint esiste.

**Mi sono connesso a `api.wink.travel/mcp/channel-manager` e non ho ottenuto nulla**

Quell’endpoint non esiste. L’integrazione channel manager è servita solo da `https://integrations.wink.travel/mcp/channel-manager`. Se devi anche leggere o scrivere le tariffe di una proprietà manualmente, è un lavoro separato su un endpoint separato — vedi `/mcp/extranet/rates`.

**Il server appare ma le chiamate agli strumenti restituiscono "account non trovato"**

Sei autenticato con un account Wink che non ha un’entità gestore. Vai su [Wink Portal](https://app.wink.travel) e assicurati che il tuo account sia configurato prima di usare il server MCP.

**Il token scade durante la sessione**

I token sono validi per 3 ore. Claude Code e Claude Desktop aggiornano i token silenziosamente senza interrompere la sessione. Se vedi errori di autenticazione dopo un lungo periodo di inattività, invia un nuovo messaggio — il client si ri-autenticherà automaticamente.

**Codex CLI mostra "MCP server unreachable"**

Controlla che il tuo `~/.codex/config.json` sia JSON valido (senza virgole finali) e che `"type": "http"` sia impostato. Codex richiede il trasporto HTTP per server remoti; il trasporto stdio è solo per binari locali.

**Il menu "Connettori" di ChatGPT manca**

Il supporto MCP richiede la versione **1.2024.352** o successiva dell’app desktop ChatGPT e un abbonamento Plus, Pro, Team o Enterprise attivo. Aggiorna l’app e verifica il piano in Impostazioni → Account.

**Il server Cursor mostra rosso / "Connessione fallita"**

Verifica che il tuo `~/.cursor/mcp.json` sia JSON valido e contenga `"type": "http"`. Poi vai su **Impostazioni → Impostazioni Cursor → MCP** e clicca su **Aggiorna**. Se l’errore persiste, riavvia completamente Cursor — le modifiche alla configurazione non sempre vengono rilevate senza un riavvio.

**I server MCP di Windsurf non compaiono nelle impostazioni**

Windsurf richiede un riavvio completo (non solo ricaricare la finestra) per rilevare le modifiche a `mcp_config.json`. Usa **File → Quit** e riapri. Se i server non appaiono ancora, conferma di usare Windsurf **1.4+** tramite **Aiuto → Informazioni su Windsurf**.

**L’opzione "Aggiungi Server" in Cline non è visibile**

Il gestore server MCP richiede Cline **2.0** o successivo. Apri il pannello Estensioni di VS Code, trova Cline e clicca su **Aggiorna** se disponibile. Dopo l’aggiornamento, ricarica VS Code (`Ctrl+Shift+P` → "Developer: Reload Window").
