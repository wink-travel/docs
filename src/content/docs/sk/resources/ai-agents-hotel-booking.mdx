## Odporučiť hotel nie je to isté ako ho rezervovať

Väčšina dnešného „AI cestovania“ končí pri odporúčaní. Asistent navrhne tri hotely a potom odovzdá cestovateľa na web alebo OTA, aby si rezerváciu spravil sám. Vzniká prerušenie, cena nemusí byť rezervovateľná a nikto neuchováva kontext zdroja.

**AI agent** sa líši od AI odpovede. Agent nielen popisuje hotel — koná: kontroluje aktuálnu dostupnosť, zostavuje rezerváciu, prijíma platbu a dokáže reagovať na zmeny. Aby sa to dalo bezpečne robiť, agent potrebuje viac než text. Potrebuje štruktúrované, aktuálne, rezervovateľné údaje a transakčnú vrstvu, ktorú môže volať.

Toto je rozdiel medzi [AI objavovaním](/sk/resources/ai-discovery-hotels/), ktoré je o **nájdení a pochopení**, a agentickým obchodom, ktorý je o **realizácii transakcie**.

## Čo agent potrebuje predtým, než môže realizovať transakciu

Rezervácia hotela je skutočná obchodná udalosť: správna izba, správna cena, reálna dostupnosť, pravidlá, platba a potvrdenie, ktoré sa synchronizuje späť do hotela. Agent to môže dokončiť len ak je každý prvok dostupný ako volateľná operácia.

| Agent potrebuje | Prečo je to dôležité |
|---|---|
| Štruktúrovanú, aktuálnu ponuku | Dáta zo scraping-u sa rýchlo zastarajú; agent potrebuje aktuálny inventár riadený hotelom. |
| Ceny a dostupnosť v reálnom čase | Cena, ktorú agent uvádza, musí byť v danom momente skutočne rezervovateľná. |
| Operáciu rezervácie | Vytvorenie rezervácie musí byť skutočné API volanie, nie odovzdanie na webový formulár. |
| Platbu | Agent (alebo cestovateľ cez neho) musí byť schopný zaplatiť, s aplikovanou logikou pravidiel. |
| Atribúciu | Zdroj, kampaň alebo agent, ktorý vytvoril rezerváciu, by mali zostať priradené. |
| Udalosti | Agent by mal vedieť reagovať na potvrdenia, zmeny, zrušenia a vrátenia peňazí. |

Bez týchto prvkov môže agent odporúčať — ale nemôže rezervovať.

## Ako AI agent rezervuje hotel na Wink

Wink je API-first: každá funkcia platformy je volateľná zvonka a hostovaný MCP server poskytuje agentom živé API kontrakty. Typický agentický tok:

### 1 — Pripojiť sa a prečítať živé kontrakty

Agent sa pripojí k hostovanému MCP serveru a použije `api_search` a `docs_search` na nájdenie správnych operácií a prečítanie ich skutočných schém požiadaviek/odpovedí — bez hádania endpointov, bez zastaraných dokumentov.

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — Vyhľadávať rezervovateľný inventár

Agent vyhľadáva ponuku riadenú hotelom, vrátane priestorového vyhľadávania podľa geolokácie, a číta aktuálne ceny a dostupnosť cez prepojených channel managerov.

### 3 — Vytvoriť rezerváciu

Vytvorenie rezervácie je REST API operácia. Agent zostaví izbu, cenu, dátumy a hostí a vytvorí rezerváciu cez API.

### 4 — Prijať platbu a potvrdiť

[Booking Engine](/sk/products/booking-engine/) realizuje transakciu — checkout, platbu (Wink je obchodníkom záznamu), logiku storno podmienok, potvrdenie a synchronizáciu rezervácie do prepojeného PMS alebo channel managera. Zdroj a atribúcia partnera sa zachovávajú počas celej rezervácie.

### 5 — Reagovať na udalosti

Agent sa môže prihlásiť na odber udalostí `booking.created` a ďalších webhookov, aby vykonal zúčtovanie, upozornil cestovateľa alebo spustil následné akcie.

Princíp: **agent vytvára alebo smeruje zámer; Booking Engine zostáva vrstvou plnenia pod každým odovzdaním.**

## AI vyhľadávanie vs AI agenti

Riešia rôzne úlohy a hotel musí byť pripravený na obe.

| | AI vyhľadávanie / odpovedacie engine | AI agenti |
|---|---|---|
| Cieľ cestovateľa | Nájsť a porovnať hotely | Rezervovať a spravovať pobyt |
| Čo hotel potrebuje | [Štruktúrovaný, prehľadateľný obsah](/sk/resources/hotel-content-answer-engines/) | Živé API, ceny, rezervácie, platby |
| Konečný stav | Odporúčanie | Potvrdená rezervácia |
| Povrch Wink | Čistá ponuka + obsah pripravený na odpovede | REST API, MCP server, Booking Engine |

[AI objavovanie pre hotely](/sk/resources/ai-discovery-hotels/) pokrýva vyhľadávaciu stránku; tento sprievodca pokrýva transakčnú stránku.

## Kto buduje agentov pre hotelový obchod

Agentický cestovný obchod nie je len o spotrebiteľských asistentoch. Rovnaká infraštruktúra poháňa:

- **Spotrebiteľských cestovných asistentov**, ktorí vyhľadávajú, rezervujú a spravujú pobyt od začiatku do konca.
- **Bankových, vernostných a super-aplikácií agentov**, ktorí vkladajú hotelové rezervácie do existujúceho zákazníckeho zážitku.
- **Partnerov a tvorcov automatizácií**, ktorí objavujú vhodné hotely, vytvárajú aktíva a udržiavajú priradenie — získavajúc 10 % štandardnú províziu z potvrdených rezervácií.
- **Hotelových kopilotov**, ktorí pomáhajú tímom generovať obsah a analyzovať výkonnosť cez [Extranet](/sk/products/extranet/), [Social](/sk/products/social/) a [Studio](/sk/products/studio/), zatiaľ čo hotel si udržiava pravidlá.

## Kam to smeruje

Vyššie uvedené schopnosti sú dnes živé cez REST API a MCP server. Smerovanie je hlbší agentický obchod: bohatšie agentom orientované rezervačné primitivá, identita a autorizácia agenta na realizáciu transakcií v mene cestovateľa a agenti ako priradené, zárobkové zdroje v partnerskej sieti. Spoločným menovateľom je konzistentné — **infraštruktúra cestovného obchodu pre AI agentov**, s Booking Engine ako vrstvou plnenia pod tým.

## Bežné chyby

- **Považovať AI objavovanie a AI agentov za ten istý projekt.** Jeden je o obsahu a štruktúre; druhý o API a plnení. Potrebujete oboje.
- **Nechať agentov uvádzať ceny, ktoré nemôžu rezervovať.** Ceny musia pochádzať z živých cien a dostupnosti, nie zo scraping-u stránok.
- **Stratiť atribúciu pri odovzdaní.** Ak agent vytvára dopyt, rezervácia by mala zostať priradená k tomu zdroju.
- **Preskočiť vrstvu plnenia.** Odpoveď nie je rezervácia, kým sa skutočne neuskutoční checkout, platba a potvrdenie.
