## Warum Konnektivität wichtig ist

Jeder Buchungspfad hängt von genauen Hotelangeboten ab. Wenn der Preis falsch ist, verliert der Gast Vertrauen; wenn die Verfügbarkeit falsch ist, riskiert das Hotel eine fehlgeschlagene Buchung; wenn das Inventar veraltet ist, funktioniert kein Kanal zuverlässig. Wink treibt mehr als nur einen Buchungsbutton auf der Website an — dieselben Hoteldaten unterstützen Website-Pfade, teilbare Links, QR-Codes, Webkomponenten, WinkLinks-Shops, Partnerlinks, Traveliko-Listings, Social-Buchungskanäle, Agentic AI-Übergaben und Entwickler-Flows. Alle benötigen dieselbe Grundlage: genaue **ARI** — Verfügbarkeit, Preis und Inventar.

## Die zwei Einrichtungswege

**Weg 1 — Verbinden Sie einen unterstützten Provider.** Verwenden Sie dies, wenn das Hotel Preise bereits in einem Channel Manager, PMS, CRS oder Preisprovider verwaltet, den Wink unterstützt. Das Hotel wählt den Provider im Extranet aus, aktiviert Wink als Kanal im Provider-Dashboard, ordnet Zimmertypen und Tarifpläne zu, und der Provider sendet ARI an Wink — wodurch der Master Rate Calendar automatisch gefüllt wird. Am besten für Multi-Channel-Hotels, häufige Preisänderungen, Live-Inventarbedarf und geringeren manuellen Aufwand.

**Weg 2 — Preise manuell im Extranet laden.** Verwenden Sie dies, wenn das Hotel keinen unterstützten Provider nutzt oder Wink manuell über `Distribution > Master rate calendar` betreiben möchte — Einzel- und Massenupdates über Datumsbereiche. Am besten für kleines Inventar, frühe Einrichtung oder Tests. **Es erfordert Disziplin:** Wenn sich Preise im Betrieb ändern, muss jemand Wink aktualisieren. Und wenn ein Provider verbunden ist, kann eine manuelle Änderung überschrieben werden, wenn der Provider das nächste Update für dieselben Daten sendet.

## Verbundener Provider vs. manuelles Laden

| Frage | Verbundener Provider | Manuelles Laden im Extranet |
|---|---|---|
| Wer aktualisiert ARI? | Der unterstützte Provider sendet Updates an Wink. | Das Hotel aktualisiert Preise und Verfügbarkeiten manuell. |
| Am besten für | Multi-Channel-Hotels, häufige Änderungen, Live-Inventar. | Kleines Inventar, begrenzte Nutzung, kein verbundener Provider. |
| Arbeitsaufwand | Geringerer täglicher Aufwand nach Einrichtung. | Laufende manuelle Pflege. |
| Echtzeit-Verhalten | ARI wird automatisch vom Provider aktualisiert. | Nur so aktuell wie das letzte manuelle Update. |
| Risiko | Mapping oder Provider-Einrichtung muss korrekt sein. | Veraltete Preise oder Verfügbarkeiten, wenn nicht gepflegt. |
| Buchungsbenachrichtigung | Channel Manager / CRS / PMS wird bei Konfiguration benachrichtigt. | Hotel erhält Buchungsbenachrichtigungen über Wink. |

## Unterstützte Provider

Wink unterstützt eine Reihe von Channel Managern sowie PMS-Verbindungen direkt oder über Channex als Proxy. Bestätigen Sie Ihre spezifische Providerversion, Einrichtungsweg und Mapping-Anforderungen mit dem Wink-Team, bevor Sie live gehen.

| Provider | Typ | Hinweise |
|---|---|---|
| SiteMinder | Channel Manager | Direkte Integration |
| Cloudbeds | Channel Manager | Direkte Integration |
| Travelclick | Channel Manager | Direkte Integration |
| RateGain | Channel Manager | Direkte Integration |
| D-EDGE | Channel Manager | Direkte Integration |
| YieldPlanet | Channel Manager | Direkte Integration |
| Rate Tiger | Channel Manager | Direkte Integration |
| Hotel Link | Channel Manager | Direkte Integration |
| Channex | Channel Manager + PMS Proxy | Direkt, plus Proxy für viele PMS-Provider |
| SynXis | CRS | Zusätzliche Einrichtung über SynXis Channel Connect Express kann erforderlich sein |

Viele PMS-Systeme — zum Beispiel Mews, Apaleo, Opera Cloud und OTA Sync — können ARI **über Channex** als Proxy an Wink weiterleiten. Wenn Ihr PMS an Channex angebunden ist, kann es Wink erreichen; bestätigen Sie Ihre PMS-Version und Channex-Einrichtung vor dem Livegang. (Dies ist eine repräsentative Liste — bestätigen Sie Ihren Provider mit dem Wink-Team.)

## Provider-Einrichtung, kurz gefasst

Gehen Sie im Extranet zu `Distribution > Channel manager`, wählen Sie Ihren Preisprovider aus und speichern Sie. Fügen Sie im Provider-Dashboard den **Wink**-Kanal hinzu und ordnen Sie die in Wink erstellten Zimmertypen und Tarifpläne zu. Starten Sie einen vollständigen Preis-Push, falls der Provider dies nicht automatisch macht, und prüfen Sie den Master Rate Calendar — die Aktualisierung kann innerhalb weniger Minuten erfolgen (Zeitpunkt variiert je nach Provider und Mapping). Verwenden Sie den **Verifier**, um eine Reisenden-Preisanfrage zu simulieren und Verfügbarkeit, Währung, Rabatte und Preisanzeige vor dem Livegang zu testen. Erstellen Sie eine Testbuchung erst, wenn das Team das Benachrichtigungsverhalten verstanden hat.

## Buchungsbenachrichtigungen

Konnektivität bedeutet nicht nur, Preise *an* Wink zu senden — es geht auch darum, wie Buchungen zurückfließen. Wenn eine Buchung erfolgt, können Channel Manager, CRS oder PMS dort benachrichtigt werden, wo es konfiguriert ist; das Hotel und der Gast erhalten Bestätigungs-E-Mails; Partner erhalten Buchungs- und Attributionsbestätigungen auf Partnerkanälen; und Entwickler können auf ein `booking.created` Webhook für Echtzeitdetails hören.

## Wo Wink passt

Konnektivität sitzt zwischen Extranet und Buchungsengine. [Extranet](/de/products/extranet/) ist die Hotelseite-Steuerungsebene für Inhalte, Zimmer, Tarifpläne, Einschränkungen, Verfügbarkeiten, Richtlinien und Buchungsengine-Einstellungen; ein unterstützter Provider speist ARI ein, oder das Hotel pflegt den Master Rate Calendar manuell; und die [Buchungsengine](/de/products/booking-engine/) nutzt diese freigegebenen Daten, um Buchungen aus direkten, Social-, WinkLinks-, Partner-, Traveliko-, Agentic AI- und Entwicklerkanälen zu erfüllen. Die einfache Regel: **Je stärker die Konnektivität, desto zuverlässiger der Buchungspfad.**

## Häufige Fehler

- **Annehmen, Wink kann ohne aktuelle Verfügbarkeit verkaufen.** Es benötigt zuerst ARI von einem Provider oder manuelle Extranet-Updates.
- **Provider verbinden, aber Zimmer und Tarifpläne nicht zuordnen.** Die Einrichtung ist erst abgeschlossen, wenn das Mapping korrekt ist.
- **Preise manuell ändern, während ein Provider verbunden ist.** Manuelle Änderungen können durch das nächste Provider-Update überschrieben werden.
- **Vergessen zu verifizieren.** Testen Sie Preisanzeige, Verfügbarkeit und Rabattlogik vor dem Livegang.
- **Konnektivität nur als technische Aufgabe betrachten.** Sie beeinflusst Umsatz, Marketing, Partnerkanäle, Conversion und Gästevertrauen.
