Winks MCP-Tools werden als **Toolsets** veröffentlicht – fokussierte Endpunkte, die jeweils eine Aufgabe abdecken. Sie verbinden Ihren KI-Client nur mit dem oder den ein bis zwei Toolsets, die zu Ihrer Arbeit passen, nicht mit allen.

Jeder Endpunkt verwendet **interaktives OAuth2-Login** (PKCE-Autorisierungscode-Fluss): Ihr KI-Agent öffnet einen Browser-Tab, Sie melden sich mit Ihrem Wink-Konto an, und das war’s. Keine Client-Geheimnisse zu verwalten.

```bash title="Ein Channel-Manager-Integrator verbindet sich mit einem Endpunkt"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="Ein Hotelier, der seine eigenen Preise verwaltet, verbindet sich mit einem anderen"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## Warum die Tools auf verschiedene Endpunkte aufgeteilt sind

Wink stellt etwa 500 Tools bereit. Alle auf einmal einem Agenten zu übergeben ist technisch möglich – aber keine gute Idee.

**Tool-Definitionen beanspruchen Kontext.** Jedes Tool, das ein MCP-Server anbietet, wird vor der Arbeit in das Kontextfenster des Modells geladen, zusammen mit seiner Beschreibung und dem vollständigen Parameterschema. Fünfhundert davon verbrauchen einen großen Teil des Budgets, das Ihre eigentliche Aufgabe bei jeder einzelnen Anfrage benötigt.

**Die Qualität der Auswahl sinkt mit der Länge der Liste.** Ein Agent, der aus 500 ähnlich benannten Tools auswählt, trifft schlechtere Entscheidungen als einer, der aus 40 auswählt. Wenn Sie einen Channel Manager integrieren, sind etwa zwanzig Tools für Sie relevant; die anderen 480 sind Rauschen, das das richtige Tool schwerer auffindbar macht.

**Die Arbeit ist tatsächlich trennbar.** Jemand, der Verfügbarkeiten aus einem PMS synchronisiert, und jemand, der Affiliate-Landingpages kuratiert, teilen fast keine Tools. Die Aufteilung nach Aufgaben bedeutet, dass jede Verbindung den Wortschatz einer Aufgabe trägt.

<Aside type="caution" title="Toolsets sind keine Berechtigungen">
Die Wahl eines engen Toolsets schränkt **nicht** ein, was Ihr Konto tun kann, und die Wahl eines breiten Toolsets gewährt nichts zusätzlich. Jedes Tool erzwingt dieselben Kontoberechtigungen wie das Webportal, unter Ihrer angemeldeten Identität. Wenn Ihr Konto keine Buchung im Wink Portal stornieren kann, kann der Agent das auch nicht – unabhängig davon, mit welchem Endpunkt er verbunden ist.

Wählen Sie Toolsets für **Fokus**, nicht für Sicherheit.
</Aside>

### `https://integrations.wink.travel` — Channel-Manager-Integrationen

Ein Endpunkt, da dieser Host für eine Aufgabe existiert.

| Endpunkt | Tools | Was abgedeckt wird |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Verbindung und Verifizierung einer Channel-Manager-, PMS- oder CRS-Integration |

<Aside type="note" title="Channel-Manager-Integration vs. eigene Preisverwaltung">
Dies sind unterschiedliche Aufgaben für unterschiedliche Personen, und sie teilen keinen Endpunkt.

Ein **Channel-Manager-, PMS- oder CRS-Anbieter** integriert sich einmal über `integrations.wink.travel/mcp/channel-manager` und tauscht von da an Objekte, Preise, Verfügbarkeiten und Reservierungen über diese Integration aus. Dieser einzelne Endpunkt ist die gesamte Oberfläche.

Ein **Hotelier, der seine eigenen Preise manuell ändert**, nutzt die Extranet-Toolsets auf `api.wink.travel` — `/mcp/extranet/rates` und weitere. Diese sind kein Teil einer Channel-Manager-Integration und ein Integrator hat keinen Grund, sich damit zu verbinden.

Die Kontoverwaltung befindet sich ebenfalls auf `api.wink.travel`, unter `/mcp/settings`. Auf dem Integrations-Host gibt es kein `/mcp/settings`.
</Aside>

Jeder Endpunkt bietet auch ein `ping`-Tool, mit dem Sie bestätigen können, dass eine Verbindung aktiv ist, bevor Sie echte Arbeit anfordern.

## Welche Toolsets benötige ich?

| Wenn Sie… | Verbinden Sie sich mit |
|---|---|
| **einen Channel Manager, PMS oder CRS integrieren** | `integrations.wink.travel/mcp/channel-manager` — nur dieser eine |
| **den Inhalt einer Unterkunft verwalten** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Zimmer und Zimmertypen verwalten** | `/mcp/extranet/facilities` |
| **Preise und Verfügbarkeit verwalten** | `/mcp/extranet/rates` |
| **tägliche Reservierungen abwickeln** | `/mcp/extranet/operations` |
| **Distribution ausbauen** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Affiliate-Seiten erstellen** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Link-in-Bio-Seiten betreiben** | `/mcp/link-manager` + `/mcp/social` |
| **im Auftrag von Reisenden buchen** | `/mcp/travel-agent` |
| **Geld abgleichen** | `/mcp/payment` |
| **ein Buchungserlebnis aufbauen** | `/mcp/booking-engine` + `/mcp/reference` |

Beginnen Sie mit einem. Fügen Sie einen weiteren hinzu, wenn Sie etwas anfragen, das der erste nicht kann – jede Verbindung ist unabhängig, und das Hinzufügen eines weiteren beeinflusst die anderen nicht.

<Aside type="tip" title="Sie wollen trotzdem alles?">
`https://api.wink.travel/mcp` und `https://integrations.wink.travel/mcp` sind weiterhin verfügbar und bieten **alle** Tools ihres Hosts an. Sie sind nützlich, um zu erkunden, was existiert, aber wir empfehlen sie nicht für die tägliche Arbeit: Die Tool-Liste ist groß genug, um Ihre Aufgabe zu überlagern und die Tool-Auswahl des Agenten zu verschlechtern. Bevorzugen Sie die oben genannten Toolsets.
</Aside>

## Wie die Authentifizierung funktioniert

Wink MCP-Server verwenden den **OAuth2 Authorization Code + PKCE**-Fluss und unterstützen **Dynamic Client Registration (RFC 7591)**. So läuft es ab, wenn Sie sich zum ersten Mal verbinden:

1. Ihr KI-Client entdeckt den Autorisierungsserver aus den `/.well-known/oauth-protected-resource`-Metadaten des MCP-Endpunkts.
2. Der Client registriert sich selbst über **Dynamic Client Registration** – keine manuelle Anwendungsregistrierung erforderlich.
3. Der Client öffnet einen **Browser-Tab** zu `https://iam.wink.travel`. Sie melden sich mit Ihrem Wink-Konto an und genehmigen die angeforderten Berechtigungen auf dem Zustimmungsbildschirm.
4. Wink stellt ein **Access Token** aus, das auf Ihr Konto beschränkt und mit Ihrer Identität verknüpft ist.
5. Der KI-Client hängt das Token an jede MCP-Anfrage an. Alle Tool-Ergebnisse sind automatisch auf Ihre Verwaltungseinheit beschränkt.
6. Tokens laufen nach 3 Stunden ab. Ihr KI-Client erneuert sie im Hintergrund still, ohne erneut zu fragen.

Jeder Tool-Aufruf läuft **unter Ihrer Identität** – dieselben ACL-Regeln, die das Webportal schützen, gelten für den KI-Agenten.

## Berechtigungen (Scopes)

Wenn Sie den Zustimmungsbildschirm genehmigen, sehen Sie eine Aufschlüsselung dessen, was der Agent anfordert. MCP-Clients verwenden denselben Berechtigungswortschatz wie der Rest der Plattform – siehe die vollständige
[Vollständige Scope-Referenz auf der Authentifizierungsseite](/de/developers/authentication#scopes).

Zwei Dinge sind spezifisch für MCP:

- **Die Scopes `mcp.read`, `mcp.write` und `mcp.remove` sind zusätzlich erforderlich**, um den MCP-Transport zu öffnen. Ein Client mit einem `mcp.*`-Scope wird an jeden Wink MCP-Endpunkt zugelassen, aber jedes Tool erzwingt weiterhin den Bereichsscope des Endpunkts, den es umschließt (z. B. `booking.read`).
- **Der KI-Client fordert nur die Scopes an, die er benötigt.** Sie können einzelne Berechtigungen auf dem Zustimmungsbildschirm ablehnen – Tools, die einen abgelehnten Scope benötigen, geben bei Aufruf einen Fehler zurück.

**Toolsets ändern daran nichts.** Der Endpunkt, mit dem Sie sich verbinden, entscheidet, welche Tools *aufgelistet* werden, nicht, was sie *tun dürfen*. Die Verbindung zu `/mcp/payment` gewährt keine finanziellen Berechtigungen, die Sie nicht bereits hatten, und die Verbindung zu `/mcp/reference` verhindert nicht, dass ein Tool dort seinen eigenen Scope erzwingt. Die Autorisierung wird pro Tool-Aufruf anhand Ihres Tokens und der Berechtigungen Ihres Kontos entschieden.

## Fehlerbehebung

**Browser-Tab öffnet sich nicht**

Ihr KI-Client unterstützt möglicherweise noch nicht den interaktiven PKCE-Fluss. Vergewissern Sie sich, dass Sie eine aktuelle Version verwenden:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT Desktop:** Aktualisieren Sie über den integrierten Updater der App

**`401 Unauthorized` nach der Anmeldung**

Ihr zwischengespeichertes Token ist möglicherweise veraltet. Entfernen Sie den Server und fügen Sie ihn erneut hinzu, um eine frische Anmeldung auszulösen:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

Für Claude Desktop und ChatGPT entfernen Sie den Servereintrag aus den Einstellungen, starten die App neu und fügen ihn erneut hinzu.

**`403 Forbidden` bei Aufruf eines bestimmten Tools**

Das Tool benötigt einen Scope, den Sie auf dem Zustimmungsbildschirm nicht genehmigt haben, oder eine Berechtigung, die Ihr Konto nicht besitzt. Verbinden Sie den Server erneut – der Zustimmungsbildschirm erscheint wieder und Sie können die fehlende Berechtigung genehmigen. Wenn es weiterhin fehlschlägt, benötigt das Tool eine Kontoberechtigung, die Sie nicht haben; die Verbindung zu einem anderen Toolset hilft nicht, da Toolsets keine Berechtigungen gewähren.

**Das benötigte Tool ist nicht in der Liste**

Sie sind wahrscheinlich mit einem Toolset verbunden, das diese Aufgabe nicht abdeckt. Prüfen Sie das [Endpunktverzeichnis](#endpoint-directory) und fügen Sie das Toolset hinzu, das es abdeckt – Verbindungen sind unabhängig, das Hinzufügen eines Toolsets ändert nichts an den anderen. Wenn Sie unsicher sind, welches Toolset es hat, verbinden Sie sich vorübergehend mit `https://api.wink.travel/mcp`, finden das Tool und sehen dann nach, welches Toolset es listet.

**`404 Not Found` bei einem Toolset-Endpunkt**

Prüfen Sie den Pfad sorgfältig – die verschachtelten Toolsets haben zwei Segmente (`/mcp/extranet/rates`, nicht `/mcp/extranet-rates`), die flachen haben eines (`/mcp/link-manager`). Beachten Sie, dass eine *nicht authentifizierte* Anfrage an einen Pfad unter `/mcp` `401` zurückgibt, nicht `404`, daher sagt ein `401` allein nicht, ob der Endpunkt existiert.

**Ich habe mich mit `api.wink.travel/mcp/channel-manager` verbunden und nichts erhalten**

Diesen Endpunkt gibt es nicht. Channel-Manager-Integration wird nur von `https://integrations.wink.travel/mcp/channel-manager` bedient. Wenn Sie auch die eigenen Preise einer Unterkunft manuell lesen oder schreiben müssen, ist das eine separate Aufgabe auf einem separaten Endpunkt – siehe `/mcp/extranet/rates`.

**Der Server erscheint, aber Tool-Aufrufe geben „Konto nicht gefunden“ zurück**

Sie sind bei einem Wink-Konto angemeldet, das keine Verwaltungseinheit hat. Gehen Sie zu [Wink Portal](https://app.wink.travel) und stellen Sie sicher, dass Ihr Konto eingerichtet ist, bevor Sie den MCP-Server verwenden.

**Token läuft mitten in der Sitzung ab**

Tokens sind 3 Stunden gültig. Claude Code und Claude Desktop erneuern Tokens still, ohne Ihre Sitzung zu unterbrechen. Wenn Sie nach langer Inaktivität Authentifizierungsfehler sehen, senden Sie eine neue Nachricht – der Client authentifiziert automatisch neu.

**Codex CLI zeigt „MCP server unreachable“**

Prüfen Sie, ob Ihre `~/.codex/config.json` gültiges JSON ist (keine abschließenden Kommas) und `"type": "http"` gesetzt ist. Codex benötigt HTTP-Transport für Remote-Server; stdio-Transport ist nur für lokale Binärdateien.

**ChatGPT „Connectors“-Menü fehlt**

MCP-Unterstützung erfordert ChatGPT-Desktop-App Version **1.2024.352** oder höher und ein aktives Plus-, Pro-, Team- oder Enterprise-Abonnement. Aktualisieren Sie die App und prüfen Sie Ihren Plan unter Einstellungen → Konto.

**Cursor-Server zeigt rot / „Verbindung fehlgeschlagen“**

Prüfen Sie, ob Ihre `~/.cursor/mcp.json` gültiges JSON enthält und `"type": "http"` gesetzt ist. Gehen Sie dann zu **Einstellungen → Cursor-Einstellungen → MCP** und klicken Sie auf **Aktualisieren**. Wenn der Fehler bleibt, starten Sie Cursor vollständig neu – Konfigurationsänderungen werden nicht immer ohne Neustart übernommen.

**Windsurf MCP-Server werden in den Einstellungen nicht angezeigt**

Windsurf benötigt einen vollständigen Neustart (nicht nur Fenster-Neuladen), um Änderungen an `mcp_config.json` zu übernehmen. Verwenden Sie **Datei → Beenden** und starten Sie neu. Wenn die Server immer noch nicht erscheinen, prüfen Sie, ob Sie Windsurf **1.4+** verwenden (über **Hilfe → Über Windsurf**).

**Cline „Server hinzufügen“-Option ist nicht sichtbar**

Der MCP-Server-Manager benötigt Cline **2.0** oder höher. Öffnen Sie das VS Code-Erweiterungsfenster, suchen Sie Cline und klicken Sie auf **Aktualisieren**, falls verfügbar. Nach dem Update laden Sie VS Code neu (`Ctrl+Shift+P` → „Developer: Reload Window“).
