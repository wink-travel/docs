Wenn Sie Werbekampagnen über Sojern durchführen, können Sie Ihr Sojern-Konto mit Wink verbinden, indem Sie Ihre Sojern GTM Container-ID im Wink-Portal eingeben. Nach der Verbindung wird das Tracking-Pixel von Sojern automatisch für Ihre Unterkunft ausgelöst – und deckt die gesamte Gästereise von der Suche bis zur abgeschlossenen Buchung ab.

<Aside type="tip">
Dies setzt voraus, dass Sie bereits ein aktives Sojern-Konto haben und Ihre GTM Container-ID von Ihrem Sojern-Kundenbetreuer erhalten haben. Falls Sie noch kein Sojern-Konto besitzen, besuchen Sie [sojern.com/contact](https://www.sojern.com/contact), um zu starten.
</Aside>

---

## Was Sie tun müssen

<Steps>

1. **Holen Sie Ihre GTM Container-ID von Sojern**

   Kontaktieren Sie Ihren Sojern-Kundenbetreuer und fordern Sie Ihre **GTM Container-ID** an. Sie hat das Format `GTM-XXXXXXX`. Diese unterscheidet sich von Ihrer Sojern Pixel-ID – stellen Sie sicher, dass Sie speziell nach der GTM Container-ID fragen.

2. **Geben Sie sie im Wink-Portal ein**

   Melden Sie sich bei [app.wink.travel](https://app.wink.travel) an, wählen Sie Ihr Konto aus und gehen Sie zum Tab **Anpassungen**. Fügen Sie Ihre Sojern GTM Container-ID in das Sojern-Feld ein und speichern Sie. Ihre Integration ist nun aktiv.

3. **Bestätigen Sie mit Ihrem Sojern-Kundenbetreuer**

   Informieren Sie Ihren Sojern-Kundenbetreuer, dass die Integration aktiv ist. Er kann von seiner Seite aus überprüfen, ob das Pixel korrekt auf `wink.travel` für Ihre Unterkunft ausgelöst wird und ob Daten in Ihr Sojern-Konto fließen.

</Steps>

<Aside type="note">
Für diese Integration müssen Sie keinen Pixel-Code auf Ihrer eigenen Website platzieren. Wink lädt Ihren Sojern-Container automatisch auf allen Seiten, auf denen Ihre Unterkunft aktiv ist.

Diese Konfiguration funktioniert für jede benutzerdefinierte GTM Container-ID. Wir haben Sojern nur als Beispiel verwendet, da es eine sehr häufige Integration ist.
</Aside>

## Was Wink auf unserer Seite macht

Zur Transparenz hier, was Wink konfiguriert, um diese Integration zu ermöglichen:

- **Ein Sojern GTM Container-ID-Feld** ist im Tab Anpassungen Ihres Wink-Portals verfügbar. Wenn Sie Ihre Container-ID eingeben, validiert Wink das Format und speichert sie sicher für Ihre Unterkunft.
- **Auf jeder Seite, auf der Ihre Unterkunft bei Wink aktiv ist**, wird Ihre Sojern GTM Container-ID in die Seite eingebettet und Winks Tag-Management-System lädt Ihren Sojern-Container dynamisch neben dem eigenen. Dies geschieht automatisch – es sind keine manuellen Schritte vom Wink-Team pro Unterkunft erforderlich.
- **Ihr Sojern-Container wird asynchron geladen**, was bedeutet, dass die Seitenladezeit für Ihre Gäste nicht beeinträchtigt wird.
- **Winks eigenes Tracking und Ihr Sojern-Pixel laufen parallel** und lesen aus denselben gemeinsamen Ereignisdaten. Jedes Buchungsereignis, das Wink verfolgt, steht gleichzeitig Ihrem Sojern-Container zur Verfügung.
- **Wenn Ihre Unterkunft nicht angezeigt wird** – zum Beispiel, wenn ein Gast ein anderes Hotel bei Wink durchsucht – wird Ihr Sojern-Container nicht geladen. So erhält Sojern nur Daten, die für Ihre Unterkunft relevant sind.

## DataLayer-Referenz

Wink pusht GA4-kompatible Events während der gesamten Gästereise in den `dataLayer`. Ihr GTM-Container liest aus demselben gemeinsamen `dataLayer`, sodass jeder Trigger oder jede Variable, die Sie konfigurieren, Zugriff auf alle unten beschriebenen Eigenschaften hat.

Jedes Event folgt der standardmäßigen GA4 Enhanced Ecommerce-Struktur: einem obersten `event`-String und einem `ecommerce`-Objekt. Vor jedem Push löscht Wink die vorherigen Ecommerce-Daten, um zu verhindern, dass veraltete Daten in neue Trigger gelangen.

<Aside type="note">
**dataLayer Reset-Muster**

Wink setzt das Ecommerce-Objekt vor jedem Event-Push zurück:

```js
dataLayer.push({ ecommerce: null });   // vorheriges Event löschen
dataLayer.push({ event: '...', ecommerce: { ... } });
```

Verlassen Sie sich nicht darauf, dass Ecommerce-Eigenschaften zwischen Events erhalten bleiben. Lesen Sie sie immer zum Zeitpunkt des Triggers innerhalb desselben Events aus.
</Aside>

### Buchungsreise-Events

Diese Events werden automatisch ausgelöst, wenn ein Gast den Buchungstrichter durchläuft. Konfigurieren Sie Ihre GTM-Trigger als **Custom Event**-Trigger, die den untenstehenden Eventnamen entsprechen.

| Schritt | Event | Wann es ausgelöst wird |
|------|-------|-----------------------|
| 1 | `view_item_list` | Hotel-Inventar-Gitter oder Liste wird geladen |
| 2 | `view_item` | Gast sieht sich eine bestimmte Unterkunftsseite an |
| 3 | `add_to_cart` | Gast legt ein Zimmer in den Warenkorb |
| 4 | `begin_checkout` | Checkout- / Zahlungsseite wird geladen |
| 5 | `add_payment_info` | Gast wählt eine Zahlungsmethode aus |
| 6 | `login` | Gast authentifiziert sich via SSO |
| 7 | `purchase` | Buchung wird bestätigt |
| 8 | `refund` | Buchung wird storniert |

### Benutzerdefinierte Dimensionen in GA4

GA4 ignoriert benutzerdefinierte Artikelparameter in Berichten, bis Sie sie explizit als artikelbezogene benutzerdefinierte Dimensionen registrieren. Sie müssen nur die Parameter registrieren, die Sie in Berichten verwenden möchten – nicht alle 20.

<Steps>

1. **Öffnen Sie die benutzerdefinierten Definitionen**

   Gehen Sie in GA4 zu **Admin** (Zahnrad-Symbol unten links) → wählen Sie Ihre Property → **Datenanzeige** → **Benutzerdefinierte Definitionen**.

2. **Erstellen Sie eine neue benutzerdefinierte Dimension**

   Klicken Sie auf **Benutzerdefinierte Dimensionen erstellen**.

3. **Füllen Sie die Details der Dimension aus**

   - **Dimensionsname** — die lesbare Bezeichnung, die in GA4-Berichten erscheint (siehe Tabelle unten)
   - **Bereich** — wählen Sie **Artikel**
   - **Ereignisparameter** — der genaue Parametername, wie er im dataLayer erscheint (siehe Tabelle unten)
   - **Beschreibung** — optional, aber empfohlen

4. **Speichern und wiederholen**

   Klicken Sie auf **Speichern** und wiederholen Sie den Vorgang für jeden Parameter, den Sie verfolgen möchten.

</Steps>

<Aside type="note">
Benutzerdefinierte Dimensionen können bis zu 24 Stunden benötigen, bis sie nach der Registrierung in GA4-Berichten erscheinen. Historische Daten, die vor der Registrierung gesammelt wurden, werden nicht nachträglich eingefügt.

GA4 erlaubt bis zu 50 artikelbezogene benutzerdefinierte Dimensionen pro Property bei Standard-Properties (360 Properties erlauben mehr).
</Aside>

Verwenden Sie die folgende Tabelle als Referenz beim Erstellen benutzerdefinierter Dimensionen. Der Wert für **Ereignisparameter** muss exakt übereinstimmen – GA4 ist case-sensitive.

| Dimensionsname | Ereignisparameter | Typ |
|----------------|-------------------|-----|
| Unterkunfts-ID | `property_id` | Text |
| Unterkunftsname | `property_name` | Text |
| Unterkunftsmarke | `property_brand` | Text |
| Unterkunftskette | `property_chain` | Text |
| Unterkunfts-URL-Name | `property_url_name` | Text |
| Stadtname | `city_name` | Text |
| Ländercode | `country_code` | Text |
| Check-in-Datum | `start_date` | Text |
| Check-out-Datum | `end_date` | Text |
| Anzahl Erwachsene | `num_adults` | Zahl |
| Anzahl Kinder | `num_children` | Zahl |
| Stornierungsbedingungen | `cancellation_policy` | Text |
| Tarifplan-ID | `rate_plan_id` | Text |
| Zimmerpreis-ID | `room_rate_id` | Text |
| Zimmerpreisname | `room_rate_name` | Text |
| Anzahl Extras | `num_perks` | Zahl |
| Zimmerstandort | `room_location` | Text |
| Zimmerausblick | `room_view` | Text |
| Zimmerklassifikation | `room_classification` | Text |
| Bettenart | `bed_type` | Text |

### `virtualPageView`

Dies ist ein benutzerdefiniertes Wink-Event – kein Teil des standardmäßigen GA4-Event-Sets. Es wird bei jeder Seiten-Navigation gepusht und enthält Geräte- und Sitzungs-Kontext. Es enthält kein `ecommerce`-Objekt.

```json
{
  "event": "virtualPageView",
  "device": "Desktop",
  "deviceAgent": "Mozilla/5.0 ...",
  "os": "MacOS",
  "path": "/hotels/grand-resort",
  "title": "Grand Resort — Wink",
  "userId": "user_abc123",
  "startDate": "2026-06-01",
  "endDate": "2026-06-05",
  "guests": "2",
  "rooms": "1"
}
```

| Eigenschaft | Beschreibung |
|----------|-------------|
| `device` | Erkanntes Gerätetyp – `Desktop`, `Android`, `iPhone`, `iPad` oder ähnlich |
| `deviceAgent` | Rohes User-Agent-String |
| `os` | Erkanntes Betriebssystem – `Windows`, `MacOS`, `Linux`, `UNIX` |
| `path` | Aktueller Seitenpfad |
| `title` | Aktueller Seitentitel |
| `userId` | Authentifizierte Benutzerkennung (nicht vorhanden, wenn nicht eingeloggt) |
| `startDate` | Check-in-Datum aus der aktuellen Suchsitzung |
| `endDate` | Check-out-Datum aus der aktuellen Suchsitzung |
| `guests` | Anzahl der Gäste aus der aktuellen Suchsitzung |
| `rooms` | Anzahl der Zimmer aus der aktuellen Suchsitzung |
