## Hvorfor tilkobling er viktig

Hver bookingvei er avhengig av nøyaktig hotelltilbud. Hvis prisen er feil, mister gjesten tillit; hvis tilgjengeligheten er feil, risikerer hotellet en mislykket booking; hvis lageret er utdatert, fungerer ingen vei pålitelig. Wink driver mer enn en nettsidebookingknapp — de samme hotelldataene støtter nettsidestier, delbare lenker, QR-koder, webkomponenter, WinkLinks-butikker, partnerlenker, Traveliko-oppføringer, sosiale bookingveier, Agentic AI-overleveringer og utviklerflyter. Alle trenger det samme grunnlaget: nøyaktig **ARI** — Tilgjengelighet, Pris og Lager.

## De to oppsettsveiene

**Veien 1 — Koble til en støttet leverandør.** Bruk dette når hotellet allerede administrerer priser i en channel manager, PMS, CRS eller prisleverandør som Wink støtter. Hotellet velger leverandøren i Extranet, aktiverer Wink som kanal i leverandørens dashbord, kartlegger romtyper og prisplaner, og leverandøren sender ARI til Wink — og fyller Master Rate Calendar automatisk. Best for hoteller med flere kanaler, hyppige prisendringer, behov for live lager og lavere manuelt arbeid.

**Veien 2 — Last opp priser manuelt i Extranet.** Bruk dette når hotellet ikke bruker en støttet leverandør eller ønsker å drive Wink manuelt via `Distribution > Master rate calendar` — enkeltoppdateringer og masseoppdateringer over datointervaller. Best for lite lager, tidlig oppsett eller testing. **Det krever disiplin:** hvis priser endres i driften, må noen oppdatere Wink. Og hvis en leverandør er tilkoblet, kan en manuell endring bli overskrevet når leverandøren sender sin neste oppdatering for de samme datoene.

## Tilkoblet leverandør vs manuell innlasting

| Spørsmål | Tilkoblet leverandør | Manuell innlasting i Extranet |
|---|---|---|
| Hvem oppdaterer ARI? | Den støttede leverandøren sender oppdateringer til Wink. | Hotellet oppdaterer priser og tilgjengelighet manuelt. |
| Best for | Hoteller med flere kanaler, hyppige endringer, live lager. | Lite lager, begrenset bruk, ingen tilkoblet leverandør. |
| Arbeidsmengde | Lavere daglig arbeidsmengde etter oppsett. | Løpende manuelt vedlikehold. |
| Sanntidsatferd | ARI oppdateres automatisk fra leverandøren. | Bare så oppdatert som siste manuelle oppdatering. |
| Risiko | Kartlegging eller leverandøroppsett må være korrekt. | Utdaterte priser eller tilgjengelighet hvis ikke vedlikeholdt. |
| Bookingvarsling | Channel manager / CRS / PMS varsles der det er konfigurert. | Hotellet mottar bookingvarsler gjennom Wink. |

## Støttede leverandører

Wink støtter en rekke channel managers, pluss PMS-tilkoblinger direkte eller gjennom Channex som en proxy. Bekreft din spesifikke leverandørversjon, oppsettsvei og kartleggingskrav med Wink-teamet før du går live.

| Leverandør | Type | Notater |
|---|---|---|
| SiteMinder | Channel manager | Direkte integrasjon |
| Cloudbeds | Channel manager | Direkte integrasjon |
| Travelclick | Channel manager | Direkte integrasjon |
| RateGain | Channel manager | Direkte integrasjon |
| D-EDGE | Channel manager | Direkte integrasjon |
| YieldPlanet | Channel manager | Direkte integrasjon |
| Rate Tiger | Channel manager | Direkte integrasjon |
| Hotel Link | Channel manager | Direkte integrasjon |
| Channex | Channel manager + PMS proxy | Direkte, pluss en proxy for mange PMS-leverandører |
| SynXis | CRS | Ekstra oppsett via SynXis Channel Connect Express kan være nødvendig |

Mange PMS-systemer — for eksempel Mews, Apaleo, Opera Cloud og OTA Sync — kan rute ARI til Wink **gjennom Channex** som en proxy. Hvis din PMS kobler til Channex, kan den nå Wink; bekreft din PMS-versjon og Channex-oppsett før du går live. (Dette er en representativ liste — bekreft din leverandør med Wink-teamet.)

## Leverandøroppsett, kort fortalt

I Extranet, gå til `Distribution > Channel manager`, velg din prisleverandør og lagre. I leverandørens dashbord, legg til **Wink**-kanalen og kartlegg romtypene og prisplanene opprettet i Wink. Start en full pris-push hvis leverandøren ikke gjør det automatisk, og sjekk Master Rate Calendar — den kan oppdatere innen noen minutter (tiden varierer etter leverandør og kartlegging). Bruk **Verifier** for å simulere en reisendes prisforespørsel og teste tilgjengelighet, valuta, rabatter og prisvisning før du sender live etterspørsel. Lag en testbooking først når teamet forstår varslingsatferden.

## Bookingvarsler

Tilkobling handler ikke bare om å sende priser *til* Wink — det handler også om hvordan bookinger flyter tilbake. Når en booking gjøres, kan channel manager, CRS eller PMS varsles der det er konfigurert; hotellet og reisende mottar bekreftelses-e-poster; partnere mottar booking- og attribusjonsbekreftelse på partnerveier; og utviklere kan lytte til en `booking.created` webhook for sanntidsdetaljer.

## Hvor Wink passer inn

Tilkobling sitter mellom Extranet og Booking Engine. [Extranet](/no/products/extranet/) er hotellens kontrolllag for innhold, rom, prisplaner, restriksjoner, tilgjengelighet, retningslinjer og Booking Engine-innstillinger; en støttet leverandør mater ARI inn i det, eller hotellet vedlikeholder Master Rate Calendar manuelt; og [Booking Engine](/no/products/booking-engine/) bruker disse godkjente dataene til å oppfylle bookinger fra direkte, Sosiale, WinkLinks, partner-, Traveliko-, Agentic AI- og utviklerveier. Den enkle regelen: **jo sterkere tilkobling, desto mer pålitelig bookingvei.**

## Vanlige feil

- **Å anta at Wink kan selge uten oppdatert tilgjengelighet.** Det trenger ARI fra en leverandør eller manuelle Extranet-oppdateringer først.
- **Å koble til en leverandør uten å kartlegge rom og prisplaner.** Oppsettet er ikke fullført før kartleggingen er korrekt.
- **Å redigere priser manuelt mens en leverandør er tilkoblet.** Manuelle endringer kan bli overskrevet av neste leverandøroppdatering.
- **Å glemme å verifisere.** Test prisvisning, tilgjengelighet og rabattlogikk før du sender live etterspørsel.
- **Å behandle tilkobling som bare en teknisk oppgave.** Det påvirker inntekter, markedsføring, partnerruter, konvertering og gjestens tillit.
