Winks MCP-verktøy publiseres som **verktøysett** — fokuserte endepunkter, hver dekker én jobb. Du kobler AI-klienten din til én eller to som passer til arbeidet ditt, ikke til alle.

Hvert endepunkt bruker **interaktiv OAuth2-pålogging** (PKCE autorisasjonskodeflyt): AI-agenten din åpner en nettleserfane, du logger inn med Wink-kontoen din, og det er det. Ingen klienthemmeligheter å håndtere.

```bash title="En kanalmanager-integrator kobler til ett endepunkt"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="En hotellier som administrerer egne priser kobler til et annet"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## Hvorfor verktøyene er delt opp i endepunkter

Wink eksponerer rundt 500 verktøy. Å gi alle til en agent på en gang er teknisk mulig — og en dårlig idé.

**Verktøydefinisjoner koster kontekst.** Hvert verktøy en MCP-server annonserer lastes inn i modellens kontekstvindu før den gjør noe arbeid, sammen med beskrivelse og full parameter-skjema. Fem hundre slike bruker en stor del av budsjettet som den faktiske oppgaven din trenger, ved hver eneste forespørsel.

**Valgkvaliteten faller når listen vokser.** En agent som velger blant 500 verktøy med lignende navn gjør dårligere valg enn en som velger blant 40. Hvis du integrerer en kanalmanager, er omtrent tjue verktøy relevante for deg; de andre 480 er støy som gjør det vanskeligere å finne riktig verktøy.

**Arbeidet er genuint separerbart.** Noen som synkroniserer tilgjengelighet fra et PMS og noen som kuraterer affiliate landingssider deler nesten ingen verktøy. Å splitte etter jobb betyr at hver tilkobling bærer vokabularet til én jobb.

<Aside type="caution" title="Verktøysett er ikke tillatelser">
Å velge et smalt verktøysett begrenser **ikke** hva kontoen din kan gjøre, og å velge et bredt gir ikke noe ekstra. Hvert verktøy håndhever de samme kontotillatelsene som nettportalen, under din påloggede identitet. Hvis kontoen din ikke kan kansellere en booking i Wink Portal, kan ikke agenten det heller — uansett hvilket endepunkt den er koblet til.

Velg verktøysett for **fokus**, ikke for sikkerhet.
</Aside>

### `https://integrations.wink.travel` — kanalmanager-integrasjoner

Ett endepunkt, fordi denne verten finnes for én jobb.

| Endepunkt | Verktøy | Hva det dekker |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | Koble til og verifisere en kanalmanager-, PMS- eller CRS-integrasjon |

<Aside type="note" title="Integrering av kanalmanager vs. administrasjon av egne priser">
Dette er forskjellige jobber for forskjellige personer, og de deler ikke et endepunkt.

En **kanalmanager-, PMS- eller CRS-leverandør** integrerer én gang via `integrations.wink.travel/mcp/channel-manager`, og utveksler deretter eiendommer, priser, tilgjengelighet og reservasjoner over den integrasjonen. Det ene endepunktet er hele overflaten.

En **hotellier som endrer egne priser manuelt** bruker extranet-verktøysettene på `api.wink.travel` — `/mcp/extranet/rates` og lignende. Disse er ikke en del av en kanalmanager-integrasjon, og en integrator har ingen grunn til å koble til dem.

Konto-administrasjon er også på `api.wink.travel`, på `/mcp/settings`. Det finnes ikke `/mcp/settings` på integrasjonsverten.
</Aside>

Hvert endepunkt har også et `ping`-verktøy, slik at du kan bekrefte at en tilkobling er aktiv før du ber det gjøre reelt arbeid.

### Agentiske betalinger

For komplett bookingflyt for reisende, koble til **Wink Booking Engine** på `https://api.wink.travel/mcp/booking-engine` og en kompatibel **betalingslommebok**. Å legge til Wink MCP åpner nettleser-pålogging og tillatelsesvalg; klienten din håndterer deretter autentisering.

Booking Engine inkluderer destinasjonsoppslag, hotell- og romsøk, `agentic_booking_quote`, `agentic_booking_pay`, `agentic_booking_book`, bookinghenting og kvitteringer, når agentisk booking og betaling er aktivert for det miljøet. Se [Agentic Payments](/no/developers/agentic-payments/) for oppsett av tilkobling, tillatelser som skal velges og trinnene fra søk til bekreftelse.

## Hvilke verktøysett trenger jeg?

| Hvis du er… | Koble til |
|---|---|
| **Integrerer en kanalmanager, PMS eller CRS** | `integrations.wink.travel/mcp/channel-manager` — bare dette |
| **Administrerer en eiendoms innhold** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **Administrerer rom og romtyper** | `/mcp/extranet/facilities` |
| **Administrerer priser og tilgjengelighet** | `/mcp/extranet/rates` |
| **Driver daglige reservasjoner** | `/mcp/extranet/operations` |
| **Øker distribusjon** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **Bygger affiliate-sider** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **Driver link-in-bio-sider** | `/mcp/link-manager` + `/mcp/social` |
| **Booker på vegne av reisende** | `/mcp/travel-agent` |
| **Avstemmer penger** | `/mcp/payment` |
| **Booker et rom med en AI-agent** | `/mcp/booking-engine` + en kompatibel betalingslommebok — se [Agentic Payments](/no/developers/agentic-payments/) |
| **Bygger en bookingopplevelse** | `/mcp/booking-engine`; valgfritt `/mcp/reference` for ekstra oppslag |

**Booking Engine inkluderer kjerneflyten for booking.** Den tilbyr konto- og tilpasningsoppdagelse, destinasjonsoppslag, hotelltilgjengelighet og romprisdetaljer, handlekurver, utsjekk og reisendes bookingadministrasjon. Agentiske booking- og betalingsverktøy er også inkludert når aktivert for det miljøet.

For bybasert hotell-søk, bruk `destination_lookup_search_suggestions` for å løse destinasjonen, deretter `inventory_search_city` for å finne tilgjengelige hoteller og priser. Begge verktøyene er i `/mcp/booking-engine`, så denne flyten krever ikke en Reference-tilkobling.

Legg til `/mcp/reference` når du trenger støttende oppslag som land, valutaer og valutakurser, støttede språk, tidssoner, bredere geografiske søk, OTA-klassifiseringer eller offentlig eiendomskunnskap. Dette er valgfrie tillegg til bookingflyten.

Start med ett. Legg til et annet når du oppdager at det første ikke kan gjøre noe du trenger — hver tilkobling er uavhengig, og å legge til én påvirker aldri de andre.

<Aside type="tip" title="Vil du fortsatt ha alt?">
`https://api.wink.travel/mcp` og `https://integrations.wink.travel/mcp` er fortsatt tilgjengelige og serverer **alle** verktøy på sin vert. De er nyttige for å utforske hva som finnes, men vi anbefaler dem ikke for daglig arbeid: verktøyslisten er stor nok til å fortrenge oppgaven din og forringe agentens verktøyvalg. Foretrekk verktøysettene ovenfor.
</Aside>

## Hvordan autentisering fungerer

Wink MCP-servere bruker **OAuth2 Authorization Code + PKCE**-flyten og støtter **Dynamic Client Registration (RFC 7591)**. Slik går det når du kobler til for første gang:

1. AI-klienten din oppdager autorisasjonsserveren fra MCP-endepunktets `/.well-known/oauth-protected-resource` metadata.
2. Klienten registrerer seg selv via **Dynamic Client Registration** — ingen manuell applikasjonsoppsett kreves.
3. Klienten åpner en **nettleserfane** til `https://iam.wink.travel`. Du logger inn med Wink-kontoen din og godkjenner de forespurte tillatelsene på samtykkeskjermen.
4. Wink utsteder en **tilgangstoken** som er begrenset til kontoen din og knyttet til identiteten din.
5. AI-klienten legger token til hver MCP-forespørsel. Alle verktøyresultater er automatisk begrenset til din administrerende enhet.
6. Token utløper etter 3 timer. AI-klienten din oppdaterer stille i bakgrunnen uten å be om pålogging igjen.

Hver verktøysamtale kjøres **under din identitet** — de samme ACL-reglene som beskytter nettportalen gjelder for AI-agenten.

## Tillatelser

Når du godkjenner samtykkeskjermen vil du se en oversikt over hva agenten ber om. MCP
klienter bruker samme tillatelsesvokabular som resten av plattformen — se full
[omfangsreferanse på Autentiseringssiden](/no/developers/authentication#scopes).

To ting er spesifikke for MCP:

- **`mcp.read` `mcp.write` `mcp.remove`-omfang kreves i tillegg** for å åpne MCP-transporten. En klient med `mcp.*`-omfang får tilgang til alle Wink MCP-endepunkter, men hvert verktøy den kaller håndhever fortsatt seksjonsomfanget til endepunktet det omslutter (f.eks. `booking.read`).
- **AI-klienten ber kun om de omfangene den trenger.** Du kan nekte individuelle tillatelser på samtykkeskjermen — verktøy som krever et nektet omfang vil returnere en feil når de kalles.

**Verktøysett endrer ikke noe av dette.** Endepunktet du kobler til bestemmer hvilke verktøy som *listes*,
ikke hva de *har lov til å gjøre*. Å koble til `/mcp/payment` gir ingen finansielle tillatelser du
ikke allerede hadde, og å koble til `/mcp/reference` hindrer ikke et verktøy der i å håndheve
sitt eget omfang. Autorisasjon avgjøres per verktøysamtale, basert på token og kontoens fullmakter.

## Feilsøking

**Nettleserfane åpnes ikke**

AI-klienten din støtter kanskje ikke den interaktive PKCE-flyten ennå. Sjekk at du kjører en nyere versjon:
- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** oppdater via appens innebygde oppdaterer

**`401 Unauthorized` etter pålogging**

Den bufrede tokenen din kan være utdatert. Fjern og legg til serveren på nytt for å trigge ny pålogging:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

For Claude Desktop og ChatGPT, fjern serveroppføringen fra innstillinger, start appen på nytt og legg den til igjen.

**`403 Forbidden` ved kall til et spesifikt verktøy**

Verktøyet krever et omfang du ikke godkjente på samtykkeskjermen, eller en tillatelse kontoen din ikke har. Koble til serveren på nytt — samtykkeskjermen vises igjen og du kan godkjenne manglende tillatelse. Hvis det fortsatt feiler, trenger verktøyet en kontotillatelse du ikke har; å koble til et annet verktøysett hjelper ikke, fordi verktøysett ikke gir tillatelser.

**Verktøyet jeg trenger er ikke i listen**

Du er sannsynligvis koblet til et verktøysett som ikke dekker den jobben. Sjekk [endepunktkatalogen](#endpoint-directory) og legg til verktøysettet som gjør det — tilkoblinger er uavhengige, så å legge til ett endrer ingenting for de andre. Hvis du er usikker på hvilket som har det, koble til `https://api.wink.travel/mcp` midlertidig, finn verktøyet, og se deretter opp hvilket verktøysett som lister det.

**`404 Not Found` på et verktøysett-endepunkt**

Sjekk stien nøye — de nestede verktøysettene har to segmenter (`/mcp/extranet/rates`, ikke `/mcp/extranet-rates`), og de flate har ett (`/mcp/link-manager`). Merk at en *uautentisert* forespørsel til hvilken som helst sti under `/mcp` returnerer `401`, ikke `404`, så bare `401` forteller ikke om endepunktet finnes.

**Jeg koblet til `api.wink.travel/mcp/channel-manager` og fikk ingenting**

Det endepunktet finnes ikke. Kanalmanager-integrasjon serveres kun fra `https://integrations.wink.travel/mcp/channel-manager`. Hvis du også trenger å lese eller skrive en eiendoms egne priser manuelt, er det en separat jobb på et separat endepunkt — se `/mcp/extranet/rates`.

**Serveren vises, men verktøysamtaler returnerer "konto ikke funnet"**

Du er logget inn på en Wink-konto uten administrerende enhet. Gå til [Wink Portal](https://app.wink.travel) og sørg for at kontoen din er satt opp før du bruker MCP-serveren.

**Token utløper midt i økten**

Token er gyldige i 3 timer. Claude Code og Claude Desktop oppdaterer token stille uten å avbryte økten. Hvis du ser autentiseringsfeil etter lang inaktivitet, skriv en ny melding — klienten autentiserer på nytt automatisk.

**Codex CLI viser "MCP server unreachable"**

Sjekk at `~/.codex/config.json` er gyldig JSON (ingen avsluttende komma) og at `"type": "http"` er satt. Codex krever HTTP-transport for eksterne servere; stdio-transport er kun for lokale binærfiler.

**ChatGPT "Connectors"-meny mangler**

MCP-støtte krever ChatGPT desktop app versjon **1.2024.352** eller nyere og et aktivt Plus-, Pro-, Team- eller Enterprise-abonnement. Oppdater appen og sjekk planen din i Innstillinger → Konto.

**Cursor-server viser rød / "Failed to connect"**

Sjekk at `~/.cursor/mcp.json` er gyldig JSON og inneholder `"type": "http"`. Gå deretter til **Innstillinger → Cursor Settings → MCP** og klikk **Oppdater**. Hvis feilen vedvarer, start Cursor helt på nytt — konfigurasjonsendringer plukkes ikke alltid opp uten omstart.

**Windsurf MCP-servere vises ikke i innstillinger**

Windsurf krever full omstart (ikke bare vindusoppdatering) for å plukke opp endringer i `mcp_config.json`. Bruk **Fil → Avslutt** og start på nytt. Hvis serverne fortsatt ikke vises, bekreft at du har Windsurf **1.4+** via **Hjelp → Om Windsurf**.

**Cline "Add Server"-alternativet er ikke synlig**

MCP-serverbehandleren krever Cline **2.0** eller nyere. Åpne VS Code Extensions-panelet, finn Cline og klikk **Oppdater** hvis en oppdatering er tilgjengelig. Etter oppdatering, last inn VS Code på nytt (`Ctrl+Shift+P` → "Developer: Reload Window").
