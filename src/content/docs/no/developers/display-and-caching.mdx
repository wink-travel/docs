Demand Partner Agreement tillater ikke pris-sammenligning med Wink-tilbud "annet enn som uttrykkelig tillatt" (klausul 11.3). Denne siden forklarer hvordan Wink gir denne tillatelsen for søkevisning, og reglene visningen din må følge når du har den.

## Hva søkevisning betyr

**Søkevisning** er å vise hoteller fra Partner API som svar på et brukersøk, sammen med andre hotelltilbud, inkludert ubetalte alternativer fra andre kilder, med en klikk-ut som åpner det valgte hotellets Wink Booking Engine under din affiliate-konto.

Det dekker kun søk, innhold og klikk-ut. Opprettelse, endring eller kansellering av bestillinger gjennom Partner API krever Winks separate skriftlige godkjenning.

## Regler for hver visning

- **Live priser.** Priser og tilgjengelighet må gjenspeile live data på visningstidspunktet (klausul 8.2).
- **Uendret pris.** Vis hver pris nøyaktig slik Partner API returnerer den, uten påslag, tillegg eller endringer. Hotellet setter og kontrollerer sin pris.
- **Nøyaktig presentasjon.** Vis priser, inkluderinger og avbestillingsregler nøyaktig og uten å endre betydningen (klausul 6.1).
- **Presenter aldri Wink som selger.** Produktet ditt skal være visuelt og strukturelt adskilt fra Wink, aldri presentere seg som Wink, og aldri presentere Wink som et eget nettbasert reisebyrå eller som selger (klausul 7.4). Kontrakten for oppholdet er mellom reisende og hotellet.
- **Åpenhet.** Oppgi ditt kommersielle forhold til Wink der loven krever det (klausul 6.2).
- **Ingen videre bruk.** Ikke viderelisensier, overfør eller del Wink-tilbudsdata eller innhold med andre (klausul 11.3).

## Midlertidig visning

Wink setter ingen tidsbegrensning på hvor lenge du kan holde et søkeresultat, fordi ingen vet når en pris vil endre seg: et hotell kan endre den om fem sekunder eller om ett år. Det som betyr noe er at pris og tilgjengelighet du viser stemmer med live data på visningstidspunktet (klausul 8.2). Hent på nytt fra Partner API når reiseruten endres, og før du viser et resultat du ikke kan være sikker på fortsatt er aktuelt.

Visning som følger disse reglene er ikke en "statisk kopi av innhold" under klausul 7.5, og heller ikke caching av utdaterte priser under klausul 8.2.

## Caching av eiendomsinnhold

Eiendomsinnhold (navn, beskrivelser, bilder, fasiliteter og regler) har ingen tidsbegrensning for caching. Bruk hver eiendoms `lastUpdate` fra Partner API som cache-nøkkel, og oppdater eiendomsinnholdet når det endres.

## Identifikatorer du kan beholde

Du kan beholde disse, og kun disse:

- Wink eiendoms-ID og eiendommens `urlName`,
- bookingreferansenummer for bestillinger tilskrevet deg,
- dine egne attribusjons-, klient- og konfigurasjons-IDer, med tilhørende klikk- og bestillingsdatoer.

Bruk dem kun for å unngå duplikater av hotellister på tvers av kilder, og for attribusjon, rapportering og provisjonsavstemming. Ikke behold priser, tilgjengelighet eller eiendomsinnhold utover reglene ovenfor, og ikke bruk noen data fra Wink, inkludert disse identifikatorene, til å trene, finjustere eller evaluere en modell, eller til å bygge eller forbedre en tilbudsdatabase (klausulene 7.5 og 10.6).

## Hvordan be om tillatelse

Søkevisning krever Winks uttrykkelige skriftlige tillatelse, gitt som et sidebrev til din Demand Partner Agreement. Den trer i kraft når både brevet og avtalen er akseptert, og Wink kan trekke den tilbake med varsel eller umiddelbart hvis reglene ovenfor brytes.

For å be om tillatelse, send e-post til [legal@wink.travel](mailto:legal@wink.travel) med:

- produktnavnet ditt,
- URL-en hvis det er live,
- hvordan du planlegger å bruke Wink-tilbudet: hva du vil vise, hvor og sammen med hva.

Vi tar det derfra.
