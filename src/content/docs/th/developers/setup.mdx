บทความนี้แสดงวิธีการตั้งค่าอย่างรวดเร็วในฐานะนักพัฒนาและเริ่มทดสอบ API ของเราใน Wink

:::note
การทดสอบควรทำใน [สภาพแวดล้อม staging](/th/getting-started/environments) เสมอ ที่นั่นจะมีข้อมูลน้อยกว่าแต่คุณสามารถทดสอบได้อย่างเต็มที่โดยไม่ส่งผลกระทบต่อสภาพแวดล้อม production

เมื่อคุณพร้อมแล้ว ให้ย้ายไปยัง production ด้วยตัวเอง: สร้างแอปพลิเคชันใน production (ข้อมูลรับรองจะไม่ถูกโอนระหว่างสภาพแวดล้อม) และลบ `staging-` ออกจาก URL เช่น `https://staging-api.wink.travel` จะกลายเป็น `https://api.wink.travel` ไม่มีขั้นตอนการอนุมัติสำหรับนักพัฒนา มีเพียง [channel managers](/th/guides/integrators/add-your-channel-manager/#certification) และ [travel agents](/th/portal/travel-agent/what-is-agent/) เท่านั้นที่ได้รับการรับรองก่อนเข้าสู่ production

การสร้างบัญชีใน staging หรือ production ต้องยอมรับข้อกำหนดและเงื่อนไขของ Wink และข้อกำหนดการชำระเงิน และการยอมรับนั้นถือเป็นข้อผูกพัน
:::

ทำตามขั้นตอนเหล่านี้:

<Steps>
1. [ลงทะเบียน](/th/getting-started/sign-up) บัญชีผู้ใช้ของคุณบน Wink
2. [สร้างบัญชีพันธมิตร](/th/portal/create-account) คุณจะต้องใช้บัญชีนี้เพื่อผูกกับแอปพลิเคชันของคุณ ดู [Studio คืออะไร](/th/portal/studio/what-is-studio) เพื่อบริบทเพิ่มเติม
3. [สร้างแอปพลิเคชัน](/th/account/applications) และเชื่อมโยงกับบัญชีพันธมิตรที่คุณสร้างในขั้นตอนที่ 2 สำหรับการรวม API แบบเซิร์ฟเวอร์ต่อเซิร์ฟเวอร์ ให้เลือก **MACHINE_2_MACHINE** เป็นประเภทไคลเอนต์
4. เมื่อคุณสร้าง `Application` แล้ว ให้คัดลอกและบันทึก client-id และ secret key ทันที — secret key จะแสดงเพียงครั้งเดียวและไม่สามารถดึงคืนได้อีก
</Steps>

## CDN

ที่ Wink เราใช้ Cloudinary สำหรับสินทรัพย์ภาพและวิดีโอทั้งหมดของเรา เมื่อคุณเข้าถึงสินค้าคงคลังการเดินทางของเรา คุณจะสามารถใช้ฟีเจอร์ขั้นสูงทั้งหมดของ Cloudinary ได้อย่างเต็มที่

`cloud_name` ของเราคือ `traveliko`

### ตัวอย่าง

สำหรับทุกประเภทสินค้าคงคลังการเดินทางที่เรารองรับ จะมีอาร์เรย์ JSON ซ้อนชื่อ `multimedias` JSON สำหรับรายการมัลติมีเดียมีลักษณะดังนี้:

```json {3}
{
  "multimediaIdentifier": "multimedia-1",
  "identifier": "partners/radisson_blu_logo",
  "type": "IMAGE",
  "width": "1024",
  "height": "768",
  "category": "1",
  "descriptions": [
    {
      "name": "Lobby",
      "description": "Picture of the lobby",
      "language": "en"
    }
  ],
  "lifestyleType": "LIFESTYLE_BUSINESS",
  "attribution": [
    {
      "url": "https://www.hilton.com",
      "name": "Hilton"
    }
  ]
}
```

บรรทัดที่เน้นด้านบนแสดง ID เฉพาะของ Cloudinary คือ `partners/radisson_blu_logo` นั่นคือทั้งหมดที่คุณต้องใช้เพื่อดึงภาพในรูปแบบ คุณภาพ และขนาดที่คุณต้องการ

## การทดสอบ

ไปที่ส่วน [APIs](/th/api/overview/) ของเราและเลือก API ที่คุณต้องการใช้งาน

### เอกสาร API

เว็บไซต์เอกสารของเราถูกตั้งค่าให้คุณสามารถรันคำสั่ง API ได้จากภายในเว็บไซต์

ในตัวอย่างนี้ คุณต้องการใช้การเรียก API `Search Lookups (OAuth2)`

:::tip[เคล็ดลับมือโปร]
เพื่อความสะดวก เราแนะนำให้นักรวมระบบใช้ endpoints ที่เรากำหนดเป็น `OAuth2` endpoints เหล่านั้นจะรู้ว่าคำเรียก API มาจากใครและรู้ว่าคุณอยู่ในบัญชีใด ดังนั้นคุณไม่ต้องระบุ `companyIdentifier` ใน URL ของคุณ
:::

<Steps>
1. ใช้ [Lookup API](https://developer.wink.travel/lookup) เพื่อดึงข้อมูลปลายทางหรือโรงแรม
2. ในแถบนำทางด้านซ้าย คลิกที่ `Authentication`
3. กรอก client-id และ client secret ของคุณแล้วคลิกปุ่ม `Get TOKEN`
4. หากข้อมูลรับรองของคุณถูกต้อง คุณจะเห็นว่า API key ของคุณถูกนำไปใช้แล้ว
5. ตอนนี้คุณสามารถทดสอบ endpoint lookup ได้
</Steps>

### Postman
คุณสามารถทำสิ่งเดียวกันนี้ด้วย Postman

<Steps>
1. ดาวน์โหลด [Postman](https://www.postman.com/downloads)
2. คลิกที่ `Download OpenAPI spec` จากด้านบนของหน้า [Lookup API](https://developer.wink.travel/lookup)
3. นำเข้าไฟล์นั้นเข้าสู่ Postman
4. หากคุณนำเข้าเป็นคอลเลกชันใหม่ชื่อ `Wink API` ให้คลิกที่จุดสามจุดแนวนอนถัดจากชื่อคอลเลกชันแล้วคลิก `Edit`
5. ในแท็บ `Authorization` ตั้งค่า `Auth type` เป็น OAuth2
6. ตั้งค่า `Add auth data to` เป็น `Request headers`
7. ตั้งค่า `Header prefix` เป็น `Bearer`
8. ตั้งค่า `Token Name` เป็นชื่อที่คุณต้องการตั้งให้กับโทเค็นที่บันทึกใน Postman เช่น Wink Staging
9. ตั้งค่า `Grant type` เป็น `Client Credentials`
10. ตั้งค่า `Access token URL` เป็น https://staging-iam.wink.travel/oauth2/token
11. ตั้งค่า `Client ID` เป็น Client ID ที่แอปของคุณช่วยสร้าง
12. ตั้งค่า `Client Secret` เป็น Client Secret ที่แอปของคุณช่วยสร้าง
13. ตั้งค่า `Scope` เป็นสโคปที่การรวมระบบของคุณต้องการโดยเว้นวรรค เช่น `inventory.read inventory.write inventory.remove` ดู [รายการสโคป](/th/developers/authentication#scopes) สำหรับรายการเต็ม
14. ตั้งค่า `Client Authentication` เป็น `Send as Basic Auth header`
15. คลิกปุ่ม `Get New Access Token` เพื่อดึงโทเค็นและบันทึกมัน
16. สำหรับการเรียก API ทั้งหมดภายใต้คอลเลกชัน Wink API ให้แน่ใจว่าแท็บการรับรองความถูกต้องระบุว่า `Inherit auth from parent` เพื่อให้รวมโทเค็นของคุณในทุกคำเรียก
</Steps>

:::tip[เคล็ดลับมือโปร]
แนะนำให้ตั้งค่าชื่อโดเมนเซิร์ฟเวอร์, Client ID และ Client Secret เป็นตัวแปรสภาพแวดล้อม เพื่อให้คุณสามารถสลับระหว่างสภาพแวดล้อม staging และ production ได้ง่ายและใช้ซ้ำทุกการดำเนินการที่คุณสร้างไว้
:::
