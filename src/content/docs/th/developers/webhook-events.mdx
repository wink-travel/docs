หน้านี้แสดงรายการเหตุการณ์ webhook ทุกประเภทที่คุณสามารถสมัครรับบน Wink สำหรับคำแนะนำการตั้งค่า ดูที่ [คู่มือการรวม Webhook](/th/developers/webhook-integration) หรือ [หน้าการจัดการ Webhooks](/th/portal/settings/webhooks)

## วิธีการสมัครรับ

1. ไปที่ **Applications > Webhooks** ในพอร์ทัลของคุณ
2. สร้าง webhook และเลือกเหตุการณ์ที่คุณต้องการรับ — หรือปล่อยให้รายการว่างเพื่อรับทุกเหตุการณ์
3. Wink จะส่ง HTTP POST ที่ลงลายมือชื่อไปยัง endpoint ของคุณทุกครั้งที่เกิดเหตุการณ์ ดูที่ [Webhook Integration](/th/developers/webhook-integration) สำหรับข้อมูลเกี่ยวกับซองจดหมาย, headers, การตรวจสอบลายเซ็น และการลองใหม่

## ทุกประเภทเหตุการณ์

ตารางนี้ถูกสร้างจากแคตตาล็อกเหตุการณ์ของแพลตฟอร์มในเวลาสร้าง จึงตรงกับ API เสมอ
ประเภทเหตุการณ์ที่ระบุว่าได้ส่งจะลิงก์ไปยังหน้าข้อมูลอ้างอิงใน [Webhooks API](/th/api/webhooks/) ซึ่ง
บันทึกข้อมูล JSON body ที่แน่นอน (`WebhookEnvelope` พร้อม `object` เฉพาะเหตุการณ์), headers `Wink-*` และ
นโยบายการลองใหม่ ประเภทเหตุการณ์ที่ไม่ได้ส่งมีอยู่ภายใน (การชำระเงิน, ledger, การซิงค์ channel-manager, …) แต่ไม่ได้ส่งไปยังผู้สมัครรับ webhook ในปัจจุบัน

**ผู้รับ** หมายถึงผู้ที่ได้รับเหตุการณ์: `SUPPLIER` (โรงแรม), `AFFILIATE` (ผู้ขายต่อที่มีช่องทางขายที่ใช้งานกับโรงแรม), `AGENT` (ตัวแทนท่องเที่ยวที่ทำการจอง) หรือ `SELF` (หน่วยงานที่จัดการซึ่งเหตุการณ์เกี่ยวข้อง) ผู้รับแต่ละรายจะได้รับ payload รูปแบบเดียวกัน; รายละเอียดเฉพาะบทบาทจะอยู่เบื้องหลัง URL `links.self` ของ payload

เริ่มต้นด้วยการสมัครรับทุกเหตุการณ์ในช่วงพัฒนา เมื่อคุณเข้าใจว่า payload ใดที่ระบบของคุณต้องการ ให้จำกัดการสมัครรับเพื่อลดเสียงรบกวน ส่งเหตุการณ์ทดสอบให้ตัวเองจาก **Applications > Webhooks** (หรือ `POST …/webhook/{id}/test`) เพื่อยืนยัน endpoint และการตรวจสอบลายเซ็นก่อนใช้งานจริง
:::
