เครื่องมือ MCP ของ Wink ถูกเผยแพร่เป็น **ชุดเครื่องมือ** — จุดเชื่อมต่อที่เน้นงานเฉพาะแต่ละงาน คุณเชื่อมต่อไคลเอนต์ AI ของคุณกับหนึ่งหรือสองชุดที่ตรงกับงานของคุณ ไม่ใช่ทั้งหมด

ทุกจุดเชื่อมต่อใช้ **การเข้าสู่ระบบ OAuth2 แบบโต้ตอบ** (PKCE authorization code flow): เอเจนต์ AI ของคุณจะเปิดแท็บเบราว์เซอร์ คุณลงชื่อเข้าใช้ด้วยบัญชี Wink ของคุณ และเท่านี้ก็เสร็จ ไม่มีความลับของไคลเอนต์ให้จัดการ

```bash title="ผู้รวมระบบจัดการช่องทางเชื่อมต่อกับจุดเชื่อมต่อหนึ่งจุด"
claude mcp add wink-channel-manager https://integrations.wink.travel/mcp/channel-manager --transport http
```

```bash title="ผู้จัดการโรงแรมที่จัดการอัตราของตนเองเชื่อมต่อกับอีกจุดเชื่อมต่อหนึ่ง"
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

## ทำไมเครื่องมือจึงแยกเป็นหลายจุดเชื่อมต่อ

Wink มีเครื่องมือประมาณ 500 รายการ การส่งมอบทั้งหมดให้เอเจนต์ในครั้งเดียวเป็นไปได้ทางเทคนิค — แต่เป็นความคิดที่ไม่ดี

**คำจำกัดความของเครื่องมือใช้บริบท** เครื่องมือแต่ละตัวที่เซิร์ฟเวอร์ MCP โฆษณาจะถูกโหลดเข้าไปในหน้าต่างบริบทของโมเดลก่อนทำงาน พร้อมคำอธิบายและสคีมาพารามิเตอร์เต็มรูปแบบ เครื่องมือห้าร้อยตัวนั้นใช้ส่วนแบ่งงบประมาณบริบทที่งานจริงของคุณต้องการในทุกคำขอ

**คุณภาพการเลือกลดลงเมื่อรายการยาวขึ้น** เอเจนต์ที่เลือกจากเครื่องมือ 500 ตัวที่มีชื่อคล้ายกันจะเลือกได้แย่กว่าเอเจนต์ที่เลือกจาก 40 ตัว หากคุณรวมระบบจัดการช่องทาง ประมาณยี่สิบเครื่องมือเกี่ยวข้องกับคุณ ส่วนที่เหลือ 480 เป็นเสียงรบกวนที่ทำให้เครื่องมือที่ถูกต้องหายากขึ้น

**งานแยกจากกันได้จริง** คนที่ซิงค์ความพร้อมใช้งานจาก PMS กับคนที่ดูแลหน้าแอฟฟิลิเอตแทบไม่มีเครื่องมือร่วมกัน การแยกตามงานหมายความว่าการเชื่อมต่อแต่ละอันมีคำศัพท์ของงานนั้น

<Aside type="caution" title="ชุดเครื่องมือไม่ใช่สิทธิ์">
การเลือกชุดเครื่องมือแคบ **ไม่** จำกัดสิ่งที่บัญชีของคุณทำได้ และการเลือกชุดกว้างไม่ได้ให้สิทธิ์เพิ่ม เครื่องมือทุกตัวบังคับใช้สิทธิ์บัญชีเดียวกับพอร์ทัลเว็บ ภายใต้ตัวตนที่คุณลงชื่อเข้าใช้ หากบัญชีของคุณไม่สามารถยกเลิกการจองใน Wink Portal เอเจนต์ก็ไม่สามารถทำได้ — ไม่ว่าจุดเชื่อมต่อจะเชื่อมต่อกับอันไหนก็ตาม

เลือกชุดเครื่องมือเพื่อ **ความเน้น** ไม่ใช่เพื่อความปลอดภัย
</Aside>

| `/mcp/link-manager` | ~28 | คอลเลกชันลิงก์ที่เผยแพร่, การออกแบบ, หมวดหมู่และแท็ก, รวมถึง URL ย่อ |

### `https://integrations.wink.travel` — การรวมระบบจัดการช่องทาง

มีจุดเชื่อมต่อเดียว เพราะโฮสต์นี้มีไว้สำหรับงานเดียว

| จุดเชื่อมต่อ | จำนวนเครื่องมือ | ครอบคลุมอะไร |
|---|---:|---|
| `/mcp/channel-manager` | ~9 | การเชื่อมต่อและยืนยันระบบจัดการช่องทาง, PMS หรือการรวม CRS |

<Aside type="note" title="การรวมระบบจัดการช่องทาง vs. การจัดการอัตราของตนเอง">
นี่คืองานที่แตกต่างกันสำหรับคนที่แตกต่างกัน และไม่มีการแชร์จุดเชื่อมต่อเดียวกัน

**ผู้ขายระบบจัดการช่องทาง, PMS หรือ CRS** รวมระบบครั้งเดียวผ่าน `integrations.wink.travel/mcp/channel-manager` และจากนั้นแลกเปลี่ยนข้อมูลทรัพย์สิน, อัตรา, ความพร้อมใช้งาน และการจองผ่านการรวมระบบนั้น จุดเชื่อมต่อเดียวนี้คือพื้นผิวทั้งหมด

**ผู้จัดการโรงแรมที่เปลี่ยนอัตราของตนเองด้วยมือ** ใช้ชุดเครื่องมือ extranet บน `api.wink.travel` — `/mcp/extranet/rates` และชุดที่เกี่ยวข้อง ชุดเหล่านี้ไม่ใช่ส่วนหนึ่งของการรวมระบบจัดการช่องทาง และผู้รวมระบบไม่มีเหตุผลที่จะเชื่อมต่อกับชุดเหล่านี้

การบริหารบัญชียังอยู่บน `api.wink.travel` ที่ `/mcp/settings` ไม่มี `/mcp/settings` บนโฮสต์ integrations
</Aside>

ทุกจุดเชื่อมต่อยังมีเครื่องมือ `ping` เพื่อให้คุณยืนยันว่าการเชื่อมต่อยังใช้งานได้ก่อนขอให้ทำงานจริง

### การชำระเงินแบบ Agentic

สำหรับกระบวนการจองนักเดินทางครบถ้วน ให้เชื่อมต่อ **Wink Booking Engine** ที่ `https://api.wink.travel/mcp/booking-engine` และ **กระเป๋าเงินที่รองรับ** การเพิ่ม MCP ของ Wink จะเปิดการเข้าสู่ระบบผ่านเบราว์เซอร์และการเลือกสิทธิ์ จากนั้นไคลเอนต์ของคุณจะจัดการการตรวจสอบสิทธิ์

Booking Engine รวมการค้นหาปลายทาง, การค้นหาโรงแรมและห้องพัก, `agentic_booking_quote`, `agentic_booking_pay`, `agentic_booking_book`, การดึงข้อมูลการจองและใบเสร็จ เมื่อเปิดใช้งานการจองและชำระเงินแบบ agentic สำหรับสภาพแวดล้อมนั้น ดู [Agentic Payments](/th/developers/agentic-payments/) สำหรับการตั้งค่าการเชื่อมต่อ สิทธิ์ที่ต้องเลือก และขั้นตอนตั้งแต่การค้นหาจนถึงการยืนยัน

## ฉันต้องใช้ชุดเครื่องมือใด?

| หากคุณเป็น… | เชื่อมต่อกับ |
|---|---|
| **รวมระบบจัดการช่องทาง, PMS หรือ CRS** | `integrations.wink.travel/mcp/channel-manager` — แค่ชุดนี้ชุดเดียว |
| **จัดการเนื้อหาทรัพย์สิน** | `/mcp/extranet/property` + `/mcp/extranet/facilities` |
| **จัดการห้องพักและประเภทห้อง** | `/mcp/extranet/facilities` |
| **จัดการราคาและความพร้อมใช้งาน** | `/mcp/extranet/rates` |
| **ดำเนินการจองประจำวัน** | `/mcp/extranet/operations` |
| **ขยายช่องทางการขาย** | `/mcp/extranet/distribution` + `/mcp/analytics` |
| **สร้างหน้าแอฟฟิลิเอต** | `/mcp/studio/curation` + `/mcp/studio/embeds` |
| **จัดการหน้า link-in-bio** | `/mcp/link-manager` + `/mcp/social` |
| **จองแทนนักเดินทาง** | `/mcp/travel-agent` |
| **กระทบยอดเงิน** | `/mcp/payment` |
| **จองห้องพักด้วยเอเจนต์ AI** | `/mcp/booking-engine` + กระเป๋าเงินที่รองรับ — ดู [Agentic Payments](/th/developers/agentic-payments/) |
| **สร้างประสบการณ์การจอง** | `/mcp/booking-engine`; เพิ่มเติม `/mcp/reference` สำหรับการค้นหาเสริม |

**Booking Engine รวมเวิร์กโฟลว์การจองหลัก** มันให้การค้นหาบัญชีและการปรับแต่ง, การค้นหาปลายทาง, ความพร้อมใช้งานโรงแรมและรายละเอียดอัตราห้อง, รถเข็น, เช็คเอาต์ และการจัดการการจองของนักเดินทาง เครื่องมือการจองและชำระเงินแบบ agentic ก็รวมอยู่ด้วยเมื่อเปิดใช้งานสำหรับสภาพแวดล้อมนั้น

สำหรับการค้นหาโรงแรมในเมือง ให้ใช้ `destination_lookup_search_suggestions` เพื่อแก้ไขปลายทาง จากนั้นใช้ `inventory_search_city` เพื่อค้นหาโรงแรมและอัตราที่มี ทั้งสองเครื่องมือนี้อยู่ใน `/mcp/booking-engine` ดังนั้นกระบวนการนี้ไม่ต้องการการเชื่อมต่อ Reference

เพิ่ม `/mcp/reference` เมื่อคุณต้องการการค้นหาสนับสนุน เช่น ประเทศ, สกุลเงินและอัตราแลกเปลี่ยน, ภาษา, โซนเวลา, การค้นหาทางภูมิศาสตร์ที่กว้างขึ้น, การจัดประเภท OTA หรือความรู้สาธารณะเกี่ยวกับทรัพย์สิน เหล่านี้เป็นส่วนเสริมที่ไม่บังคับสำหรับกระบวนการจอง

เริ่มต้นด้วยชุดเดียว เพิ่มอีกชุดเมื่อคุณพบว่าต้องการสิ่งที่ชุดนั้นทำไม่ได้ — การเชื่อมต่อแต่ละชุดเป็นอิสระ และการเพิ่มชุดหนึ่งไม่ส่งผลต่อชุดอื่น

<Aside type="tip" title="ยังอยากได้ทุกอย่างอยู่ไหม?">
`https://api.wink.travel/mcp` และ `https://integrations.wink.travel/mcp` ยังคงใช้งานได้และให้บริการ **ทุก** เครื่องมือบนโฮสต์ของพวกเขา เหมาะสำหรับการสำรวจสิ่งที่มีอยู่ แต่เราไม่แนะนำให้ใช้สำหรับงานประจำวัน: รายการเครื่องมือมีขนาดใหญ่พอที่จะบดบังงานของคุณและลดคุณภาพการเลือกเครื่องมือของเอเจนต์ โปรดใช้ชุดเครื่องมือข้างต้นแทน
</Aside>

## วิธีการทำงานของการตรวจสอบสิทธิ์

เซิร์ฟเวอร์ MCP ของ Wink ใช้ **OAuth2 Authorization Code + PKCE** flow และรองรับ **Dynamic Client Registration (RFC 7591)** นี่คือสิ่งที่จะเกิดขึ้นเมื่อคุณเชื่อมต่อครั้งแรก:

1. ไคลเอนต์ AI ของคุณค้นหาเซิร์ฟเวอร์อนุญาตจากเมตาดาต้า `/.well-known/oauth-protected-resource` ของจุดเชื่อมต่อ MCP
2. ไคลเอนต์ลงทะเบียนตัวเองผ่าน **Dynamic Client Registration** — ไม่ต้องตั้งค่าแอปพลิเคชันด้วยตนเอง
3. ไคลเอนต์เปิด **แท็บเบราว์เซอร์** ไปที่ `https://iam.wink.travel` คุณลงชื่อเข้าใช้ด้วยบัญชี Wink และอนุมัติสิทธิ์ที่ร้องขอบนหน้าจอการยินยอม
4. Wink ออก **โทเค็นเข้าถึง** ที่มีขอบเขตสำหรับบัญชีของคุณและเชื่อมโยงกับตัวตนของคุณ
5. ไคลเอนต์ AI แนบโทเค็นกับคำขอ MCP ทุกคำขอ ผลลัพธ์เครื่องมือทั้งหมดจะถูกจำกัดขอบเขตตามหน่วยงานจัดการของคุณ
6. โทเค็นหมดอายุหลัง 3 ชั่วโมง ไคลเอนต์ AI ของคุณจะรีเฟรชโทเค็นเงียบ ๆ ในเบื้องหลังโดยไม่ต้องแจ้งเตือนอีกครั้ง

การเรียกใช้เครื่องมือทุกครั้งจะทำงาน **ภายใต้ตัวตนของคุณ** — กฎ ACL เดียวกับที่ปกป้องพอร์ทัลเว็บจะใช้กับเอเจนต์ AI

## ขอบเขตสิทธิ์

เมื่อคุณอนุมัติหน้าจอการยินยอม คุณจะเห็นรายละเอียดสิ่งที่เอเจนต์ร้องขอ MCP
ไคลเอนต์ใช้คำศัพท์สิทธิ์เดียวกับแพลตฟอร์ม — ดูรายการ
[ขอบเขตสิทธิ์เต็มที่หน้า Authentication](/th/developers/authentication#scopes)

สองอย่างที่เฉพาะเจาะจงสำหรับ MCP:

- **ขอบเขต `mcp.read` `mcp.write` `mcp.remove` จำเป็นเพิ่มเติม** เพื่อเปิดการขนส่ง MCP ไคลเอนต์ที่มีขอบเขต `mcp.*` จะได้รับอนุญาตให้เข้าถึงจุดเชื่อมต่อ MCP ใดก็ได้ของ Wink แต่เครื่องมือที่เรียกใช้จะยังบังคับใช้ขอบเขตส่วนของจุดเชื่อมต่อที่ห่อหุ้ม (เช่น `booking.read`)
- **ไคลเอนต์ AI ขอเฉพาะขอบเขตที่ต้องการ** คุณสามารถปฏิเสธสิทธิ์แต่ละรายการบนหน้าจอการยินยอม — เครื่องมือที่ต้องการขอบเขตที่ถูกปฏิเสธจะส่งคืนข้อผิดพลาดเมื่อเรียกใช้

**ชุดเครื่องมือไม่เปลี่ยนแปลงสิ่งนี้** จุดเชื่อมต่อที่คุณเชื่อมต่อกำหนดว่าเครื่องมือใด *แสดง* ไม่ใช่ว่าเครื่องมือใด *ได้รับอนุญาต* การเชื่อมต่อกับ `/mcp/payment` ไม่ได้ให้สิทธิ์ทางการเงินที่คุณไม่มี และการเชื่อมต่อกับ `/mcp/reference` ไม่ได้หยุดเครื่องมือที่นั่นจากการบังคับใช้ขอบเขตของตัวเอง การอนุญาตตัดสินใจตามการเรียกใช้เครื่องมือแต่ละครั้ง จากโทเค็นของคุณและสิทธิ์บัญชีของคุณ

- **Claude Code:** `npm install -g @anthropic-ai/claude-code`
- **Codex CLI:** `npm install -g @openai/codex`
- **Claude Desktop / ChatGPT desktop:** อัปเดตจากตัวอัปเดตในแอป

**`401 Unauthorized` หลังจากลงชื่อเข้าใช้**

โทเค็นที่แคชอาจหมดอายุ ลบและเพิ่มเซิร์ฟเวอร์ใหม่เพื่อเริ่มการลงชื่อเข้าใช้ใหม่:

```bash
# Claude Code
claude mcp remove wink-rates
claude mcp add wink-rates https://api.wink.travel/mcp/extranet/rates --transport http
```

สำหรับ Claude Desktop และ ChatGPT ให้ลบรายการเซิร์ฟเวอร์จากการตั้งค่า รีสตาร์ทแอป แล้วเพิ่มใหม่

**`403 Forbidden` เมื่อเรียกใช้เครื่องมือเฉพาะ**

เครื่องมือต้องการขอบเขตที่คุณไม่อนุมัติบนหน้าจอการยินยอม หรือสิทธิ์ที่บัญชีของคุณไม่มี เชื่อมต่อเซิร์ฟเวอร์ใหม่ — หน้าจอการยินยอมจะปรากฏอีกครั้งและคุณสามารถอนุมัติสิทธิ์ที่ขาดได้ หากยังล้มเหลว เครื่องมือต้องการสิทธิ์บัญชีที่คุณไม่มี การเชื่อมต่อชุดเครื่องมืออื่นจะไม่ช่วย เพราะชุดเครื่องมือไม่ให้สิทธิ์

**เครื่องมือที่ต้องการไม่อยู่ในรายการ**

คุณอาจเชื่อมต่อกับชุดเครื่องมือที่ไม่ครอบคลุมงานนั้น ตรวจสอบ [ไดเรกทอรีจุดเชื่อมต่อ](#endpoint-directory) และเพิ่มชุดเครื่องมือที่ครอบคลุม — การเชื่อมต่อแต่ละชุดเป็นอิสระ การเพิ่มชุดหนึ่งไม่เปลี่ยนแปลงชุดอื่น หากไม่แน่ใจว่าเครื่องมืออยู่ในชุดใด ให้เชื่อมต่อกับ `https://api.wink.travel/mcp` ชั่วคราว หาเครื่องมือ แล้วดูว่าชุดเครื่องมือใดมีเครื่องมือนั้น

**`404 Not Found` บนจุดเชื่อมต่อชุดเครื่องมือ**

ตรวจสอบเส้นทางอย่างละเอียด — ชุดเครื่องมือที่ซ้อนกันมีสองส่วน (`/mcp/extranet/rates` ไม่ใช่ `/mcp/extranet-rates`) และชุดเครื่องมือแบบแบนมีส่วนเดียว (`/mcp/link-manager`) โปรดทราบว่าคำขอที่ *ไม่ได้รับการตรวจสอบสิทธิ์* ไปยังเส้นทางใด ๆ ภายใต้ `/mcp` จะส่งคืน `401` ไม่ใช่ `404` ดังนั้น `401` เพียงอย่างเดียวไม่บอกว่าจุดเชื่อมต่อมีอยู่หรือไม่

**ฉันเชื่อมต่อกับ `api.wink.travel/mcp/channel-manager` แล้วไม่ได้อะไร**

จุดเชื่อมต่อนั้นไม่มีอยู่จริง การรวมระบบจัดการช่องทางให้บริการจาก `https://integrations.wink.travel/mcp/channel-manager` เท่านั้น หากคุณต้องการอ่านหรือเขียนอัตราของทรัพย์สินด้วยตนเอง นั่นเป็นงานแยกบนจุดเชื่อมต่อแยกต่างหาก — ดู `/mcp/extranet/rates`

**เซิร์ฟเวอร์ปรากฏแต่การเรียกเครื่องมือส่งคืน "account not found"**

คุณลงชื่อเข้าใช้บัญชี Wink ที่ไม่มีหน่วยงานจัดการ ไปที่ [Wink Portal](https://app.wink.travel) และตรวจสอบให้แน่ใจว่าบัญชีของคุณตั้งค่าเรียบร้อยก่อนใช้เซิร์ฟเวอร์ MCP

**โทเค็นหมดอายุระหว่างเซสชัน**

โทเค็นมีอายุ 3 ชั่วโมง Claude Code และ Claude Desktop จะรีเฟรชโทเค็นเงียบ ๆ โดยไม่ขัดจังหวะเซสชัน หากคุณเห็นข้อผิดพลาดการตรวจสอบสิทธิ์หลังจากไม่ได้ใช้งานนาน ให้พิมพ์ข้อความใหม่ — ไคลเอนต์จะตรวจสอบสิทธิ์ใหม่โดยอัตโนมัติ

**Codex CLI แสดง "MCP server unreachable"**

ตรวจสอบว่าไฟล์ `~/.codex/config.json` เป็น JSON ที่ถูกต้อง (ไม่มีลูกน้ำท้าย) และ `"type": "http"` ถูกตั้งค่า Codex ต้องการการขนส่ง HTTP สำหรับเซิร์ฟเวอร์ระยะไกล; การขนส่ง stdio สำหรับไบนารีในเครื่องเท่านั้น

**เมนู "Connectors" ของ ChatGPT หายไป**

การสนับสนุน MCP ต้องใช้แอป ChatGPT บนเดสก์ท็อปเวอร์ชัน **1.2024.352** ขึ้นไป และสมัครสมาชิก Plus, Pro, Team หรือ Enterprise อัปเดตแอปและตรวจสอบแผนใน Settings → Account

**เซิร์ฟเวอร์ Cursor แสดงสีแดง / "Failed to connect"**

ตรวจสอบว่าไฟล์ `~/.cursor/mcp.json` เป็น JSON ที่ถูกต้องและมี `"type": "http"` จากนั้นไปที่ **Settings → Cursor Settings → MCP** และคลิก **Refresh** หากยังมีข้อผิดพลาด รีสตาร์ท Cursor อย่างสมบูรณ์ — การเปลี่ยนแปลงคอนฟิกบางครั้งไม่ถูกโหลดโดยไม่รีสตาร์ท

**เซิร์ฟเวอร์ Windsurf MCP ไม่แสดงในการตั้งค่า**

Windsurf ต้องรีสตาร์ทเต็มรูปแบบ (ไม่ใช่แค่โหลดหน้าต่างใหม่) เพื่อโหลดการเปลี่ยนแปลงใน `mcp_config.json` ใช้ **File → Quit** แล้วเปิดใหม่ หากเซิร์ฟเวอร์ยังไม่แสดง ให้ตรวจสอบว่าใช้ Windsurf **1.4+** ผ่าน **Help → About Windsurf**

**ตัวเลือก "Add Server" ของ Cline ไม่แสดง**

ตัวจัดการเซิร์ฟเวอร์ MCP ต้องใช้ Cline **2.0** ขึ้นไป เปิดแผงส่วนขยาย VS Code หา Cline และคลิก **Update** หากมีอัปเดต หลังอัปเดตให้โหลด VS Code ใหม่ (`Ctrl+Shift+P` → "Developer: Reload Window")
