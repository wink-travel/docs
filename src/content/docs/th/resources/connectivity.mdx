## ทำไมการเชื่อมต่อจึงสำคัญ

ทุกเส้นทางการจองขึ้นอยู่กับข้อมูลสินค้าคงคลังของโรงแรมที่ถูกต้อง หากอัตราค่าห้องผิด ผู้เข้าพักจะสูญเสียความไว้วางใจ หากความพร้อมใช้งานผิด โรงแรมเสี่ยงต่อการจองล้มเหลว และหากสินค้าคงคลังล้าสมัย ไม่มีช่องทางใดที่ทำงานได้อย่างน่าเชื่อถือ Wink ขับเคลื่อนมากกว่าปุ่มจองบนเว็บไซต์ — ข้อมูลโรงแรมเดียวกันนี้สนับสนุนเส้นทางเว็บไซต์, ลิงก์ที่แชร์ได้, รหัส QR, ส่วนประกอบเว็บ, ร้านค้า WinkLinks, ลิงก์พันธมิตร, รายการ Traveliko, เส้นทางการจองโซเชียล, การส่งต่อ Agentic AI และกระบวนการสำหรับนักพัฒนา ทั้งหมดนี้ต้องการพื้นฐานเดียวกัน: **ARI** ที่ถูกต้อง — ความพร้อมใช้งาน, อัตราค่าห้อง และสินค้าคงคลัง

## เส้นทางการตั้งค่าทั้งสองแบบ

**เส้นทางที่ 1 — เชื่อมต่อกับผู้ให้บริการที่รองรับ.** ใช้เมื่อโรงแรมจัดการอัตราค่าห้องใน channel manager, PMS, CRS หรือผู้ให้บริการอัตราที่ Wink รองรับอยู่แล้ว โรงแรมเลือกผู้ให้บริการใน Extranet, เปิดใช้งาน Wink เป็นช่องทางในแดชบอร์ดของผู้ให้บริการ, ทำการแมปประเภทห้องและแผนอัตรา และผู้ให้บริการจะส่ง ARI ไปยัง Wink — เติมปฏิทินอัตราหลักโดยอัตโนมัติ เหมาะสำหรับโรงแรมหลายช่องทาง, การเปลี่ยนอัตราบ่อยครั้ง, ความต้องการสินค้าคงคลังสด และลดภาระงานแมนนวล

**เส้นทางที่ 2 — โหลดอัตราแบบแมนนวลใน Extranet.** ใช้เมื่อโรงแรมไม่ใช้ผู้ให้บริการที่รองรับหรืออยากดำเนินการ Wink ด้วยตนเอง ผ่าน `Distribution > Master rate calendar` — อัปเดตแบบวันเดียวและแบบกลุ่มในช่วงวันที่ เหมาะสำหรับสินค้าคงคลังขนาดเล็ก, การตั้งค่าเริ่มต้น หรือการทดสอบ **ต้องมีวินัย:** หากอัตราเปลี่ยนแปลงในการดำเนินงาน ต้องมีคนอัปเดต Wink และถ้ามีผู้ให้บริการเชื่อมต่อ การเปลี่ยนแปลงแบบแมนนวลอาจถูกเขียนทับเมื่อผู้ให้บริการส่งอัปเดตครั้งถัดไปสำหรับวันที่เดียวกัน

## ผู้ให้บริการที่เชื่อมต่อกับการโหลดแบบแมนนวล

| คำถาม | ผู้ให้บริการที่เชื่อมต่อ | การโหลดแบบแมนนวลใน Extranet |
|---|---|---|
| ใครอัปเดต ARI? | ผู้ให้บริการที่รองรับส่งอัปเดตไปยัง Wink | โรงแรมอัปเดตอัตราและความพร้อมใช้งานด้วยตนเอง |
| เหมาะสำหรับ | โรงแรมหลายช่องทาง, การเปลี่ยนแปลงบ่อย, สินค้าคงคลังสด | สินค้าคงคลังขนาดเล็ก, ใช้งานจำกัด, ไม่มีผู้ให้บริการเชื่อมต่อ |
| ภาระงาน | ภาระงานรายวันต่ำหลังตั้งค่า | การบำรุงรักษาแมนนวลอย่างต่อเนื่อง |
| พฤติกรรมแบบเรียลไทม์ | อัปเดต ARI อัตโนมัติจากผู้ให้บริการ | อัปเดตล่าสุดเท่าที่อัปเดตแมนนวล |
| ความเสี่ยง | ต้องแมปและตั้งค่าผู้ให้บริการให้ถูกต้อง | อัตราหรือความพร้อมใช้งานล้าสมัยหากไม่ดูแล |
| การแจ้งเตือนการจอง | แจ้ง channel manager / CRS / PMS ตามที่ตั้งค่า | โรงแรมได้รับการแจ้งเตือนการจองผ่าน Wink |

## ผู้ให้บริการที่รองรับ

Wink รองรับ channel managers หลายราย รวมถึงการเชื่อมต่อ PMS โดยตรงหรือผ่าน Channex เป็นพร็อกซี ยืนยันเวอร์ชันผู้ให้บริการ เส้นทางการตั้งค่า และข้อกำหนดการแมปกับทีม Wink ก่อนเปิดใช้งานจริง

| ผู้ให้บริการ | ประเภท | หมายเหตุ |
|---|---|---|
| SiteMinder | Channel manager | การเชื่อมต่อโดยตรง |
| Cloudbeds | Channel manager | การเชื่อมต่อโดยตรง |
| Travelclick | Channel manager | การเชื่อมต่อโดยตรง |
| RateGain | Channel manager | การเชื่อมต่อโดยตรง |
| D-EDGE | Channel manager | การเชื่อมต่อโดยตรง |
| YieldPlanet | Channel manager | การเชื่อมต่อโดยตรง |
| Rate Tiger | Channel manager | การเชื่อมต่อโดยตรง |
| Hotel Link | Channel manager | การเชื่อมต่อโดยตรง |
| Channex | Channel manager + PMS proxy | การเชื่อมต่อโดยตรง พร้อมพร็อกซีสำหรับ PMS หลายราย |
| SynXis | CRS | อาจต้องตั้งค่าเพิ่มเติมผ่าน SynXis Channel Connect Express |

ระบบ PMS หลายระบบ เช่น Mews, Apaleo, Opera Cloud และ OTA Sync สามารถส่ง ARI ไปยัง Wink **ผ่าน Channex** เป็นพร็อกซี หาก PMS ของคุณเชื่อมต่อกับ Channex ก็สามารถเข้าถึง Wink ได้ ยืนยันเวอร์ชัน PMS และการตั้งค่า Channex ก่อนเปิดใช้งาน (นี่เป็นรายการตัวอย่าง — ยืนยันผู้ให้บริการกับทีม Wink)

## การตั้งค่าผู้ให้บริการโดยย่อ

ใน Extranet ไปที่ `Distribution > Channel manager` เลือกผู้ให้บริการอัตราของคุณแล้วบันทึก ในแดชบอร์ดผู้ให้บริการ เพิ่มช่องทาง **Wink** และแมปประเภทห้องและแผนอัตราที่สร้างใน Wink เริ่มการส่งอัตราเต็มรูปแบบหากผู้ให้บริการไม่ทำโดยอัตโนมัติ จากนั้นตรวจสอบปฏิทินอัตราหลัก — อาจอัปเดตภายในไม่กี่นาที (เวลาขึ้นอยู่กับผู้ให้บริการและการแมป) ใช้ **Verifier** เพื่อจำลองคำขอราคาผู้เดินทางและทดสอบความพร้อมใช้งาน สกุลเงิน ส่วนลด และการแสดงอัตราก่อนส่งคำขอจริง สร้างการจองทดสอบเมื่อทีมเข้าใจพฤติกรรมการแจ้งเตือนแล้วเท่านั้น

## การแจ้งเตือนการจอง

การเชื่อมต่อไม่ได้หมายถึงแค่การส่งอัตรา *ไปยัง* Wink เท่านั้น — แต่ยังรวมถึงการไหลของการจองกลับ เมื่อมีการจองเกิดขึ้น channel manager, CRS หรือ PMS สามารถได้รับการแจ้งเตือนตามที่ตั้งค่า โรงแรมและผู้เดินทางได้รับอีเมลยืนยัน พันธมิตรได้รับการยืนยันการจองและการอ้างอิงบนเส้นทางพันธมิตร และนักพัฒนาสามารถฟัง webhook `booking.created` เพื่อรับรายละเอียดแบบเรียลไทม์

## Wink อยู่ตรงไหน

การเชื่อมต่ออยู่ระหว่าง Extranet และ Booking Engine [Extranet](/th/products/extranet/) คือชั้นควบคุมฝั่งโรงแรมสำหรับเนื้อหา ห้อง แผนอัตรา ข้อจำกัด ความพร้อมใช้งาน นโยบาย และการตั้งค่า Booking Engine; ผู้ให้บริการที่รองรับจะป้อน ARI เข้าไป หรือโรงแรมจะดูแลปฏิทินอัตราหลักด้วยตนเอง; และ [Booking Engine](/th/products/booking-engine/) ใช้ข้อมูลที่ได้รับการอนุมัตินั้นเพื่อดำเนินการจองจากช่องทางตรง, โซเชียล, WinkLinks, พันธมิตร, Traveliko, Agentic AI และช่องทางนักพัฒนา กฎง่าย ๆ คือ: **ยิ่งการเชื่อมต่อแข็งแกร่ง เส้นทางการจองก็ยิ่งน่าเชื่อถือมากขึ้น**

## ความผิดพลาดที่พบบ่อย

- **สมมติว่า Wink สามารถขายได้โดยไม่มีความพร้อมใช้งานปัจจุบัน** ต้องมี ARI จากผู้ให้บริการหรืออัปเดตแมนนวลใน Extranet ก่อน
- **เชื่อมต่อผู้ให้บริการแต่ไม่แมปห้องและแผนอัตรา** การตั้งค่าไม่สมบูรณ์จนกว่าจะทำการแมปถูกต้อง
- **แก้ไขอัตราแบบแมนนวลขณะที่มีผู้ให้บริการเชื่อมต่อ** การเปลี่ยนแปลงแมนนวลอาจถูกเขียนทับโดยอัปเดตผู้ให้บริการครั้งถัดไป
- **ลืมตรวจสอบความถูกต้อง** ทดสอบการแสดงอัตรา ความพร้อมใช้งาน และตรรกะส่วนลดก่อนส่งคำขอจริง
- **มองว่าการเชื่อมต่อเป็นแค่เรื่องเทคนิค** มันส่งผลต่อรายได้ การตลาด เส้นทางพันธมิตร อัตราการแปลง และความไว้วางใจของผู้เข้าพัก
