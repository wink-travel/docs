## การแนะนำโรงแรมไม่ใช่การจองโรงแรม

“AI การเดินทาง” ส่วนใหญ่ในปัจจุบันหยุดอยู่ที่การแนะนำ ผู้ช่วยแนะนำโรงแรมสามแห่ง จากนั้นส่งต่อนักเดินทางไปยังเว็บไซต์หรือ OTA เพื่อจองจริง ๆ เส้นทางขาดหาย ราคาอาจไม่สามารถจองได้ และไม่มีใครเก็บบริบทแหล่งที่มาไว้

**ตัวแทน AI** แตกต่างจากคำตอบ AI ตัวแทนไม่ได้แค่บรรยายโรงแรม — มันทำงาน: ตรวจสอบความพร้อมใช้งานแบบสด รวบรวมการจอง รับชำระเงิน และตอบสนองเมื่อมีการเปลี่ยนแปลง เพื่อให้เกิดขึ้นอย่างปลอดภัย ตัวแทนต้องการมากกว่าข้อความ มันต้องการข้อมูลที่มีโครงสร้าง ปัจจุบัน และสามารถจองได้ รวมถึงชั้นธุรกรรมที่สามารถเรียกใช้ได้

นี่คือความแตกต่างระหว่าง [AI discovery](/th/resources/ai-discovery-hotels/) ซึ่งเกี่ยวกับการ **ถูกค้นพบและเข้าใจ** กับ agentic commerce ซึ่งเกี่ยวกับการ **ทำธุรกรรม**

## สิ่งที่ตัวแทนต้องมีเพื่อทำธุรกรรมได้

การจองโรงแรมเป็นเหตุการณ์ทางการค้าที่แท้จริง: ห้องที่ถูกต้อง อัตราราคาที่ถูกต้อง ความพร้อมใช้งานจริง นโยบาย การชำระเงิน และการยืนยันที่ซิงค์กลับไปยังโรงแรม ตัวแทนจะทำธุรกรรมได้ก็ต่อเมื่อแต่ละส่วนพร้อมใช้งานในรูปแบบการดำเนินการที่เรียกใช้ได้

| ตัวแทนต้องการ | ทำไมจึงสำคัญ |
|---|---|
| ซัพพลายที่มีโครงสร้างและสด | ข้อมูลที่เก็บจากเว็บจะล้าสมัย; ตัวแทนต้องการสต็อกที่โรงแรมควบคุมและเป็นปัจจุบัน |
| อัตราราคาและความพร้อมใช้งานแบบเรียลไทม์ | ราคาที่ตัวแทนเสนอจะต้องสามารถจองได้จริงในขณะนั้น |
| การดำเนินการจอง | การสร้างการจองต้องเป็นการเรียก API จริง ไม่ใช่การส่งต่อไปยังฟอร์มเว็บ |
| การชำระเงิน | ตัวแทน (หรือนักเดินทางผ่านตัวแทน) ต้องสามารถชำระเงินได้ พร้อมใช้ตรรกะนโยบาย |
| การอ้างอิงแหล่งที่มา | แหล่งที่มา แคมเปญ หรือตัวแทนที่สร้างการจองควรยังคงเชื่อมโยงอยู่ |
| เหตุการณ์ | ตัวแทนควรตอบสนองต่อการยืนยัน การเปลี่ยนแปลง การยกเลิก และการคืนเงินได้ |

หากไม่มีสิ่งเหล่านี้ ตัวแทนสามารถแนะนำได้ — แต่ไม่สามารถจองได้

## วิธีที่ตัวแทน AI จองโรงแรมบน Wink

Wink เป็น API-first: ทุกฟีเจอร์ของแพลตฟอร์มสามารถเรียกใช้งานจากภายนอกได้ และเซิร์ฟเวอร์ MCP ที่โฮสต์จะเปิดเผยสัญญา API สดให้ตัวแทน โฟลว์ตัวแทนทั่วไป:

### 1 — เชื่อมต่อและอ่านสัญญาสด

ตัวแทนเชื่อมต่อกับเซิร์ฟเวอร์ MCP ที่โฮสต์และใช้ `api_search` กับ `docs_search` เพื่อค้นหาการดำเนินการที่ถูกต้องและอ่านสคีม่า request/response จริง — ไม่ต้องเดา endpoint หรือใช้เอกสารที่ล้าสมัย

```bash
claude mcp add --transport http \
  wink-docs https://docs.mcp.wink.travel/mcp
```

### 2 — ค้นหาสต็อกที่จองได้

ตัวแทนค้นหาซัพพลายที่โรงแรมควบคุม รวมถึงการค้นหาตามตำแหน่งทางภูมิศาสตร์ และอ่านอัตราราคาและความพร้อมใช้งานสดจาก channel manager ที่เชื่อมต่อ

### 3 — สร้างการจอง

การสร้างการจองเป็นการดำเนินการ REST API ตัวแทนรวมห้อง อัตรา วันที่ และแขก แล้วสร้างการจองผ่าน API

### 4 — รับชำระเงินและยืนยัน

[Booking Engine](/th/products/booking-engine/) ดำเนินการทำธุรกรรม — เช็คเอาต์ การชำระเงิน (Wink เป็นผู้ค้ารายการ) ตรรกะนโยบายการยกเลิก การยืนยัน และการซิงค์การจองกับ PMS หรือ channel manager ที่เชื่อมต่อ การอ้างอิงแหล่งที่มาและพันธมิตรจะถูกเก็บรักษาผ่านการจอง

### 5 — ตอบสนองต่อเหตุการณ์

ตัวแทนสามารถสมัครรับเหตุการณ์ webhook เช่น `booking.created` เพื่อกระทบยอด แจ้งนักเดินทาง หรือกระตุ้นการดำเนินการติดตามผล

หลักการ: **ตัวแทนสร้างหรือส่งต่อเจตนา; Booking Engine ยังคงเป็นชั้นการดำเนินการรองรับทุกการส่งต่อ**

## การค้นหา AI กับตัวแทน AI

พวกเขาแก้ปัญหาที่แตกต่างกัน และโรงแรมต้องเตรียมพร้อมสำหรับทั้งสองอย่าง

| | การค้นหา AI / เครื่องมือคำตอบ | ตัวแทน AI |
|---|---|---|
| เป้าหมายนักเดินทาง | ค้นหาและเปรียบเทียบโรงแรม | จองและจัดการการเข้าพัก |
| สิ่งที่โรงแรมต้องการ | [เนื้อหาที่มีโครงสร้างและสามารถรวบรวมได้](/th/resources/hotel-content-answer-engines/) | API สด อัตรา การจอง การชำระเงิน |
| สถานะสุดท้าย | คำแนะนำ | การจองที่ยืนยันแล้ว |
| พื้นที่ของ Wink | ซัพพลายสะอาด + เนื้อหาพร้อมตอบคำถาม | REST API, เซิร์ฟเวอร์ MCP, Booking Engine |

[AI discovery for hotels](/th/resources/ai-discovery-hotels/) ครอบคลุมด้านการค้นหา; คู่มือนี้ครอบคลุมด้านการทำธุรกรรม

## ใครสร้างตัวแทนบนการค้าโรงแรม

Agentic travel commerce ไม่ได้มีแค่ผู้ช่วยผู้บริโภค โครงสร้างพื้นฐานเดียวกันนี้ขับเคลื่อน:

- **ผู้ช่วยเดินทางผู้บริโภค** ที่ค้นหา จอง และจัดการการเข้าพักตั้งแต่ต้นจนจบ
- **ตัวแทนธนาคาร โปรแกรมสะสมแต้ม และซูเปอร์แอป** ที่ฝังการจองโรงแรมไว้ในประสบการณ์ลูกค้าที่มีอยู่แล้ว
- **ระบบอัตโนมัติของพันธมิตรและผู้สร้าง** ที่ค้นหาโรงแรมที่มีสิทธิ์ สร้างสินทรัพย์ และรักษาการอ้างอิงแหล่งที่มา — ได้รับค่าคอมมิชชั่นเริ่มต้น 10% จากการจองที่ยืนยันแล้ว
- **ผู้ช่วยข้างโรงแรม** ที่ช่วยทีมสร้างเนื้อหาและวิเคราะห์ประสิทธิภาพผ่าน [Extranet](/th/products/extranet/), [Social](/th/products/social/) และ [Studio](/th/products/studio/) ขณะที่โรงแรมยังคงควบคุมกฎเกณฑ์

## ทิศทางในอนาคต

ความสามารถข้างต้นพร้อมใช้งานแล้วผ่าน REST API และเซิร์ฟเวอร์ MCP ทิศทางคือการค้า agent-native ที่ลึกขึ้น: primitive การจองที่หลากหลายสำหรับตัวแทน, ตัวตนและการอนุญาตของตัวแทนสำหรับการทำธุรกรรมแทนนักเดินทาง, และตัวแทนที่มีส่วนร่วมในฐานะแหล่งรายได้ที่อ้างอิงได้ในเครือข่ายพันธมิตร เส้นทางหลักคือความสม่ำเสมอ — **โครงสร้างพื้นฐานการค้าเดินทางสำหรับตัวแทน AI** โดยมี Booking Engine ดำเนินการรองรับเบื้องหลัง

## ข้อผิดพลาดทั่วไป

- **ถือว่า AI discovery และตัวแทน AI เป็นโปรเจกต์เดียวกัน** อย่างหนึ่งคือเนื้อหาและโครงสร้าง อีกอย่างคือ API และการดำเนินการ คุณต้องมีทั้งสองอย่าง
- **ปล่อยให้ตัวแทนอ้างราคาโดยที่ไม่สามารถจองได้** ราคาต้องมาจากอัตราราคาและความพร้อมใช้งานสด ไม่ใช่จากหน้าที่เก็บข้อมูลมา
- **ละทิ้งการอ้างอิงแหล่งที่มาที่จุดส่งต่อ** หากตัวแทนสร้างความต้องการ การจองควรเชื่อมโยงกับแหล่งที่มานั้น
- **ข้ามชั้นการดำเนินการ** คำตอบไม่ใช่การจองจนกว่าจะมีการเช็คเอาต์ ชำระเงิน และยืนยันจริง
